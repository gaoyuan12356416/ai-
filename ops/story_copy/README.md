# 四端剧情分行文案 v1.1

2026-11-20 起按实际发布时间优先生成，默认三路并发；五分钟内到期任务跳过凑批等待。时间映射、配置、验证及仅切换独立 worker 的部署/回滚见 `doc/20261120.story-copy-priority-concurrency.md`。

FB、X 素材池、X 短剧池和 X 标签画像自动发布模板按端开关。两种素材池界面共享 X 素材池状态。模板自动任务使用模板冻结的任务编号和账号语言。开关记录切换时各来源的高水位，仅对之后创建的任务生效。源队列是实际发布的唯一所有者。

生成器在 CPU 上使用当前 Codex 登录的 app-server。按产品、剧、语种合并实际需求，满 100 条或准备时限到达后提交；遇到模型输入或输出预算不足才拆分。一条用一行 JSON，已完整验收的行独立保存。程序使用真实任务归因链接组装七行正文。每个 X 发布端均在最终文本上检查 280 加权限制。按 2026-11-17 的运营要求，每条任务仅依据当前剧目、素材与语言生成文案，不读取历史发布文案、旧草稿或旧引导语，也不要求减少重复表达。正文相似或完全相同均可使用，引导语直接选用首个合格候选。已有历史与指纹仅保留作审计记录；任务主键与发布幂等保护不变。部署和回滚见 `doc/20261117.story-copy-no-history.md`。

人工单条成稿优先。源发布器先得到既有正文，再以有界的本地读取尝试选稿。无稿、离线、额度不足、文案不合格均保留现行正文，发布线程不发起模型或飞书调用。源数据库保存最终用稿回执，晚到的结果不能替换定稿。额度监控沿用 CPU 既有主备策略。首次生成失败持久记录，随下一批文案队列重试一次；暂无新队列则 60 秒后独立重试。仅第二次仍失败才在独立队列投递给郜远的私聊告警，持续同因故障仍每 15 分钟汇总。已成功项不重做，已定稿项不回放，详见 `doc/20261117.story-copy-retry-once.md`。

运行 `python -m unittest tests.test_story_copy` 验证发布降级和批次边界。部署脚本从经核对的 GitHub 提交生成对当前不同版本发布器的精确补丁，保存原文件及摘要。回滚仅涉及代码、静态资源和新增服务，不恢复业务数据库。
