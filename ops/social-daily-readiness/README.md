# 社媒日报次数检查

北京时间 10:00 登记前一个 UTC 统计日。原日报 timer 每五分钟调用一次
`youtube_publisher_daily_report.py --poll`。每次只对还在等待采集的日期读业务源表。
停机错过的日期从首次启用后的登记进度续上，跨日等待的报告沿用原统计日。

次数来自只读副本的 `kunlunads_dev.ads_facebook_page_insight`。按统计日与日报站点
检查点击、访问和激活记录的更新时间。各站点均有次数记录，且这些记录均在该 UTC 日
结束后写入，才开始完整采集。真实零次数可通过。查询出错、部分站点仍旧或归属和
账单校验未完成时，下一轮继续。完整采集沿用 480 秒预算，单条 SQL 仍走 FIFO 限流。
次数来源证据冻结在正式报告的 `count_source`。投递沿用原群和日期防重账本。
发送中、结果未知、明确失败的投递可在 `delivery.sqlite3` 按日期与群查看并核对回执。

部署从 GitHub 固定提交叠加到当前独立日报 release。将本次 timer/service drop-in
装到原日报，两个日报服务均装 TikTok WAL 辅助文件访问配置，主数据库维持只读。
停用旧预采集 timer，保留手动准备入口。部署目录记录旧指针、unit 备份和运行校验。
运行该目录内的 `bash rollback.sh` 可恢复旧代码和两个 timer 的原状态，并保留
当前日报、调度登记与飞书回执。
