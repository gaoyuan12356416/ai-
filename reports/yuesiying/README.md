# 岳思颖素材确认表指标（2026-11-07）

本目录保存无业务数据的页面模板及共享素材目录工具；不是独立可发布站点。只覆盖已备份且校验哈希的当前私有报表中的同名文件，不替换其他资源、授权配置或独立报表。不创建定时器或自动执行任务。

用户确认口径：总收入=AF D0 (`af_revenue0`)，新增用户数=AF安装数 (`af_installs`，不是去重人数)，广告曝光=`impressions`，广告点击=`clicks`。收入直接沿用D0 ROAS分子；排名、门槛、所复制ID不因新增列改变。

使用次数沿用素材聚合器的 `delivery_cnt`：取所选窗口最新日记录；最新日多个产品或平台的 MIN/MAX 不一致时显示范围并标待核对，不跨日求和，也不把各分组计数相加。

## 手工刷新数据契约

素材库存刷新使用 [共享目录工具](catalog/README.md) 的 `refresh-source` 入口，把原有只读SELECT分批写入 `ads_ai` 的已核验目录版本；不再为每次刷新导出完整 `library.json`。保持原查询过滤范围，完成校验后给工作目录绑定固定版本，再运行既有构建入口。旧版原始JSON先核验私有归档回执再清理，未知/未核验版本不作为报表输入。

沿用既有 `ads_custom_source_insight` 查询的产品、应用、平台、日期、分组、HAVING 范围。
同一个分组查询同时输出 `SUM(af_installs) new_users, SUM(impressions) impressions, SUM(clicks) clicks`。
素材点数组的前10项保持不变，末尾追加上述3项；空值保留null，不伪造0。

数组顺序为 `dt, drama_key, material_id, app_index, platform, spend, af_revenue0, event2, delivery_min, delivery_max, af_installs, impressions, clicks`。
`data.json.materials.point_schema` 必须记录该顺序。缺失扩展项时3列显示待核实而非0。
当日/近3日、产品/渠道过滤同时作用于全部指标。主表 points 从同一批素材数据重聚合并逐项对账。

总收入的AF D0标记、AF安装说明、使用次数最新日/冲突说明必须保留。桌面及手机的指标表局部横向滚动，不应撑宽整个页面。

验证聚合兼容旧数组、空值、零值、最新日使用数冲突，分类标签/排名与原算法一致；测试两种确认入口、当日及近3日、四种产品范围，并验证复制ID未变化。
真实数据回归需逐字段比较聚合结果与表格显示，核对收入/消耗=D0 ROAS。
保留Top+Good、本次复制类型、权限和已有独立报表。上传COS私有目录，核对文件清单与核心文件内容、匿名403；原受保护入口匿名302、鉴权端点401。

回滚：交换本次部署目录与保存的旧site目录；不恢复数据库，不重启服务。须先确认原站点未被其他任务更新。
