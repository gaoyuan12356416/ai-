# 小语种宽松候选匹配（2026-11-13）

用户在原话题明确选择“核心名称部分相似即可列为候选，全部需人工核对”。
仅修改已有手工报表的匹配模块；不创建定时器、自动执行器或媒体写操作。

## 范围与算法

- 先按短剧ID唯一关联同一资源及语种，未知/冲突仍跳过。
- 原有名称归一化基础上移除开头“跑量迭代”标签。
- 同资源下，将核心名称拆成去重连续3字符片段。共有片段至少6个，且
  Dice=`2×共有片段/(两边片段数之和)`达到0.55时进入候选。
- 也保留非空核心名完全相等、以及较短核心名至少12字符的包含匹配。
- 排除英语候选、同语种、原素材本身、已选素材、无有效库存ID候选。
- 名称分数不是内容一致概率。不做视频内容识别，不把名称相似视为同版。
- 索引用资源内倒排片段生成，输出每条原素材的matches，前端不做全库二次扫描。
- 序列化使用indexVersion=2的matchRefs/matchSets共享列表；仅压缩重复内容，
  不截断候选，不改分数、关联或筛选。构建后逐条还原比对原结果。

## 人工核对与兼容

所有候选初始不勾选。按需求人2026-11-18确认，支持表头全选当前筛选结果，不包含被过滤版本；筛选改变清空选择，复制仍去重并检查确认范围有效。批量选择不代表完成内容核对。

覆盖表支持分别筛选需要人工确认、被当前筛选过滤、来源待核实、未匹配及无有效ID／已排除。原素材花费与D0 ROAS固定使用原确认窗口，不随小语种窗口变化；缺失指标显示“—”，零花费ROAS显示“—”。
保留消耗窗口/上限、零消耗、语种、版本、有效ads_source.id过滤；无ROAS门槛。
时长缺失或相差超过2秒额外提示，时长接近也不免除人工核对。
新前端只接受loose-name-v1-manual-review索引，旧缓存不静默回退为精确匹配。

回归样例：8166308（1097秒）应能检索8181355（ko，1094秒），显示待人工核对
及3秒时长差；本例名称证据不能证明两视频内容完全一致。

源码：catalog/consumer.py、catalog/build_localizations.py、low-language.js。
测试：python3 -B -m unittest discover -s reports/yuesiying/catalog -p test_catalog.py。
部署只更新既有受保护报表及既有构建组件，不改鉴权、Nginx或服务配置，不需重启。
快照数据与原报表一致，效果和库存时间分别标注；不声称已刷新为当前全库。
# 当前规则（2026-11-17，替代下方历史宽松规则）

匹配标识 `structured-body-author-version-v2`，索引版本3。直接使用已确认原素材名称
查找候选字段键，不要求原素材ID存在库存。当前报表所需候选可由显式、完整、校验过的
当前CID/字段键分片补查；未完成读取不能发布，不以旧库存覆盖缺口假称后台没有。
同一资源内，剧号、完整主体片段
（忽略独立语种标记）、作者（大小写归一化）、日期之后的数字版本号必须一致。
日期可以不同；AI小语种/AI翻转、跑量迭代、EN已验证、时长和扩展名不影响匹配。
保留主体的数字分段，`2_13` 不等于 `21_3`；精剪、混剪、二创不能互换。
支持 11.6_1、11_6_1、11-6-1、1106-1、261111-1；图片比例后缀先单独识别，
已知比例不同不合并。日期后的尾号缺失或有歧义时，
原素材标为待核实，不自动匹配，也不计入确定未匹配。

例：12M_30680_2_9_EN_二创_chenhan_11.6_1 与
12M_EN已验证_30680_2_9_AR_二创_CHENHAN_11.8_1 可匹配；
精剪、不同片段、不同作者、不同尾号均排除。ph/tl 是现有同一菲律宾语命名别名。
不再使用55%名称相似度或包含关系；不证明内容同版/当前可投，仍须逐条人工核对。
近3天≤$5、包括零消耗、无ROAS门槛、有效ID校验、当前语种/英语排除、确认范围失效保护不变。
