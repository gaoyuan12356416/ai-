# TT 发布池手动发布与自动发布开关修复

## 背景

TT 发布池存在两类交互故障：

1. 素材后台制作完成后，页面只刷新制作列表，没有刷新排期中的可用素材统计，导致“立即发布一条”继续保持不可用。
2. 关闭自动发布被错误地套用开启排期的发布确认、账号配置、实时 creator-info 和时间校验；后台刷新还会覆盖未保存的开关状态。

## 需求

1. 参考 X 素材池，把自动发布设置作为独立的可保存区域：
   - 开启或修改自动发布时，继续要求账号可发布、发布设置完整、实时 creator-info 成功、时间合法和用户确认。
   - 关闭自动发布时，只要求已选账号、排期已加载和版本一致；不得要求新的发布确认、creator-info、账号发布设置、正式发布门禁或合法发布时间。
   - 关闭只停止未来自动选材，不删除待发素材，不取消既有队列，也不改写历史发布确认。
2. 已有排期的账号即使后来变为不可发布，仍可在页面中保持选中并关闭自动发布。
   - 账号从安全候选列表消失时，只显示不含账号资料和凭据的匿名管理占位。
   - 账号只读源整体不可用时，页面仅展示本地已有排期并允许停用；不得新建或重新启用排期。
3. 用户修改自动发布开关或时间后，账号、素材池或制作状态的后台刷新不得覆盖未保存内容。
   - 版本冲突必须丢弃旧草稿并加载最新设置，要求用户重新修改。
   - 保存进行中锁定排期控件与账号选择；旧的异步读取不得覆盖保存结果。
4. “立即发布一条”只在存在真正 `available` 的素材且服务端允许时开放：
   - 有素材正在制作时显示制作中数量，并在完成后自动刷新排期事实和按钮状态。
   - 制作状态刷新失败后必须在后续轮询继续重试；选中账号使用账号级查询和汇总指纹，不受全局最新 100 条分页挤出影响。
   - 无可用素材且无制作任务时明确显示暂无可立即发布素材。
5. 保留排期版本冲突保护、手动发布幂等保护和现有正式发布门禁。

## 安全边界

- 本次修复不得代替用户触发真实 TikTok 发布。
- 本次修复不得在验收时关闭或开启生产排期；只验证页面草稿态和只读接口。
- GPU 制作与发布代码、COS 配置和媒体 profile 不变。
