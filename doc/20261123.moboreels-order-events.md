# Mobo order sync: recharge and refund events

The supplier's all-orders response can contain both a recharge and a later refund
with the same `ref_order_id`, different `create_time`, and different `status_text`.
Numeric status queries 0 and 1 confirm these are distinct financial events. The
former ID-only duplicate check rejected the whole order part, and the database's
ID-only unique index also prevented retaining both events.

Match each complete observation to its numeric status filter. Preserve legacy
recharge keys and use a deterministic refund key. Collapse equivalent repeated
observations, with an audit count on the run part. Keep both event dates and raw
responses. Conflicting observations or drifting status snapshots remain explicit
failures; independent advertising days still complete. Existing report aggregation
already subtracts refund amounts and needs no formula changes.

Replace `uk_order` with a nonunique `idx_order_ref`. The deterministic `row_key`
primary key remains the idempotency constraint. No existing row is rewritten or
deleted. The deployment checks and backs up the existing small, recharge-only
table before this one-table migration, then verifies identical row hashes on the
read replica. New installations use the updated base DDL.

Validation: order synchronization, matching, cross-page duplicate handling,
repeated ingestion, refund dates, amount/ownership drift, unknown-write readback,
report aggregation and task-owner attribution tests. Replay saved real supplier
responses in memory without database writes before deployment.

Deploy from the exact GitHub commit:

```sh
python3 scripts/deploy_moboreels_clicks.py stage DEPLOYMENT --profile order-events --baseline 6515875c
python3 scripts/deploy_moboreels_order_events.py migrate DEPLOYMENT
python3 scripts/deploy_moboreels_clicks.py apply DEPLOYMENT
```

Only the `orders.py` overlay is activated, preserving current unrelated runtime
files. Use the existing short port-8864 admission barrier and drain checks; do not
stop publishing channels or interrupt active supplier requests. A reviewed
`--mirror-baselines` file may pin the main API's existing mirror independently.
Reconcile the failed rolling run, then start a fresh November 22–23 run so today's
query ends at the new request time. Verify the read replica, run coverage, and
the actual report response. Advertising remains T+1.

Rollback (run using the same deployed source checkout):

```sh
python3 scripts/deploy_moboreels_order_events.py rollback DEPLOYMENT
```

Rollback preserves all current orders, refunds, raw responses and ledgers, and
retains the event-compatible index. It stops only `moboreels-report-sync.timer`
because the old collector cannot safely represent these events. Restore an
event-compatible collector and restart that timer to resume collection. Do not
restore the old financial backup over newly observed business facts.
