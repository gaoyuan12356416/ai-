# Facebook 视频发布 Page 筛选

视频发布的 Page 选择区初始不渲染全部配置。按添加者（Page 配置的
`created_by` / `created_by_name`）、语言、Page ID、名称组合筛选，点击
“确定”后显示结果；ID 和名称支持包含匹配，名称不区分大小写，空条件
可显示全部。修改条件后须再次确定，翻页继续使用已确认条件。

每页 50 条，跨页、重新筛选及刷新配置保留已选 ID、配对、文案和预约。
全选只选当前页可用项；取消本页和清空已选分别操作。失效授权继续禁用，
缺失的草稿 Page 继续显示原因。Page 查询使用 Map，勾选不重建素材控件。

本次只改善前端展示和交互；仍使用现有权限范围内的 `/pages` 全量接口。
发布范围、语言资格、预检、提交、草稿格式、未知操作核对均保持原逻辑。

验证：`node --check static/fb-video-publish.js`、既有
`node tests/test_moboreels_fb_ui.js`，以及运行完整脚本的隔离 DOM 验证：
3163 条配置初始零行、确认后最多 50 行、四条件交集、输入不自动搜索、
空结果、翻页/重新筛选保留勾选、本页选择/取消、授权失效、草稿缺失项、
原文案和预约保留、旧草稿锁定。筛选操作无写请求。

部署只替换三份 `fb-video-publish.js`（Nginx、主 API 静态目录、当前 FB
runtime），并更新三个入口页面中该脚本的版本号。保留各入口其他差异；
不重启服务，不操作数据库、队列或平台发布。

从 GitHub 拉取本分支精确提交到 `/mnt/data-disk/fb-page-filters-20261117/source` 后：

```sh
python3 /mnt/data-disk/fb-page-filters-20261117/source/ops/fb_publish_page_filters/deploy.py prepare /mnt/data-disk/fb-page-filters-20261117/deployment
python3 /mnt/data-disk/fb-page-filters-20261117/source/ops/fb_publish_page_filters/deploy.py apply /mnt/data-disk/fb-page-filters-20261117/deployment
```

先核对 12 个文件的基线哈希，备份并生成 manifest，再安装。验收公开脚本
哈希、页面版本号、服务 PID 不变和浏览器筛选/分页。回滚只还原这些静态文件：

```sh
python3 /mnt/data-disk/fb-page-filters-20261117/source/ops/fb_publish_page_filters/deploy.py rollback /mnt/data-disk/fb-page-filters-20261117/deployment
```

如有后续文件或 runtime 漂移，先核对差异，不能覆盖其他更新。
