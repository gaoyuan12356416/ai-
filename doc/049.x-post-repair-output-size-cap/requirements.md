# X 修复视频体积上限故障修复

## 背景

2026-08-18 的素材池三个自然批次均在 X 写入前失败。生产账本显示每批为零队列、零发布、零未知结果；直接原因是 FIFO 候选视频经 GPU 统一转码后超过 X 工作流的 512 MiB 上限，导致完整账号批次无法凑齐。

## 需求

1. 保留现有 H.264 High、yuv420p、30 fps、GOP 60、AAC-LC 48 kHz 双声道、720 画布、140 秒及 4 小时边界。
2. 短视频继续使用既有 5 Mbps 目标码率、6 Mbps 最大码率和 10 Mbps缓冲区。
3. 对长视频根据最终输出时长和 `max_output_bytes` 计算保守码率预算，预留音频、容器开销及 12% 体积余量。
4. 计算后仍无法满足最小视频码率时必须在转码前失败，不得产出超限文件或调用 X。
5. CPU 与 GPU 使用新 profile，禁止复用旧 profile 的 COS 修复结果。
6. 不重放 2026-08-18 的失败批次；验证不得创建真实 X 帖子。

## 验收

- 139 秒输入保持原码率参数。
- 900 秒和 14399 秒输入的最大理论码率预算不超过保守体积预算。
- 修复清单记录实际使用的目标码率、最大码率、缓冲区、音频码率和安全比例。
- 本地完整 X 回归、GPU 真实离线转码、CPU/GPU 健康检查、SQLite 完整性和自然调度检查通过。
