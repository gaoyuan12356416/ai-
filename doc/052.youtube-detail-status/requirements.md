# 052.youtube-detail-status 需求与技术设计

## 背景

YouTube 发布接口异步入队后会重新打开合成任务详情，但原页面只把英文底层字段混在产物列表中，操作者无法快速确认本次点击是否形成发布记录、当前处于哪个阶段。

## 目标

在任务详情页建立独立的 YouTube 发布记录区域；成功入队后立即显示本次记录及一个明确的中文状态值，并自动更新非终态记录。

## 范围

### 包含

- 展示当前任务最近 20 条正式 YouTube 发布记录，最新一条标记为“本次发布”。
- 展示记录 ID、标题、素材类型、创建时间、总状态、视频/评论/同步子状态和失败原因。
- 对排队、校验、下载、上传、YouTube 处理、发布成功、发布失败、结果待核查等状态做中文映射。
- 详情抽屉打开期间，每 3 秒刷新存在非终态的发布记录，终态后停止轮询。

### 不包含

- 不修改发布队列、数据库结构、YouTube API 或 Worker 行为。
- 不创建或重放真实发布任务。

## 用户故事 / 业务规则

操作者提交发布后，应在返回的详情页立即看到唯一记录和“排队中”；状态推进时原记录更新，不新增伪记录。历史记录保留并标记为“历史发布”。

## 交互与流程

发布弹窗提交成功 → 后端返回 202 → 前端重新读取任务详情 → 独立区域显示“本次发布 #ID”和状态 → 非终态自动刷新 → 终态停止刷新。

## 技术设计

### 影响模块

`static/index.html`、`static/drama-synthesis.html` 和浏览器回归测试。

### 数据结构

复用现有 `youtube_publish_tasks` 安全字段，无数据库变更。

### API / 接口

复用 `GET /api/drama-material/jobs/{job_id}` 和现有发布 POST；接口合同不变。

### 异常与边界

- `unknown_outcome=1` 必须显示“结果待核查”，不得显示成功或自动重试。
- 视频已发布但评论或统一记录同步失败时，必须显示部分失败状态。
- 关闭详情抽屉后停止轮询；刷新失败时保持现有记录并继续后续刷新。

## 验收标准

1. 入队成功后详情页出现“本次发布 #ID”和“排队中”。
2. 所有状态均为中文业务含义，并保留子状态与失败原因。
3. 非终态每 3 秒刷新，关闭详情或到达终态后停止。
4. 页面不存在记录时不显示空模块。
5. 自动测试不调用真实 YouTube。

## 风险与待确认

无待确认项。轮询复用单任务详情接口，且每个详情抽屉最多一个定时器。
