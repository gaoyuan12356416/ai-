# Allow repeated AI captions

The operator requested that caption similarity never reject a generated caption,
including exact duplicates. All four story-copy endpoints now accept repeated
plot text and reuse an existing click hook when no unused candidate is available.
Language, evidence, formatting, final length, manual-copy priority, source identity
and publication idempotency checks remain unchanged.

`store.initialize()` converts the existing `jobs_exact` unique index to an ordinary
index in one transaction. Task keys, drafts, fingerprints, history, alerts and
native publication receipts remain intact. No historical task is replayed.

Validation: `python -m unittest tests.test_story_copy` covers identical text across
four endpoints, exact and near-exact history reuse, legacy index migration,
repeated hooks, task idempotency, optional-copy fallback and publication rendering.

Deployment from the GitHub-fetched checkout:

```sh
python3 ops/story_copy/deploy_allow_repeated.py prepare /mnt/data-disk/story-copy-deploy/allow-repeated-COMMIT
python3 ops/story_copy/deploy_allow_repeated.py apply /mnt/data-disk/story-copy-deploy/allow-repeated-COMMIT
```

The staged release copies the active central runtime and replaces only `store.py`
after checking it against the reviewed parent. The existing central switch waits
for the active generation batch and holds the database write lock across worker
stop and release switching, preventing another batch claim during that interval.
Publisher and scheduler services are not restarted.

Rollback uses the same checkout and folder with `rollback` instead of `apply`.
It restores the previous producer code while preserving all current business data.
The ordinary `jobs_exact` index remains; retaining its name allows older startup
code to run even after duplicate captions exist. Never restore the database backup
over new publication receipts or delete accepted duplicate captions to recreate
the former unique index.
