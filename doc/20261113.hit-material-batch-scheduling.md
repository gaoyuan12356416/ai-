# 爆款素材一对一匹配与提前排期

FB / X（标签画像独立发布）接受 1–200 条素材 ID，重复 ID 合并。保留语言、权限、素材防重与账号能力检查，使用受众和题材的收入画像权重，在可匹配关系内先最大化分配数量，再最大化总匹配分数。一次提交中每个素材和 Page / 账号均只使用一次。单条无效素材记录原因，不阻断其他可匹配素材。

爆款素材和爆款剧冻结产品、剧目、语言及有效可投放时间。未来剧立即进入制作流程，预约时间为可投放时间减 30 分钟；已过此时间则尽快执行。普通自动发布不获得未来剧豁免。X 的原始任务、独立调度队列和最终写入入口使用同一冻结排期，避免制作完成即提前发布。

浏览器保留提交标识。网络错误后“重试确认”复用该标识与素材列表，不重建另一批任务。服务端回执保留分配对象、画像分数、排期及未匹配原因。旧单素材请求和历史任务保持兼容。

## 验证

- 一对一最优匹配与穷举结果比较、语言隔离、时长能力、素材排重、部分无效输入、同标识重试。
- 未来目标精确选择、立即准备、预约时间前不能发布、恰好到点允许发布、调度 prepare / publish 阶段分别使用正确时间。
- 浏览器实际加载两个页面；多 ID 去重、模拟 503 后同标识重试、分配结果与北京时间显示。
- 仅模拟发布依赖与临时 SQLite；不创建线上测试帖子。

## 部署和回滚

使用 GitHub 上已提交的两个分支作为 source。`deploy/hit-publish-overlay.json` 记录已核对的原始版本及覆盖文件。服务器执行 `python3 -m scripts.deploy_hit_publish prepare --x-source X_SOURCE --fb-source FB_SOURCE --folder DEPLOYMENT`，保留最新运行树的其他文件、文件归属和四份在线 SQLite 备份。无需数据库迁移。

切换前分别保存 fb / x / coordinator 调度健康快照。先在完整候选运行树执行测试，再依次执行 `activate --lane coordinator`、`activate --lane x`、`activate --lane fb`，最后执行 `static`（均带相同 `--folder`）。X 使用已部署的非 daemon 请求线程与 graceful shutdown；FB 和协调器仅在本进程已接收请求排空后切换。远程 GPU 作业、租约和回执保留，不要求其他渠道空闲。切换后恢复原来启用的 timer / path 与健康快照中的依赖服务，核对端口、文件摘要和进程目录。

`python3 -m scripts.deploy_hit_publish rollback --folder DEPLOYMENT --ui-only` 只恢复入口。去掉 `--ui-only` 同时恢复旧执行版本，但若新格式爆款任务仍在执行，保留兼容执行代码并明确报告未完成任务；待它们终态后再执行完整回滚。所有回滚仅回滚代码，绝不覆盖当前账本、凭据或回执。实际 SHA、服务器目录、验证记录与命令在上线记录中另列。
