# BUG-002 短剧高优 PUT 返回 HTTP 502

## 现象

2026-08-11 15:42:54 和 15:43:03，管理员在生产页面对短剧池记录 `137` 提交
`PUT /api/admin/x-posts/drama-pool/137/priority`，Nginx 两次返回 HTTP 502。

## 根因

主 API 只通过 `from urllib.parse import ... urlparse` 导入了 `urlparse`，但新增的
`DramaMaterialHandler.do_PUT()` 使用了未导入的 `urllib.parse.urlparse`。请求因此在
鉴权、审计和 Sidecar 调用之前抛出 `NameError`，连接提前关闭后被 Nginx 表现为 502。

原静态合同测试只断言 PUT 白名单和路由字符串存在，没有断言该分发器实际使用已导入
的解析函数，因此未捕获这个运行时名称错误。

## 状态核对

- 两次请求都没有到达 Sidecar 的内部高优路由。
- 池记录 `137` 仍为 `pending`、未绑定，`priority_at` 和操作人字段均为空。
- 当时全表高优记录数为 `0`，没有半成功或需要回滚的高优状态。
- 此问题与 X 发布账本和外部 X 写接口无关；排障及修复验收不得创建 Post。

## 修复

- `do_PUT()` 改为调用模块已经导入的 `urlparse(self.path)`。
- 合同测试提取完整 `do_PUT` 分发器，要求存在 `parsed = urlparse(self.path)`，并禁止
  再次出现 `urllib.parse.urlparse`。

- `test_x_post*.py`：330 项通过，1 项按既有环境门禁跳过。
- `scripts/test_x_accounts.py`：58 项通过。
- 生产提交：`ae0b5a99f29506a4651b2c860d3a3a1306d787b8`；主 API 文件 SHA-256：
  `2cf6be5f28ba6ec3039cb2b596ec4cc9d418d10f89939808324b904ff3488dac`。
- 生产 loopback 与公网匿名 PUT 都返回结构化 `401 auth_required`，不再返回 502；
  新主 API PID 日志无 traceback。
