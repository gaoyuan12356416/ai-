# 015.tt-drama-resolver-cache 需求与技术设计

## 背景

`/tt` 当前只校验 `content_id` 字符格式，格式合法但不存在的 ID 仍会生成 W2A 链接；W2A 又可能把错误 ID 渲染成默认剧，造成误跳。页面也无法显示输入剧目的真实封面、剧名和简介。

线上只读剧库 `kunlunads_dev.ads_drama_resource` 已有 `content_id`、`name`、`desc`、`cover`、`language` 和分集字段，且 `content_id` 有索引。无需下发或复制完整剧库。

## 目标

- 只有远端只读剧库精确命中的 `content_id` 才能生成继续观看按钮。
- 命中后显示剧名、封面、简介、语言和集数。
- 远端剧库保持唯一事实源；本地只保存有界、带 TTL 的查询缓存。
- 同一 ID 的重复请求不重复查询数据库，并能区分冷查询与缓存命中耗时。
- 元数据接口不等待封面图片下载；封面由浏览器直接访问已允许的 CDN。

## 范围

### 包含

- 新增公开、只读、同源 GET resolver 接口。
- 固定查询 DramaWave `app_id=1479`，浏览器不得覆盖产品范围。
- 参数化精确查询、只读端点校验、连接/读取超时。
- 正缓存、负缓存、LRU 容量限制、同 ID single-flight、数据库并发闸门和轻量 IP 限流。
- `/tt` 搜索、加载、命中、未命中、服务异常和封面失败状态。
- 保留现有 W2A 固定目标及追踪参数透传契约。
- `Server-Timing` 与缓存状态响应头，支持冷/热查询测速。

### 不包含

- 不复制完整 `ads_drama_resource` 到本地。
- 不保存视频文件，不代理或下载封面图片。
- 不修改 W2A 服务端模板、SDK、归因或 App 唤醒逻辑。
- 不提供剧名模糊搜索、推荐排序或完整剧库浏览。
- 不新增数据库表或执行 DDL。

## 用户故事 / 业务规则

- 用户输入正确 Content ID 后，应看到对应剧目的真实信息并可继续观看。
- 用户输入不存在、重复参数或格式错误的 ID 时，不得出现可点击 W2A 链接。
- 远端数据库异常不得被误判为“剧目不存在”，页面应提示稍后重试。
- 封面缺失或加载失败不能把真实存在的剧目误判为不存在；使用占位封面继续展示文本与 CTA。
- 只有 resolver 返回 `found=true` 后，前端才可调用现有 `createTarget()` 生成固定 W2A URL。
- Resolver 只接收 `content_id`；`af_adset_id` 等追踪参数不进入数据库查询，继续由浏览器在最终链接中安全透传。

## 交互与流程

1. 用户输入 ID，前端先执行现有格式校验。
2. 点击按钮或按 Enter 后，页面进入加载状态并请求同源 resolver。
3. 缓存命中时直接返回；未命中时执行一次远端精确查询。
4. 命中后先渲染文本和 CTA，再由结果图片直接访问 CDN。
5. 404、429、503 或网络超时时移除 `href`、隐藏结果卡并显示对应提示。
6. 输入变化或新查询会中止/废弃旧请求，旧响应不得覆盖新结果。

## 技术设计

### 影响模块

- `features/tt_drama_resolver/`：查询、校验、缓存、single-flight、限流和异常分类。
- `app.py`：公共 GET 路由、环境配置、HTTP 状态与观测响应头。
- `static/tt-drama-search.html`：结果卡、封面骨架、简介与 CSP。
- `static/tt-drama-search.js`：异步 resolver 流程及失败关闭。
- `deploy/nginx/tt-drama-search.conf`：允许同源接口和已确认封面 CDN。
- `.env.example`：缓存、超时、并发和限流示例配置。

### 数据结构

内存缓存键固定为标准化后的 `content_id`。值包含 `found`、剧集元数据、`expires_at` 和 stale 截止时间。

默认正缓存 3600 秒，负缓存 300 秒，最多 10000 个 ID。数据库异常不写负缓存；过期正缓存可在远端异常时作为有限时长的 stale 结果返回。

### API / 接口

`GET /api/public/tt-drama/resolve?content_id=<id>`

- `200`：命中，返回 `found=true` 和安全裁剪后的元数据。
- `400`：参数缺失、重复、多余或格式错误。
- `404`：剧库中不存在可用剧集。
- `429`：访问频率过高。
- `503`：只读库未配置、超时、暂不可用或全局并发闸门已满。

响应始终 `Cache-Control: no-store`；通过 `X-TT-Drama-Cache` 和 `Server-Timing` 暴露服务端缓存状态与 resolver 耗时。

### 异常与边界

- Content ID 只允许 `[A-Za-z0-9_-]{10,32}`。
- SQL 使用参数绑定，数据库名/表名只来自服务端安全配置。
- 数据库连接必须执行只读会话设置并确认 `@@read_only=1`。
- 同一 ID 的并发冷请求只允许一个 leader 查询；waiter 必须在 leader 成功或失败后释放。
- 不同 ID 的远端查询并发默认最多 4。
- 公开 resolver 同时在途请求默认最多 32；超过后立即失败，不在无界 HTTP 线程中排队。
- 封面 URL 只接受 HTTPS 和允许域名；不符合条件时返回空 URL并展示占位图。
- 简介按纯文本处理、压缩空白并限制长度；前端只使用 `textContent`。
- 页面 CSP 仅把 `connect-src` 放宽到 `'self'`，目标 W2A origin/path 仍保持固定。

## 验收标准

- 已知 ID `l9rP6ey2CB` 返回正确剧名、非空封面和简介，页面显示结果卡。
- 随机合法格式但不存在的 ID 返回 404，页面没有 `href` 或 CTA。
- 现有 `af_adset_id=XXX` 等参数在命中后完整进入最终 W2A URL，核心参数不可覆盖。
- 同一 ID 并发查询只执行一次 loader；正/负缓存 TTL 和容量限制通过自动测试。
- 数据库异常返回 503，不写负缓存；有合格 stale 正缓存时可返回该缓存并标记 `STALE`。
- CPU 服务端实测冷查询总耗时不超过 1500 ms，热缓存查询不超过 100 ms，并记录实际数值。
- 页面先收到 JSON，再独立加载封面；封面失败时文本和 CTA仍可使用。
- 390x844 真实浏览器中无布局溢出、控制台错误或阻断 CSP。
- 服务、Nginx 和原有 AI 后台健康检查通过，并有明确回滚点。

## 风险与待确认

- 同一 `content_id` 可能包含多个国家/语言变体；首版沿用“可用分集最多、更新时间最新”的确定性选择规则。
- 封面实际 CDN 可能变化；只允许已只读核对的域名，其他域名显示占位图并通过日志观察。
- 服务进程重启会清空内存缓存；首版接受冷启动，后续多实例或高 QPS 再评估共享缓存。
- 用户端网络与 CDN 会影响封面加载时间，需与 resolver 元数据耗时分开测量。
