# SA 评审意见

## 结论

有条件通过。公开 resolver 可行，但必须落实只读连接、single-flight、并发闸门、失败关闭和 CSP 白名单，不能直接复用字符串拼接 SQL 或把 W2A 200 当成存在性验证。

## 问题清单

| 编号 | 严重级别 | 位置 | 问题 | 建议 | 状态 |
| --- | --- | --- | --- | --- | --- |
| SA-001 | 高 | 公共 API | 无鉴权接口可能被枚举并放大远端查询 | 严格格式、固定 app_id、IP 限流、并发 4、正负缓存 | 已接受 |
| SA-002 | 高 | 缓存 | 并发冷 miss 可能形成缓存击穿 | 实现 per-key single-flight，DB I/O 不持有全局缓存锁 | 已接受 |
| SA-003 | 高 | 错误语义 | DB 超时若缓存为不存在会误伤真实剧目 | 503 与 404 分离，异常不写负缓存，可使用有限 stale 正缓存 | 已接受 |
| SA-004 | 中 | 数据选择 | 同一 ID 有多行分集和潜在语言变体 | 按可用分集数、更新时间确定选择一个变体 | 已接受 |
| SA-005 | 中 | 封面 | DB 查询封面 URL与图片下载耗时容易混淆 | API 不下载图片；前端骨架、高优先级 CDN 直连和失败占位 | 已接受 |
| SA-006 | 中 | 前端安全 | 当前 CSP 禁止接口请求，动态封面域名也未放行 | 仅允许同源 API和确认过的 HTTPS 图片域名 | 已接受 |
| SA-007 | 中 | 可观测性 | 用户无法区分冷查、热缓存和 CDN 慢 | 增加缓存状态和 Server-Timing，分别测 API 与图片 | 已接受 |

## 决策记录

- 不建立本地全量剧库或同步表。
- 不把 resolver 设计成开放跳转接口；最终 W2A URL继续由现有固定逻辑生成。
- 首版使用进程内有界缓存；共享 Redis/本地索引表留待实际流量证明需要。
- 查询只走当前 63350 只读端点，任何非只读配置均失败关闭。
