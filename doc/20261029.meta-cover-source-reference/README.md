# Cover source and reference read optimization

The cover worker spent about ten seconds preparing each source wave because lineage, material metadata, and drama cover enrichment opened three independent gated MySQL sessions. These bounded reads now share one short read-only consistent snapshot per wave. The snapshot closes before Graph work and the next wave opens a new one. No cross-wave source cache, direct-driver gate bypass, source identity relaxation, or write-time freshness change is introduced.

Old Creative cleanup already batches complete inventories by account and runs up to four account scans concurrently. Its inventory page request size changes from 100 to 500, reducing serial HTTP overhead. Every returned cursor is still followed, archived Ads remain included, identity/status/duplicate checks remain exact, and a failed page invalidates the scan. Reference freshness, shared reservations, deletion intents and unknown fences remain unchanged. No partial inventory or stale cache can authorize deletion.

Read-only comparisons use the same source candidates or account inventories with alternating old/new order. Before deployment, three source waves per version returned identical validated output: average 10.831 to 5.080 seconds, with three sessions reduced to one. Reference measurements record counts, archived counts, full normalized inventory hashes, page counts, and elapsed time. Failed or changed inventories are excluded from paired speed comparisons and reported separately. Live acceptance must measure fresh naturally queued tasks; these microbenchmarks are not promises about whole-worker throughput.
