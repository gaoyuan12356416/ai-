素材任务最终状态飞书播报接口

甲方推送任务最终状态，我方实时匹配优化师并发送飞书私聊；无法私聊时自动通知兜底群。

API v1 HTTPS + Bearer Token JSON 支持幂等重试

1. 接口地址

POST https://ai.yingliangads.com/api/integrations/v1/material-task-status-events
成功返回 202 Accepted 表示事件已经可靠落库并进入实时投递队列，不代表飞书在响应前已经送达。

2. 请求头

Header必填值/规则
Authorization 是 Bearer <由我方通过安全渠道单独提供的 Token>；Token 至少 32 个字符
Idempotency-Key 是 8–128 位；同一业务事件重试时必须复用同一值。允许字母、数字、点、下划线、冒号和短横线。
Content-Type 是 application/json; charset=utf-8

3. 请求字段

请求体严格包含以下十个字段，不接受额外字段。本次契约升级新增 resource_name 和 drama_dubbing_type； task_type 为原有字段并继续保留。

旧版仅包含八个字段的请求会返回 422 invalid_payload； 甲方必须先完成字段升级。
字段类型必填最大长度说明
resource_idstring是128资源 ID，必须按字符串传输
resource_namestring是255资源名
task_start_timestring是64RFC 3339 且必须带时区；秒的小数部分可省略，提供时限 1–6 位
drama_dubbing_typestring是64剧集配音类型
task_typestring是64任务类型
original_material_namestring是255素材原始名
material_namestring是255素材名
languagestring是32语种，推荐 BCP-47，例如 zh-CN
final_statusstring是64最终状态
optimizer_namestring是100优化师名称；字段必传，空字符串会触发兜底提醒

4. 成功响应

首次接收

HTTP/1.1 202 Accepted

{
  "code": "accepted",
  "message": "事件已接收，正在投递",
  "event_id": "MSE-0000000123",
  "duplicate": false,
  "delivery_status": "queued",
  "received_at": "2026-07-28T06:30:01.000000Z"
}

相同事件重试

相同 Idempotency-Key 与相同请求体会复用原事件，不再创建第二条正常播报。

HTTP/1.1 202 Accepted

{
  "code": "duplicate_accepted",
  "message": "事件已接收",
  "event_id": "MSE-0000000123",
  "duplicate": true,
  "delivery_status": "delivered",
  "received_at": "2026-07-28T06:30:01.000000Z"
}

5. 错误码

HTTPcode说明甲方处理
400idempotency_key_required缺少 Idempotency-Key补充请求头
400invalid_idempotency_key幂等键格式不正确按请求头规则修正
400invalid_request请求体传输方式或 Content-Length 不合法修正 HTTP 请求
400invalid_jsonJSON 无法解析修正请求
401invalid_tokenToken 缺失或错误核对 Token
409idempotency_conflict同一 key 对应不同请求体核对是否误用了 key
413payload_too_large请求体超过 32 KiB缩小请求
415unsupported_media_typeContent-Type 不是 JSON改为 JSON
422invalid_payload字段缺失、额外字段、超长、非字符串或时间无时区修正请求
503service_unavailable服务暂时无法可靠接收保持原 key 重试
甲方只应对网络超时和 5xx 使用原 Idempotency-Key 重试；4xx 需要先修正请求。

6. 匹配与播报规则

optimizer_name → admin_users.username → admin_users.id → admin_user_group.sub_user_id → email → Feishu open_id → 私聊

名称只去除首尾空白后做大小写敏感的精确匹配，不做模糊匹配或别名猜测。优化师、email、飞书用户无法匹配，或私聊最终失败时，系统会将同一事件发送到我方兜底群并附带失败原因。

7. 安全与 Token 轮换

  • 全程使用 HTTPS；接口只接受 Authorization: Bearer。
  • Token 不放 URL、请求体、前端代码、群消息、截图或公开仓库。
  • 接口不使用来源 IP 白名单；来源 IP 仅用于我方内部审计。
  • 轮换时我方可短期同时接受新旧 Token，切换完成后立即撤销旧 Token。

文档中不包含生产 Token；生产 Token 由我方通过安全渠道单独提供。
