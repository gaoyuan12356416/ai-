# BUG-002 Meta 时间无法写入 MySQL DATETIME

## 发现阶段

生产 PAUSED 复制 Canary。

## 现象

Meta 回读的 `start_time=2026-07-17T10:55:39+0800` 原样写入 FB created_data 的 MySQL DATETIME 字段时事务失败。

## 安全表现

新 Campaign、Ad Set、Ad 已创建，但全部保持 PAUSED；created_data 和 lineage 事务均未产生半条数据；intent 保留已创建的 Meta ID 并进入隔离状态。

## 根因分析

Meta Graph 返回带时区的 ISO 8601 字符串，MySQL DATETIME 需要 `YYYY-MM-DD HH:MM:SS` wall-clock 格式。

## 修复说明

写 created_data 前解析 ISO 时间并规范化为 MySQL DATETIME；恢复时复用同一个 intent 中的 Meta ID，只补齐回读、映射和落表，不再次调用复制接口。同时修正失败响应中的真实 `meta_write_count` 和 `copy_intent_id`。

## 验证结果

- 原 intent `6a19ac49edf24c4c8363ef1a7aa76362` 恢复完成，恢复过程 Meta 写入 0 次。
- created_data 和 lineage 各新增 1 行，复制对象保持 PAUSED。
- 再次重放返回 `duplicate_completed_intent`，Meta 写入 0 次。
- V3 unittest 154/154 通过。

## 回归结论

关闭。
