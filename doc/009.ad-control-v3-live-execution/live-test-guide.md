# V3 线上真实暂停与复制测试指南

## 入口与当前能力

打开：`https://ai.yingliangads.com/api/ad-control/v3/ui/rule-groups`

页面顶部应显示“真实暂停、复制与自动调度已开放”和“正式执行可用”。如果不是这个状态，停止测试并检查服务能力，不要反复点击执行。

V3 当前支持 Facebook 的 Campaign、Ad Set、Ad 三个调控层级，动作支持暂停和复制。TikTok 只预留通道，不执行真实操作。

## 最安全的首次测试顺序

### 1. 新建规则组

1. 点击“新建规则组”。
2. 渠道选择 Facebook。
3. 选择优化师；普通优化师只能选本人，管理员可选其他优化师。
4. 多选短剧产品，产品枚举与 `custom_source_insight` 对齐。
5. 选择调控对象：Campaign、Ad Set 或 Ad。
6. 保持“只观察”，保持规则组禁用。

表单不会替你填写业务阈值；输入框里的浅色文字只是提示，不是已保存的值。

### 2. 配置筛选条件

至少用产品、优化师和一个明确的绩效条件缩小范围。首次验收建议再限制剧目、账号时区和候选 Top N，确保试算结果只包含你准备操作的测试对象。

规则条件按所选对象层级读取对应 insights。先检查对象 ID、名称、账户、产品、优化师、消耗、CPI 和 ROAS，不能只看命中数量。

### 3. 配置动作

暂停测试：动作选择“暂停”。该动作只暂停所选层级对象；暂停 Campaign 会连带停止其下投放，暂停 Ad 不影响同 Ad Set 的其他广告。

复制测试：动作选择“复制”，再设置承载方式、预算和可选 ROAS 调整。复制内部始终先创建 PAUSED 对象，完成回读、created_data、lineage 和一致性校验后，正式模式才允许激活。

首次复制建议：单规则每日上限 1、Top 1、同源冷却至少 1 天，并使用明确的测试对象。

### 4. 保存并立即试算

1. 保存规则组。
2. 点击“立即试算”。
3. 逐条核对候选对象和计划动作。

试算永远不会调用 Meta 写接口，也不会写复制后的 created_data。试算结果不正确时，回到规则条件继续收窄，不能切正式执行。

### 5. 手动执行一次真实操作

1. 将运行模式改为“正式执行”。
2. 按页面要求完成二次确认。
3. 保持规则组禁用，先使用单次手动执行。
4. 再次确认最新试算未过期，执行真实操作。
5. 立即进入“执行日志”查看成功、跳过、失败、Meta 写入次数和复制 intent。

服务端手动执行确认短语为 `EXECUTE_LIVE_RULE_GROUP`。前端会负责提交，测试人员不需要手工调用接口。

### 6. 核对 Meta 和系统数据

暂停：Meta 对象 configured status 应为 PAUSED，日志 `meta_write_count` 应符合实际写次数。

复制：核对新 Campaign / Ad Set / Ad / Creative ID、预算、出价、状态、素材和剧目；复制 N 个 Ad 时，FB created_data 应新增 N 行，并且 lineage 能追溯来源和规则。

失败或映射不完整时，新对象必须保持 PAUSED。不要重新点复制；系统应依据同一个 intent 恢复或由人工处理。

### 7. 再启用自动调度

只有单次手动执行核对通过后，才启用规则组。正式调度启用确认短语为 `ENABLE_LIVE_MODE`。调度器按账户时区、允许时间窗、间隔、每日额度和冷却期执行。

## 紧急停止

发生异常时先禁用具体规则组；需要全局停止复制时关闭 `AD_CONTROL_V3_LIVE_COPY_ENABLED` 和 `AD_CONTROL_V3_RUNNER_LIVE_RELEASED`。已由 Meta 创建的对象不能靠数据库回滚删除，必须依据 lineage 精确 PAUSE 并保留审计数据。
