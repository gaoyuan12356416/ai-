# GPU render math optimization and controlled measurement

Scope: reduce repeated CUDA scaling/composition arithmetic while retaining
the current pixels, encoder settings, timestamps and audio. No production
activation is included in the initial measurement revision.

Baseline: `33ce9744034e0ecf82f06fd6d58403cab7ed3cc4`. All 14 files currently
under `features/random_gpu` on the Hong Kong production renderer match this
baseline. Its service points at older release `68407465...` with these later
patches installed, so that older commit alone is not the comparison baseline.

Candidate:

- Cache each pixel's Lanczos normalization using the original accumulation
  order. Keep the rounded weight multiplication separate from addition.
- Calculate common U/V coordinates and weights once while retaining the
  independent accumulation order for both channels.
- Calculate the recipe's sine/cosine on CUDA once with the same functions.
- Preserve full precision, geometry, output profiles and codec settings.

Verification:

1. Existing clock, frame ownership, encoder-budget and cancellation tests.
2. `verify_gpu_render_math.py`: compare raw fitted and composited pixels with
   the baseline across 18 geometry/chroma/bit-depth cases and multiple frames;
   require zero changed channels. Record paired, reversed-order CUDA timings.
3. `benchmark_gpu_render_math.py`: identical frozen samples, H.264 and HEVC,
   decoded video/audio frame hashes; require exact equality. Then four
   16-worker, 120-second A/B/B/A batches with the same encoder settings.
4. Report media-only batch throughput separately from projected daily
   production capacity. Do not apply kernel speedup to the full pipeline.

The user authorized a bounded exclusive window: let existing GPU preparation
finish, temporarily stop new GPU preparation claims for about 20 minutes,
leave CPU/COS and publishing active, and restore the original GPU capacity.
Never terminate or replay business jobs. Tests use an isolated GitHub checkout
and output directory. The benchmark watchdog cancels only its owned children
if any external media process appears. Preparation capacity must be restored
on completion or failure. Preserve before/after configuration and running-job
receipts outside Git.

Initial planning baseline is 222.85 output video hours/day, about 1,152 videos
at the observed average 11.61 minutes, based on 2,015 rendered completions over
41.98 hours. A two-T4 projection is 445.70 hours/day ideal or 356.56 with 20%
headroom. These are not promises about current demand or unmeasured hardware.
