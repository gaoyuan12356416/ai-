# Moboreels 剧集、推荐剧单与媒体账号报备

本变更在独立仓库目录开发，基于 `1742279d`，分支 `codex/moboreels-catalog-tools-20261113`。未部署、未执行建表 SQL、未提交真实媒体账号报备，不包含主会话进行中的订单报表与 `{{m_url}}` 功能。

## 功能

- 短剧库每行增加「获取剧集地址」，从目录读取上游 story_id 和语言。弹窗显示分集链接、复制按钮、复制全部和重新获取。供应方声明地址有效期一小时；缓存从请求开始时间计时，提前一分钟失效，最多缓存64部剧。
- `/moboreels-recommendations.html`：当天／历史日期、短剧／网文、名称／ID、语言、等级筛选，50条分页，展示推荐理由、备注、标签和推荐日期。汇总基于该日期完整列表，保留供应方顺序，支持导出当前页CSV。
- 推荐列表按机构、日期和业务类型保存数据盘快照，十分钟复用；获取全部分页且总数、唯一ID校验通过后才替换。上限20000条，超限或缺页明确失败，不覆盖旧快照，不把旧快照作为当前查询的成功响应。
- `/moboreels-media-accounts.html`：选择媒体类型、每批粘贴最多100个平台原始账号ID、去重、匹配资料、勾选／补全后提交。YouTube应输入频道ID，通常为UC开头的字符串；不能把后台数字主键当成平台ID。
- 普通用户查看本人报备；管理员查看本租户记录。沿用 `moboreels_library` 权限、Cookie和同源校验，独立导航条目可以单独禁用。达人ID复用现有推广身份算法，前端不能指定达人或租户。
- 报备记录逐条显示等待提交、提交中、成功、失败、待核实及供应方报备记录ID。相同机构、媒体和平台账号唯一占用，其他达人提交时提示已有归属，不转移归属。
- 供应方回执先耐久保存，MySQL失败不重复调用供应方。明确失败亦不自动重试；超时、异常成功结构和重启中的请求保持待核实。管理员核实成功可补录原报备ID；核实未创建后仅允许原用户再次主动提交。

## 上游契约依据

来源：[KOC接口文档v6.3](https://cvbadml3pe5.feishu.cn/docx/AAXydWTWKoQ0Ahx264pcXyWEndD)，使用2026-11-12已读取的文档正文，2026-11-13找回原始读取记录。当前网页入口跳转登录，浏览器控制连接超时；不声称重新核对了文档最新版本。

| POST接口 | 请求 | 返回 |
|---|---|---|
| `/api/story/getepislist` | story_id、lang_id、project_type | data为epis_no、epis_url数组，地址一小时有效 |
| `/api/story/recommend` | query_date、project_type、page_index、page_size≤100 | data.total/list；story_id、story_name、lang_id、recommend_time、recommend_reason、recommend_remark、recommend_grade、tags |
| `/api/story/addplatformaccount` | project_type、nickname、platform_type、platform_link、star_user_id≤32 | data.id、project_type、platform_type、platform_name、nickname、platform_link、create_time |

媒体类型：1 TikTok、2 YouTube、3 Facebook、4 Instagram。文档写明“返回成功即为报备成功”，未提供独立的审核或状态查询接口；页面状态是本系统耐久记录的提交结果，不虚构审核中／驳回等供应方审核状态。文档的账号示例混用了YouTube类型与Facebook链接，实现验证实际回执的平台和主页一致性，不照抄错误示例。

## ID匹配

经CPU服务器只读核对的字段：

- TikTok：`ads_ai.tiktok_personal_account_snapshot` 的 external_account_id / main_account_id，读取 account_name 和 account_link，仅匹配当前is_active记录；不使用source_account_id、不读取凭据。
- YouTube：`kunlunads_dev.ads_youtube_channels.channel_id`，读取channel_name，使用频道ID组成主页；不使用表的id、不访问授权表。
- Facebook：`kunlunads_dev.ads_facebook_page_post.page_id`，读取page_name，使用精确Page ID组成主页；不读取凭据。
- 未发现已验证的Instagram映射表。Instagram及其他未匹配的账号需操作人补全名称和正确主页。冲突匹配不允许提交，需先核对来源。

所有来源通过既有63350 FIFO读端查询，每批最多100个精确ID；不调用发布接口，不变更社媒授权或账号归属。

## 后台接口

| 接口 | 用途 |
|---|---|
| GET `/api/moboreels/dramas/{story_id}/episodes` | 获取剧集，`refresh=1`强制更新 |
| GET `/api/moboreels/recommendations` | query_date、project_type、q、lang_id、grade、page_index、page_size |
| POST `/api/moboreels/media-accounts/preview` | platform_type、account_ids；匹配不产生报备 |
| GET `/api/moboreels/media-accounts` | 本人／管理员本租户报备列表及状态 |
| POST `/api/moboreels/media-accounts` | platform_type、accounts[{account_id,nickname,platform_link}]；立即返回已入队的记录 |
| POST `/api/moboreels/media-accounts/{record_key}/resolve` | 管理员提交outcome、provider_id、evidence核实结果 |
