# Generate captions from current task facts

All four endpoints generate each task's caption from its current facts, language,
title, material and episode context. The producer no longer reads published
captions, previous drafts or previous click hooks. Prompts have no historical
examples, assigned plot-beat rotation, angle rotation or cross-task variety rule.
Generated text and hooks may repeat; the first valid hook is used. The legacy
hook-upgrade utility follows the same rule.

Existing history rows and fingerprints remain as audit data. Task identity,
manual-copy priority, evidence/language/length checks, native final receipts and
publication idempotency remain intact. Model failures still use legacy copy.
Existing finalized posts and failed jobs are not replayed by this code deployment.

Validation: `python -m unittest tests.test_story_copy` (17 tests), including
generation with unavailable source databases and a missing history table,
identical outputs across all four endpoints, 100-task partial results, rendering,
manual priority, frozen receipts and fallback.

From the exact GitHub-fetched checkout, run:

```sh
python3 ops/story_copy/deploy_no_history.py prepare /mnt/data-disk/story-copy-deploy/no-history-COMMIT
python3 ops/story_copy/deploy_no_history.py apply /mnt/data-disk/story-copy-deploy/no-history-COMMIT
```

The deployment compares all four changed producer modules with the reviewed
parent, preserves the previous release and changes only the central caption
runtime. It waits for an active generation batch, then holds the caption ledger
write lock through the scoped worker stop/switch/start. Publishers, schedulers,
settings, queues and production receipts are not changed. The release record
contains source hashes and before/after service identities.

Rollback: use the same checkout and deployment folder with `rollback` in place
of `apply`. This safely switches only producer code; do not restore a database.
