# 社媒按目标随机与零点备料

随机发布按账号/Page冻结每日时刻，零点开始当天选材和制作；成片按任务自身时间发布，制作迟到（含跨天）后尽快发布。覆盖 X Auto/素材池/剧目池、Facebook Auto/Page组素材池、TikTok Auto/素材池。固定、手动和 YouTube 保持原规则。

共享策略 `target_midnight_v1` 使用持久生效日期与目标日计划，配置编辑不重抽当天。原生发送与统一流水线均保留时间检查。X 同池预约按计划时间串行，冻结后立即释放规划顺序；制作与发布独立进行。剧集只推进已确认发布游标，后集等待前集。

Facebook 既有未来任务保留 ID、素材、成片、短链与归属，只同步修改原生时间和未领取的流水线发布时间。旧任务通过稳定 slot 绑定避免重复生成；失败、跳过、外部意图和回执不被恢复。准备计数/时间不作为实际发布证据。

## GitHub 部署

以 `7b45af9f` 汇集的实际运行源码为补丁基线，保留每个服务自身的其他差异。先 push 精确提交，再在服务器从 GitHub fetch 并创建干净源码检出。

```text
python -m scripts.deploy_social_random_schedule prepare SOURCE COMMIT DEPLOYMENT --effective-date 2026-11-11
python -m scripts.deploy_social_random_schedule rehearse DEPLOYMENT
python -m scripts.deploy_social_random_schedule initialize DEPLOYMENT
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT coordinator
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT x
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT tt_auto
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT tt
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT fb
python -m scripts.deploy_social_random_schedule activate DEPLOYMENT app
```

生效日期必须是实际上线的北京次日。`prepare` 校验数据盘、GitHub来源、现行代码差异，保存逐服务代码及 SQLite 在线备份；`rehearse` 在副本验证加列保留旧业务字段、双库改时及重复执行。`initialize` 统一固化日期，不生成新任务。

切换仅短暂停止受影响服务的新请求，等待其当前 HTTP 操作结束，保留执行任务、租约和其他平台；使用原有安全切换实现，切换前后保存/恢复对应平台调度器。主 API 的 X 操作代理到 8810，因此不覆盖其不同版本且未参与本次执行的存储模块；主目录仅更新静态内容，无须重启主 API。

切换完成后，检查未来随机旧 due 槽没有正在执行的规划，再重新生成并执行真实改时清单：

```text
python -m scripts.migrate_social_random_schedule plan --fb FB_DB --dispatch DISPATCH_DB --manifest DEPLOYMENT/retime-live.json --effective-date 2026-11-11
python -m scripts.migrate_social_random_schedule apply --fb FB_DB --dispatch DISPATCH_DB --manifest DEPLOYMENT/retime-live.json
```

清单在数据盘私有保存，不提交业务明细。验收公开静态版本、服务健康、调度依赖、所有策略日期、改时前后任务/成片不变及双队列时间一致。

## 回滚边界

生效日前、尚未冻结任何目标日计划（包括既有 FB 任务映射迁移）时可执行：

```text
python -m scripts.deploy_social_random_schedule rollback-before-effective DEPLOYMENT
```

该命令核对尚无冻结日计划和新目标任务，再按实际服务链接及静态文件哈希回切代码和页面；保留当前数据库、回执、凭据、成片和审计记录，绝不恢复整个数据库备份。健康检查失败会在服务切换内部自动回切。

一旦迁移或调度已冻结日计划，即使尚未到生效日，也保留兼容消费代码和冻结时间，以前向修复处理问题；不能把已产生日计划的日期交给旧整批生成器重复建单。备份用于核对与取回代码，不用于覆盖当前业务事实。
