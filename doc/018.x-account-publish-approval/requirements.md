# 018.x-account-publish-approval 需求与技术设计

## 背景

X 账号完成 OAuth 授权后会直接成为发布候选，管理员缺少单独控制某个账号能否参与发布的开关。

## 目标

在 X 账号列表增加“允许发布”复选框。只有管理员勾选且凭据状态有效的账号，才可在素材发布池、短剧发布池和自动发布流程中被选择或使用。

## 范围

### 包含

- 账号表新增持久化发布许可字段，历史及新账号默认关闭。
- 管理员列表展示并修改许可。
- 发布池候选、排期保存、计划生成和最终取发布凭据统一使用有效许可。
- 操作审计、迁移、测试与生产回滚。

### 不包含

- 不改变 OAuth 授权、Token、账号停用或解除授权。
- 不自动勾选任何现有账号。
- 不删除历史发布、发布池记录或已保存的排期配置。

## 用户故事 / 业务规则

1. 管理员可以对任一 X 账号勾选或取消“允许发布”。
2. `publish_eligible = credential_publish_eligible AND publish_approved`。
3. 新授权和历史迁移账号的 `publish_approved` 均为 false。
4. 取消勾选后，账号不再出现在可选账号中；已有排期仍保留，但后续执行必须失败关闭。
5. 重新授权、资料同步和 Token 刷新不得覆盖管理员选择。
6. 非管理员不得修改许可。

## 交互与流程

列表显示“已允许/未允许”以及“发布池可选/不可选”。修改时禁用当前复选框，成功后重新加载服务端状态；失败则恢复并提示错误。

## 技术设计

### 影响模块

- `features/x_accounts/oauth_service.py`：数据迁移、有效资格计算、管理员写接口、最终发布凭据闸门。
- `features/x_accounts/client.py`、`app.py`：主服务管理员接口和安全错误透传。
- `static/x-account-list.html`：管理员复选框。
- 发布池和排期逻辑继续消费既有 `publish_eligible` 字段，无需双轨判断。

### 数据结构

`x_authorized_account.publish_approved INTEGER NOT NULL DEFAULT 0`。启动时执行幂等加列迁移。

### API / 接口

新增 `POST /api/admin/x-accounts/{id}/publish-approval`，请求体 `{"approved": true|false}`。内部转发至 `POST /internal/accounts/{id}/publish-approval`。

### 异常与边界

- 未勾选账号最终发布返回 HTTP 409 / `x_account_publish_not_approved`。
- 账号无效时即使已勾选也不可选。
- 修改许可与发布共享账号锁；已进入锁内的单次发布完成后，取消许可才生效，之后的发布全部被阻断。

## 验收标准

- 列表存在可保存的“允许发布”复选框。
- 未勾选账号不在两个发布池的可选账号中，且无法通过旧排期或直接发布绕过。
- 勾选且状态有效的账号可正常进入候选和发布流程。
- 历史账号迁移后全部默认未勾选，Token 与历史记录不变。
- 非管理员和跨站请求无法修改。

## 风险与待确认

上线会使全部现有 X 账号立即退出未来发布候选，需由管理员逐个确认后勾选。这是本需求的预期安全默认。
