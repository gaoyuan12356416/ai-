# X 成长画像与频道选材模式

频道选材模式由操作者在 X 画像自动发布模板的频道列表中选择并单独保存：收入画像 / 成长画像。所有未设置频道默认收入画像。服务永不自动切换频道模式；新自动任务冻结模式和成长画像版本，已生成任务保持原选择。素材池的新选材也读取同一频道设置。

## 数据与学习

- 已使用 3 个近期有效授权频道的真实帖子验证公开、非公开、自然流量指标及 users/me：均返回 200。
- 获取帖子曝光、主页/链接点击、赞转评引及收藏，媒体播放/观看时长/播放进度，账号粉丝总数。媒体指标可能跨帖聚合；不以媒体播放替代帖子曝光。没有单帖涨粉归因。
- 独立定时器每 15 分钟运行；帖子 6h/24h/72h/7d 采样，允许 6 小时采集窗口；粉丝每 6 小时一次。缺失保留空值，不填 0；错误按频道退避，不改发布状态。
- 只使用真实年龄 72–78h 的最近 28 天帖子做学习，低于 100 曝光视为证据不足。首次发现从启用前 24 小时内的已确认发布帖开始，无法补造历史同龄指标。
- 同产品、语言、时长段和指标可用性内比较：自然曝光 60%、主页点击率 25%、转发收藏率 15%。稀疏样本向中性收缩、按剧平衡，多个题材共享样本权重。
- 每题材至少 6 个有效样本、3 部剧才可优先；清晰领先后目标分配 60% 第一题材、20% 第二题材、20% 探索，只有一个成熟题材时探索占 40%。初期均衡测试 3 个题材。每周各分配部分最多变化 20 个百分点。
- 两周账号净增粉均非正且已有至少 18 条有效帖子时，提高探索目标至 40%。这是账号整体反馈，不声称单帖带粉。
- 不改变素材资格、语言、时长能力、历史去重或发布回执保护；缺少题材标签时保留原有候选顺序并记录原因。

## 运行与验证

状态库 `/mnt/data-disk/x-tag-publisher/growth/state.sqlite3`，与发布账本分离。OAuth 刷新继续由已有 8810 服务负责。新服务 `x-growth-profile.service` / `x-growth-profile.timer`。采集服务仍使用 x-post-automation 身份，通过仅限读取的 capability 读取另一服务用户的账本；系统只允许写成长状态目录，屏蔽 home，不放宽原有账本权限。频道设置入口由现有登录、导航权限和频道 owner/admin 权限保护，并做版本冲突检测。

测试：`python scripts/test_x_growth_profile.py`；部署候选还运行 `test_hit_drama_launch_window.py` 和 `test_auto_material_products.py --platform x`。浏览器验证频道选择保存、提示、数据弹窗和不误选频道，使用本地模拟接口，不改实际频道。

## 部署和回滚

先提交并推送 GitHub，在 CPU 数据盘检出准确提交后，依次执行：

```
python3 scripts/deploy_x_growth_profile.py prepare --folder /mnt/data-disk/x-growth-profile/releases/RELEASE
python3 scripts/deploy_x_growth_profile.py apply --folder /mnt/data-disk/x-growth-profile/releases/RELEASE
python3 scripts/deploy_x_growth_profile.py verify --folder /mnt/data-disk/x-growth-profile/releases/RELEASE
```

prepare 从当前 runtime 建候选，合并本次增量并验证，备份受影响文件和发布数据库。apply 仅重启 auto/gateway；post 和原 OAuth/publisher 进程保持不变。verify 恢复原先活跃的 X 调度依赖，再发布静态入口并启动采集。文件哈希冲突时保留后来的变更。

回滚：相同 GitHub 来源脚本运行 `rollback --folder RELEASE`，待 auto/gateway 活跃后运行 `verify --folder RELEASE`。保留新增成长数据库及历史；若已有操作者选用成长画像，先明确处理其选择或前向修复，不能悄悄改回收入画像。新增未使用模块可保留，恢复旧入口并停用采集 timer 即不参与运行。
