# SocialKit 剧语言分组

总览、收入效果和发布执行增加“剧语言”筛选及组合分组；CSV 使用相同查询和固定快照。原“账号语言”保留在发布执行，不能替代剧语言。

语言来自只读端口 63350 的 `kunlunads_dev.ads_drama_info`，按 App ID + 精确 content ID 关联。使用 `ac` 索引，每批至多 500 个 content ID，按产品分批，遵循现有 SQL FIFO 队列。统一语言代码大小写及 `jp/ja`；重复同语言不会重复收入，多语言冲突单列“语言冲突”，无匹配单列“未提供”。

语言维表只写入本地不可变 SQLite 快照，不变更 MySQL 事实表结构和发布记录。每小时刷新同步语言；语言读取失败保留上次资料、显示提示，收入采集继续。网页筛选和 CSV 只读快照。旧快照仍能查询，未采集的语言显示“未提供”。

## 部署

从已推送 GitHub 的精确提交创建独立 release。先在备份目录的快照副本验证，再执行：

```
python3 RELEASE/ops/socialkit-analytics/install_drama_language.py --apply
```

安装器只替换 SocialKit 的 query/refresh/schema/drama_language 模块、两个静态文件及独立刷新 release 链接，按当前运行基线校验后备份。使用已有 systemd EnvironmentFile 运行一次 `python3 -m features.socialkit_analytics.drama_language`，仅复制当前快照补充语言资料；保留事实、逐日源版本和真实收入更新时间。沿用既有 API 排空切换流程激活查询代码，并核对受影响依赖调度器；不停止其他发布渠道。

## 验证与回滚

运行相关 query/data/language 单元测试，Playwright 点击剧语言分组、筛选、导出，JS/Python 语法检查。真实快照验证分组金额、安装数、成功发布数与原合计一致，核对未知项与语言冲突项。部署后检查公网 ACL、页面缓存版本、API 与固定版本 CSV。

回滚命令为 `python3 RELEASE/ops/socialkit-analytics/install_drama_language.py --rollback BACKUP/manifest.json`，再沿用安全 API 切换流程激活并核对依赖调度器。仅回滚代码；保留当前账本、收入事实、语言快照和发布回执，其他线程的后续改动须先合并。
