# X 素材效果与成长画像下线

成长画像停止生成并退出选择流程。当前成长模板新增收入画像版本，保持启停、确认状态与已抽取的随机时刻；历史版本、已选材任务、队列、回执和令牌不改写。普通与标签画像模板的剧目、素材两层支持 X 浏览、点赞、评论、分享、收入的上下限及升降序。

## 数据口径

`ads_ai.x_material_post_effect` 按版本和真实帖子 ID 唯一；`x_material_effect` 按版本和素材命名空间/ID 唯一。`x_material_effect_refresh_runs` 记录完整版本与校验。查询时使用最新 `status='verified'` 的版本，不能跨版本累加。索引覆盖素材、账号/发布日期、剧目/语言/产品、主归因 campaign 和五类指标排序。完整 campaign 集合保留在 JSON；同一原帖被多个账号转发只计一次曝光与收入。

浏览 = X public impression_count；评论 = reply_count；分享 = retweet_count + quote_count，分项另存；收藏 = bookmark_count。缺失保持 NULL，同时提供已知小计和覆盖数。收入/退款为 USD 分，沿用社媒数仓唯一 campaign 和确认发布归因，仅截至完整 UTC 日期，不能确认归因的收入不分摊给素材。页面日期筛选的是北京时间发布批次，指标仍为累计值。

独立 systemd 定时器每小时 20 分刷新。7 日内帖子每小时、8–30 日每 6 小时、更早每天采集；收入每小时读取已有完整快照。每批最多 100 个帖子，只调用读取接口。429/授权失败保留已知结果并延后重试。写入新版本后，通过只读副本逐表核对行数、内容校验和及收入；成功才切换本地不可变快照，保留旧版本供在途读者使用。

## 选材和权限

效果查询跨全部 X 账号汇总，专用 `x_material_effects` 权限，管理员默认可见。普通用户的帖子明细限定本人账号。页面 `/x-material-effects.html`，接口 `/api/x-material-effects`，无导出。

只有启用 X 效果条件或排序的模板允许其他账号复用；未启用时保留原去重规则。跨普通/标签两条发布链路核对同账号历史、全部在途任务、手动占用和未知写入；独立 broker 持久化串行授权，实际入队再核对。冻结选材快照保留效果版本、命中指标和策略。授权失败不自动放行或重新发布。

## 部署与回滚

从 GitHub 检出精确提交后执行 `scripts/deploy_x_material_effects.py prepare --folder /mnt/data-disk/DEPLOYMENT`。准备阶段逐文件对当前运行版本合并审核差异，不覆盖其他并发改动，保存源码/配置和 SQLite 备份。先在隔离目录执行 `refresh --prepare-only --root PREVIEW --limit 20`，确认读取和收入归因，再显式运行 `EffectWriter.install_schema()` 建立三个自有表，首次完整刷新校验。

`activate` 安装经审核的代码差异，使用 systemd 原子重启和已安装的发布 stop barrier 等待 X／主 API 在途工作；完成后刷新模板 API、网关和静态页面。执行成长模板迁移，安装独立 API，停成长定时器，恢复原依赖调度器。单独 stop 会被依赖 timer 的 start 覆盖，因此使用 restart 并核对新 PID。独立效果刷新 timer 在首次正式刷新成功后启用。部署不创建测试帖子、不重放历史任务、不清空锁或未知结果。

代码回滚命令：`python3 SOURCE/scripts/deploy_x_material_effects.py rollback --folder /mnt/data-disk/DEPLOYMENT`。保留现有 SQLite、令牌、MySQL 表及效果快照；不把历史备份覆盖到业务数据。回滚后仍保留收入模板新版本和停止的成长 timer。新效果模板应先停用并等待已授权任务结束后回滚，以免旧版本无法继续执行新策略。失败部署查看 manifest、journal 与 scheduler 前后快照，不强制终止发布请求。

## 验证

专项覆盖帖子去重、跨账号汇总、NULL 与零、USD 精度、北京日期边界、升降序缺失值、双层筛选、模板兼容、保留账本的迁移、收入守恒、持久复用授权及队列同账号保护。沿用选择器、模板参数、发布桥接和执行器回归；所有验证不发布真实 Post。
