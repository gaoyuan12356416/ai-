# FB template list status control

The second layout revision removes the top yellow notice at the user's request,
centers the badge and smaller switch as one control, vertically aligns row
contents and right-aligns the action group in a bounded column. The list has a
subtle header background and a narrower-screen layout for the action group.
Only list HTML/CSS change; the existing in-place toggle script is retained.

The enable/disable action previously rendered the table, replaced every row with
a loading placeholder, fetched the entire list, and rendered it again. The list
now places an accessible switch below each status badge, matching the X template
control. Toggling updates the existing badge, switch and manual-run availability
in place. Only the affected row is busy; successful unfiltered toggles issue no
list request. A status-filtered result refreshes without the loading placeholder.

The existing enable/disable API and `expected_version` contract are unchanged.
Failed or incomplete responses trigger one GET for that template, never another
write. A changed configuration version replaces only that row. Copy/delete/run
confirmation, explicit publishing and all server publishing protections remain.

Only three static assets are installed: `fb-auto-publish-templates.html`,
`fb-auto-publish-templates.js`, and the new list-only stylesheet
`fb-auto-publish-templates.css`. Existing shared stylesheet, navigation and
hit-publishing asset versions are preserved. No services or schedulers restart.

Validation: JavaScript syntax and diff whitespace checks; real Chromium against
local API fixtures covering layout, successful enable/pause, pending-state
isolation, repeated clicks, keyboard activation, failure/readback, version
conflicts, filtered results, and preservation of existing table DOM nodes.
No production template is toggled for testing.

Deploy the pushed commit from a clean CPU checkout:

```sh
python3 scripts/deploy_fb_template_status_ui.py install \
  --folder /mnt/data-disk/fb-template-status-ui-20261120/layout2/backup
```

The installer checks the observed affected-file hashes before replacing them,
backs up each copy, and updates the main API static directory, Nginx document
root and active FB release static directory. `manifest.json` records the exact
commit, file hashes, backup locations and service PIDs.

Rollback using the same checkout:

```sh
python3 scripts/deploy_fb_template_status_ui.py rollback \
  --folder /mnt/data-disk/fb-template-status-ui-20261120/layout2/backup
```

Rollback restores only those assets and removes the new stylesheet after checking
for newer edits. It does not restore ledgers, change saved template status, or
touch in-flight work.
