# Recover X claims that never entered native publishing

A coordinator claim can fail before the native publisher reserves it. The native
queue remains queued with its original reserved log. A previously authorized
retry can encounter the same failure without consuming its authorization, leaving
the permission aimed at the generation that just failed.

`scripts/recover_x_unentered_publish.py` accepts explicit job IDs and defaults to
a read-only plan. Apply checks acknowledged terminal failure, no native entry or
operation for the failed generation, no publication, active resource, unknown
result or unrelated hold. It retains the original account, material, body, log and
attempt count. For an unused recovery, the prior authorization remains as a
superseded audit record and exactly the next generation receives permission.

Collect node outbox evidence using `recover_x_prepost_failures.node_evidence` for
the nodes in the plan. Pass those files to the apply command. The same node
receipt validation applies. Each selected job is held while its optional native
authorization is transferred, then returned to ready. A crash can be resumed
with the same plan and fresh evidence. No service restart or unrelated drain is
required. Back up the original rows in the plan and keep the existing database
backup; never restore an old database over newer publication facts.

The existing prepost recovery utility remains appropriate for explicit failures
whose native queue/log are failed. This companion handles only a reserved native
log and a failed coordinator generation with no native entry. It is an operator
tool, not an automatic retry policy.

Validation: first unentered claim retains its unstarted log; unused permission
advances once while preserving attempts and frozen descriptor; native entry,
unknown results and consumed permission reject recovery; repeated apply is
idempotent. Run `python -m unittest
scripts.test_x_unentered_publish_recovery.UnenteredPublishTests -v`.

Rollback of the tool is removal of the operator script; it has no runtime
installation. For an admitted task, use the existing scoped stop mechanism only
before execution. Once claimed, preserve the new claim and its receipts. Never
rewind a generation or restore an old authorization after execution begins.
