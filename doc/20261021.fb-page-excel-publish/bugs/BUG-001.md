# BUG-001：Excel J 列后的数据和公式未被校验

日期：2026-10-21。级别：P2。状态：已修复并独立复测通过。

## 发现与复现

代码评审发现解析器只读取到 I 列。隔离构造三种 `.xlsx`：A:H 为正常模板，在 J2 写入公式、J2 写入非空文本，或 J1 写入额外表头。修复前分别执行独立用例，均被按正常八列文件接受；没有产生应有的公式、额外数据或表头错误。

期望：八列外的公式按行提示修正，额外数据按行跳过，额外表头使文件结构校验失败。不能将这些单元格静默截断后继续发布。

## 根因与修复

`features/fb_video_publish/excel.py:read_workbook` 使用 `sheet.iter_rows(max_col=9)`，校验器无法看到 J 及以后单元格。

改为读取每行实际列范围，对全部额外列检查，按需补足前八列的空值。增加累计 200,000 个扫描单元格上限，避免稀疏格式列展开过量空单元格；保留原 200 数据行、2 MiB、解压大小和最大行号限制。

## 验证证据

`python scripts/test_fb_excel_review.py -q` 修复前运行 11 例，其中上述 3 例失败，其余 8 例通过。

修复后补充「可选尾部单元格不存在」和「13 个 XFD 空格式单元格展开超过扫描上限」用例，再运行 `python scripts/test_fb_excel_review.py -v`：13/13 通过。用例使用临时 SQLite 和本地构造的工作簿，没有真实发布或数据库外部写入。
