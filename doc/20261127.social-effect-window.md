# FB / TT 社媒指标统计窗口

FB 模板和新版 TT 自动发布模板的 `metric_window_days` 同时约束广告指标和社媒指标筛选、排序。短剧、素材两个层级及原渠道、产品、语言、人员权限维持不变。X 模板及素材效果报表仍沿用其累计口径。

## 日期与数据

- 使用选材时北京时间之前 N 个完整日期，不含今天，不限制帖子的发布时间；老帖在窗口内的新增数据同样参与。
- 浏览、点赞、评论、分享取窗口前一天与窗口末日的最后可用观测值之差。新帖以零为初始基线。这里是采集快照的净增近似，不是平台提供的精确事件时间统计；页面明确提示采集时间会影响精度。
- 缺任一边界快照、未采集、计数回落保持未知，不回退累计值、不当零。现有已知子集合仅可证明下限，上限仍要求覆盖完整。
- 收入按相同日期标签范围内的源 UTC 收入事实汇总；不把 UTC 日收入伪称北京时间小时收入。沿用精确发布/素材/短链归属。缺日期保持未知/部分回传。
- 每小时报告投影保留最近 32 天按指标、真实观测日期去重的日快照，过期值不能通过再次刷新变成新的观测。原始观察、累计报表、发布账本不改写。
- TT 单独发布 `social-income.json`，即使画像因某些日期缺失保留旧版，窗口收入仍能读取其他已验证日期；缺日写入选材证据。

## 验证

覆盖旧帖增量、1/7/30 天、北京时间跨日、今天排除、新帖零、缺基线、过期观测、回落、按指标时间、跨渠道合计与覆盖、窗口收入、筛选/排序/证据、FB 共享目录、Mobo 上线窗口，以及 TT 收入权限和发布流程。测试均使用隔离数据，无测试发帖。

## 部署及回滚

FB/采集代码来自 `codex/fb-social-effect-window-20261127`；TT 代码来自 `codex/social-effect-window-20261127`。先推送 GitHub，服务器检出确切提交。安装脚本：`scripts/deploy_social_effect_window.py`。

`stage DEPLOYMENT --tt-source TT_SOURCE` 克隆当前组合运行版本，仅覆盖此次文件，核对来源、备份两端账本和静态文件。`collector` 仅切换下次采集的源码入口，不终止正在运行的历史采集；`fb` 使用现有发布服务安全切换与调度恢复；`tt` 暂停新版 API 新请求、等待已接受处理结束后切换，独立发布执行器继续运行。分别核对服务账号读取、窗口日期、公开页面资源和调度健康。

`python3 SOURCE/scripts/deploy_social_effect_window.py rollback DEPLOYMENT` 回滚 FB、TT 消费端代码与页面，保留新增的日快照采集、当前数据和发布事实。不得恢复旧账本或覆盖当前收入/观测数据库。若出现后续并行发布，先核对现版本并合并回退，不覆盖其他改动。
