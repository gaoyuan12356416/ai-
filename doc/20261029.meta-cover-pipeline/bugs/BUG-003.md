# BUG-003 活跃共享账本使逐页备份反复重启

## 现象与根因

窄部署第一次使用分步online backup时，共享账本存在持续writer，分步源快照可能被外部提交不断更新，导致复制反复重启而无法及时收敛。该操作只写备份目录，没有替换API、切换业务代码或重放任务。

## 修复

提交 `23b3d606c12ea15bc2c5104cf041e45648e1ef8e` 的online_snapshot在源连接上显式BEGIN，并读取sqlite_master建立固定只读事务快照；随后pages=256逐步复制。progress回调检查15秒预算，超时抛错。无论成功、复制异常或截止触发，finally均rollback源事务；成功路径先释放源锁，再对备份目标执行integrity_check。

## 影响与边界

DELETE journal模式的其他writer可能在该固定读快照期间等待。15秒预算选择低于现有API的30秒busy_timeout；它在每步progress回调检查，并非操作系统级硬超时，单个底层I/O步骤可能越过预算后才返回。完整性检查不再延长源读锁。各文件分别一致，不提供跨多个SQLite文件的同一瞬时快照。失败目录不含可用完成计划，不得据其进行apply或恢复。

## 验证

新增3个用例分别断言：超时rollback且不做完整性扫描；复制异常rollback后关闭源；成功先rollback再完整性检查。与原5个窄部署用例合计8项，主代理报告本地与Linux均通过。完整Linux业务/窄部署回归此前733项通过，最新补丁仅修改备份辅助代码，业务执行代码未变化。
