# BUG-002 滑动补位初版可能退化为单条来源查询

## 发现阶段与根因

独立SA审查发现：首次准备64、提交32且buffer32时，一个future完成后补位，buffer降到31，原公式立即计算size=1并发起新SQL快照。候选多且完成错峰时，这会抵消批量查询优化。

## 修复

仅在fresh buffer耗尽，或执行仍有无法由buffer填充的空位时才新开来源批。已有buffer和满执行槽时继续消费已准备数据。保留账户偏斜下必要的小批补位与TTL检查。

## 验证

新增 test_staggered_completions_consume_buffer_before_another_sql_batch：12任务、4并发，第一批8，任务错峰释放；下一批保持4，禁止无必要单条查询。独立运行 test_cover_scheduler.py 共7项通过。

## 状态

已修复并完成专项回归；完整模块回归由主代理记录。
