# BUG-002 V2 在横竖屏切换时重置 source 时间轴

## 发现阶段

T4 exact release 视觉对照。

## 现象

候选 `d2b49b2` 的 30 秒 legacy/V2 成片均可完整解码，但全片 SSIM 仅 `0.865390`；并排帧显示片头与首段剧集提前重叠，后续镜头也在分段边界出现帧位差。

## 复现步骤

使用包含 16:9 片头和竖屏剧集的真实只读源，按同一冻结配方分别运行 legacy 与 `opencl_fused_v2`，比较全片 SSIM 和逐帧统计。

## 期望结果

V2 保持源流的连续 demuxer 时间轴；滤镜因分辨率变化重建时不得把后续段重新归零。

## 实际结果

source 输入链使用 `setpts=PTS-STARTPTS`。FFmpeg 在横竖屏切换时重建滤镜，`STARTPTS` 再次取新段起点，导致片头与后续段在相同时间位置竞争。

## 根因分析

循环模板素材需要各自从零开始，但 source 与它们共用了同一个时间戳表达式。源输入的 chunk seek 已完成分片重基准，不应在滤镜内部再次使用会随重建变化的 `STARTPTS`。

## 修复说明

source 单独使用 `setpts=PTS,fps=30`，保留分片内 demuxer 时间戳；border、opacity、corners、tint 四个循环素材继续使用 `setpts=PTS-STARTPTS`。增加命令图契约回归，确保 source 与四个模板输入采用不同时间轴语义。

## 影响文件

`features/drama_synthesis/gpu_compositor.py`、`scripts/test_drama_gpu_compositor_v2.py`。

## 验证命令与结果

单项命令图测试及 503 项完整回归通过；新 exact release 的 T4 视觉复测待执行。

## 回归结论

候选 `d2b49b2` 已拒绝，未切换生产 worker；正式任务与 CPU lease 已按用户指令暂停并保留证据。
