# BUG-002 视觉差异被误判为 source 时间轴重置

## 发现阶段

T4 exact release 视觉对照。

## 现象

候选 `d2b49b2` 的 30 秒 legacy/V2 成片均可完整解码，但全片 SSIM 仅 `0.865390`。使用输入级快速 seek 抽取的 1 秒对照帧看似出现片头/剧集错位，因此最初怀疑 source 时间轴被重置。

## 复现步骤

使用真实只读源，按同一冻结配方分别运行 legacy 与 `opencl_fused_v2`；除输入级 seek 截图外，再执行顺序解码接触表、逐帧元数据、源/旧版/V2 三联图和只保留 source 双层的隔离渲染。

## 期望结果

诊断必须区分关键帧 seek 取样差异、真实时间轴差异和空间几何差异，不能用单张快速定位帧代替顺序解码证据。

## 实际结果

真实 30 秒样本始终为 `1080×1920 / 25fps`，不存在横竖屏切换。提交 `782c41d` 将 source 改为 `setpts=PTS` 后，同源 SSIM 反而从 `0.865390` 降至 `0.862533`，且视觉差异模式不变，证明该假设不能解释本次失败。

## 根因分析

输入级 `-ss` 截图在场景切换附近会受两条输出各自关键帧位置影响。顺序解码显示两路场景次序一致；只保留 source 双层后仍有 `0.845413` 的差异，最终根因转向 legacy 空间几何契约，见 `BUG-003.md`。

## 修复说明

撤销“BUG-002 已修复视觉问题”的结论。`setpts=PTS` 仍保留为与现行 legacy source 链一致的独立时间轴契约，但不得再把它描述为此次 SSIM 失败的根因或修复。

## 影响文件

`features/drama_synthesis/gpu_compositor.py`、`scripts/test_drama_gpu_compositor_v2.py`。

## 验证命令与结果

`782c41d` 本地 503 项回归通过，但 T4 同源视觉复测为 `0.862533 < 0.90`，候选已拒绝。后续以 BUG-003 的几何修复继续验收。

## 回归结论

本条以“诊断假设已证伪”关闭，不计为已修复生产缺陷。候选 `d2b49b2`、`782c41d` 均已拒绝，未切换生产 worker；正式任务与 CPU lease 已按用户指令暂停并保留证据。
