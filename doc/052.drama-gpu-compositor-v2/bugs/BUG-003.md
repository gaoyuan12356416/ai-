# BUG-003 V2 未复刻 legacy 旋转画布与 YUV420 坐标契约

> 状态：兼容诊断已完成，但该可见行为被用户明确拒绝作为最终成片；生产方案由
> `BUG-004` 的 clean profile 取代。本记录仅保留根因证据。

## 发现阶段

T4 exact release 真实源视觉隔离。

## 现象

候选 `782c41d` 的完整随机模板输出可解码，但 SSIM 为 `0.862533 < 0.90`；只保留 source background/main 两层后仍仅为 `0.845413`。提高 OpenCL 采样阶数没有改善，表明差异主要不是纹理插值质量。

## 根因分析

legacy 图使用：

```text
scale=w='trunc(iw*scale/2)*2':h='trunc(ih*scale/2)*2',
rotate=angle:ow=rotw(iw):oh=roth(ih),
overlay=(W-w)/2:(H-h)/2
```

`rotw/roth` 应接收旋转角，但历史图传入了缩放后的宽高。以本次冻结配方 `scale=0.9963`、`rotation=1.554°` 为例，legacy 实际主层为 `716×1274`，错误旋转画布为 `1043×821`，并在默认 YUV420 overlay 中把坐标从 `(-161.5, 229.5)` 截断并偶数对齐为 `(-162, 228)`。V2 此前按连续归一化几何计算，未复刻这些已进入既有成片的可见行为。

## 修复说明

- 编译 OpenCL kernel 时冻结 legacy 主层尺寸、错误 `rotw/roth` 画布尺寸和 YUV420 偶数叠加坐标。
- 使用 FFmpeg rotate 的中心点反向映射，并严格限制在历史旋转画布边界内。
- 保留单次 `program_opencl` 融合与 NVENC，未增加 CPU scale/rotate/overlay 路径。
- 将本兼容契约封装为独立几何编译函数，后续若发布修正视觉的新 profile，可显式迁移而不污染 V1 兼容输出。

## 验证结果

真实 30 秒冻结配方一次性诊断：

| 版本 | SSIM | 30 秒渲染耗时 |
| --- | ---: | ---: |
| 原 `782c41d` | 0.862533 | 约 22.6 秒 |
| 仅正确数学旋转尺寸 | 0.889731 | 约 22.6 秒 |
| legacy 错误尺寸，未偶数对齐 | 0.897032 | 约 22.7 秒 |
| legacy 尺寸及偶数对齐 | 0.909079 | 约 22.7 秒 |
| 再限制历史旋转画布边界 | **0.931400** | **22.888 秒** |
