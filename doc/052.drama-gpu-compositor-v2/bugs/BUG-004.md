# BUG-004 兼容候选继承横向断层和异常裁切

## 发现阶段

用户审阅 T4 对比截图时确认，左右拼图只是诊断输出；正式成片不得包含 legacy
几何造成的黑块、横向断层、错位裁切或画面跳变。

## 根因

`BUG-003` 为了与历史 CPU 成片保持高相似度，曾在 GPU kernel 中显式冻结错误的
`rotw(iw)/roth(ih)` 旋转画布和 YUV420 偶数坐标。该兼容策略会把已确认的旧缺陷
继续带入新成片，与“制作效率和泛用性优先”的目标冲突。

## 修复

- 主体层先 contain 到透明 `720x1280` 平面，再按冻结配方缩放。
- 每个输出像素围绕画布中心执行一次逆旋转，直接映射回缩放后的主体平面。
- 不创建中间旋转画布，不再编译错误旋转宽高或 legacy overlay 坐标。
- renderer profile 升级为 `drama-opencl-fused-h264-720x1280-v3-clean`，使旧候选
  kernel、分片和最终检查点全部身份不匹配并 fail closed。
- 真机验收改为正确角度 CPU 参考与 GPU clean 候选对照，同时单独导出候选单画面
  预览；不再以复制旧错误成片作为发布目标。
- 任意非零时间点的验收短样必须精确解码重编码；禁止关键帧流复制把请求的 30 秒
  样本扩成更长区间并污染时序判断。
- 验收短样标准化使用 `libx264`，不直接把历史 `yuvj420p` 输入送入 NVENC；后者在
  当前 565.57.01 驱动的独立截取阶段触发过 `libnvidia-encode` 段错误。正式 fused
  compositor 仍按设计使用 OpenCL 后的 `yuv420p` 输出和 NVENC。

## 验收

需要完成本地完整回归、香港 T4 exact release preflight、代表性视觉样本、受控恢复、
长样性能及生产自然续制。所有正式 worker 在通过前保持停止。
