# BUG-005 横屏主体 contain 仍形成横向分层

## 发现阶段

clean profile 横屏真实 30 秒样本。两条视频均完整解码，但 GPU 候选画面仍存在一个
居中的横屏主体矩形，上下边界清晰；虽然不再是错误旋转画布，视觉仍与用户明确拒绝
的“横向断层效果”接近，因此候选未通过且未切换生产。

## 根因

主体层保持了历史 `contain + transparent pad` 语义。横屏输入在 9:16 画布内必然只占
中间区域，再叠到 cover 背景上；scale/rotation 会让两条边界更明显。该行为是数学上
正确的 contain，但不符合本次“单个连续全画幅”的业务验收。

## 修复

- Composition 中 `source-main.fit` 改为 `cover`。
- OpenCL 主体平面内部直接复用 cover 采样；透明只发生在缩放/旋转后的平面外缘。
- clean CPU 参考同步使用 `increase + crop`，并继续使用正确角度的 `rotw/roth`。
- renderer profile 升级为 `drama-opencl-fused-h264-720x1280-v4-fullbleed`，使 v3
  contain 分片、kernel 和最终检查点全部失效。

## 验收

必须重新完成横屏、竖屏、分辨率切换、分片边界和长样测试。横屏单画面不得再出现
居中的 contain 矩形或上下横向边界。
