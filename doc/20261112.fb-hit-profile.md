# Facebook hit-drama Page matching and receipt repair

The explicit hit-drama action now selects Pages using the same strict reverse
profile match as X: the target drama has the Page's language, its audience has
positive income in that Page's portrait, and at least one of its themes has
positive income under that same audience. Any positive matching branch qualifies;
this action does not use the random first preference from ordinary automatic
selection. Missing/invalid portraits, labels or matching branches skip the Page.
No matching Page returns an explicit rejection before creating a run.

Freeze the target's matched Page IDs, Page languages, allowed content versions and
compact per-Page/content income evidence. Both Page reads in the planner intersect
with this frozen scope. Material selection cannot move to another target version.
Per-task audit contains only its actual Page/content evidence. Existing operations
return their original receipt before reading current portraits; no historical task
is retried, redirected or rewritten.

The existing template's material product, launch window, metrics, source rules,
cooldown and occupancy still apply. No-source-material is no longer misreported as
drama cooldown merely because an unrelated drama is cooling down. Actual drama
cooldown, material cooldown and no eligible material have separate reasons.

Only the named-drama POST `/run-now` receives a 240-second upstream timeout, below
the existing 300-second Nginx timeout. A read timeout is `fb_auto_result_pending`;
the browser retains its operation ID for reconciliation. It reports zero queued
Pages as “本轮未发布” and displays both profile rejection and task skip reasons.
X's existing submission and selection behavior remain unchanged.

## Validation and scoped deployment

Tests: `python -B -m unittest tests.test_fb_hit_profile tests.test_fb_hit_receipt
scripts.test_fb_hit_drama scripts.test_hit_drama_target
tests.test_fb_profile_selection tests.test_fb_profile_integration
scripts.test_fb_target_midnight scripts.test_fb_auto_validation -q`.
The receipt tests execute the shared UI JavaScript with Node, covering zero queue,
specific Page rejection reasons, unknown-result retries and X behavior.

Push the exact commit and fetch it on CPU 43.166.187.96. Run
`python3 -B scripts/deploy_fb_hit_profile.py prepare --folder DEPLOYMENT`, then
the read-only `scripts/preview_fb_hit_profile.py --run-id 324` to verify the actual
target and Page mapping without creating any publication work. `--selection`
additionally checks the matching Pages' material availability and reservations.

Activate with `python3 -B scripts/deploy_fb_hit_profile.py apply --folder DEPLOYMENT`.
The helper overlays only the FB selector files, updates only the main API's FB
client after draining accepted requests, and patches the shared dialog asset and
its cache version in each existing HTML copy. It preserves different live HTML
contents, X processes, frozen tasks, queues, short links and platform receipts.
The FB and affected API-dependent scheduler states are saved/restored and checked.

Rollback: `python3 -B SOURCE/scripts/deploy_fb_hit_profile.py rollback --folder
DEPLOYMENT`. Restore code/assets and the previous FB pointer, keeping current
databases and receipts. Never restore `ledger-before.sqlite3` over live results.
