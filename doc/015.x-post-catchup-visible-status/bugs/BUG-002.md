# BUG-002 补发日志批次显示为空

## 发现阶段

生产真实浏览器验收。

## 现象

六条补发日志、Post 预览和短链均已出现，但批次列显示“批次 —”，
没有显示“补发批次 1”。

## 根因分析

`features/x_posts/service.py` 同时被 X Sidecar 和主后台 API 两个运行时加载。
初次部署只更新了不可变 X release/Sidecar；主后台
`/root/drama_material_service` 仍加载旧版共享 service，因此日志 API
没有返回 `batch_kind` 和 `catchup_run_id`。前端虽然已是新版，但没有字段
可供显示。

## 修复说明

1. 将主后台旧 service 备份到部署前备份目录。
2. 从同一不可变 Git release 安装新版 service；两份文件 SHA-256 均为
   `8258130b439006fbfffb7850062cbf37044ca8b2b78b2a52aa2fde1854ce13e4`。
3. 只重启 `drama-material-api.service`，未重启 daily runner、Sidecar
   或再次触发发布。

## 验证结果

- 主后台日志 API 返回 200。
- 真实浏览器读取到六条“补发批次 1”日志。
- 六条仍为已发布、尝试 1 次，Post 预览和短链入口齐全。
- 父批次 4、子批次 1、队列/日志及发布计数均未被重启改写。

## 回归结论

已关闭。
