# FB 停用模板允许爆款发布

停用模板可进入爆款剧、爆款素材弹窗并确认创建任务，无需先启用自动调度。
仅改变这两个明确指定内容的入口；普通手动执行和自动计划仍要求启用模板。

新建爆款运行由服务器在冻结配置中记录 `explicit_publish_independent=true`。
领取制作、制作完成/重试、领取发布都识别该标记；后续关闭自动调度不会取消这类新任务。
旧运行不补标记、不回放。删除、版本变化、权限、Page 资格、容量、素材占用、
幂等回执、未知写入和发布租约保持原规则。停用模板不占用“已启用模板”的容量快照。
素材接口容量计算不再把停用模板的自动日配额计入。

验证：31 项相关测试覆盖既有爆款流程、停用模板创建/幂等回读/制作重试/成片/发布领取、
未来发布时间、防重、保持停用、旧任务不恢复、普通手动/自动限制、权限、版本和删除。
浏览器模拟验证两个按钮和确认弹窗可用，打开弹窗不自动启用或发出发布写入。
服务候选目录额外用当天 Mobo 的真实规划器模拟用例，将模板先停用，验证画像、冷却和幂等回执。
扩展 Page 隔离套件 23 项存在 8 个旧断言失败，未改基线复现相同 8 项；本次未改该保护策略。
生产验证不发送真实 Post，不启用或修改业务模板。

部署从 GitHub 拉取精确提交，复制当前 FB 运行目录，仅覆盖 5 个 Python 文件和 2 个静态文件，
保留当天已上线的 Mobo 路由等并行修改。使用既有 FB admission/drain/switch 流程，
只切换 FB sidecar，并保存及恢复 FB 定时器/调度器原状态，不重启其他渠道。
旧运行目录、静态文件备份、SQLite 一致性快照和验收文件均在部署目录；回滚不恢复数据库。

```sh
python3 /mnt/data-disk/x-tag-template-ui-20261119/source/scripts/deploy_fb_disabled_hit_publish.py prepare --folder /mnt/data-disk/fb-disabled-hit-20261119
python3 /mnt/data-disk/x-tag-template-ui-20261119/source/scripts/deploy_fb_disabled_hit_publish.py apply --folder /mnt/data-disk/fb-disabled-hit-20261119
python3 /mnt/data-disk/x-tag-template-ui-20261119/source/scripts/deploy_fb_disabled_hit_publish.py rollback --folder /mnt/data-disk/fb-disabled-hit-20261119
```

旧版本不识别新标记，回滚后停用模板下未完成的新爆款任务会暂停，账本和回执仍保留。
正常回滚应先让这批已确认任务完成；不能清空队列、重新提交或恢复旧数据库来绕过。
