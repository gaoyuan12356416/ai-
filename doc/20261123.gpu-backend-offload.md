# GPU backend assistance

This release stages independent CPU preparation and read/compute services on
the existing 40-core Hong Kong host. It does not replace existing GPU workers.
The CPU preparation dependencies are frozen from the running CPU preparation
release; social analytics dependencies are frozen from the current main API.
Reconciled files are deployed only into the new isolated runtime, never over
existing publishers, coordinators or renderer directories.

The new `hk-cpu-assist` identity only enables prepare adapters, locally clamps
publication to zero and preparation to at most two slots. Register and set
both server-side capacities to zero before starting it. Transfer one existing
CPU preparation slot only after that slot's current task naturally completes.
Use the versioned coordinator capacity API, preserving all other node limits.
Keep the original backend/profile, output contracts, leases and receipts.

The parent assistance slice is capped at 8 CPUs and 16 GiB; the media child at
6 CPUs and 12 GiB. Existing GPU services are outside this slice and are not
restarted. A stop requests natural draining and never SIGKILLs media children.

Rollback: set only the assistance preparation capacity to zero through the
versioned API, wait for its claims and receipts to settle, restore each released
CPU slot, then stop only the assistance service. Preserve state and artifacts.
Database access remains disabled until read-only connectivity and the shared
14-query plus one-watchdog budget have been verified.
