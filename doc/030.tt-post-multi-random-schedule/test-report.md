## 缺陷情况

无未关闭产品缺陷。开发中的初始失败均为新增测试断言与样例数据错误，没有进入产品代码。首次生产切换遇到 release 根目录权限问题，自动回滚后按既有不可变权限模型修复并重新发布，详见 `bugs/BUG-001.md`。桌面 100% 缩放错位已按纯 CSS 范围关闭，详见 `bugs/BUG-002.md`。

## 验证证据

- 旧版配置/排期 schema 在临时数据库中执行加法迁移，单时间保持为固定模式，`PRAGMA integrity_check=ok`。
- 1、2、12、24 次随机计划均覆盖；全部分钟非 `00`，同日相邻时间差不少于 60 分钟。
- 两个存储实例并发确保同一账号日期时只保留一份完全相同的计划。
- 自然调度只认领持久化计划中的精确槽位，同一槽位重复扫描不创建第二个队列。
- 所有用例使用临时 SQLite、假账号源和假 GPU；未发起真实 TikTok 发布。
- 页面契约确认 `.direct-test-panel` 不再创建外层隐式列，内部 `.schedule-panel` 的正确跨列规则保持不变。
- 2560、1920、1680、1600、1440、1280、1180、820px 宽、100% 缩放浏览器检查中，页面与随机计划区均无横向溢出，保存按钮和账号设置无重叠。
- 生产迁移后历史配置仍为版本 6、7 个账号、固定 `14:00`；随机计划表为 0 行。
- 生产部署前后队列/运行/发布 ID 基线分别保持 `7/7/6`；自然 runner 的发布请求数为 0。

## 遗留风险

- 跨北京时间自然日不承诺前一日最后一个时间与次日第一个时间仍间隔 60 分钟；该限制仅适用于同一日计划。若把跨日也纳入且每天 24 次，会与“每天计划不同”产生数学冲突。
- 服务异常停机超过槽位的 10 分钟安全窗口时仍按既有规则不追补历史发布。
