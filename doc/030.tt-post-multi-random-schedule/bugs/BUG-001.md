# BUG-001 新 release 目录权限阻止服务启动

## 状态

已关闭，不是业务代码缺陷。

## 现象与影响

2026-08-04 15:14:57 CST 首次切换 release 后，`tt-post-service` 报 `Permission denied`，健康检查失败。自动回滚立即恢复旧 release 和两处静态页；生产数据库尚未迁移，队列 7、运行 7、非空 `publish_id` 6 均未变化。

## 根因

使用 `mktemp -d` 构建 release 后直接重命名，根目录保留 `0700`。服务以 `tt-post` 用户运行，无法穿越该目录读取 `scripts/tt_post_service.py`。

## 修复

按服务器既有不可变 release 模型设置：目录 `0555`、普通文件 `0444`、可执行文件 `0555`。切换前使用 `runuser -u tt-post` 完成源码读取和 Python 导入检查。

## 验证

- 15:16:50 CST 重新切换成功，health 返回 200。
- 15:17 CST 自然 runner 返回 `status=ok`，发布请求数为 0。
- 服务、数据库、静态页及部署前后业务计数验证全部通过。
