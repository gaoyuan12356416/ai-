# BUG-002 空目录查询触发剧集表长时间扫描

## 发现阶段

2026-10-22，真实目录只读canary验证；由API实施者发现。前端契约审查同步确认产品展示字段与搜索入口需调整。

## 现象与复现

选择产品时，页面自动发送空 `q` 的 `/api/video-editing/catalog/dramas` 请求。旧查询对剧集明细表执行宽范围聚合 / 模糊条件，可能扫描大量剧集行，导致请求长时间不返回。实施者定位并终止本次canary的确切SQL连接，没有批量终止其他业务查询。

## 期望结果

选择产品不触发无条件剧目扫描。用户输入完整剧ID或至少两个字符的剧名前缀后才查询；查询沿用产品可用性检查和现有SQL门控，在限定预算内成功或明确失败。

## 根因

目录接口允许空搜索，前端产品选择事件直接调用查询；剧集明细按剧归并时缺少索引范围和执行预算。产品DTO实际使用 `label` / `app`，只使用name也会让选择项退化为ID，不利于判断选中产品。

## 修复

- 前后端拒绝空查询；非数字至少2字符、总长最多100字符。前端选择产品后只显示输入提示，不发送空请求。
- 纯数字完整ID精确匹配 `content_id`；混合字母数字及下划线 / 连字符标识先精确匹配ID，非数字未命中再执行name前缀查询。中文等名称直接查前缀，转义通配符。
- 使用 `content_id` / `name` 索引，SQL读取最多500行，再按剧ID去重返回最多50部；移除宽范围OR模糊聚合。
- SQL5秒、连接3秒、单次进程15秒预算；超时终止本次进程组并返回固定安全错误，保留原全局SQL门控。
- 产品显示兼容 `label || app || app_id`，请求继续传原app_id。

## 影响文件

`features/video_editing/catalog.py`、`static/video-editing.js`、`static/video-editing.html`及对应service / 前端契约测试。

## 验证

前端新增2项契约用例：真实产品字段可读展示且ID不变；空白 / 单字不请求目录，两字前缀发起查询。JS23项通过；最新完整Python回归117项、116通过、1项可选COS SDK跳过，包含BUG-006新增9项，子集不另行累计。BUG-006部署回读待主实施，不影响本目录缺陷的独立证据。

后端实施者已执行真实只读目录核对：两个剧ID精确查询均约2秒，剧集读取分别44/57项且约3秒，名称前缀返回2项约2秒；EXPLAIN为 `ref/content_id/225` 和 `range/name/527`，无全表scan。证据为CPU `/mnt/data-disk/video-editing/validation/canary20261022_a/catalog-read-validation.json` 与 `catalog-index-plans.json`。正式Chrome后续成功查询并添加真实剧集；这些观测不保证所有查询都具有相同耗时。

## 状态

代码修复、本地测试和上述真实目录查询通过。无条件长扫入口已关闭；完整业务出片与浏览器文件选择仍按测试报告单独验收，不影响本项缺陷关闭。
