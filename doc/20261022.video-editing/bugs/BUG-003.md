# BUG-003 FFmpeg 7.1 的 setpts 清除滤镜链帧率，导致 xfade 组装失败

## 发现阶段与现象

2026-10-22，香港GPU隔离canary使用真实FFmpeg执行新剪辑链路。3个来源probe和4个标准化片段成功，进入join组装后失败。标准化文件均为H.264 / AAC、720×1280、30fps、SAR 1:1，因此不是BUG-001的SAR问题。

在候选 `8cb7b65b2d25deecf353a3704e221df2ff552d22` 和首次修订候选 `c80f7e17de170df19efed432e81ed3d033778095` 上，分别对保留的本地标准化片段执行隔离诊断，均实际取得以下stderr，退出码为234：

```text
[Parsed_xfade_16 ...] The inputs needs to be a constant frame rate; current rate of 1/0 is invalid
Failed to configure output pad on Parsed_xfade_16
Error reinitializing filters!
```

`Parsed_xfade_16` 是此配方的第一个xfade。不能将它误记成concat之后的第二次过渡，也不能只依据文件层面的30fps推断滤镜链仍保留帧率。诊断仅使用本地媒体路径，未输出短期签名URL。

## 根因与直接证据

GPU运行FFmpeg `n7.1-152-gd72536008a-20250113`，本地测试为 `8.0.1-full_build-www.gyan.dev`。在此次GPU 7.1构建中，setpts会把输出滤镜链的frame_rate变为1/0；本地8.0.1的setpts具备默认false的 `strip_fps` 选项，因而仅在本地正常执行未暴露这个差异。GPU构建没有该选项，不能以增加 `strip_fps=false` 作为兼容修复。

GPU上对同一标准化片段逐项执行showinfo，得到以下滤镜输入配置：

| 滤镜链 | time_base | frame_rate |
| --- | --- | --- |
| `showinfo` | 1/15360 | 30/1 |
| `settb=1/30,showinfo` | 1/30 | 30/1 |
| `settb=1/30,setpts=PTS-STARTPTS,showinfo` | 1/30 | 1/0 |
| `fps=30,settb=1/30,setpts=N,showinfo` | 1/30 | 1/0 |
| `settb=1/30,setpts=PTS-STARTPTS,fps=30,showinfo` | 1/30 | 30/1 |

首次修订把fps放在时间戳重写之前，真实GPU复验仍失败。上表证明fps必须放在setpts之后，才能为下一个xfade恢复有效的恒定帧率。

## 修复

- 对进入组装的每一路视频使用 `settb=1/30,setpts=PTS-STARTPTS,fps=30`。
- 对每次concat / xfade的结果使用 `settb=1/30,setpts=N,fps=30`，然后再接下一次拼接，避免后续时间戳重写再次清除帧率。
- 保留30fps帧数裁切与0.3秒 / 9帧淡化契约。音频继续按48kHz处理，不通过改变预期片长绕过错误。
- 补充每次normalize / join等本地媒体命令的安全诊断路径，持久保存返回码、进度、stderr大小 / 摘要及允许的错误标签；不把原始命令、签名URL或任意stderr写入公开结果。

影响文件：`features/video_editing/render.py`、`features/video_editing/gpu_integration.py`、`tests/test_video_editing_render.py`。

## 验证

本地 `test_video_editing_render.py` 5项全部通过。真实制作用例使用4段、fade→cut→fade，并对画面和声音完整解码；在本地FFmpeg支持 `strip_fps` 时，为组装链每个视频setpts注入 `strip_fps=1` 模拟7.1行为，再制作并完整解码一次。这项检查能在本地新版FFmpeg上捕获本次兼容问题。

最终候选 `ab27b932c272c63766ffc4d930f22291b5248e8e` 已在同一香港GPU完成3个probe和2个完整render，使用合成测试素材，两条独立时间线分别输出108帧 / 3.6秒、102帧 / 3.4秒。两条成片下载SHA256和字节数与COS回执一致，完整解码无错误，格式为H.264 / AAC、720×1280、30fps、SAR 1:1、48kHz双声道，音视频时长相同。

逐帧与冻结配方比较，全片平均RGB绝对误差为0.254 / 0.261；四处9帧淡化的中点混合误差为0.616—0.827，远低于单侧画面误差。无声源与显式静音窗口RMS为0，原声、淡化和后续声音恢复位置符合配方。两条render及三个probe均通过私有COS、重复缓存与成功工作目录清理检查。

本地验收证据位于 `output/video-editing-validation/`：

- `join-diagnostic.json`、`join-diagnostic-v2.json`：两次真实组装失败、输入元信息与命令摘要。
- `frame-link-diagnostic.json`：实际GPU的showinfo帧率配置。
- `gpu-canary-results.json`：最终候选、冻结配方、COS产物回执、私有性 / 缓存 / 清理结果。
- `finished-media-validation.json`：独立下载校验、FFprobe、完整解码、逐帧内容 / 几何 / 淡化及音频RMS数据。
