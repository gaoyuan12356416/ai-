# BUG-005 首次CPU部署缺少局部sys导入与Nginx接口转发

## 发现与影响

2026-10-22，CPU按 `0d4af1b` 窄范围安装后，新接单入口仍关闭。正式浏览器请求 `/api/video-editing/config` 返回404；直接访问CPU回环接口时连接被中断。主实施读取journal，定位到实时 `app.py` 的 `do_GET` 第94172行：注入的 `video_editing_handle(..., sys.modules[__name__])` 抛出 `NameError: name 'sys' is not defined`。

这次发现两个独立缺口：Python分发块未能执行，以及Nginx没有将新增API路径转发给CPU服务。仅修复其中一项不能证明公开入口可用。

## 根因

1. AST注入脚本依赖宿主app已经导入sys，但实际复合运行文件没有顶层sys导入。旧验证只做编译及AST结构比较，测试fixture还显式提供了顶层 `import sys`，没有执行新分发路径，因而漏掉运行时错误。
2. 首次部署未安装 `/api/video-editing/` 的专用Nginx location；新增后端路由没有自动进入既有站点转发规则。
3. 原CPU健康检查只验证 `/api/auth/status`。旧接口正常不能证明新增模块分发和公开代理链路正常。

## 修复与实际部署

修复提交为 `c6d394ab39bdabacfefde1d33890b583eb03adb6`。

- `scripts/patch_video_editing.py` 在新分发块中加入局部 `import sys`；对于已安装旧块，按AST识别bridge导入位置并幂等补齐局部导入。既有业务方法不重写。对当前checkout的内存预检确认仅增加4行局部导入，再次patch不产生变化。
- 新增 `deploy/video-editing-nginx.conf`，使用 `location ^~ /api/video-editing/` 转发至 `127.0.0.1:8787`，限制JSON请求体2MiB并禁用响应缓存。视频字节仍由浏览器直接发往COS。
- CPU部署脚本纳入该Nginx片段、配置检查及reload，并在旧健康接口正常后检查新模块config的未登录JSON401响应；不能再以旧health单独判定安装成功。
- 主实施按GitHub提交完成独立备份、实时app哈希核对和窄范围修补 / 重启，补齐Nginx路由。未将整个checkout覆盖到复合运行目录，也未为修复重新执行整套首次安装。

## 验证证据

本地集成测试使用没有全局sys的可执行stub，先复现旧块的NameError，再执行修复后的GET、POST、PATCH、DELETE以及HTML / JS / CSS入口；确认分发取得当前模块对象，原有无关路径仍调用原处理逻辑。覆盖旧块修补和重复执行幂等，集成测试6项通过。

主实施已实际回读修复后的新模块接口，未登录返回JSON401，确认请求到达模块鉴权层；公开入口不再以404或Python连接中断结束。401是预期的未登录响应，不代表用户已登录、已获权限或整条制作流程已通过。线上修复及回读由主实施执行，本缺陷记录编写过程没有再次操作服务器。

## 状态与边界

两项入口故障已修复并完成真实回读。正式Chrome继续执行登录后的业务验收；已观察到真实剧集校验完成及剪切操作，不据此扩大为完整浏览器出片通过。Chrome尚未开启所需file URL访问，文件选择 / 上传页面操作链路仍待验收；工作站到COS的程序直传证据不能代替该浏览器步骤。
