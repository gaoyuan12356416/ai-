# BUG-004 部署helper未等待HTTP监听就绪，导致启动后误入异常处理

## 发现与影响

2026-10-22，主实施将香港GPU切换至 `81f75eca25bd472cddec21ccbd2e09b5f728fe51`。候选预检已通过，但systemctl启动返回后，应用HTTP监听尚未就绪，helper立即调用health检查失败。进入异常处理后，媒体活动守卫因无法确认监听返回 `media_listener_unverified`，保留新reader，没有盲目停止或切回旧版本。

主实施随后独立回读确认health正常、release / renderer profile / 并发1 / 环境均符合预期，23份历史账本SHA256未变，媒体执行为空闲。回读没有再次重启。备份目录为 `/data/drama-synthesis-gpu/deploy-backups/video-editing-20261022T050848Z`，有效状态补充记录为其中的 `result-reconciled.json`。本次部署不能记作helper全程无异常成功，也不能因helper报错推断新worker未运行。

## 根因

systemd的进程启动成功并不保证应用已经绑定HTTP端口。helper直接执行 `check_health(health(), ...)`，没有区分短暂的连接拒绝与身份 / 配置错误，首次连接失败便进入回滚流程。媒体守卫按既定规则对未知状态拒绝操作；本次应修正启动就绪等待，保留守卫的失败关闭行为。

## 本地修复

`scripts/deploy_video_editing_gpu.py` 增加 `wait_for_health`，候选启动及恢复旧版本后的启动均使用该检查：

- 仅当连接失败的实际errno为 `ECONNREFUSED` 时，按最多0.5秒间隔等待，默认总期限60秒；期限耗尽返回固定安全错误 `worker_health_start_timeout`。
- 成功读取health后立即执行原有release、旧模块参数、编辑profile和接单关闭校验，任一不符立即失败，不继续等待“变好”。
- HTTP错误、连接超时、非连接拒绝网络错误和非法JSON不视为就绪等待；错误详情不进入公开输出。
- 不修改媒体活动守卫、账本、回滚边界或线上运行配置。

## 验证

新增4项测试覆盖：连接拒绝后恢复并校验身份；持续拒绝在期限内失败；release / 并发 / 接单状态不符立即失败；HTTP错误 / 超时 / 非法JSON不重试。`test_video_editing_gpu_deploy.py` 共14项通过。最新完整Python回归为117项、116通过、1项可选COS SDK跳过，无失败，包含BUG-006新增9项，子集不另行累计；BUG-006部署回读待主实施。

## 状态与边界

原因已确认，helper修复已完成本地验证，供后续部署使用。本次没有为验证helper再次操作服务器，没有改变已独立回读通过的线上payload。改进后的部署helper尚未再次执行完整线上部署；不能把已有版本回读成功写成新helper真实部署通过。
