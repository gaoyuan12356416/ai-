# BUG-001 SAR 导致 contain / cover 标准化与拼接异常

## 发现阶段

2026-10-22，GPU实施者进行本地真实 FFmpeg 制作验证时发现。原始失败的完整stderr和独立失败输入快照没有保存，本文不补写未经留存的报错原文；修复后已完成本地执行和真实GPU成片复验。

## 现象

不同来源视频在 contain 黑边 / cover 铺满转换后可能仍带有非1:1像素宽高比（SAR），导致显示比例异常或拼接阶段尺寸 / SAR 不一致。

## 复现步骤

使用横屏 / 竖屏来源，分别生成 contain / cover 的720×1280片段，再执行直接拼接或交叉淡化。对比标准化片段的宽高与 SAR。该检查覆盖缩放可能调整SAR的情况；不是对原始失败输入的逐字重放，不能据此声称已保留最初失败日志。

## 期望结果

所有标准化片段为720×1280、SAR 1:1、30fps、yuv420p；contain完整显示并补黑，cover按显示比例裁切；后续cut / fade接入相同几何契约。

## 实际结果

发现阶段出现几何 / SAR 不统一，不能仅凭编码宽高相同判定可拼接。该结论来自实施时的真实制作检查；原始错误原文未留存。后续香港GPU的 `frame rate 1/0` 故障属于另一项兼容问题，单独记录于 `BUG-003.md`，不能用其日志替代本缺陷的原始证据。

## 根因分析

原来源像素宽高比参与实际显示比例，FFmpeg的scale也可能为保留显示比例调整SAR。即使进入适配前已设为1:1，后续缩放 / 裁切后未重新统一SAR，仍可能破坏拼接输入的几何契约。

## 修复说明

标准化视频先执行 `scale=trunc(iw*sar/2)*2:ih,setsar=1`，将来源显示宽度折算为偶数像素；随后执行 contain 的等比缩放+pad，或 cover 的等比缩放+crop；在适配后再次 `setsar=1`。继续统一30fps、时间基与像素格式，确保拼接输入一致。

## 影响文件

`features/video_editing/render.py`；回归测试 `tests/test_video_editing_render.py`。
