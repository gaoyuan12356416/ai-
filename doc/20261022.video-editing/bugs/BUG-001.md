# BUG-001 SAR 导致 contain / cover 标准化与拼接异常

## 发现阶段

2026-10-22，真实 FFmpeg 制作验证阶段；由主实施者发现。前端人员已复核修复后的 filter graph，原始失败日志及主机实测证据由主实施补充。

## 现象

不同来源视频在 contain 黑边 / cover 铺满转换后可能仍带有非1:1像素宽高比（SAR），导致显示比例异常或拼接阶段尺寸 / SAR 不一致。

## 复现步骤

使用具有非1:1 SAR 的视频或缩放后保留来源 SAR 的素材；分别生成 contain / cover 的720×1280片段，再执行直接拼接或交叉淡化。对比标准化片段的宽高与 SAR、最终FFmpeg拼接结果。具体原始输入及报错由主实施补充。

## 期望结果

所有标准化片段为720×1280、SAR 1:1、30fps、yuv420p；contain完整显示并补黑，cover按显示比例裁切；后续cut / fade接入相同几何契约。

## 实际结果

发现阶段出现几何 / SAR 不统一，不能仅凭编码宽高相同判定可拼接。原始错误原文待主实施补充。

## 根因分析

原来源像素宽高比参与实际显示比例。仅按编码 iw / ih 计算 contain / cover，或在缩放后未重新声明SAR，可能把来源SAR传播到标准化片段，破坏统一拼接输入契约。

## 修复说明

标准化视频先执行 `scale=trunc(iw*sar/2)*2:ih,setsar=1`，将来源显示宽度折算为偶数像素；随后执行 contain 的等比缩放+pad，或 cover 的等比缩放+crop；在适配后再次 `setsar=1`。继续统一30fps、时间基与像素格式，确保拼接输入一致。
