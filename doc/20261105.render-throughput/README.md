# 香港 GPU 制作提速：CPU 码流处理与 Lanczos 权重复用

## 行为与范围

原流水线逐个压缩视频包在 CPU/GPU 间往返，并为每个输出像素重新计算 Lanczos 系数。在 6 路长视频制作下，计算核心接近满载，编码器尚有余量。

本次只改变独立 native 渲染子进程：

- Annex B 包整理改为 CPU 字节处理；MP4 表、交错和序列化使用 NumPy。复用现有时间轴、色彩标记、文件提交与异常处理。
- 对相同输入尺寸，GPU 一次计算缩放权重并复用。保留原二维累加顺序、边界、色度位置和色彩转换；兼容格式仍走原转换路径。
- 保持 NVENC 编码参数、分辨率、帧率、码率、音频处理和冻结模板配方。制作/发布并发及调度状态没有改动。

当前用户明确授权 CPU 码流/封装优化，取代过去对这些环节全部在 GPU 执行的实现选择。

## 验证

验证使用独立目录和已有源文件副本，没有创建发布任务。测试期间生产继续运行，因此短样本数字反映当时共享负载，不是固定产能保证。

| 项目 | 结果 |
|---|---|
| CPU 封装边界 | 16 项通过，含 B 帧、负 DTS、AAC priming、co64、取消与原文件保护 |
| native 视频契约 | 14 项通过 |
| 子进程控制 | 本地 7 项通过，Linux 服务器全部 8 项通过，包括取消时子进程组清理 |
| GPU 像素矩阵 | 18 组；720p/1080p/4K、横竖屏、非整齐比例、8/10 位，像素差异为 0 |
| 实际素材模板画面 | 前 900 帧中每 30 帧取样，30 帧逐像素相同 |
| GPU/CPU 容器 | 相同编码包产生的 MP4 全文件逐字节相同 |
| HEVC 30 秒，旧/新/新/旧 | 旧版 44.749 / 34.326 秒；新版 18.375 / 18.434 秒；平均耗时降低约 53.5%，速度约 2.15 倍 |
| H.264 15 秒，旧/新 | 22.337 → 9.455 秒；耗时降低约 57.7%，速度约 2.36 倍；解码视频与音频完全相同 |

HEVC 旧实现重复运行本身出现两种 sequence header（旧版两次输出也不一致），因此不能要求所有运行的文件哈希相同。按实际 sequence header 配对后，两次新版分别与对应旧版的完整 MP4 逐字节相同；音频在全部运行中一致。验证脚本逐项检查编码参数、帧数、时基，并要求每个新版样本有完全相同的旧版对应输出，没有降低画质验收标准。

HEVC 分段均值：视频阶段约 23.98 → 15.98 秒；码流整理约 12.71 → 0.16 秒；封装约 0.94 → 0.32 秒。
