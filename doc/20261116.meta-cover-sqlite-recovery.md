# Meta cover worker database recovery

The worker stopped on 2026-11-13 at 13:30 with `OperationalError` and exit 78.
The reporting snapshot held the DELETE-journal cover database open for about
36 seconds while execution transactions had a 30-second busy timeout. The
historical exception text was suppressed, so lock contention is inferred from
the transaction lifetimes and matching timestamps.

`CoverStore` now initializes the cover queue in WAL mode before opening its
schema transaction. Long report snapshots retain consistent results while
workers commit their operation intents and receipts. Existing rows, unknown
outcomes, transaction boundaries and FULL synchronization continue to apply.
SQLite failures expose fixed diagnostic categories without exception text.

Hourly discovery also timed out on the sparse composite-wrapper query over
`ads_source`. Its `(source_type,id)` index fetched full rows across a large
type-3 range. The query now uses the covering `(source_type,source_id)` index,
24 exhaustive adjacent ranges and `(source_id,id)` pagination. Complete CSV,
JSON, whitespace and duplicate-value handling remains covered. The production
read-only range probe completed in 33.75 seconds, with each range under 3.3
seconds. Database statement limits and FIFO routing keep their existing values.
