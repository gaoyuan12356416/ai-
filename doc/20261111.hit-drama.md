# Exact-drama publishing

The X tag template list adds **爆款剧发布**. The operator selects a content ID
or a business resource ID (`ads_drama_info.series_code`); resource IDs resolve
to all language versions in the target product. Content IDs preserve case and
accept letters and digits. Existing source, media, metric, launch-window, cooldown and queue
rules still apply. Saved templates and daily schedules are not changed.

Only configured, publishable, same-language channels with positive matching
audience AND theme income are admitted. Missing/outdated/unavailable portraits
never fall back to all channels. The exact drama and channel scope are frozen
in the run; claimed selectors enforce that scope again before reservation.
Existing frozen material reservations and unknown external receipts remain
unchanged. Submission keys survive a lost response and return the same run.

`scripts/test_x_hit_drama.py` exercises matching, no-profile rejection, claimed
selector scope, product-scoped resource resolution and response-loss replay.
The shared dialog was exercised in Chromium with mocked publication endpoints.

Deploy the pushed source with `python3 scripts/deploy_hit_drama.py prepare
--platform x --folder /mnt/data-disk/hit-drama-20261111/x-deployment`, then the
same command with `apply`. The installer copies the current runtime, checks
affected baselines, preserves other overlays, validates its candidate and backs
up the ledger. It restarts only the tag automatic owner and restores its triggers.
It does not start verification Posts. Static transformations preserve concurrent
list-layout changes. The regular runtime builder includes the new service and UI.

Rollback: run the same source script with `rollback --platform x --folder` and
the deployment folder. Unfinished exact-drama tasks prevent reverting to the old
selector. Keep current databases, reservations, tokens and external receipts.

## Multilingual resource fix

Stage the pushed fix with `python3 scripts/deploy_hit_drama_resource_fix.py prepare
--platform x --folder /mnt/data-disk/hit-drama-resource-fix-20261111/x-deployment`,
then use `apply` with the same arguments. `rollback` restores the previous runtime
without restoring the ledger. The manifest records exact hashes and backups.
The new resolver freezes language-to-content-ID mappings. Each channel keeps only
its language's profile-matching versions, enforced again by the claimed selector.
Legacy frozen single-drama runs remain readable. Validation must use read-only
resource resolution and isolated fixtures; deployment does not authorize Posts.

## Audience and Portuguese correction

`Overpowered Dominance` contributes to the revenge theme but no longer infers a
male audience. Directional signals such as Female Growth remain usable; conflicting
explicit audiences are still unknown. The classification version changes; the
audience/theme tree shape does not. Refresh the derived income portraits with the
same taxonomy so candidate classification and channel weights use the same rules.

The hit-drama target groups `pt` and `pt-br` together. Lookups normalize old frozen
keys as well, while preserving original account/task languages and excluding
`pt-pt`. The current X repository already queries both catalog aliases and normalizes
selection rows to `pt`; preserve that runtime overlay.

Use `scripts/deploy_hit_drama_audience_fix.py prepare --folder DEPLOYMENT`, then
`apply` from the pushed source. This overlays only the two X runtime files, patches
the main taxonomy/refresh without replacing its separate collector implementation,
backs up the portrait and restarts only X Auto. It invokes the existing derived
profile refresh service; verify completion and `audience_taxonomy_version` before
accepting the release. `rollback` restores code and starts a new profile refresh,
never restores publishing databases or receipts. Keep the versioned profile export
as the pre-change comparison point. No live test Posts are authorized by deployment.

Verify actual data without creating a run: `python3 -B scripts/inspect_x_hit_drama.py
--resource RESOURCE --template TEMPLATE --output PRIVATE_JSON`. It uses the active
resolver/classifier and current channel profiles, but does not reserve materials,
refresh tokens or publish. Material/cooldown/authorization checks still run later
when the operator submits an actual publication.
