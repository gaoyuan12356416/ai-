# Shared manual Facebook Page access

Users admitted by the Facebook video publishing module can select the same
authorized Page catalog regardless of the Page responsible user, authorizing
business user, Page pool owner, or configuration creator. This applies to Page
management and its shared configuration, manual/Excel previews and submissions,
and the final Page source check. The old automatic-template and group-pool
repositories retain their existing scope.

`SourceRepository._page_rows` no longer adds owner predicates. Real Page existence
and eligible authorization counts remain checked. The gateway still requires a
trusted session and module/navigation permission; publisher email mapping,
tenant-scoped configurations, task ownership, personal-token mode, active write
leases, duplicate and unknown-outcome protections remain in force. Page-pool
operations use the same shared Page configuration and retain their own enablement
identity checks and frozen task facts.

Configuration creator fields remain historical: editing preserves `created_by`
and updates `updated_by`; deleting archives the old pool, and recreating creates
a new configuration instance attributed to the recreating user. An existing
configuration cannot be created twice. New publication attribution follows the
actual submitting user, not the configuration creator. No data backfill or
historical replay is needed.

Validation: `python -B -m unittest tests.test_fb_shared_manual_pages -v` exercises
the SQL-backed catalog, unrelated-user selection, unavailable authorization,
shared configuration access, tenant isolation, creator preservation/recreation,
preview plus submission, and frozen publisher/personal-token identity. All writes
in these tests are to temporary local ledgers; no real Facebook posts are made.

Deploy from the pushed commit with:

```sh
python3 scripts/deploy_fb_shared_manual_pages.py prepare --folder /mnt/data-disk/fb-shared-manual-pages-20261120/release
python3 scripts/deploy_fb_shared_manual_pages.py apply --folder /mnt/data-disk/fb-shared-manual-pages-20261120/release
```

The installer patches only the reviewed `_page_rows` method into the current FB
runtime and main API source copy, preserving their different material policies.
It backs up the ledger and main source, copies the existing FB runtime, tests that
candidate, drains only affected FB owner work using the existing release
controller, and restores the original FB scheduling state. No main API restart
or database migration is required. Runtime fingerprints detect concurrent edits.

Rollback from that same fetched checkout:

```sh
python3 scripts/deploy_fb_shared_manual_pages.py rollback --folder /mnt/data-disk/fb-shared-manual-pages-20261120/release
```

Rollback checks queued/running tasks accepted under the shared policy against
the prior Page scope and waits only when a task actually needs broader access.
The rollback restores code only and never restores the ledger backup,
deletes receipts or links, changes Page owners, or alters creator history.
