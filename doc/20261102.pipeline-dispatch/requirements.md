# 双机制作、发布与动态节点调度

目标：可视化实时调度、充分利用 CPU 与香港 GPU、以后新增服务器无需修改调度代码。范围覆盖 X、Facebook、TikTok、YouTube 的现有模板、素材池、人工任务及已明确触发的分享。

规则：原渠道账本保留发布事实；协调器负责原子领取、租约、账号资源锁、节点及观测。两个独立进程池按渠道、批次、单条任务轮转。制作完成进入共享 COS，冻结 SHA、大小、媒体参数、配方与 profile，发布节点不得重新制作。

初始容量：CPU 制作 2/上限4、发布2/4；GPU 制作1/2、发布2/4。全部渠道共享主机池，全局发布8，X4/FB8/TT4/YT2。CPU 每任务软件编码4线程；GPU保留原兼容配置。每分钟评估资源，至少3完成样本且有待办才增加，每5分钟最多1；缩容只停止新领取。

心跳15秒，租约120秒。平台操作前持久化意图；未知结果只核对、不重新派发、不释放冲突账号。节点先持久化回执再幂等回传；迟到回执仍按原身份接收。长期平台凭据和刷新留在CPU。

逐渠道 X→FB→TT→YT 切换，冻结时间、精确暂停清单和单条在途豁免。历史到期未开工及成片未开始发布任务暂停，保留素材占用与去重；未来预约和新任务正常执行，历史暂停不自动恢复。保留审核、语言、剧集、转发和首评规则。

默认首页每15秒展示渠道、服务器、进程当前任务/阶段/等待原因、容量、吞吐和阶段P50/P95。管理员全局，普通用户仅现有渠道权限及本人范围。默认北京时间今天、最近1小时效率；旧记录缺少耗时显示未记录。保留旧深链。

完成门槛：四渠道接入、双机分别实际制作和发布、默认监控首页、第三节点可加入，并取得正常到期任务真实回执；不得把服务启动当业务验收，不创建额外测试帖。
