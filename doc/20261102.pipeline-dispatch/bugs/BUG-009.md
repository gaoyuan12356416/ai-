# BUG-009 空字典响应可被 outbox 误认为已确认

- 级别：P1；发现日期：2026-11-03。
- 状态：独立代码审查与最终回归通过；没有生产丢回执证据，节点 95fdaa4 已部署，原八条回执均已取得合法 ACK。
- 修复提交：`6bca72b`；worker 接线：`2f9e60c`。

## 根因与修复

原 `ReceiptOutbox.flush` 仅在 `accepted is False` 或 `ok is False` 时拒绝 ACK。HTTP200 若携带 `{}`、无关字典或仅 `ok=true`，会被当成成功并永久跳过该原回执。合法 checkpoint/complete/fail 和重复回执路径都明确返回 `accepted=true`，因此空字典不是可接受的协议兼容情况。

新实现要求 `accepted is True` 且 `ok` 不为 false，其他字典保持原 payload/id，记录有界错误码并按退避重交。数值 1 不等同布尔 true。不修改协调器幂等协议，不重新执行制作或平台写操作。

涉及 `features/pipeline_dispatch/receipt_outbox.py` 和 `scripts/test_pipeline_receipt_outbox.py`。
