# BUG-005 多进程重复投递共享 outbox 导致回执风暴

- 级别：P1；发现日期：2026-11-03。
- 状态：最终回归和独立审查通过；节点 95fdaa4 已部署，原八条回执全部 ACK，双方 pending=0。
- 模块提交：`6bca72b`；worker 接线提交：`2f9e60c`。

## 现象与根因

节点各进程每约 2 秒读取同一个 SQLite outbox 的未 ACK 记录，没有投递 owner、租约或失败退避。两节点原八条未确认回执会被多进程同时重复提交；原生调用可等待 90 秒而节点原请求 10 秒即放弃，服务端未完成的请求不断积累。`collect_x_bridge.json` 保存 1,012 线程样本；`cpu-pending-receipts.json` / `gpu-pending-receipts.json` 保存原待投递事实。

独立审查另发现异常字典可能被假 ACK，单独记录于 BUG-009，不将其算作本次生产线程堆积的已证实原因。

## 修复范围

独立 `receipt_outbox.py` 增量迁移现有表，逐回执事务领取投递租约，阻塞时续租；进程崩溃后才可按租约到期接手。过期 owner 不能 ACK 或释放新 owner。原 route/payload/id/claim 身份不变，失败以 15/30/60 秒退避并保存有界错误码，单次最多投递 100 条。

同任务代次前序未 ACK 时后序不提交，其他任务可继续。fresh checkpoint/complete/fail 后台避让 15 秒，由 inline only 优先；only 遇其他 owner、未确认前序或退避返回 False，不假 ACK。只有明确 `accepted=true` 且 `ok` 非 false 才记成功；失败回执仅重交协调器，不重新执行制作或平台发布。

涉及 `features/pipeline_dispatch/receipt_outbox.py`、`worker.py`、`scripts/test_pipeline_receipt_outbox.py` 及 worker 原有两个测试的退避时钟更新。
