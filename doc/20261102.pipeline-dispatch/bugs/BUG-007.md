# BUG-007 TT 选材后冻结指纹与 claim 阶段不能安全重领

- 级别：P1；发现日期：2026-11-03。
- 状态：生产只读证据与真实 SQLite 回归确认，本地已修；尚未上线。
- 修复提交：`dede4bf`。

## 现象与根因

`tt:auto` 4544/4546/4549/4553/4554/4569/4570/4571 共八条原生已 preparing，均有 gen1 `pipeline_tt_claim` 与匹配 token，但原 `claim_phase` 仍为 selection。选材将 material/content/gpu_job/source 四个字段从空填入，中央仍持有选材前 fingerprint。原领取响应因 BUG-002 超时丢失后，gen2 在 adapter 处收到 `canonical_identity_changed`；即使放过 fingerprint，原 rebind 仅允许 prepare 阶段也会拒绝已有 selection 记录。

证据：`business-full.json`、`tt-native-diagnosis.json`、`tt-selection-recovery-analysis.json`、`tt-frozen-proof-readonly.json`。02:13:50Z 的候选纯函数/只读校验对八条冻结证明均为 true，历史状态未改。

## 修复范围

不放宽一般 fingerprint 检查，只对 TT auto prepare 的本节点冻结选材给予精确证明例外：原 account/template/source 不能漂移，native token、claim generation/hash、frozen request、GPU job/content/source、profile 必须一致，且无 receipt、unknown、publish ID/attempt/operation。已有 preparing selection 可以按原冻结身份转为 prepare 并重绑新代，不重新选材或更换配方。

新冻结成功后持久化 `claim_phase=prepare`；跨代复用完整原描述器/required capabilities。缺失绑定或任一业务身份改变仍失败关闭。涉及 `adapters.py`、`tt_native.py` 和新增 `test_pipeline_tt_selection_recovery.py`。

```text
python -m unittest -v scripts.test_pipeline_tt_selection_recovery
```

渠道代理报告初次相关 65 项通过；随后含账号占用分类修复的 TT 相关 37 项通过。专项现有六项，包含 12 类身份/发布证据 mutation 子场景；验证原生材料 ledger 仍一份、无 GPU prepare/publish 调用、跨 CPU/GPU 不重新选材、旧代不得覆盖新代完成。

上线后仍需正常任务经历选材、原请求制作和最终回执。原八条中央 failed 与原生 preparing 不自动修改，不以当前修复为历史重试授权；已有冻结源和产物保留等待核对。
