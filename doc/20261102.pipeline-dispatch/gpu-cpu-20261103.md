## 实施与回滚

安装器允许导入准确的缓存环境变量，GPU 示例显式配置；节点 doctor 在实际服务用户下
校验所有已声明素材目录及四类可选素材的缓存回执、文件属性和可读性。
旧 light 素材只用于保留清单兼容，不进入四层配方，不要求其缓存。

上线使用 `scripts/enable_pipeline_gpu_asset_cache.py` 默认只读预检，`--apply`
备份安装清单后同时保存未来配置及独立 systemd drop-in。只允许已审阅的 `95fdaa4`
节点和 `KillMode=mixed / TimeoutStopSec=infinity`。`restart --no-block` 触发当前单条
任务自然结束，子进程心跳与原回执提交继续；旧节点全部退出后才启动使用缓存的新节点。
不对在途 FFmpeg 发退出信号。线上执行代码仍为 `95fdaa4`，使用其已有缓存实现。

回滚：先确认本次 drop-in 内容与审计一致，删除本次 `30-rgba-asset-cache.conf`，
恢复备份的安装清单，`systemctl daemon-reload`，然后仅对
`pipeline-node-hk-gpu.service` 执行 `systemctl restart --no-block`，同样等待自然排空。
不恢复旧数据库，不重试或重复发布。
