# X 频道标签收入画像

频道列表新增历史标签收入列，展示累计收入及前三个标签占比；点击展开全部标签，再点击标签查看对应剧目、总收入、分摊收入、完整标签及成功发布数。此版本仅提供画像，不调整自动发布、素材池、任务或归因链接。

## 口径

- 复用已核验的 social-analytics-warehouse SQLite 快照，精确匹配 X / 2116 / campaign ID，保持既有确认成功发布与归属冲突规则。按稳定 X user ID 映射频道，改名、重新授权不拆分历史。
- 累计范围从快照最早日期到最近完整 UTC 日；不包含尚未完整的当天。USD 收入字段与现有社媒效果报表一致，不另减退款。
- 剧目标签读取 63350 只读副本的 `ads_drama_resource`，以 app_id=1479、精确 content_id、规范化语言匹配。沿用 jp/ja、pt/pt-br 别名；不同语言保持独立。原始同义词或翻译不做猜测合并。
- 同剧多行标签合并，Unicode 兼容归一化、去空格、忽略大小写去重后平均分摊。用 Fraction 累加，最终按最大余数法平衡分币尾差；标签金额合计等于频道收入，标签内剧目分摊合计等于标签收入。正收入且各标签无负金额时占比总计 100.00%。
- 使用当前完整标签回算历史，明确展示标签资料更新时间；不是历史发布时标签快照。缺标签/缺剧目/歧义保留“未识别标签”，不抹除收入。零收入、无发布历史、画像不可用、归因冲突分别显示。
- 剧目数与成功发布数按真实 ID 去重；同一剧跨多个标签的数量不可加总。归因冲突只影响相关频道；全局金额对账保留未归属项。

## 实现及权限

新增独立只读 HTTP 服务 127.0.0.1:8896，Nginx 仅代理 `/api/x-channel-tag-revenue` 与数字频道详情路径。每次请求携带原 Cookie 到固定回环 `/api/admin/x-accounts`，由现有接口完成登录、模块权限与平台账号范围核验；不会接受 API token 或客户端传入的用户身份，不缓存授权结果，不跟随重定向，不记录 Cookie。详情 ID 不在授权列表时返回 404。

HTTP 仅读取 `/mnt/data-disk/x-channel-tag-revenue/current.json` 指向的不可变快照。收入快照与标签查询在独立小时任务中完成：北京时间每小时第 20 分运行；源 SQL 使用现有 FIFO Gate、63350 只读校验、100 个剧目一批、超时及结果上限。无 MySQL 写入或 DDL。刷新失败保留上一版本并显示错误/延迟；保留当前和上一快照。

新增模块在 `features/x_tag_revenue/`，静态资产 `static/x-tag-revenue.js/.css`。`integration.py` 对正在运行的频道列表 HTML 进行四处可逆插入并调整表格 colspan，保留其他线程的页面功能。部署不替换 app.py，不重启主 API 或发布进程，只启动新增画像服务和刷新 timer，校验后 reload Nginx。

## 部署与回滚

先提交并推送 GitHub，再由 CPU 从远程检出精确提交。执行：

```bash
python3 scripts/deploy_x_tag_revenue.py install
```

安装器先验证数据盘、GitHub 来源、频道列表当前哈希，备份所涉文件；先预热画像成功，再发布静态列与接口。备份记录包含精确版本、全部文件前后哈希、源快照核验、原主 API/X/YouTube/制作 worker 的 PID 前后对比。

回滚使用该 release 的脚本与安装输出的备份目录：

```bash
python3 /mnt/data-disk/x-channel-tag-revenue/releases/COMMIT/scripts/deploy_x_tag_revenue.py rollback --backup /mnt/data-disk/x-channel-tag-revenue/backups/TIMESTAMP
```

只停止新增画像服务及 timer、恢复所涉文件并 reload Nginx。页面若有后续并行修改，使用精确逆向插入保留其他修改。当前发布账本、回执、账号、凭据和画像数据均保留。
