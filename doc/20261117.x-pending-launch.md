# X 画像模板支持待上架剧

未来上线窗口已有排期能力，但候选 SQL 仅接受 `drama_status=3`，导致状态 2 的待上架剧在画像匹配前消失。本次允许 2（待上架）和 3（已上架），保留投放开启、产品、语言、可投放时间、素材、画像、冷却与防重条件。未上架、已下架、待下架不在候选状态中。

`-1~0` 仍是现在至未来 24 小时；选中的未来剧按实际可投放时间冻结排期，提前量为 0。旧整数窗口仍排除未来可投放的剧。保留当前线上显式未来目标的上下文；不改变已冻结任务或恢复历史发布。

仅部署 X Tag 的 `features/x_auto_posts/repositories.py`，正常排空并重启 `x-tag-auto.service`。原生发布、GPU、主 API 和协调器继续运行。

验证：`python -B scripts/test_x_pending_launch.py` 对真实 SQL 条件执行混合状态和时间边界数据；完整线上副本运行 `python -B scripts/test_drama_launch_range.py --platform x`，验证任务冻结时间及到期发布门禁。

GitHub 推送后在 CPU 独立源码目录运行：

```sh
python3 -B scripts/deploy_x_pending_launch.py prepare --folder /mnt/data-disk/x-pending-launch-20261117/deploy
python3 -B scripts/deploy_x_pending_launch.py apply --folder /mnt/data-disk/x-pending-launch-20261117/deploy
python3 -B scripts/deploy_x_pending_launch.py verify --folder /mnt/data-disk/x-pending-launch-20261117/deploy
```

回滚：同一精确源码目录执行 `rollback`，随后 `verify`，参数不变。只恢复本文件，不恢复旧数据库或凭据；已有未来排期仍保留已有时间门禁。

另一个已观测问题是 Auto runner 每轮最多领取 20 项，优先处理旧任务回执；超过一轮额度的旧任务按 30 秒间隔重新到期，可长期占满每分钟轮次。这会延迟新任务筛选。原生发布由独立 worker 处理，不能根据 Auto runner 结果推断其成功或停摆。本次未调整该调度策略。
