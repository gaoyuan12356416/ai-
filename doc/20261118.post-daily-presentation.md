# 发布日报精简样式

正式日报采用用户确认的三项汇总、三行平台进度、主要原因和折叠明细。平台继续使用 TT、FB、X；来源及原因使用中文，去除原始错误码。只隐藏全零来源，部分数据缺失仍显示未知。成功、未完成和按规则跳过分别保留原口径；历史积压、费用估算及排除项收进说明区。

展示在 `features/post_daily_report/presentation.py`，采集、统计校验、发送入口和投递账本保持原样。原更正入口的布局说明不再假定第一个组件是文本。

## 验证

- 28 项展示、日报入口与发送防重、更正投递检查通过。
- 本地扩展回归 131 项中 128 项通过；3 项发布器审计/迁移测试在未修改的基线 `a68c66fb` 上复现相同错误，属于该报告分支与发布器版本的既有差异。
- 安装器在保留线上复合版本的候选目录运行上述 28 项检查，并重新渲染所有历史归档，检查输入未改变及消息不超过 29,000 字节。

## 部署与回滚

先推送 GitHub，由 CPU 上 `/mnt/data-disk/post-daily-report/repo.git` 拉取确切提交并导出源码。运行 `scripts/install_post_report_presentation.py --commit COMMIT --source SOURCE` 预备候选，再添加 `--apply` 切换日报符号链接。

安装器持有日报锁，核对现有三个入口文件哈希，只覆盖展示及相应更正入口；保留现有采集代码、配置、归档、投递账本和每天北京时间 10:00 的定时器。预备阶段备份投递账本并生成 `manifest.json`、`rollback.sh`。无需重启发布器或定时器，也不补发历史群日报。

回滚：`bash /mnt/data-disk/post-daily-polish-20261118/COMMIT前12位/rollback.sh`。仅恢复旧代码目录，保留全部发布与投递记录。
