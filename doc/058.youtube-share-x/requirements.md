# YouTube 视频转发到 X

2026-09-16。用户要求在 YouTube 自动发布列表增加【转发到X平台】，弹窗选择 X 账号、自定义描述并支持宏。

- 已公开的视频可操作，未公开任务显示禁用原因。兼容精简列表，不逐行查询详情。
- 弹窗支持选择 1–20 个有权限、授权有效且允许发布的 X 账号。普通用户仅本人，管理员可用全部账号；无 Premium 门槛。
- 默认描述 `{title}\n\n{youtube_url}`。支持 `{title}` 视频标题、`{youtube_url}` 视频链接、`{short_url}` 推广短链、`{channel_name}` 频道名、`{channel_url}` 频道链接、`{name}` 剧名、`{desc}` 剧情简介。
- 2026-09-17 新增 `{short_url}`：复用当前 YouTube 任务已保存的剧集推广短链，保持原有归因。不新建、重写或缩短 YouTube 视频链接；任务缺少短链时，仅使用该宏的文案无法提交。
- 宏单次展开。未知/缺值/格式错误阻止提交。漏填视频链接自动补充；有推广等其他链接时补在文案前面。手动填写的视频链接必须位于其他链接之前，否则提示修改。预览完整文案；280 权重上限，不静默截断。
- 最终点击提交才转发；多账号用相同文案和原视频直链。由 YouTube/X 决定卡片与内嵌播放表现，不能保证所有视频都是播放器卡片。
- 提交前只读确认 YouTube 同一频道同一视频已处理、公开且允许嵌入，保持原视频/封面/预约/首评不变。
- 2026-09-17 播放器校验修正：弹窗检查 YouTube 公共页面的 `twitter:card=player`、同视频的 `twitter:player` 及 `og:url`。仅图片卡片、身份不一致或查询失败均阻止提交，页面可重新检查。入队前重新检查，不相信前端传值或旧预览。已有提交仍按原 UUID 核对，不重新发帖。播放器源元数据合格不代表 X 客户端已实际展示/成功播放。
- 逐账号展示状态和成功帖子链接。原操作重放、同视频同账号的成功/处理中/未知记录不能重发。明确失败可发起新操作，保留历史。
- 发送前持久化尝试。网络超时、5xx、无效成功响应保留未知，禁止自动重发。关闭重开可核对原结果。

架构：真实 Cookie+YouTube/X 双模块权限+同源 JSON；主服务负责源任务和 YouTube 检查，X sidecar 使用账号锁和刷新后的凭据。独立台账在数据盘，不使用素材队列。本次验证不新增真实 X 帖子。

## 2026-09-17 列表播放器卡片标记

- 用户要求直接在 YouTube 自动发布列表识别可发播放器卡片的视频。在已确认公开视频的状态下方增加标记及北京时间检测时间，不改动原发布状态。
- 绿色「可发播放器卡片」要求当前页面 Player Card、同视频播放器/规范地址、YouTube API 同频道/同视频、public、processed、允许嵌入，且未返回地区/年龄限制。受限视频单独显示「卡片播放受限」；图片卡片、未公开、不可嵌入、待检测、检查中和暂未确认不能显示绿色。
- 标记是有时效的检查结果，不承诺 X 实际播放；现有转发前 fresh-check、账号权限及重复围栏保持权威。
- 每个 API 进程使用有界内存缓存和 2 个后台检测线程。任务接口只读取快照并排队，不在请求线程进行平台/SQL请求；15 分钟复查，失败 2 分钟后重查。过期标记不能继续作为绿色结果。
- 缓存不落盘、不写发布账本；已发布历史任务和新公开任务在列表/详情读取时按权限自动检测。保持精简 DTO、revision/since 和弹窗编辑行为。
- 本次仅重启主 API，YouTube 发布 worker、X sidecar、发布任务和历史记录保持运行。本次验收不新增社交平台帖子。
