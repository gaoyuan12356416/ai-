# SA 测试用例评审

## 结论

D7/D10 测试设计覆盖数据口径、防放大、缓存原子性、API 白名单、浏览器性能、缓存语义与部署安全后有条件通过。D10 生产用例仍被日期边界阻塞，未执行结果不得沿用历史 D30 的“通过”状态。

## 覆盖性问题

| 编号 | 场景/用例 | 问题 | 补充要求 | 状态 |
| --- | --- | --- | --- | --- |
| TR-001 | revenue Join | 只测总额不能发现 OS 多行放大 | 构造同一 Ad 的 Android/iOS 两行并断言只合并一次 | 已纳入 |
| TR-002 | fallback | 只测 Ad 无法覆盖 Google/UAC | 覆盖 Ad Set、Campaign 和 ambiguous 分支 | 已纳入 |
| TR-003 | 比率 | 行级 ROAS 平均可能偶然通过 | 使用不同 spend 的两组数据断言汇总后相除 | 已纳入 |
| TR-004 | 缓存失败 | 删除后异常可能丢失上一版 | 故障注入并断言旧日期和 data_version 保持 | 已纳入 |
| TR-005 | 性能 | 静态测试不能证明浏览器不下载明细 | 真实浏览器检查网络请求、首屏和切换筛选 | 已纳入 |
| TR-006 | 安全 | API 动态列可能被注入 | 非白名单维度/排序/日期必须 400 | 已纳入 |
| TR-007 | 定时器 | 手动刷新不等于自然调度成功 | D10 上线后观察一轮自然 timer 和版本推进 | D10 待执行；D30 历史基线曾通过 |
| TR-008 | 汇总性能 | 最细事实每日超过 7 万行，单纯 LRU 无法保证新版本首个请求 | 校验 D10 汇总路由与事实守恒，新版本发布后预热真实全范围常用路径，并记录未预热组合 | D10 待执行；D30 历史基线常用路径 `<3 ms` |
| TR-009 | 排除量语义 | 候选内未匹配为 0 不代表全源没有被排除行 | 单列日期级全源排除量；有业务筛选时验证“不可归属筛选”标记 | 已纳入 |
| TR-010 | 日期边界 | 当前 D10 最早日期为 8/1，原 7/29～7/31 无数据 | 分别定义“源侧补齐后保留 7/29”和“用户批准后改 8/1”两条验收分支；决策前保持阻塞 | 待业务决策 |
| TR-011 | 缓存语义 | 历史 D30 SQLite 可能被误用于 D10 | 结构或 `comparison_window` / `new_attribution_source` 不匹配时，Web 与刷新均拒绝打开 | 已纳入，待候选库执行 |
