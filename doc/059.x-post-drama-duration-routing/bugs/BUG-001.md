# BUG-001 短剧池用 141 秒占位提前冻结 relay

## 发现阶段

需求与生产只读诊断。

## 现象

目标账号无会员时，实际小于 140 秒的短剧也只出现在目标账号 Repost 页面；无同语言会员号时候选被跳过。

## 复现步骤

1. 让无会员目标账号轮到一部真实成片不超过 140 秒的剧集。
2. 执行短剧 fixed/random 排期。
3. 检查冻结 queue：未下载媒体却已写 `preflight_duration=141` 并选择 relay。

## 期望结果

最终成片 `<=140` 由目标账号 direct；只有最终成片 `>140` 且目标无资格才 relay。

## 实际结果

目标账号能力在真实时长未知时替代了媒体时长判断，短片被错误归入 relay。

## 根因分析

短剧排期阶段不 probe，却用 141 秒哨兵冻结 route；发布阶段只验证已冻结路线，不会把短片改回 direct。

## 修复说明

新短剧统一冻结为逻辑 `duration_pending`；发布日志前一次下载/必要修复，按最终文件时长原子解析 direct/relay/waiting。历史 141 不迁移。

## 影响文件

`service.py`、`oauth_service.py`、`publish_media_repair.py`、`x_post_schedule_runner.py`、两个管理页面与对应测试。

## 验证命令与结果

本地 store 128/128、合并生产并行变更后全量 X 891 项无失败（889 通过、2 项环境跳过）；全仓 5 个 TT 错误已在干净基线复现，非本次新增。测试使用临时 SQLite、mock HTTP/X，未创建真实 Post/Repost。生产 quick/FK、feature-off schema 与自然发布对账在部署阶段补录。

## 回归结论

已覆盖 139.999/140/140.000001/141、短长短同剧绑定、无 relay waiting、目标升级、最终媒体漂移、解析后崩溃、公平轮询、下一 slot 隔离和历史 141 严格例外。生产自然 direct/relay 结果仍待上线后验收。
