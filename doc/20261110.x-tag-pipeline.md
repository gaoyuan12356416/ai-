# X 标签画像发布接入统一制作发布调度

画像自动发布和画像素材池原先使用独立同步执行器，制作、上传等待会占住自动发布唯一 worker。现在两条入口保留原有选材、独立账本、模板快照与归因，通过已有 X 原生执行协议交给统一 CPU/GPU 节点制作和发布。

## 实现

- 画像已使用 `>=9000000000000` 的独立编号区间。来源仍为 `x:auto:ID` / `x:queue:ID`，兼容节点、恢复账本和只读状态 broker；协调器按编号选择画像适配器，原有编号保持原路由。
- 两个画像数据源分别轮转采集、单独记录健康状态和游标。画像 queue 只关联画像 auto 库；auto 父任务只作选材/冻结与回执对账，不重复执行子队列的发布。
- 画像原生桥开放独立认证的调度路由，保留账号原 OAuth owner；归因解析指向画像 gateway，短链、素材防重、配额和业务事实仍存画像账本。
- 复用现有 X 节点能力及账号资源保护，不重启执行节点。随机模板请求沿用原有 X 生产素材清单版本。监测页显示画像来源并跳转画像记录页。

## 验证

在部署运行时快照上执行 `scripts.test_x_tag_dispatch.DispatchTests`（6 项）及 `NativeTests`（2 项），覆盖独立账本路由、父子关联、防重复发布、未知结果保留、真实账本回执读回、认证和归因身份一致性。服务器 staging 重跑相同测试，实际模板和业务数据库不作测试写入。

## 部署

先将提交推送 GitHub，服务器 fetch 精确提交到独立源码目录，然后：

```bash
python3 scripts/deploy_x_tag_pipeline.py stage
python3 scripts/deploy_x_tag_pipeline.py activate --backup /mnt/data-disk/x-tag-pipeline/deployments/DEPLOYMENT
```

stage 校验涉及模块的现网基线，生成候选运行时，备份配置、代码指针和 SQLite 一致性快照。activate 暂停画像触发器，画像 Auto HTTP 服务优雅关闭并等待已接受的请求完成；不终止上传、不清租约。切换画像发布端后，以已有短时 HTTP 控制请求排空方式切换协调器，执行节点的在途工作和租约保留。最后恢复原先活动的触发器并验收协调器依赖调度。

## 回滚

```bash
python3 scripts/deploy_x_tag_pipeline.py rollback --backup /mnt/data-disk/x-tag-pipeline/deployments/DEPLOYMENT
```

回滚先检查受影响的画像执行状态：已有执行权、结果未知的任务必须继续用现有桥接核对/完成，不清锁重发。允许回滚时，只将从未领取的统一调度画像 offer 暂停，恢复原代码、环境和原有活动触发器；所有当前业务数据库、归因、帖子和平台回执均保留，不用部署前数据库覆盖现状。若之后已有其他代码/配置修改，脚本拒绝覆盖，应按记录做针对性合并回滚。
