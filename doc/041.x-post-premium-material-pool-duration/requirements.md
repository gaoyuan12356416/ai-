# 041.x-post-premium-material-pool-duration 需求与技术设计

## 背景

X 素材池自动发布此前在候选 SQL 和 GPU 修复策略中固定限制为 600 秒；手动发布已允许 Token 确认有会员资格的账号使用 4 小时原片门禁，两个入口规则不一致。

## 目标

- X 素材池的固定、随机和日调度均取消会员账号的 600 秒业务上限。
- 标准账号仍严格限制 140 秒。
- 仅当前账号 Token 返回 `basic|premium|premium_plus` 时允许超过 140 秒。
- 仍保留 X API 的 4 小时、512 MiB、编解码器、分辨率和帧率门禁。
- 独立的 X 自动发布模板继续保持其既有 600 秒配置上限，不随本需求放宽。

## 技术设计

1. 正式素材池候选 SQL 的时长上界从 600 秒提高到 API 边界 14400 秒。
2. 账号感知预检保持不变：非会员上限 140 秒，会员上限 14400 秒；最终发布前再次刷新会员资格。
3. Premium GPU 修复策略从 600/599 秒改为 14400/14399 秒，并升级 profile 至 `x-h264-nvenc-720-duration-policy-v4`，防止复用旧修复产物或 CPU/GPU 策略错配。
4. 自动模板选择显式传入独立 600 秒上限，隔离两个产品边界。
5. 更新素材池页面说明，不再展示“自动素材池 600 秒上限不变”。

## 验收标准

- 763.938 秒素材能被正式素材池候选加载。
- Token 确认有会员资格的账号保留 763.938 秒原片，不触发时长修复。
- 非会员账号面对任何超过 140 秒的素材仍在 X 写入前失败。
- Premium 修复策略不会把 600–14400 秒素材裁成 599 秒。
- 自动模板仍拒绝超过 600 秒的素材。
- 既有 X 回归测试无失败，测试期间不产生真实 X 写入。

## 不包含

- 不改变 X 自动发布模板的 600 秒配置范围。
- 不部署生产、不手动创建真实 Post。
- 不取消 X API 自身的 4 小时或 512 MiB约束。
