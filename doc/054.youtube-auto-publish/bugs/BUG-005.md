# BUG-005 工作台首屏等待导航和频道查询

## 现象与证据

2026-09-10用户反馈：已显示登录用户和导航，但正文长期停留在“正在加载发布工作台”。

旧初始化串行等待auth、QuickNav.render（包括navigation.json网络请求）、bootstrap内频道查询，然后才显示正文并获取任务。导航会先使用本地默认值/缓存渲染，再等待远程配置，所以可见导航不代表该请求已结束。前端fetch和正文读取没有截止时间。

CPU实际服务适配器只读测量：bootstrap 2626 ms（25个频道），任务列表1 ms，素材2059 ms（3条）。这些是函数测量，不是用户截图当次请求耗时；历史access日志没有duration，不能推断其完整等待时长。

## 修复

- 新增轻量bootstrap参数与独立channels接口，保留原bootstrap默认行为及所有权限校验。
- 首屏不查询频道/素材，不等待导航网络；任务列表单独显示加载态。
- 新建弹窗立即打开，频道按需加载、缓存60秒，支持失败重试。创建时服务器仍重新校验资格。
- 所有前端API请求和正文读取都有超时；POST结果未知时保留草稿与operation_id，禁止自动重发。
- 初始化旧响应隔离，轮询不重叠，审核成功不再等待列表刷新才解除忙碌状态。
- HTML脚本样式版本更新，源目录和Nginx静态目录同时部署。

## 验证与边界

后端service 43项、HTTP 17项通过，包括轻量初始化不调用频道/素材SQL、独立频道权限和安全字段投影、创建时重新查询频道。浏览器慢请求和全流程验证及生产回读见本次发布记录。

素材SQL五个WHERE条件（包括created_at>=2026-09-10）保持不变。本次没有真实生图、飞书发送、上传或评论测试。
