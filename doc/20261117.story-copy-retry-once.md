# 文案失败随下一队列重试一次

FB、X 素材池、X 短剧池、X 标签自动模板共用此规则：一次生成中已验收的文案保留；未成功项进入 `retry_wait`，首次不发送失败通知。`retries` 表保存任务键、首次批次/原因、等待时间、重试批次及最终结果，重启后继续使用。

下一批就绪的新文案优先携带待重试项，总批量仍至多 100 条。没有新文案时，首次失败 60 秒后也能独立进入重试队列。一个队列批次可含不同剧目，但模型请求继续按产品、剧目、语言分组，必要时按原有 token 预算拆分。同一任务仅额外重试一次；无返回、模型异常、输出校验失败及执行中断均遵守此次数限制。第二次仍失败才记录最终失败并汇总告警，明确注明“重试一次仍失败”。

发布到点仍可使用原文案；源发布器冻结最终用稿后，回执同步终结待重试记录，晚到结果不替换定稿，不重放发布。首次失败的兜底回执不另发重复告警。成功重试清除当前任务错误，首次失败原因保留在 `retries`。本变更不恢复旧版已失败任务，不使用历史文案，也不改变发布幂等或现有开关。

验证：`python -m unittest tests.test_story_copy`，包括 100 条部分成功、随新队列重试与剧目隔离、60 秒独立重试、重启恢复、输出校验重试、二次失败唯一告警、原生用稿冻结及旧库升级。

从服务器 GitHub 拉取的精确提交运行：

```sh
python3 ops/story_copy/deploy_retry_once.py prepare /mnt/data-disk/story-copy-deploy/retry-once-COMMIT
python3 ops/story_copy/deploy_retry_once.py apply /mnt/data-disk/story-copy-deploy/retry-once-COMMIT
```

仅切换 `/opt/story-copy/current` 的四个模块并重启独立文案 worker。沿用既有批次排空：持有文案账本写锁核对无在途批次后再停 worker，避免检查与切换间产生新批次。保留旧代码、SQLite 在线备份和前后服务 PID；不重启任何发布器、调度器或设置服务。新增 `retries` 表是幂等附加迁移。

回滚：同一 checkout、同一部署目录，把 `apply` 换成 `rollback`。只回滚代码，不恢复数据库、队列或回执。旧版仍能正常使用已验收文案及发布兜底；尚未完成的 `retry_wait` 记录保留，恢复此版本后继续处理。
