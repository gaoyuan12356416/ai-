# BUG-001 超长剧集被判不可修复且无法重新进入短剧候选

## 发现阶段

2026-07-29 生产 10:06 短剧批次诊断及管理员短剧池复核。

## 现象

源剧集超过 X API 140 秒上限时，CPU 或 GPU 返回
`invalid_media_duration` / `source_not_repairable`。未绑定短剧被写为
`validation_failed` 后没有成功重验清错入口，部署新修复逻辑也不会自然重检。

## 期望结果

保留视频开头，固定裁掉 139 秒之后的尾部；GPU/COS/CPU 全链重验通过后，
未绑定且无历史的精确短剧池记录原地恢复 `pending`，由后续自然调度发布。

## 实际结果

v1 worker 只允许 codec/dimensions，且二次 probe 明确拒绝 `>140s`；
输出校验又要求保持源时长。短剧池查询排除 `validation_failed`，因此池 53/54
无法再次进入调度。

## 根因分析

旧合同把所有 duration 错误视为不可修复，没有区分“过短/损坏”和可确定裁尾
的“超长”；短剧池 check 也只有失败写入，没有受保护的成功重验状态迁移。

## 修复说明

- profile 升级为 `x-h264-nvenc-720-trim139-v2`。
- CPU/GPU 接受 duration 触发；GPU 精确区分，只裁 `>140s`，固定目标 139 秒。
- codec/dimensions 首错下发现的额外超长也在同次转码中裁尾。
- 过短、NaN/Inf、损坏、异常帧率/扫描继续失败关闭。
- 新增短剧精确恢复工具和 dry guard；仅 GPU 修复、COS HEAD、CPU 重下载、
  SHA/大小/probe 全部成功后，才原地清错恢复 `pending`。
- 工具共享调度锁，不包含建计划或发布调用；10:06 原失败批次不恢复。
