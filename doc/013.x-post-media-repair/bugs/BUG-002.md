# BUG-002 sidecar 重启激活了无效短链域名并停止冻结短剧批次

## 发现阶段

2026-07-29 16:20 自然短剧批次 run 17 完成全部媒体预检并开始发布时。

## 现象

首队列 45 在任何 X 请求前返回
`invalid_short_base_url`。run 17 停止，后续五条冻结队列保持 queued。

## 已核验事实

- log 45 `attempt_count=0`、`unknown_outcome=0`。
- `long_url`、`short_url`、`post_text`、X media/Post ID 和 Post URL 均为空。
- 其余队列 46-50 没有 publish log。
- 账号 10 的池 2 Episode 8 被标记 needs_review，但粘性账号和剧集进度未变。
- `/etc/x-post-automation.env` 在 14:44 CST 已是
  `https://gy.g2flow.com/s2l`；15:46 sidecar 重启后首次加载该磁盘值。
- 发布代码和既有短链页面合同只允许
  `https://ai.yingliangads.com/s2l`。

## 根因

磁盘配置与已运行 sidecar 的内存配置发生漂移。此前进程继续使用允许的旧值，
因此没有立刻暴露；本次必要重启加载了无效值。错误发生在发布阶段的短链构建处，
任何 X API 请求均未开始，属于可证明的本地零尝试失败。

## 修复

1. 备份 SQLite 和 `/etc/x-post-automation.env` 后，将短链基础地址精确恢复为
   `https://ai.yingliangads.com/s2l` 并重启 sidecar。
2. 新增唯一的受保护恢复方法和 CLI，只允许
   `invalid_short_base_url`，并要求：
   - 冻结短剧 run 第一队列失败，其余队列 queued 且无 log；
   - failed log attempt=0、unknown=0，所有 X/短链/文案字段为空；
   - frozen account 顺序、候选 rank、slot 身份精确匹配；
   - run、queue、log、pool、已发布粘性来源、账号、Episode 和旧错误精确匹配；
   - 共享 schedule lock 已获取。
3. 先 validate-only，再在一个 SQLite 事务中把同一 log 恢复 reserved、同一
   queue/run 恢复 queued、同一绑定池恢复 active；不建新计划、不直接发布。
4. 真实恢复强制写一份新的 `.json` 报告；路径只能位于 root 专用的
   `/mnt/data-disk/x-post-automation/recoveries/`，并拒绝符号链接祖先或覆盖
   既有文件，避免审计参数误指向 SQLite、配置或 release。
5. 恢复 timer 后，由正常 frozen-plan 恢复路径继续顺序发布。

## 回归

新增 started/unknown/disallowed-code/重复恢复拒绝、dry guard、同批兄弟队列、
报告路径隔离和失败输出脱敏测试。完整 `test_x*.py` 为 351 项。
