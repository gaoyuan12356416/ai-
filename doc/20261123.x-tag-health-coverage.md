# X tag maintenance coverage

The X template editor returned 503 after maintenance stopped `x-tag-auto.service`
and the previous X lane snapshot omitted all independent X tag services. The
maintenance stage had completed, but its old snapshot could not restore a unit
it had never captured. The service was separately restored after verifying the
historical task protection and confirming the scoped maintenance stage ended.

Include the three X tag daemons and their existing timers in X health checks and
future maintenance snapshots. The hourly metric timer gets a two-hour age window;
minute/short-interval timers use the same existing tolerance as comparable jobs.
The runner path is discovered by the existing systemd dependency snapshot logic.
This does not change restoration semantics: only previously active daemons,
timers and paths may be restored, and oneshots are never explicitly replayed.
Older snapshots do not implicitly activate newly listed services.

Deploy only the pushed GitHub release's health-tool pointer with
`scripts/deploy_x_tag_health_coverage.py apply --state STATE_DIRECTORY`.
The old pointer and hashes are retained in its manifest. No service restart,
daemon reload, scheduler start, queue change, or database restoration occurs.
Rollback uses the same script with `rollback --state STATE_DIRECTORY`.

Validation: scheduler health unit tests cover a stopped X tag editor, preservation
of intentional pauses, no oneshot replay, and old-snapshot compatibility. After
deployment, take a read-only X snapshot and inspect X tag checks. Existing
intentionally disabled legacy X scheduling is not enabled to make a check green.
