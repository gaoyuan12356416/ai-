## V2 增量测试设计（2026-08-27）

以上 TC-001—TC-032 的“通过”及统计仅属 V1 历史证据。以下 V2 用例是测试设计，全部尚未执行；待代码完整后由独立 QA 记录命令、数据版本、实际结果和缺陷，不借用 V1 测试结果。

### V2 测试数据与证据要求

- F-GG：合成 `type=3` video2/image4 资产事实、`type=0` 平台事实、完整/缺失/重复/歧义 mapping、`ads_source(source_type=3)` 及 OPay/非 OPay 素材；包含同名异账户、同资产异日。
- F-FX：仅用于单测的虚构币种 LCY。两日各 `cost=1_000_000_000`，即每天1000原币；USD/LCY分别为1、2（仓库存LCY/USD则为1、0.5），正确月USD为3000。另设历史报表 `spend=100,spend_usd=5,exchange_rate=10,last_exchange_rate=20`，应核验旧候选20；历史spend_usd改为10后才可核验候选10。另含缺失/0/负值/非有限/冲突记录；这些数值不是实际生产汇率。
- F-METRICS：完整素材 `spend=6000`、`impressions=1_000_000`、`clicks=20_000`、`installs=1000`、`af_d0_first_transactions=100`，期望 `d0_cpa=60,cpm=6,apm=0.1,ctr=0.02,cvr=0.05,install_to_d0_rate=0.1`。再构造每个原始量的null、真实0、正数及加权聚合组合；预期独立手算，不能由被测代码反算。
- F-CACHE：带冻结 2026-01—07 状态的 V1 临时 SQLite；包含 V1 Meta/TT 原表、已提交 WAL 数据、重复 clone、同路径/别名、预先存在目标及故障注入场景。先记录源库结构和稳定快照哈希。
- 生产抽样只读，使用已核验的 `-P63350` 与 `@@read_only=1`，不访问写端口、不执行 MySQL DDL/DML。历史 FX 需记录原始来源/生效日期/方向和所验证 SQL 的脱敏证据。
- 每条执行证据至少记录候选 commit、缓存/快照/FX 版本、用例参数、预期/实际、产物哈希与执行人；UI/CSV 另记录视口、筛选排序条件和导出文件。当前文档不填造测试结果。
