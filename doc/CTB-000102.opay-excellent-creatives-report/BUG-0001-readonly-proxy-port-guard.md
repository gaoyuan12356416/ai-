# BUG-0001 只读代理端口护栏误判

## 状态

已修复，生产影子回归通过。

## 严重级别

P0。阻止报表生成，但因默认失败关闭，没有读取业务数据或替换公开版本。

## 发现环境

- 时间：2026-08-26
- 候选提交：`9c36d839442e72ceae29dbc19899f3c6cebb4035`
- 环境：43.166.187.96，生产只读影子命令

## 复现

1. MySQL CLI 通过 `-P63350` 连接只读代理。
2. 执行 `SELECT @@read_only, @@port`。
3. 返回 `1, 25437`，生成器因 `@@port != 63350` 拒绝继续。

## 预期与实际

- 预期：入口 CLI 端口为 63350 且 `@@read_only=1` 时通过。
- 实际：错误地要求代理后端的 `@@port` 也等于入口 63350。

## 根因

`@@port` 描述代理后端 MySQL 实例监听端口，并不能证明客户端实际连接的代理入口。护栏混淆了入口和后端端口。

## 修复

- 从移除密码后的 MySQL CLI 参数解析并严格验证入口端口为 63350。
- 另行查询并严格验证 `@@read_only=1`。
- 覆盖 `-P63350`、`-P 63350`、错误入口端口和非只读返回测试。

## 回归要求

- 本地及服务器自动测试全部通过。
- 生产影子生成必须通过护栏，并在日志中不暴露密码。
- 任何入口端口漂移或 `@@read_only=0` 仍必须失败关闭。

## 回归结果

- 修复提交后服务器自动测试 23/23 通过。
- 63350 CLI 入口与 `@@read_only=1` 双重校验通过。
- 2026-07 影子生成成功：31 天、41,637 条平台源行、32,949 条 AF 聚合行、26 条优秀素材。
- 公开目录与 Nginx 在影子阶段未变更。
