# 制作发布监控四类任务状态

用户要求渠道表将排队中改为待执行、执行中、预约中、异常。范围为统计与展示，保留原调度、发布事实、并发配置、任务权限、完成量与效率指标。

- 待执行：到期 queued/ready，无明确 hold、缺失身份或未知结果账号锁；正常账号前序、冷却、渠道/全局并发等待仍属待执行，不等于当前可领取数。
- 执行中：running/legacy_running，排除具有明确监控证据的执行器失联、反复领取未推进。
- 预约中：queued/ready、未来 scheduled_at、无明确 hold。到期后按相同规则重新统计。
- 异常：所选时段 failed + 全部未解决 unknown + 到期异常锁阻塞/缺失身份/时间、显式 hold、运行异常。失败和待核对原因仍可辨认。
- 历史暂停不混入四类；完成统计仍按既有唯一平台回执，允许已发帖但首评待核对同时具有完成事实与异常工作流。

顶部使用相同四类口径；制作完成、发布成功、历史暂停单独保留。原任务明细仍展示原账本状态，筛选器标注“原任务状态”。不增加自动重试，不更新任务，不解除锁。

实现采用现有增量终态计数 + 有索引、最多 10001 行的活跃任务读取。超过上限四类全部显示未知并提示，不使用部分计数。所有查询在同一只读事务内，权限先于分类；异常账号跨归属判断只返回原因计数，不返回他人任务或账号。
