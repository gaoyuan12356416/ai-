# Resume a dispatch-owned cover without reviving publication

The channel cutover check projected every native `generating` preparation as
legacy work. A cover whose descriptor had been lost after native reservation
was already owned by the new dispatch system, but could not resume because
enabling that system rejected its own outstanding native row.

The adapter now reads the latest persisted preparation claim and verifies
the exact task ID, pipeline lease owner, row version and current body version.
Only a matching claim makes the generating row dispatch-owned rather than
legacy work. Missing/mismatched proof still blocks legacy cutover. The owning
dispatch job, native lease and generation-intent journal continue to control
execution; this projection change does not mutate a native task or retry a
paid model call.

For an operator-authorized cover-only recovery, pass `preparation_only: true`
to the existing cutover-enable route. It still validates the held plan and
all native legacy work, then atomically enables the channel with a persistent
`preparation_only_channels` admission marker. Publication claims remain
paused. All saved host/global/channel concurrency values remain unchanged.
A later explicitly authorized full enable clears this marker. Existing review
and historical unknown publication fences remain unchanged; the admission
marker does not interrupt already claimed work.

Deploy the four changed pipeline modules from the exact pushed commit into
the coordinator, preserving newer shared files. Back up the live
files, current config and SQLite state, compile and run targeted tests before a
coordinated narrow coordinator restart. Do not stop node renderers, reset
tasks or restart the main API. Keep current databases and receipts on rollback;
reverse this commit's code patch after disabling the channel and draining
relevant claims. Older code does not understand the stage-admission marker,
so it must never be rolled back while a preparation-only channel is enabled.

Tests use real canonical and dispatch SQLite ledgers: a previously held
cutover enables a persistently owned generation without changing its native
row, lease/version mismatches and prefix-only ownership remain blocked, and
preparation-only admission allows preparation while refusing uploads without
changing the user's saved capacity.
