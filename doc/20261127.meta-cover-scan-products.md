# Meta cover scan recovery and product scope

On November 27, the source-alias fallback repeatedly failed with MySQL 3024 at
120 seconds. A sparse `original_source_id IS NULL / empty / zero` predicate
forced a large secondary-index scan before `LIMIT 2000` could return a page.
The scan retry whitelist also omitted statement timeouts. The 09:00 successful
scan read 5,827 violation records, 3,424 matching policy records and queued 307
new Ads; the report's zero replacement count did not mean zero violations.

Scalar reverse lookup now uses 64 aliases per range. For source aliases it
pages only ID/source/original-source fields, filters empty originals in memory,
and hydrates matching primary keys inside the same read-only snapshot. Every
page and historical/composite encoding remains covered. No query timeout,
lookback, policy threshold, credential, review, write-once or receipt rule is
relaxed. MySQL 3024 receives the existing single fresh-batch scan retry.

Product roots are DramaWave 1479, HotDrama 3302, FreeReels 979 and TopShort 3049,
plus their configured direct children. The verified directory includes
FreeReels child 2580 and TopShort child 3637. Similar names such as standalone
`iap-topshort` do not establish a parent relationship. Scope is applied through
discovery, durable triggers, fresh contexts, worker validation, own-product
cover selection and report labels. Existing HotDrama reuse remains unchanged.

Validation covers sparse fallback pagination, tied values, hydration, composite
encodings, bounded fresh-scan retries, exact new roots/direct children,
trigger persistence, per-product cover choice and fresh execution contexts.

Deploy from the verified GitHub commit with `deploy/install_cover_worker.py`.
Save scan/notify timer and worker states plus the reporter release drop-in.
Stop only cover timer admission, allow active scanning to finish, and gracefully
drain the cover worker. Prepare consistent SQLite audit backups and switch the
release using the existing installer. Render the report release template to
the new SHA, then reload systemd; do not change the four-hour window or target.
Validate a complete natural scan and a bounded worker cycle before restoring
continuous execution and the saved timers. Do not send an extra report.

Rollback drains the same cover services, runs the candidate installer's
`rollback <backup>`, restores the saved reporter drop-in and timer states, and
restarts the previously active cover worker. Retain current SQLite databases,
notification receipts and unknown-write fences; backups are audit copies and
must not replace current operational facts. New-product queued rows remain
recorded even if the previous version cannot process their root.
