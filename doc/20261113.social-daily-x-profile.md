# Social publisher daily report: include X profile publications

The 11:00 social publisher report read only the original X database. Confirmed
posts and effects attributed to the independent profile publisher were omitted.
The daily collector now reads both ledgers in read-only snapshots and supplies
the combined frozen catalog to publication, insight and purchase-bill reporting.
Existing Post ID deduplication, frozen owner attribution and conflict handling
are preserved. A configured unreadable profile database makes X incomplete;
it cannot silently report the original channel as the complete total.

The default additional database is `/mnt/data-disk/x-tag-publisher/posts.sqlite3`.
`--x-profile-db` overrides it for isolated previews. The shared adapter uses the
optional `SOCIAL_ANALYTICS_X_PROFILE_DB_PATH` setting; this deployment affects
the independent daily report, not publisher services or the web warehouse.

Validation:

```text
python -m unittest tests.test_social_analytics tests.test_social_daily_report tests.test_social_daily_billing tests.test_social_daily_correction tests.test_social_daily_retry
```

Deployment: start from the current `/opt/youtube-publisher-daily-report/current`
release and verify the four changed Python files against baseline
`abf3d3b0d30e796a912e090e55a89596fac1ba7a`. Stage only those files from the pushed
commit. Keep the previous release, back up the original report and delivery
database, and add `deploy/social-daily-x-profile-access.conf` as the report
unit's `95-x-profile.conf` drop-in. Reload systemd, verify a preview under the
same sandbox, then atomically switch the report symlink while holding its
existing run lock. No publisher restart is required.

For an explicitly authorized correction, preview and send the same frozen
revision with `scripts/social_daily_correction.py --date YYYY-MM-DD
--revision x-profile-v1 --reason x-profile`, adding `--send` only after checking
the preview. Read back the returned Feishu message and verify a repeat returns
`already_sent`. Preserve unknown receipts; do not change revision to retry.

Rollback: restore the previous report symlink and the backed-up
`95-x-profile.conf` (remove it if previously absent), then `systemctl daemon-reload`.
Keep all original/correction report snapshots and delivery databases; do not
restore older publisher databases or erase correction receipts.
