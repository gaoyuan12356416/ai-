# BUG-005 缺少新 outbox 表时部署验证可能误通过

## 发现阶段

2026-08-27 主负责人发布前复查发现，严重级别 P1；原功能提交 CPU 243 项通过之后、实际部署之前补充修复。

## 现象与根因

`verify()` 原先仅用 `snapshot.get("material_replication_broadcast_outbox")` 判断新表非空。新 worker 未初始化成功或统计快照缺少新表时，`get()` 返回 `None`，同样走“空表”通过分支，可能生成误导性的 `verification.json`。

## 期望与修复

主负责人修复为先显式要求新 outbox 键存在，再要求表为空。缺表必须报错，不能写入验证证明或输出成功结果。只加强部署门禁，不修改 HTTP API、消息模板或投递状态机。

## 影响文件

`scripts/deploy_material_replication.py`、`scripts/test_material_replication_safety.py`。

## 独立验证

- 正例 `test_verification_submits_only_invalid_batches` 改用显式存在且为空的新表快照，八个拒绝-only 探针仍通过。
- 新增 `test_verification_missing_outbox_fails_without_writing_proof`：分别传入空快照与仅旧表快照，断言 `RuntimeError`、`atomic_bytes` / 成功输出零调用及 `verification.json` 不存在。
- `python scripts/test_material_replication_safety.py --full-regression`：244/244 PASS，18.619 秒，失败 / 错误 / 跳过 / 外网尝试均为 0；8 个 Python 文件编译及 diff 检查通过。

## 结论

2026-08-27 本地修复复验通过，代码缺陷关闭。发布负责人随后对最终提交 `0a391260f6de1d2e99b351b21d41a613866a5cfb` 完成 CPU Python 3.9.6 同范围 244/244 PASS（16.792 秒、外网 0），并在实际部署时确认新表存在且 0 条后写入 verification.json，未沿用原版本 243 项结果。缺陷回归本身没有生产 API 调用；上线仅运行无消息拒绝探针，没有真实飞书测试发送。
