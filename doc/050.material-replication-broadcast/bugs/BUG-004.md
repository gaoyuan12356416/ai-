# BUG-004 带 Token 的部署验证可能跟随重定向

## 发现阶段

2026-08-27 独立部署验证脚本审查，严重级别 P1。

## 现象与复现

原 urllib 默认重定向可能使携带本接口 Token 的 POST 转到其他地址，并把重定向后的错误页误当原端点验证。实际回归只使用本机 302 stub 和虚构 Token。

## 期望与根因

精确端点探针必须拒绝 30x，不转发 Token。根因是默认 opener 自动跟随跳转。

## 修复

主负责人加入 NoRedirect handler，同时核对 HTTP 与业务错误码，并关闭 HTTPError 响应资源。

## 影响文件

`scripts/deploy_material_replication.py`、`scripts/test_material_replication_safety.py`。

## 验证与结论

`test_token_bearing_probe_never_follows_redirect` 通过，302 后零捕获请求；`test_verification_submits_only_invalid_batches` 验证八个探针仅为 401 / 422 空 items / 413 超限。完整影响范围 243/243 PASS。2026-08-27 已关闭，无生产网络请求。
