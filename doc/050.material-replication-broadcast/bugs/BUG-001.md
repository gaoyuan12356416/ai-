# BUG-001 共享发送器内部鉴权重试丢失历史未知结果

## 发现阶段

2026-08-27 独立代码评审。主负责人确认缺陷并修复；独立 QA 添加跨 sender 和 runtime 的故障注入回归。

## 现象

第一次响应 HTTP 503 + 鉴权刷新码属于未知结果。发送器内部刷新 Token 后，第二次明确拒绝仅携带 `uncertain=False`，可能让新 runtime 清除预置标记并转入群兜底，产生跨目标重复。

## 复现步骤

1. 临时 outbox 创建最多 1 次阶段尝试的私聊批次。
2. Mock 两次飞书响应依次为 HTTP 503 / `code=99991663`、HTTP 400 / `code=230001`。
3. 通过真实 `send_material_status_feishu_text` 适配器执行；HTTP 全部 Mock。
4. 检查终态与兜底正文，必须为 `delivery_unknown` / `private`，且无兜底正文。

## 期望结果

同一次 helper 内任何较早未知都必须保留；后来的明确失败不能清除它。旧调用方的 retryable、刷新次数、异常码及兜底分支不变。

## 实际结果

修复前异常元数据仅代表最后一次响应。经独立静态控制流审查和主负责人确认；不虚构修复前的测试执行统计。

## 根因分析

鉴权重试位于共享 sender 内部，新 runtime 的 previous_uncertain 仅能看见调用前持久化历史，无法观察同次调用的早先未知。

## 修复说明

主负责人增加 `send_outcome_uncertain` 累计元数据，后续异常保持累计未知；不改变 legacy 分支。

## 影响文件

- `app.py`：共享发送器内部重试元数据。
- `scripts/test_material_replication_safety.py`：两个 auth_retry 故障注入测试。

## 验证命令与结果

`python scripts/test_material_replication_safety.py --full-regression`：243/243 PASS，含两个 auth_retry 独立回归及全部旧接口专项；失败 / 错误 / 跳过 / 外网尝试为 0。

## 回归结论

2026-08-27 已关闭。本地回归通过；未发送真实飞书消息。
