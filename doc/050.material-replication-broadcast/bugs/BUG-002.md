# BUG-002 部分发布时回滚基线判断过窄

## 发现阶段

2026-08-27 独立部署脚本审查，严重级别 P1；未执行真实部署。

## 现象与复现

apply 已写模块和配置、但 nginx -t 失败时，app 仍为原 SHA。原 rollback 只接受已部署 SHA，因而拒绝处理脚本自身的部分发布。该控制流缺陷经主负责人确认。

## 期望与根因

已知原版 / 已部署版都可安全恢复；其他版本必须拒绝。根因是把完整发布当成回滚唯一前提。

## 修复

主负责人允许 manifest 中 original / deployed 两种已知 app SHA，并保持备份与配置 checksum 校验及后续漂移保护。仅撤回本次配置，不恢复数据库。

## 影响文件

`scripts/deploy_material_replication.py`、`scripts/test_material_replication_safety.py`。

## 验证与结论

`test_partial_deploy_with_original_app_can_rollback` 使用临时目录及 Mock systemctl 通过；完整影响范围 243/243 PASS。2026-08-27 已关闭；无真实服务操作。
