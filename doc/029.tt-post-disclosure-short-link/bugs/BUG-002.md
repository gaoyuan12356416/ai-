# BUG-002 候选 release 顶层目录不可遍历

## 现象

首次切换到新 release 后，`tt-post-service.service` 重启失败，日志为入口脚本 `Permission denied`。

## 根因

候选目录由 `mktemp -d` 创建为 `0700`。归档解压后执行递归去写权限，把顶层目录变为 `0500`；systemd 使用 `tt-post` 用户运行，无法遍历该目录。

## 修复

把已核对 release 顶层目录改为 `0555`，再以 `tt-post` 用户检查目录可遍历、入口脚本可读，随后重启服务。

## 验证

- sidecar 恢复 `active/running`，健康接口返回 `ok=true`。
- 14:40 后服务日志无 `error`、`traceback` 或 `failed`。
- 14:40 下一次自然 runner tick 成功，发布请求计数为 0。
- 发布文档已增加候选目录权限检查，避免复发。

## 状态

已关闭。
