# BUG-001 新 release 根目录权限阻止服务启动

## 发现阶段

生产部署健康检查。

## 现象

原子切换到新 release 后，`x-auto-post-service.service` 无法监听 18833，日志为
`can't open file ... Permission denied`。三个 X Auto timer 已先暂停，未创建任务或 Post。

## 复现步骤

1. 用 `mktemp -d` 在 releases 目录创建构建目录。
2. clone 并将该目录直接移动为最终 release。
3. 以 `x-post-daily` 服务用户启动入口脚本。

## 期望结果

release 根目录与旧 release 一致为 `0755`，服务用户可读取入口脚本。

## 实际结果

`mktemp` 创建的根目录为 `0700`，移动后权限不变，服务用户无法穿越目录。

## 根因分析

构建流程验证了 Git 提交和测试，但未在切换前验证最终 release 根目录权限。

## 修复说明

将精确 release 根目录修正为 `0755`，与旧 release 对齐；重启 X Auto 后健康门通过，
再恢复计时器。未修改源码、SQLite、Token 或发布任务。

## 影响文件

无源码文件；运行时目录：
`/mnt/data-disk/x-post-automation/releases/e96ecad3b2af33cc6a53e3154f69e4a36dfff769`。

## 验证命令与结果

- `stat -c %a <release>`：`755`。
- `curl http://127.0.0.1:18833/health`：`ok=true`、全部 gates 为 true。
- 14:42 scheduler/runner 自然执行：`Result=success`、`ExecMainStatus=0`。
- X Auto Run/Task/Ledger=`27/65/4`，活动数 0；未产生 Post。

## 回归结论

通过。后续部署脚本应在切换前显式断言 release 根目录至少为 `0755`。
