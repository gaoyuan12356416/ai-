# 046.x-auto-ignore-drama-blacklist 需求与技术设计

## 背景

2026-08-17 运行 26 的只读诊断显示，X 自动发布模板会读取
`ads_facebook_post_blacklist`，并用 `type=0` 的剧黑名单排除候选剧。业务现确认：
X 自动发布模板不需要经过剧黑名单。

## 目标

取消 X Auto 两阶段素材选择中的剧黑名单拦截，同时保持素材黑名单、素材合规、
语言、指标、时长、历史去重、原子预留和最终发布保护不变。

## 范围

### 包含

- 初始候选筛选忽略 `BlacklistSnapshot.drama_series_codes`。
- 最终预留前的黑名单刷新同样忽略剧黑名单。
- `BlacklistSnapshot.material_data_source_ids` 仍在初筛和最终刷新时生效。
- 增加回归测试、部署和无真实 X Post 的验证证据。

### 不包含

- 不改变素材池、短剧池、人工发布或 TikTok/Meta 逻辑。
- 不删除或修改黑名单源表数据。
- 不放宽色情、裸露、暴力等素材合规检查。
- 不改变 ROAS、Spend、语言、时长、冷却、去重和排序规则。
- 不修复或改写历史模板语言；该问题另行处理。

## 用户故事 / 业务规则

1. 作为运营，我希望 X Auto 可选择处于剧黑名单中的剧，只要其素材通过其他 X 条件。
2. 若剧对应的数据源 ID 进入素材黑名单，X Auto 仍必须排除该剧的全部素材。
3. 黑名单在选择期间发生变化时，新增剧黑名单不能打断预留；新增素材黑名单必须阻止预留。

## 交互与流程

本需求没有 UI/API 字段变化。预览、自然调度和任务执行自动使用新选择规则。

## 技术设计

### 影响模块

- `features/x_auto_posts/selector.py`
- `scripts/test_x_auto_post_selector.py`
- `doc/046.x-auto-ignore-drama-blacklist/`

### 数据结构

无数据库结构变更。保留现有黑名单快照字段，继续用于素材黑名单审计。

### API / 接口

无 API 契约变化。

### 异常与边界

- 初始快照和最终快照中的剧黑名单均不得影响选择。
- 素材黑名单在初始快照命中时跳过，在最终快照新命中时也跳过。
- 若所有候选仍被其他条件排除，继续返回 `x_auto_no_eligible_material`。

## 验收标准

1. 仅命中剧黑名单的候选可以被选择和预留。
2. 最终刷新时新增剧黑名单不改变已排名候选。
3. 初始或最终命中素材黑名单的候选仍不能被预留。
4. 现有 X 自动发布回归测试通过；无真实 X Post。
5. GitHub 精确提交部署到不可变 release，生产账本无意外新增。

## 风险与待确认

- 风险：误删素材黑名单保护。通过初始/最终两组素材黑名单测试防护。
- 风险：扩大到其他 X 发布路径。实现只修改 `features/x_auto_posts`。
- 待确认：无，用户已明确批准此业务规则。
