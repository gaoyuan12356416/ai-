# BUG-001 SafeDataRoot 合法数据盘路径被误拒绝

## 发现阶段

2026-07-16，SA 独立代码评审与本地 storage 自动化补测。

## 现象

初版路径校验把 filesystem root 同时放入“禁止祖先”集合，并用“禁止路径出现在 candidate.parents”判断。任意 Unix 绝对路径的 parents 都包含 `/`，导致合法 `/mnt/data-disk/ai-ad-control-v3` 也返回 `unsafe_data_root`。

## 复现步骤

1. 在临时非应用目录构造绝对数据根。
2. 初始化 `SafeDataRoot`。
3. 即使路径不在 `/root`、`/tmp`、应用 checkout，也被禁止祖先判断拒绝。

## 期望结果

拒绝 filesystem root 本身，以及 `/root`、`/tmp`、`/var/tmp` 和应用 checkout 及其后代；合法独立数据盘路径通过，并继续接受设备号、symlink、空间和权限检查。

## 实际结果

所有 Unix 绝对路径都可能因为父级 `/` 被误拒绝，V3 生产服务无法建立快照根。

## 根因分析

“禁止 root 自身”和“禁止明确目录的后代”两种语义使用了同一个祖先集合，条件范围过宽。

## 修复说明

- filesystem root 只做 `candidate == filesystem_root` 比较。
- `/root`、`/tmp`、`/var/tmp` 单独作为 `forbidden_descendants`，拒绝其自身和后代。
- 在任何 mkdir 前沿现有父级验证 symlink 和设备号。
- 保留 app root、Windows system drive、独立设备、权限、空间和原子写门禁。

## 影响文件

- `features/ad_control_v3/storage.py`
- `tests/test_ad_control_v3_core.py`

## 验证命令与结果

```powershell
python -m unittest discover -s tests -p "test_ad_control_v3*.py" -v
```

V3 最终套件 119/119 通过，包含合法根原子写、路径逃逸、symlink、大小限制和 Python 3.9 解析场景。

## 回归结论

已关闭。生产仍必须验证 `/mnt/data-disk/ai-ad-control-v3` 与 `/` 的真实设备号不同；本地测试显式只放宽独立设备检查，不能替代生产 mount 证据。
