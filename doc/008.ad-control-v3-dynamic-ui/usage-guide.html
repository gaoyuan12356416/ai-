Quick start

五分钟快速上手

Before configuration

权限、产品与筛选范围

V3 不再要求先选广告账户或账户池。候选广告由“优化师 + 产品”共同圈定，账户只作为最终结构归属存在。

普通优化师
创建规则时优化师固定为当前登录人，不能代其他人配置；可查看同一优化师范围的规则，但只能修改自己创建的规则。
管理员
可以选择任一有效优化师。本次演示由管理员选择“熊鑫”。
产品
支持多选；当前只提供短剧类型、有效状态的产品枚举，并与业务产品目录对齐。
产品与优化师关系
是 AND 关系：只处理既属于所选产品、又归属于所选优化师的广告。
账户时区
可选。留空表示不限制；选择后会补查候选账户时区。不匹配、缺失或冲突的对象仍保留为 blocked 审计记录，只有 eligible 口径才排除。
广告账户/账户池
V3 页面不再作为筛选入口，不需要逐个勾选账户。
!
多选产品是“任一产品”，再与优化师取交集

例如选择 Dramawave 和另一个短剧产品，含义是“产品属于这两个中的任意一个，并且优化师为所选人”，不是要求一条广告同时属于两个产品。

Navigation

页面入口与规则组列表

进入 V3 后只有两个功能页：规则组管理和执行日志。左侧导航固定展示，页面内部使用统一的动态壳层。

  1. 打开 V3 规则组管理。
  2. 列表顶部可以按名称/ID、产品、优化师、调控对象、运行模式和状态筛选。
  3. 点击右上角新建规则组进入五步配置流程。
  4. 规则 owner 或管理员可以编辑、试算、复制为新草稿或删除；普通用户看到同一优化师下他人创建的规则时只能读取，不能 Preview 或修改。当前启用入口受安全锁限制。

Step 1 of 5

第一步：范围与归属

先回答“谁的、哪些产品、哪个时区、看几天数据”。范围越准确，后面的规则条件越容易解释。

1

填写基础信息

填空项不带默认值；页面里的浅色文字只是提示，不会自动保存成配置。

字段怎么填注意事项
规则组名称建议包含对象、核心条件和模式，例如“Campaign 高 ROAS 复制（只观察）”用于列表和日志识别，避免只写“测试规则”。
说明写明数据窗口、核心条件、候选方式和安全边界便于其他人理解，不参与筛选。
渠道选择 FacebookTikTok 已预留渠道模型，但本期不可用。
优化师普通用户固定本人；管理员选择目标优化师必须与产品一起匹配。
短剧产品至少选择 1 个，最多 20 个支持多选；只显示有效短剧产品。
账户时区只有需要限制候选账户时区时选择；否则留空选择后会补查时区；不匹配、缺失或冲突对象记为 blocked，不会从总候选计数中消失。为了计划而选择时区不会让 R1 计划生效。
指标窗口输入 1–31 天这是效果指标的回看范围，不是规则有效期。

使用“估算当前范围”做第一道检查

范围估算读取 kunlunads_dev.ads_custom_source_insight，按 Facebook platform=0、data_source IN (0,6)、所选产品、优化师和日期窗口查询并去重，只投影对象身份与父级。它不是 Meta 账户资产全量，也不是实时 Graph 数据；不会查 Token、不会调用 Graph、不会读取 ROAS/CPI 条件字段。

  • 如果候选账户数为 0：优先检查优化师映射、产品选择和所选日期窗口内是否有 insight 数据。
  • 如果候选对象数异常大：检查是否多选了不需要的产品、指标窗口是否过长、是否漏选时区。
  • 如果结构对象数合理：进入第二步配置对象层级。

设置时区后，页面展示的 account_count/object_count 仍包含时区不匹配、缺失或冲突的 blocked 候选；服务端另有 eligible 与 blocked 口径，但当前估算卡片不全部展示。

i
范围估算 ≠ 手动试算，也都不是 Meta 实时扫描

范围估算按 insight 日期窗口做身份/结构候选计数；手动试算在同一受限数据源上读取规则所需指标，执行条件、优先级、冲突处理和 Top N，并写 Preview、observe execution、targets 与数据盘 gzip 快照。两者均不查 Token、不调用 Graph、不执行 Meta 写入。

Step 2 of 5

第二步：调控对象与运行模式

对象层级决定可筛选字段以及关闭/复制的目标语义；运行模式在未来决定是否允许外部写入。R1 的两种模式配置都不能写 Meta，手动 Preview 始终以 observe 记录。两者不是同一层级的配置。

调控对象指标粒度关闭配置目标复制配置目标适合场景
Campaign广告系列汇总暂停整个 Campaign，下属 Ad Set / Ad 都停止深度复制 Campaign 及其下级结构整套放量、隔日复制最佳系列
Ad Set广告组汇总只暂停命中的 Ad Set复制到来源 Campaign 或新 Campaign国家/受众/出价层的精细调控
Ad单条广告只暂停命中的 Ad复制到原 Ad Set 或独立承载结构优秀素材单独放量、差素材止损

运行模式怎么选

  • 只观察：当前 R1 仅支持手动试算，记录“本来会关闭/复制哪些对象”，不调用 Meta 写接口；持续扫描要等 Runner 发布。
  • 正式执行：为未来真实写入准备。当前 R1 受安全总开关保护，不会因为选中它就直接操作 Meta。
!
第一次配置必须保持“只观察”

至少完成一次手动试算并核对对象 ID、结果、原因、Top N 和 Meta 写入次数。当前日志界面不展示具体指标值；指标单位应按本手册的数据口径确认，必要时由管理员核对后端快照。

!
候选不保证 Meta 对象当前仍为 ACTIVE

配置状态、有效状态、当前预算等 Meta 字段在 R1 都不可筛，且 Preview 不调用 Graph 回读。正式写入开放前必须增加实时状态复核，不能直接把当前候选当成可执行对象。

Step 3 of 5

第三步：筛选条件与命中动作

一条规则由名称、优先级、条件关系、若干条件和一个命中动作组成。一个规则组最多 50 条规则，每条最多 30 个条件。

规则配置顺序

  1. 填写规则名称，描述“什么对象达到什么条件”。
  2. 设置优先级：数字越小越先判断。
  3. 选择条件关系：AND 表示全部满足；OR 表示任一满足。
  4. 逐条选择字段、运算符和值。
  5. 选择命中动作：关闭或复制。
  6. 如果选择复制，继续填写复制参数。
i
命中动作只有两个：关闭 / 复制

“观察”不再是动作，而是规则组级运行模式。也就是说，可以在“只观察”模式下预演关闭动作，也可以预演复制动作。

同一对象命中多条规则怎么办

  • 关闭优先于复制，避免同一轮里先复制又关闭。
  • 被更高优先级或关闭规则遮蔽的结果会记录为 shadowed_by_rule，方便审计。
  • 候选 Top N 未被选中的命中对象会记录为延后状态 deferred_by_selection / top_n_not_selected，不计入 skipped_count，也不会丢失审计记录。

本次演示条件

条件运算符值目的
消耗 spend大于等于50避免低消耗样本直接进入复制候选
安装 installs大于等于5保证 CPI 有基本样本量
ROAS roas大于等于1.2筛选回收达到 120% 的 Campaign

以上数字是手册演示值，不是统一的业务推荐阈值。请根据产品、国家、归因口径和投放阶段调整。

%
比例字段单位不是同一种写法

ROAS、AF ROAS、广告变现 ROAS 使用比值，1.2 表示 120%；CTR 和次日留存率使用百分数，20 表示 20%。当前对象明细不展示指标值，不能靠日志明细反推单位。

复制参数详解

只有命中动作选择“复制”时才会显示。当前这些参数参与保存和试算解释，但不会在 R1 里创建真实 Meta 对象。

预算设置

预算方式需要填写计算说明适用情况
X × 实际 CPI倍数 X，必须大于 0以来源对象实际 CPI 乘以倍数得到目标预算样本稳定，希望预算随实际获客成本变化
X × 固定目标 CPI目标 CPI 和倍数 X，均大于 0不使用来源实际 CPI，按固定目标成本计算产品有明确目标成本线
来源预算 × 比例比例百分数，必须大于 0例如填写 50 表示来源预算的 50%隔日复制最佳 Campaign 并降低预算

ROAS 出价调整

  • 选择提高或降低，再输入百分比；方向和百分比必须成对填写。
  • 百分比必须大于 0 且不超过 100。
  • 未来正式实现应在来源不是兼容的 ROAS 出价模式时跳过，不能静默切换竞价策略；R1 尚未实现这项 Meta 校验。
  • 不需要调整时两个字段都留空。

来源冷却与单规则额度

  • 来源冷却天数：可选；为未来正式复制定义同一来源的重复间隔；范围 1–3650 天。
  • 单规则每日复制上限：可选；为未来正式复制定义单条规则的日额度；范围 1–3650。
!
R1 手动试算不判断冷却，也不扣减额度

这些参数目前只保存、回显并进入不可变配置快照。不要因为填了“1 天 / 每日 1 次”就认为本次 Preview 已受保护。

✓

Step 4 of 5

第四步：执行计划、候选选择与额度

这一页同时包含当前会参与手动试算的 Top N，以及只为后续版本保存的计划、额度和冷却参数。R1 没有自动调度、额度扣减或冷却判断。

执行计划

方式配置解释校验
不设置计划执行方式、开始和截止时间全部留空只保留手动试算配置不要只填时间窗口而漏选执行方式
每天固定时间执行时间；可选允许开始/截止时间未来按广告账户本地时区解释；时区未限制时需特别谨慎时间必须完整，窗口逻辑要合理
每隔 N 分钟间隔分钟数；可选允许窗口未来在窗口内按间隔扫描N 为 1–1440

允许开始/截止时间可以留空。R1 只校验 HH:MM 并保存，不解释截止早于开始是否跨日；跨日语义要等正式 Runner 发布时再冻结，当前不要依赖。本次演示选择每天 08:00，允许窗口为 08:00–10:00，只用于展示配置。

候选选择

方式选择逻辑典型用途
全部符合条件保留所有通过条件和冲突处理的对象关闭明确不合格对象
每账户 Top N在每个广告账户内单独排序，取前 N 个每账户复制一个最佳 Campaign
每产品 Top N在每个产品内排序取前 N 个多产品统一筛选但控制各产品名额
全范围 Top N在整个规则范围内统一排序只保留全局最强候选

Top N 的 N 取值范围为 1–10000。当前只能选择一个数值排序字段和升/降序；同值时由对象 ID 做最终稳定决胜。例如选择 ROAS 降序，就不会再按消耗做第二排序。

!
从 Top N 切回“全部符合条件”时

请手动清空 Top N、排序字段和方向。后端要求“全部符合条件”不能携带 Top N 字段，残留值会导致保存被拒绝，不会自动替你收敛。

三层额度与冷却

  • 规则组每日上限：可选；为未来正式复制定义该规则组的总日额度；范围 1–10000。
  • 当前用户每日总上限：可选；为未来正式复制定义该用户的总日额度；范围 1–10000。
  • 同一对象冷却天数：可选；为未来执行定义对象重复处理间隔；范围 1–3650。
  • 复制动作还有单规则每日上限和来源冷却；未来正式执行时，多层限制共同约束并取更严格结果。

R1 仅保存和回显这些未来保护参数，不会运行额度扣减或冷却判断，也不能把当前日志当成额度已生效的证据。

Step 5 of 5

第五步：检查、安全确认与手动试算

最后一页不是形式检查。要逐项确认范围、对象、动作、指标单位、Top N、额度和运行模式是否符合预期。

保存前检查顺序

  1. 确认配置总览里的优化师、产品、对象层级和规则数量。
  2. 确认运行模式是只观察。
  3. 检查页面是否提示待完善项或非法值。
  4. 再次核对预算倍数/百分比、ROAS 和留存率单位。
  5. 第一次建议点击保存并立即试算，不要只保存后离开。
按钮结果何时用

保存并立即试算保存最新版本后立刻创建一次手动预览执行第一次配置或每次重要修改后
i
修改配置会使旧试算失效

保存采用版本校验。试算结果与当时的规则快照绑定；规则发生变化后必须重新试算，不能把旧结果当成新配置的证据。

FAQ

常见问题

保存草稿会不会直接关闭或复制广告？
不会。新规则组强制保存为停用、只观察。保存本身不会调用 Meta 写接口，也不会自动调度。
“范围估算”和“立即试算”有什么区别？
范围估算在 insight 日期窗口内只投影身份/父级并统计去重候选；立即试算在同一受限数据源读取规则所需指标，执行条件、优先级、冲突处理和 Top N，并写 Preview、execution、targets 与快照。两者都不是 Meta 实时 Graph 扫描。
为什么启用按钮不可用？
当前真实调度已经开放，但启用仍要求规则完整、最新试算有效，并在正式模式下完成二次确认。先保持停用做一次试算；如果页面顶部不是“正式执行可用”，停止操作并联系管理员。
为什么页面可以选“正式执行”，却没有真的复制？
仅选择运行模式不会执行。需要保存、生成最新试算、核对候选、完成二次确认，再点击单次真实执行；若仍未复制，在执行日志查看额度、冷却、幂等、来源映射或竞价兼容性等跳过原因。
多选产品之间是什么关系？
产品之间是“属于任一所选产品”；再与优化师、可选时区取交集。
AND 和 OR 应该怎么选？
AND 要求本条规则所有条件都满足，适合“消耗充分且 ROAS 达标”；OR 只要任一条件满足，适合多个独立风险信号，但更容易扩大命中范围。
同一对象同时命中关闭和复制会怎样？
关闭优先。其他规则结果会记录为被遮蔽，避免同一轮对一个对象产生矛盾动作。
不选择账户时区有什么影响？
表示不补查和限制时区。设置时区后，不匹配/缺失/冲突对象会保留为 blocked 供审计；未来配置固定时间自动运行时，还要明确账户本地时间语义。
每账户 Top 1 是在所有账户里只选一个吗？
不是。它会在每个广告账户内部各自排序，每个账户最多选 1 个。全范围 Top 1 才是整个规则范围只选一个。
如何确认观察模式真的没有修改 Meta？
打开日志详情，核对外部写约束明确显示“观察模式 Meta 写入 0 次”，同时确认快照完整、执行模式为观察，并保留执行 ID。
复制结果现在会写入 ads_ai 吗？
会。正式复制按“一条新 Ad 一行”写入 ads_ai.ads_facebook_auto_created_data，并在 copy intent 与 lineage 表记录来源、新对象、规则、落表和激活状态。观察和立即试算不写复制结果。
目前支持 TikTok 吗？
不支持。数据模型和页面结构预留了渠道扩展空间，本期只支持 Facebook / Meta。

Safety checklist

保存与正式开放前安全清单

可以打印本页逐项勾选。任何一项不确定，都先停留在只观察并重新试算。

  • 当前选择的是正确优化师；普通优化师没有代他人配置。
  • 产品范围正确，没有误选无关短剧产品。
  • 账户时区的“留空不限制”符合本次意图。
  • 调控对象是正确的 Campaign / Ad Set / Ad 层级。
  • 当前运行模式为只观察，规则组状态为停用。
  • 指标窗口与业务归因/数据延迟相匹配。
  • 消耗、预算、CPI、ROAS、留存率的单位已按适配器口径确认；已知当前试算明细不展示指标值，不能用它核对单位。
  • AND / OR、优先级以及关闭优先逻辑符合预期。
  • Top N 的分组范围、数量、排序字段和升降序正确。
  • 需要额度/冷却时已显式填写；不需要时保持为空；并已知这些参数在 R1 只保存、不参与手动试算。
  • 没有把输入框提示词误认为已经填写的默认值。
  • 每次重要修改后都重新保存并立即试算。
  • 执行日志快照完整、异常/阻断为 0。
  • 观察日志明确显示 Meta 写入次数为 0。

术语速查

Campaign
广告系列，Meta 结构的上层对象，可承载 CBO 预算。
Ad Set
广告组，位于 Campaign 下，承载受众、排期、出价及 ABO 预算。
Ad
广告，位于 Ad Set 下，关联创意与素材，本身没有独立预算。
只观察
计算并记录“本来会做什么”，但不调用 Meta 写接口。
立即试算
一次性手动运行最新规则快照，与未来持续调度不同。
范围估算
在 insight 日期窗口和身份范围内统计去重候选，不是 Meta 实时资产全量，也不进行效果条件判断。
Top N
对已命中对象按指定范围和排序保留前 N 个。
冷却期
为未来版本定义同一对象或来源的重复处理间隔；R1 仅保存。
would_copy
观察模式中，该对象在正式链路下本来会进入复制动作。
top_n_not_selected
对象通过了规则条件，但没有进入对应范围的 Top N。
