# Mobo 推荐资源复制与 X / FB 发布身份修复

推荐接口从 `kunlunads_dev.ads_drama_info` 中按 Mobo `app_id=2373` 和推荐 `story_id=content_id` 读取真正的 `series_code` 资源 ID。示例：164754322 → XEY468，147905322 → XEY463。复制单条或当前筛选全部分页结果，按资源去重、每行一个；页面同时区分剧 ID 与资源 ID。缺失或冲突映射不再回退成剧 ID，读取失败时禁止复制。

X 爆款剧入口按模板素材产品解析 Mobo；FB 按现有 `m_url` 分支解析 Mobo。资源代码支持字母，展开为同机构、短剧业务、当前上架的各语言版本；剧 ID 保持单版本范围。混合产品同号歧义会明确报错。DramaWave 原有解析、可投放时间和历史回执保持原语义。

Mobo 受众采用供应方 `channel_text` 明确的男频/女频，题材采用 `c_name`，对“家庭亲情”“萌宝”作明确家庭题材映射。没有受众或题材证据仍不能通过严格画像匹配。不会借用同号 DramaWave 的受众、广告指标、黑名单或可投放时间。Mobo 沿用其当前上架资格，制作完成后尽快发布；不虚构未注明时区的供应方上架时间。

FB 解除本路径旧的 Mobo 爆款请求拒绝，并在素材 SQL 分页和截断前限定目标剧/语言。X 执行时同时限定剧 ID 与 catalog。保留模板素材来源、产品、时长、指标约束、账号/Page 权限、严格画像、冷却、素材去重、操作幂等和未知结果核对。

## 验证

使用当前线上模块组合运行相关测试：X 19 项、FB 21 项、推荐接口 10 项。覆盖资源/剧身份、多语言、Mobo 受众来源、模板路由、实际选材、画像、冷却、重复回执和 SQL 范围。既有测试夹具补齐当前画像版本及发布时点，不修改生产规则以迁就夹具。

真实浏览器验证 125 条推荐跨页复制出 123 个资源（去重并跳过缺失）、单条、筛选、查询失败、部分读取失败、剪贴板回退、桌面/手机布局；X/FB 弹窗接受 XEY468/XEY463 并在批内去重。弹窗 API 全为本地模拟，没有调用真实发布。

## GitHub 部署与回滚

`scripts/deploy_moboreels_resources.py prepare --folder <data-disk-folder>` 只接受干净、已推送的 GitHub 提交，并逐个校验 `deploy/moboreels-resource-baselines.json` 记录的线上文件。候选目录基于各自完整线上运行目录，仅覆盖已审查文件；保留其余并行发布更新。

`scripts/verify_moboreels_resources.py` 用只读副本验证当前推荐映射、两种 ID 解析、全部语言分类及可用素材；不构建发布运行时、不写业务数据库。

逐 lane `apply --lane mobo|x|fb`：Mobo 拒绝新请求并等待已接收请求完成后重启；X 暂停自身触发器、排空并持锁，更新现有选择加速器的 BASE 指向当前发布目录再重启；FB 使用现有原生排空流程。X/FB 均先记录后恢复 scheduler health。最后 `static` 原子更新主站资产及内容哈希版本。

备份、前后哈希、完整原运行目录、调度器恢复记录均留在部署目录。回滚使用同脚本 `rollback --lane ...` 和 `static-rollback`，有后续版本时拒绝覆盖；未结束的 Mobo 爆款任务需保留兼容代码。仅回滚代码和必要服务配置，永不回滚业务账本或重放未知结果。

只读验收：20 条推荐均匹配真实资源，去重为 13 个；可解析 218 个现有支持语言版本，均有明确受众和题材。供应方语言编号 23（推荐剧 162432501）尚不在现有发布语言表中，保留明确的语言缺失错误；同资源 XEY463 的其他支持语言版本正常解析。补齐 X 选材中现有 pt / pt-br 别名的 Mobo 目录匹配。
