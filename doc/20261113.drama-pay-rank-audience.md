# Daily payment rank and authoritative audiences

The backend displays the provider's per-language Top100 at
`/drama-pay-rank.html`, with the assignable `drama_pay_rank` permission and a
Cookie-authenticated `/api/drama-pay-rank/list?date=&language_code=en` reader.
The reader never calls upstream or starts SQL collection. Rank dates are the
provider's generation date; the window is the preceding three UTC days.

`drama-pay-rank-refresh.timer` runs at 11:00 Asia/Shanghai. It checks the HTTP
response's business code, saves full-language snapshots on the data disk, keeps
the last good snapshot on failure and retries three times at ten-minute intervals.
The service uses the existing `/etc/drama-material-service/a-group-expansion.env`
credential without returning it to clients. No payer count or amount is invented.

`drama-audience-sync.timer` discovers source `ads_drama_info` IDs hourly at :05,
durably enqueues unseen IDs before advancing the source cursor, and fills the
SQLite `drama_audience` table at `/mnt/data-disk/drama-audience/catalog.sqlite3`.
Existing records have no expiry. Failed requests stay pending, while an explicit
empty `audience_labels` is stored as unlabeled, never general. X/FB current
portrait dramas have first priority, rank metadata second, remaining source
dramas third. Publishers read only this local table; they never call the provider.
New source IDs have a separate forward cursor and priority over the bounded
historical backfill, so old catalog volume cannot delay discovery of new dramas.

The source is `https://admin.mydramawave.com/material/list2?content_id=...`.
Only the exact case-sensitive ID and `com.dramawave.app` product are accepted;
the matching language must also agree. No resource-ID, title or third-party-ID
join is used. All seven provider audiences have distinct keys. Multiple or
unsupported values remain visible as an unresolved classification. Maintenance:
`python3 -m features.drama_audience.sync --refresh-id CONTENT_ID` explicitly
replaces one stored record. Normal hourly runs do not refresh old records.

X and Facebook keep their financial windows and source facts. Both periodic
portrait builds and new selection decisions use the catalog; labels still supply
themes. Historical frozen selections are never rewritten. The reprojector proves
per-drama facts, channel totals and all parent/child sums before publishing new
versioned `ads_ai` portraits and immutable local serving indexes. It emits before,
after, differences, missing-ID lists and SQL readback proofs in the deployment
folder. TT is unchanged.

## Validation and release

Run `python -B -m unittest discover -s tests -p test_drama_audience_rank.py` and
`node --check static/drama-pay-rank.js`. Exercise the channel assignment tests
against the actual staged standard-X runtime, whose composite dependencies are
newer than the partial source checkout. Verify the public page with logged-in
and denied access, filters, actual rows, stale notice and shared navigation.

Push the exact source before CPU staging. Commands:

```
python3 scripts/deploy_drama_audience_rank.py prepare --folder DEPLOYMENT
python3 scripts/reproject_drama_audiences.py preview --folder DEPLOYMENT/preview
python3 scripts/deploy_drama_audience_rank.py apply --folder DEPLOYMENT
```

The installer copies each current X/FB runtime and overlays only affected files,
patches the current main API/navigation without replacing unrelated code, backs
up changed files and the audience catalog, and preserves scheduler state.
Its existing FB helper drains only the affected owner. A live write causes a
retryable deployment stop; no publication locks, queues or receipts are cleared.

Rollback uses the same verified source:
`python3 scripts/deploy_drama_audience_rank.py rollback --folder DEPLOYMENT`.
It restores code pointers and previous files and disables the two new timers.
Current audience facts, rank history and all publishing databases remain intact.
Restored portrait refreshers can generate a fresh old-policy projection; do not
restore an old publishing database or overwrite newer financial facts.
