# Facebook automatic publishing by Page income portrait

Existing Dramawave automatic templates now choose dramas from the target Page's
audience/theme income portrait before choosing an edit inside that drama. The
portrait is the existing Facebook Page service's seven complete UTC report days,
including paid and confirmed AI-backend organic attribution. It is an income
preference signal, not a demographic count. No new template or switch is required.

The planner freezes one immutable local portrait generation, keeps normal source,
language, metric, duration, blacklist, material occupancy and drama cooldown
conditions, and applies X's deterministic weighted audience-then-theme order.
Candidates with equal classification retain their configured metric order. Each
classification bucket has the existing bounded candidate retention, so a later
preferred drama is not hidden behind an unrelated global top-N. The first eligible
drama at the best available rank is selected; ordinary edit randomization or
feedback then operates only inside that drama.

If a preferred theme has no eligible edit, selection tries another theme in the
same audience, then another audience. Missing/unusable portraits or unavailable
candidate classification use the original global candidate order, with an explicit
reason. Signed income corrections and unknown audience labels do not become
weights. Existing non-Dramawave products and explicit hit-drama submissions keep
their scope. Source classification normalizes X portrait aliases (including
pt/pt-br) without changing the Page's publishing language.

Every new task freezes `selection_json.tag_profile`: Page, portrait/version/date
window, policy/taxonomy versions, weights, preferred/selected paths, selected drama
and material, and fallback reason. Re-entering a frozen run does not reselect.
Historical ready/published/unknown tasks and platform receipts remain untouched.

## Validation

Run `python -B -m unittest tests.test_fb_profile_selection
tests.test_fb_profile_integration scripts.test_fb_hit_drama
scripts.test_fb_target_midnight scripts.test_fb_auto_validation -q`.

Tests cover weighted determinism, corrupt/missing snapshots, late matching dramas
beyond the old top-N, distinct Page preferences, language aliases, feedback staying
inside the chosen drama, cooldown/occupancy, original fallback bounds, frozen
replays and explicit hit-drama targeting. The old Page-isolation test module has
eight failures on both unchanged a8726888 and this branch: its pre-November-6
whole-Page unknown assumptions conflict with the already deployed pool policy.
They are not changes to this selection feature.

## Scoped release and rollback

Push the exact commit, fetch it on CPU 43.166.187.96, then run
`python3 scripts/deploy_fb_profile_selection.py prepare --folder DEPLOYMENT`.
Prepare copies the live FB release and overlays only the selector and its pure
classification dependencies, checks the a8726888 baseline, tests the actual
candidate, verifies low-privilege portrait access, and saves the current ledger
as evidence. No source database migration is needed.

Before activation, run `scripts/preview_fb_profile_selection.py` from the fetched
source/candidate as documented by its `--help`. It reads source/metric data and
shows real Page choices without creating tasks, links or posts.

Use the same deployment helper's `apply --folder DEPLOYMENT` to drain and switch
only the Facebook owner. It preserves active work and restores the prior FB
timer/daemon states using the scheduler health helper. Main API, coordinator, X,
Page portrait collector and public static assets do not need replacement.

Rollback: `python3 SOURCE/scripts/deploy_fb_profile_selection.py rollback
--folder DEPLOYMENT`. It restores the previous code pointer while preserving the
current publication database, frozen selections, short links and receipts. Never
restore the saved ledger over newer publication results.
