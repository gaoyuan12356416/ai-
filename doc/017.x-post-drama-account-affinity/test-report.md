## 缺陷情况

- BUG-001：旧逻辑将同一短剧连续集分配给多个账号，已修复并增加多层防线。
- BUG-002：首次生产迁移后，二次存储初始化会用无变化的 `UPDATE` 触发旧跨账号历史约束；已改为仅在规范值实际变化时写入，并保留全部非法历史拦截。
- BUG-003：2026-07-29 10:06 批次遇到未绑定新剧的确定性预检失败后直接结束，没有继续 FIFO 选择后续可用新剧；修复合同为“无绑定无历史则 `validation_failed` 并顺延、已绑定或有历史则 `needs_review` 并整批停止、凑齐全部账号后才原子建队列”。本修复不补跑 10:06。
- 第一轮回归发现列表查询依赖未初始化的账号表；已改为从绑定依据队列读取用户名，复测通过。
- 第二轮 UI 评审发现失效账号提示、行级下次时间和不可用状态容易误导；已改为引导校验/重新授权，并区分待分配、不可分配、暂停和历史账号。

- TC-15–TC-18 全部通过，覆盖未绑定新剧 FIFO 顺延、绑定/历史剧 fail-closed 和整批零落库；其中 TC-17 使用“绑定字段为 0、但已有旧队列”的独立历史夹具。
- 335/335 完整 X 回归包含 BUG-003 本轮改动；定向的账号、schedule store 和 runner 110/110 通过。
- 生产只读核验确认10:06原批次为 `failed_preflight`、队列0、发布日志0；池53无绑定、无历史，旧版本误记的 `needs_review` 需在部署门禁内精确改为 `validation_failed`，且不得恢复该批次。
- 精确commit的生产在线备份副本演练确认池54 Episode 1也超过140秒；新逻辑依次排除池53、54且始终零队列。当前剩余候选只能覆盖5个账号，无法覆盖6账号配置，符合整批失败门禁。
