# BUG-002 迁移后二次初始化误触发历史队列约束

## 发现阶段

生产部署后的首次迁移与只读验库阶段。

## 现象

首次启动能完成账号归属迁移；随后再次创建 `XPostStore` 时，旧版已经发布的跨账号短剧历史触发 `x_post_queue drama binding invalid`。

## 根因

`ensure_storage` 每次初始化都会对全部历史队列执行一次 `UPDATE source_type/material_key/run_date`。即使三个规范值完全没有变化，SQLite 的列级更新触发器仍会执行；旧跨账号历史在新归属规则下因此被误判为新写入。

## 修复

- 保留 `source_type`、`episode_key`、`material_key`、`run_date` 的全部 fail-closed 校验。
- 先比较数据库原值与规范值，仅当实际不同才执行历史规范化 `UPDATE`。
- 首次迁移仍会规范化旧值；迁移完成后的重复初始化不再写入无变化历史。
- 新队列插入、队列身份变更和发布前账号归属校验均不放宽。

## 回归验证

- 跨账号历史迁移后连续创建第二个 `XPostStore` 成功。
- 二次初始化前后 queue/log 数量不变。
- 人为破坏历史 `episode_key` 后仍返回 `x_post_storage_conflict`。
- 全量相关回归 328/328 通过。
