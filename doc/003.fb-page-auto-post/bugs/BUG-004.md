# BUG-004 生产 systemd 忽略 oneshot RuntimeMaxSec

## 发现阶段

CPU 生产 `systemd-analyze verify`。

## 现象

所有 `Type=oneshot` unit 报告 `RuntimeMaxSec has no effect`，发布、对账、制作和指标刷新只在代码层有限时，unit 层没有生效的最终截止时间。

## 根因分析

当前生产 systemd 版本不对 oneshot 应用 `RuntimeMaxSec`；oneshot 的启动过程必须使用 `TimeoutStartSec` 限时。

## 修复说明

所有 FB oneshot unit 将既定预算原值迁移到 `TimeoutStartSec`，scheduler 保留 60 秒、Graph 1500 秒、GPU prepare 10800 秒、指标 repair 7200 秒。部署契约测试明确拒绝 scheduler 中残留的 `RuntimeMaxSec`。

## 回归结论

本地部署契约必须通过，生产重新运行 `systemd-analyze verify` 时不得再出现 ignored runtime warning。
