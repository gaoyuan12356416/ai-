# BUG-002 Metric SQL 在 ONLY_FULL_GROUP_BY 下报 1055

## 发现阶段

生产只读 EXPLAIN。

## 现象

单日指标聚合的 `ORDER BY CAST(TRIM(s.resource_id) AS UNSIGNED)` 未出现在 `GROUP BY`，MySQL 5.7 `ONLY_FULL_GROUP_BY` 返回 1055。

## 根因分析

流式 writer 需要 material ID 数值序，但 SQL 直接在排序阶段增加未分组的 CAST 表达式；同时 `UNSIGNED` 对超大正整数并非无界排序合同。

## 修复说明

SELECT、GROUP BY 与 ORDER BY 统一使用 `CHAR_LENGTH(TRIM(resource_id))`，再以原 material ID 字符串作为稳定次序。输入已限制为无前导零的正整数字符串，因此“长度、字符串”严格等价于任意精度数值顺序，并满足 `ONLY_FULL_GROUP_BY`。

## 验证

专项测试明确断言 SELECT/GROUP BY/ORDER BY 三处表达式一致，保留 `1,10,2` 非法流式顺序的防御测试。修复后已在生产只读执行 EXPLAIN：`ONLY_FULL_GROUP_BY` 合法，不再报1055，自动选择 `pss(product,dt,series_code)`；未执行指标刷新。

## 回归结论

已关闭；本地专项与生产只读 EXPLAIN 复验均通过。
