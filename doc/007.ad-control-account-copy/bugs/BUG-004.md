# BUG-004：既有补丁不能完整生成 V2 生产 app

## 严重级别

P0（发布阻断）

## 发现方式

服务器异常恢复后，生产在 16:01 又上线了 daily-log overlay。重新将最新生产 `app.py` 作为 source fixture 时，发现 `deploy/apply_ad_control_execution_log_fix.py` 只负责 execution-log 函数兼容，并不会补入完整的账号归属、对象层级、运行模式、规则组 API 和 V2 执行门禁。该脚本自身的幂等/备份测试通过，但把它误当成完整 V2 发布器会得到“日志已修补、V2 主能力未上线”的半发布结果。

## 根因

此前把 action-log 兼容补丁验证器错误提升成了整个 V2 `app.py` 的部署链。验证器只断言其负责的函数和安全常量，没有断言 source→release target 的完整 Git blob。

## 修复

- 新增 `deploy/apply_ad_control_account_copy_v2.py`，从 GitHub checkout 内解析精确 source/target commit。
- 仅当 live `app.py` 与 source blob 字节一致时继续；受统一锁管理的发布在锁内最终重读 source，未知 source 或受控并发变化在写入前失败。锁外人工覆盖另由排他发布窗口和发布前后 hash 门禁阻断，不宣称 advisory lock 可拦截所有写入。
- 在隔离临时目录应用 source→target 的 Git diff，并要求结果与 target blob 字节一致。
- 确认变更后创建唯一、字节一致且已持久化的 source 备份，再以同目录临时文件、`fsync` 和 `os.replace` 原子安装 target；安装后异常在同一次锁定尝试内恢复 source。
- target 已安装时返回 `unchanged` 且不增加备份；中断后 source 仍在时，重新校验并 `fsync` 已有备份文件及目录后才复用。
- 原 execution-log 补丁保留为 action-log 兼容验证器，不再承担完整 V2 发布。

## 回归

`tests/test_ad_control_account_copy_deploy.py` 12/12 通过，覆盖只读 check、精确 apply、共享锁、唯一持久化备份、mode-before-fsync、幂等、已有备份复用、未知源/锁外未知字节 fail-closed、安装后失败恢复以及 diff 只包含 `app.py`。合并最新 daily-log 基线、修复产品账号列表 owner/cache 回归并收口发布门禁后的 ad-control 全量测试 171/171 通过。

生产 exact-commit staging、C1 备份与线上原子替换仍需按部署文档执行；本缺陷关闭不等于已上线。
