# BUG-005：复制熔断占用关闭批次额度

## 严重级别

P1（业务执行阻断）

## 发现方式

最终业务回归构造同一账号 `21` 个 pause 候选和 `1` 个 copy 候选。旧实现虽然先按动作排序，但随后按账号/Campaign 重新平衡，并统一套用每账号 `20` 条上限，导致已知会被 `copy_persistence_not_configured` 熔断的 copy 仍占用一个关闭名额。

## 影响

首批只执行 `19` 个 pause，另有 `2` 个 pause 未处理；copy 熔断又可能把 runner 事件收敛为 error 并写入 last key，从而让“复制持久化暂未开放”反向阻断既有 Campaign 关闭，与 mixed 规则组的硬安全契约冲突。

## 修复

- live 模式仍存在 pause 候选时，本批只将 pause 交给 global/per-account 公平分批；copy 不消费关闭额度。
- preview criteria 继续保存总 `pause_target_count/copy_target_count`，确保 mixed 二次确认和审计语义不退化。
- 当前批 pause 清空后，后续 fresh preview 才选择 copy-only 候选，并在 Token/Graph 前按既定 `copy_persistence_not_configured` 失败关闭。
- runner 对仍有剩余 pause 的结果保持 `partial` 和 continuation key，不因 deferred copy 提前终止。

## 回归

新增真实 preview→execute 场景：同账号 `21 pause + 1 copy` 时首批恰好选择并成功 mock POST `20` 个 pause，copy 不在 sample/result 中、`blocked_count=0`、`remaining_count=2`；runner 同时验证 partial 状态和 continuation key 保留。相关五套自动化回归 `121/121` 通过，未调用真实 Meta。
