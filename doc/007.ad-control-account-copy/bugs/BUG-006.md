# BUG-006：产品账号列表 owner 漏传及缓存隔离缺失

## 级别

P0。阻断生产发布。

## 现象

规则资源升级为当前用户隔离后，legacy 产品账号列表仍以旧签名读取已保存账户池。冷缓存请求在进入业务库查询前即因 `missing_owner` 失败，导致产品账号选择和大账户池 fallback 不可用。

原缓存只以 `product` 为键。若仅取消 owner 校验来恢复可用，不同用户的 saved-only 账号会进入同一产品缓存，形成跨用户可见风险。

## 根因

`GET /api/ad-control/accounts` 到 `list_ad_control_accounts`、legacy product loader、saved pool 聚合器的调用链没有贯穿当前 session owner；缓存模型也未随 owner 隔离升级。

## 修复

- HTTP route 从当前 session 解析 owner 并显式传入 service。
- `list_ad_control_accounts`、legacy product loader 和 saved pool 聚合器逐层传递 `owner_user_id`。
- legacy 产品缓存键由 `product` 改为 `(owner_user_id, product)`。
- 无产品的全产品业务库列表分支保持原有行为，不额外合并任何账户池。

## 验证

- 245 账号池可读取、生成有效 preview 并通过一次 Token 获取完成全部账号权限验证。
- 业务库不可用时只 fallback 当前 owner 的已保存账户池。
- 6 个并发请求共享一次业务库刷新。
- 同一产品下两个 owner 的 saved-only 账号和缓存互不可见。
- focused 32/32、fresh-cache 全量 171/171、route owner 注入静态契约、Python 编译和 `git diff --check` 通过。
