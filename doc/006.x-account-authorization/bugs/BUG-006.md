# BUG-006 X 账号退出失败并改为后台软停用（已修复并部署）

## 发现阶段

2026-07-14 生产验收。

## 现象

账号属主在个人授权页点击“退出授权”后，接口返回失败，记录进入 `revoke_pending`，页面显示“退出待完成”。

## 复现步骤

1. 使用已授权账号属主登录 AI 自动后台。
2. 打开 `/x-accounts.html`。
3. 点击某账号的退出操作并确认。
4. 接口返回 502，账号进入 `revoke_pending`。

## 期望结果

按 2026-07-14 最新产品决定，退出只表示在 AI 后台停止使用该账号：状态更新为 `disabled`，后续发布不得选择该账号；无需调用 X 远端撤销接口，也无需删除本地 Token。

## 实际结果

V2 实现会调用 X OAuth revoke。生产探针显示上游拒绝旧请求并提示缺少 `token_type_hint`，因此本地安全状态机保留 Token 并停在 `revoke_pending`。

## 根因分析

技术触发原因是生产 X revoke 接口对请求参数的实际要求与已部署请求不一致。更根本的产品问题是 V2 把“后台不再使用账号”实现成了不可逆的远端撤销和本地删 Token，复杂度高于最新业务需求。

## 修复说明

- 保留既有 `POST /api/x-accounts/{id}/logout` 路径，改为 owner-scoped 本地软停用。
- 单次数据库事务把状态写为 `disabled`，清除旧错误并记录操作人和停用时间。
- 不读取 Token、不调用 X、不删除 Token；重复停用保持幂等。
- 旧 `revoke_pending` 可直接收敛为 `disabled`；历史 `disconnected` 保持原终态。
- `disabled` 禁止校验，重新授权同一账号后恢复 `active`。
- 增加 `publish_credentials` 持锁上下文；只有动态状态仍为 `active` 才能取得发布凭证，敏感凭证只 yield `access_token` 字符串，停用与发布并发时由同一账号锁串行化。实际 X Post 发布尚未接入，未来调用必须留在同一 context。
- 个人页和管理员页统一显示“已停用/完成停用”，明确 Token 仍保存在服务器且不会调用 X 解除授权。
