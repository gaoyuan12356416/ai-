## 修复发现的来源冲突

旧发布系统和 AI 后台同用 `site_id=2049`，两套来源会重复使用短数字 campaign ID。旧实现先按 campaign ID 聚合源表，之后匹配后台账本，会把旧系统同 ID 的数据混入后台人员。

只读证据包括：旧系统 `ads_post_auto_publish_logs.id=128816` 的原始链接使用 `af_c_id=36`、Page `893700447168537`、素材 `9227659017`；AI 后台任务 `36` 的冻结链接却属于 Page `907861945751899`，且任务失败、没有 Graph Post ID。ID `6`、`58` 在 AI 后台虽然成功发布，源表还混有旧系统其他 Page/素材的效果，单加“发布成功”过滤仍不能隔离。

因此来源与用户归属分开验证：

1. 从 AI 后台已冻结发布证据读取真实 URL 的 `af_adset_id`（Page ID）、`af_ad_id`（素材 ID）。不修改归属账本或发布记录。
2. Facebook 原始效果先按日期、campaign ID、Page ID、素材 ID读取，防止提前聚合混入旧系统。
3. 只有 source IDs 与成功发布的冻结链接相符，且确认发布时间不晚于效果日期，才进入本日报。
4. 用户归属仍由站点内 campaign ID 的全局唯一冻结用户决定；campaign 名称、人名和 af_channel 不参与用户归属或来源判断。范围过滤不能消除原有跨用户冲突。
5. YouTube 手动短链保留；X/FB 的 manual 表示手动发布，仍须有成功发布记录。

新边界通过内部 `ai_backend_only=True` 传给共享采集器，仅在独立日报 release 启用；未重启/修改主 API 的线上口径。卡片按钮改为“打开社媒后台”，不将仍使用旧范围的后台页面标成这份卡片的同口径明细。
