# BUG-001 日语 `jp` / `ja` 历史代码不一致

## 发现阶段

需求分析与生产只读审计。

## 现象

生产 X Auto 日语模板语言为 `jp`，素材历史也出现 `ja`；若账号下拉只存标准 `ja` 并按字符串相等比较，现有日语模板会认为账号不匹配。

## 复现步骤

1. 模板语言设为 `jp`。
2. 账号语言设为 `ja`。
3. 直接字符串比较模板与账号语言。
4. 返回不匹配。

## 期望结果

历史 `jp` 与标准 `ja` 对路由等价，新持久化统一为 `ja`，历史冻结模板不改写。

## 实际结果

初始直接比较方案会拒绝现有日语模板。

## 根因分析

历史业务数据使用非标准别名 `jp`，新需求采用语言标签但未定义别名规范层。

## 修复说明

新增共享语言规范化：小写、下划线转连字符、主标签 `jp -> ja`；所有路由比较调用同一 helper，X Auto 历史模板保持原 JSON/hash/version。

## 影响文件

- `features/x_accounts/language.py`
- `features/x_auto_posts/service.py`
- `features/x_auto_posts/publisher.py`
- `features/x_posts/service.py`
- 两个调度脚本及相关 UI/测试

## 验证命令与结果

`python -m unittest scripts.test_x_account_language_routing`：6/6 通过。

## 回归结论

已修复；`jp` 模板可使用 `ja` 账号，`en` 与 `ja` 仍严格隔离。
