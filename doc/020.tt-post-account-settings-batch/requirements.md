# 020.tt-post-account-settings-batch 需求与技术设计

## 背景

“TT 个号管理”已支持逐个账号维护观看范围、互动偏好和内容披露。当前账号量较多，运营需要把同一组策略一次应用到多个 TikTok 个号，避免重复进入每个账号保存。

## 目标

1. 在现有个号管理页增加批量选择与批量设置模式。
2. 一次提交把同一组账号级策略原子保存到多个账号。
3. 批量保存前逐个读取 TikTok 最新 `creator_info`，只允许使用所有目标账号共同支持的能力。
4. 保留每个账号独立的乐观版本控制，任何账号冲突或不兼容时整批不写入。

## 范围

### 包含

- 批量模式、全选当前结果、选择全部待配置、清空和选中数量。
- 最多 50 个目标账号的批量实时能力检测。
- 共同隐私范围、评论、Duet、Stitch 能力交集。
- 共享设置表单与原子批量保存。
- 每个账号独立 `expected_version`。
- CPU sidecar、AI 后台同源代理、审计摘要、自动化测试和生产关闭态验收。

### 不包含

- 不修改 TikTok App 内的账号隐私或互动权限。
- 不批量修改 Profile/Bio，也不读取或返回 Token。
- 不修改发布池、GPU 制作或 TikTok 发布协议。
- 不开启 Direct Post 门禁，不创建发布任务或真实 Post。
- 不提供“部分成功”模式。

## 用户故事 / 业务规则

1. 运营可进入批量模式，勾选多个当前允许发布的账号。
2. “全选当前结果”只选择当前搜索过滤结果；“选择全部待配置”只选择当前列表中 `configured=false` 的账号。
3. 选择发生变化后，已有能力检测结果立即失效，必须重新检测。
4. 批量检测必须验证所有目标账号仍存在且允许发布，并逐个调用实时 `creator_info`。
5. 隐私下拉只显示所有账号 `privacy_level_options` 的交集，顺序固定。
6. 只有所有账号都允许时，评论、Duet、Stitch 开关才可开启；任一账号不允许则该开关置灰。
7. 批量表单不从首个账号静默继承设置，观看范围必须手动选择，互动和披露默认关闭。
8. 提交包含目标账号 ID 与各自当前版本。未配置账号版本为 0，已配置账号使用当前版本。
9. 服务端在提交时再次读取所有账号实时能力，然后在一个 SQLite 事务内检查全部版本并保存。
10. 任一实时检测、字段校验或版本校验失败，整批 0 写入。
11. 成功后每个账号版本独立加一，页面刷新配置统计并退出批量模式。
12. 单账号保存能力保持兼容。

## 交互与流程

1. 点击“批量设置”进入批量模式。
2. 勾选账号，或使用“全选当前结果”“选择全部待配置”。
3. 点击“检测并设置”，页面显示检测进度。
4. 服务端逐个确认账号身份与能力，返回共同能力和各账号当前版本。
5. 运营填写一份统一设置并点击“批量保存”。
6. 服务端再次检测并执行原子保存。
7. 成功后提示保存数量并刷新账号列表；失败时显示安全错误且不改变任何目标账号。

## 技术设计

### 影响模块

- `features/tt_posts/core.py`：增加原子批量保存。
- `features/tt_posts/service.py`：目标列表校验、并发受限的批量 `creator_info`、能力交集、批量保存。
- `app.py`：新增同源代理、权限与批量审计。
- `static/tt-account-settings.html`：批量选择、检测、统一表单和保存交互。
- `scripts/test_tt_posts_core.py`、`scripts/test_tt_posts_service.py`、`scripts/test_tt_posts_app_contract.py`、`scripts/test_tt_account_settings_ui.py`：新增覆盖。

### 数据结构

不新增表或字段。继续使用 `tt_post_account_setting`，通过一个 `BEGIN IMMEDIATE` 事务检查全部版本并执行多行 INSERT/UPDATE。

### API / 接口

- `POST /api/admin/tt-posts/account-settings/batch/creator-info`
- `POST /api/admin/tt-posts/account-settings/batch`

两者均要求登录、`tt_posts` 权限和同源 JSON。批量上限固定为 50。

### 异常与边界

- 空目标、重复账号、超过 50、未知字段、无效版本：400。
- 账号失效、能力不兼容：409，0 写入。
- 任一版本冲突：409，0 写入。
- 任一 TikTok 实时检测失败：整批失败，不使用过期能力继续保存。
- 服务器异常或事务失败：回滚整批。

## 验收标准

1. 页面支持手动多选、全选当前结果、选择全部待配置和清空。
2. 选择变化后旧检测结果不可提交。
3. 共同隐私和互动能力计算正确。
4. 批量保存成功时所有目标账号写入同一设置并分别更新版本。
5. 末尾账号版本冲突也能回滚前面已执行的更新。
6. 任一账号实时能力不兼容时 0 写入。
7. 单账号保存、发布池读取、队列冻结和门禁行为不回归。
8. API、DOM、日志和 SQLite 不出现 Token。
9. 生产浏览器只读验收不保存真实设置、不创建队列或真实 Post。

## 风险与待确认

- 实时检测会产生多次 TikTok 请求，服务端并发限制为 4，批量最大 50；超时按整批失败处理。
- 目标数量越大，检测耗时越长。页面明确展示检测中状态，AI 后台代理继续使用既有 360 秒安全超时。
