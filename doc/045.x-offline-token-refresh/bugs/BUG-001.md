# BUG-001 x-offline-token-refresh

## 发现阶段

生产账号列表与自然发布前检查。

## 现象

17 个账号在授权约两小时后全部显示“已到期/需要处理”，但其 Token 均包含 `offline.access` 与 Refresh Token；自动任务并未刷新，最终发布直接报 Token 失效。

## 复现步骤

1. 完成 X OAuth 授权并等待 `access_expires_at` 过去。
2. 打开管理员账号列表。
3. 观察 DTO 与列表显示 `status=expired`。
4. 自动 runner 仅发 `snapshot_only=true`；队列发布的 `publish_credentials` 拒绝过期 Token。

## 期望结果

可续期授权仍显示有效，实际执行前自动刷新；只有无法刷新时要求重新授权。

## 实际结果

短期 Access Token 到期被错误等同于账号授权到期，且自动发布链路没有续期动作。

## 根因分析

`status_for()` 只比较 `access_expires_at`，未识别 `offline.access` + Refresh Token；runner 刻意读取快照，发布凭证边界又正确地拒绝过期 Access Token，两者之间缺少按需刷新步骤。

## 修复说明

动态投影可续期授权为 `active` 并暴露安全的 Access Token 子状态；自动 runner 不再 `snapshot_only`；X Auto 在真实任务冻结前校验；队列最终写入前按账号刷新，Refresh Token 原子轮换。
