# 034. TT 自动发布模板：需求与技术设计

## 背景

现有 TT 发布池继续承担当前线上自动发布，不修改其页面、API、SQLite、调度器和发布状态机。新增一套独立的“TT 自动发布模板”系统，由模板按账号语言和两层指标规则自动选择可投放剧与素材，并通过现有 GPU TT Direct Post 能力发布。

## 目标

- 支持创建多个模板，并执行启用、停用、复制、编辑和立即执行。
- 先筛剧、再筛素材；两个层级分别支持 D0 ROAS/消耗范围与排序。
- 根据每个 TT 账号已保存的剧语言筛选，不在模板中重复编辑互动、披露等发布设置。
- 通过独立调度、任务、素材永久账本、指标日缓存和运行记录实现可审计自动化。
- 新系统上线时模板默认关闭；开发和验收不产生真实 TT 帖子。

## 范围

### 包含

- 独立模板、版本、随机计划、运行、账号任务、事件、素材账本和指标缓存。
- 模板固定北京时间时刻和随机 N 次/日两种计划。
- 多账号模板；同账号可属于多个已启用模板。
- 手动执行已启用或停用模板，创建一次异步运行。
- 账号级串行：已开始任务优先；手动任务优先于未开始定时任务；定时任务按到期时间、模板 ID 排序。
- 旧系统五张素材表的只读永久排除，以及 Facebook post 黑名单的实时排除。
- 复用现有账号快照、GPU creator-info/prepare/publish/reconcile 能力和发布门禁。

### 不包含

- 不修改现有 `features/tt_posts`、旧发布池页面或旧任务。
- 不在新旧系统间建立发布互斥锁；并行碰撞由业务测试期规避。
- 不支持题材标签筛选。
- 不允许释放已经冻结的素材；准备或发布失败也永久排除。
- 不在模板中编辑评论、Duet、Stitch、商业披露、隐私等账号设置。

## 业务规则

### 模板

1. 模板名称必填；创建和复制后的模板默认停用。
2. 编辑生成不可变版本，已创建的运行继续使用原版本快照。
3. 启用模板只影响未来调度；停用不取消已创建或执行中的任务。
4. 一个模板可选择多个账号；同一账号可同时绑定多个启用模板。
5. 手动执行必须确认真实执行，并携带预期模板版本与单次点击稳定幂等键；网络未知或 5xx 重试必须复用该键。API 仅入队，不同步等待发布。
6. 文案按模板保存；`{{content_id}}` / `{{contect_id}}` 为可选剧 ID 宏，模板不包含剧 ID 宏时仍可保存和发布；账号语言和发布设置从现有账号设置读取并冻结到任务。

### 时间与顺序

1. 所有计划和业务日按 `Asia/Shanghai` 解释。
2. 固定计划允许一天多个不重复的 `HH:mm`；随机计划设置每日次数并生成当日稳定、不重复时刻。
3. 指标窗口未填写时为最近 7 个完整北京时间自然日；填写 N 时为最近 N 个完整自然日。
4. 剧上线窗口填写 0 表示不限，否则只接受最近 N 天上线的剧。
5. 冷却窗口填写 0 表示不限，否则同一模板在窗口内不得再次选择同一 `content_id`；冷却从素材冻结时开始，模板内跨账号生效。
6. 模板从停用切换为启用时记录 `enabled_at_utc`；调度不得补建早于该时间的计划时刻。同状态重复启用不得移动启用时间。
7. 自动建 run 必须在同一事务内复核模板仍启用、版本仍是当前版本且计划时刻不早于 `enabled_at_utc`；停用或编辑后到达的陈旧 tick 不得建 run。

### 剧筛选

1. 基础条件：`ads_drama_info.app_id=1479`、`release_status=1`、`deploy_time>0` 且不晚于当前时间。
2. 剧语言必须等于当前账号已保存的剧语言。
3. 剧类型使用 `resource_type_v2` 中文枚举多选；该项非必选，未选择时不限制剧类型；不使用题材标签。
4. 剧唯一键和指标维度均为 `content_id`（兼容旧字段拼写 `contect_id` 仅限文案变量）。
5. 黑名单 `type=0` 精确匹配 `series_code`，排除该系列下全部本地化 `content_id`。
6. 按窗口聚合剧下全部素材的 `SUM(spend)`、`SUM(af_revenue0)`；D0 ROAS 为 `SUM(af_revenue0)/SUM(spend)*100%`。
7. 消耗为 0 时 ROAS 为缺失：ROAS 范围不通过，升序/降序均排最后。
8. 范围上下界均包含，多个条件按 AND；排序相同以 `content_id` 二进制升序稳定打破平局。

### 素材筛选

1. 按剧排序依次查找素材；排名第一的剧无可用素材时继续下一剧。
2. 素材来自 `ads_custom_source`，必须为有效视频、HTTPS、语言和剧映射一致，并通过现有严格违规与资源安全校验。
3. 时长使用 `ads_custom_source.video_duration`，按模板的包含式最小/最大范围筛选，并保留 TT 3600 秒硬上限。
4. 素材指标按 `(content_id, material_id)` 聚合，使用与剧层独立的范围、排序字段和方向；相同以素材数字 ID 升序打破平局。
5. 黑名单 `type=1` 精确匹配素材的 `data_source_id`；不得与 `type=0` 集合混用。
6. 旧 TT 五表任一状态出现过的素材，或新素材账本已有的素材，均永久排除。
7. 正式选择在写入素材账本前重新读取黑名单和旧历史，并通过短事务原子冻结；唯一冲突后继续下一个候选。
8. 预览不写素材账本，不产生冷却。

### 指标

1. 默认 `platform=0`，不得隐式合并 `platform=9`。
2. 原始指标按单个完整业务日流式聚合到独立 SQLite generation；读侧只使用 READY active generation。
3. 窗口缺任何一天即失败关闭；READY 且 0 行才代表有效空日。
4. 聚合与比较使用 Decimal；窗口 ROAS必须用总收入除以总消耗，不能平均每日 ROAS。
5. 日常指标在每小时 `:12` 刷新；北京时间 `00:00` 至当日首轮刷新完成前，新完整日窗口失败关闭并按瞬时错误重试，不得回退到旧窗口。模板设置在该时段时允许延后至缓存 READY 后执行。

### 发布安全

1. 当前模板每账号创建一个任务；无候选仅跳过该账号。
2. 素材冻结后，临时失败重试必须复用同一个任务、素材和 GPU job ID。
3. 一旦存在 `publish_id` 或结果未知，只允许 reconcile，禁止重新 initialize/publish。
4. 黑名单、账号快照、指标缓存或旧历史读取失败时，选择失败关闭。
5. 部署后不创建启用模板，不手动执行，不进行真实发布 canary，除非另行获得精确账号和素材授权。
6. 浏览器公开 DTO 不返回源素材 URL、GPU 准备后 URL或黑名单值明细；只返回准备完成布尔值、黑名单计数/哈希摘要和经过域名约束的 TikTok 发布链接。
7. 手动立即执行的同模板版本、同幂等键只允许对应一个 run；前端在未知响应时不得换键重试。

## 交互流程

1. 列表页创建、复制、启停、编辑模板；点击立即执行需二次确认。
2. 编辑页选择账号并显示账号 ID、剧语言、设置可用状态；配置剧规则、素材规则、指标窗口、上线窗口、冷却、时长、排序、计划和文案。
3. 运行页展示触发来源、模板版本、每账号状态、冻结素材、准备/发布/reconcile 结果和错误。

## 技术设计

### 独立边界

- 新模块：`features/tt_auto_posts/`。
- 新 sidecar：`127.0.0.1:18831`，API 前缀 `/api/admin/tt-auto-publish`。
- 新账本：`/mnt/data-disk/tt-auto-post-publisher/tt-auto-post.sqlite3`。
- 新 systemd sidecar、每分钟 scheduler tick、独立有界并发 worker timer/path 和指标 timer；耗时 GPU prepare 不得占用调度 tick，GPU 仍使用现有回环 `127.0.0.1:18830`。
- 新短链文件：`/mnt/data-disk/tt-auto-post-public/s2l/tt-auto/<task_id>.html`，由 `gy.g2flow.com` 的精确只读 location 提供。已生成文件、对应 Nginx route 和永久 ledger 在应用回滚时也不得删除。
- 主 API 仅增加独立代理和权限审计；旧 TT 路由表和实现保持不变。

### 数据结构

- `tt_auto_template`：模板身份、当前版本、启停、`enabled_at_utc` 和审计字段。
- `tt_auto_template_version`：不可变 JSON 配置、哈希、版本号。
- `tt_auto_random_plan`：模板/日期生成的稳定随机时间。
- `tt_auto_run`：一次定时或手动触发。
- `tt_auto_task`：一次运行的一个账号任务及冻结快照。
- `tt_auto_material_ledger`：素材永久唯一冻结和模板剧冷却事实。
- `tt_auto_event`：状态变化与筛选审计。
- `tt_auto_metric_day_generation`、`tt_auto_metric_daily`、active pointer：完整日指标快照。

### 只读依赖

- 旧 SQLite 通过 URI `mode=ro` 和 `PRAGMA query_only=ON` 读取，不实例化 `TTPostStore`。
- 旧排除表：`tt_post_material_pool`、`tt_post_material_intake`、`tt_post_recurring_pool`、`tt_post_queue`、`tt_post_direct_test`。
- 黑名单仅使用 `is_delete=0`、`type IN (0,1)`、非空值，保留字符串身份。

## 验收标准

- 新模板列表、编辑和运行页面功能完整，并通过登录、导航权限、same-origin 校验。
- 两层筛选、指标窗口、空 ROAS、黑名单、永久去重、冷却和稳定排序测试通过。
- 并发抢同素材只有一个冻结成功；失败任务不释放素材。
- 旧池页面、账号设置和 `features/tt_posts` 无差异，旧测试通过。
- 新服务默认发布门禁关闭；首次部署关闭默认验收时模板数量必须为 0，无真实发布。
- 浏览器响应不暴露内部媒体 URL或黑名单值；手动幂等重放与自动启停/版本竞态测试通过。
- GitHub 提交、生产备份、服务状态、健康检查和回滚命令有记录。

## 已确认决策

- 同账号可绑定多个启用模板。
- 统计窗口默认 7 天，可自定义；剧上线窗口和冷却可为 0。
- 黑名单按既有 Facebook post 表严格分型读取。
- 素材一经正式冻结永久排除；预览不冻结。
- 新旧系统无跨系统逻辑互斥，旧系统继续运行。
