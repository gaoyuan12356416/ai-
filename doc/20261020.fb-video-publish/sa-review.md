# SA 需求与架构评审

评审来自实施前 backend、UI权限、YouTube归因三个独立调查。
2026-10-20 全部以下建议纳入用户已批准方案；代码实现仍需单独验证。

| 级别 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 按租户执行锁不能阻止同一真实 Page 跨租户发布 | 占用/unknown 以全局 PageID和素材ID检查；DTO不泄露外租户 |
| P1 | GPU/短链异步结果可能恢复已取消任务 | 写回检查 lease/token/状态，Meta前原子领取 |
| P1 | 预检摘要若只绑定版本容易换配对/文案 | 绑定完整语义、操作人、fresh来源、时间及重复指纹 |
| P1 | 真实短链长度与占位不同，事务后才校验造成部分批次 | 分配账本后整批事务内最终展开和5000字节检查 |
| P1 | 旧自动模型每run/page唯一且依赖启用模板，不能复用 | 独立增量表与worker，保留旧合同 |
| P1 | 同源校验允许缺Origin、API token可能绕Cookie | 独立严格gateway边界，复用可信登录和nav |
| P2 | 预约日额度可能按创建日绕过 | 以北京时间计划发布日期预留独立日额 |
| P2 | 新200条加工吞掉既有GPU容量 | 沿用GPU限额并限制新worker准备并发 |
| P2 | 后序准备更快可能抢先发布 | 领取时检查同Page前序未完成任务 |
| P2 | 只用版本1无法识别删除重建 | config_instance_id + version CAS |
| P2 | 旧工作树覆盖live app/nav丢功能 | 当前在线文件锚点补丁与hash清单，排除GPU |

产品取舍：确认弹窗仅短链占位，最终提交才分配ID。此前“两阶段生成待确认链接”
建议未采用，不实现待确认真实短链批次。
