# BUG-003 静默截断下载未核对声明长度

## 现场证据

- 首次run348副本validate-only在第8项q642返回source_integrity_mismatch，整批未apply，X写入为0；前7项GPU已有ready缓存，不应重复转码。
- 源资源60ab627f30a53d6a65c7e50f0bf96595，pool150，第6集。CPU实际83,863,962字节，SHA256为35b09a092aff4e94c4c5b3d981d4f909a2f0c9174f39f3ff0840ce7e6da5d948。
- 以该SHA重算job得到02e1b4852caf487f5117ae14aa7a2838658db0687e8f22db79297d0c5022c961，与GPU首次失败的job lock一致，证明原CPU请求源完整且身份正确。
- GPU复现GET：Content-Length=83,863,962，但实际6,291,709即EOF，SHA不同；CPU/GPU HEAD/GET ETag一致。
- 证据分别保存在CPU备份q642-source-diagnostic.json与香港GPU/data/x-post-media-repair/diagnostics/20260828-pool-blockers/q642-source-diagnostic.json。不得将这些诊断操作计为成功发布。

## 根因

download_media只在下载前检查声明长度上限，流读取结束后仅判断非空，没有核对实收字节数。分块HTTP读取可能静默EOF，因而把截断文件误作为完整源交给GPU；GPU的独立SHA检查阻止了后续错误处理。

## 修复范围

- 单次下载严格核对最终size与Content-Length，失败保留原目标并清理临时part。
- 仅明确少字节的静默截断最多三次完整GET；正常一次，其他异常不自动重试。不拼接、不换源、不改变X写入幂等/未知结果门禁。
- 既有下载测试补齐截断恢复/耗尽/多字节/临时文件与原目标保护。
