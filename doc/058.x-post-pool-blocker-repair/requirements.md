# 058 X素材/短剧发布阻塞修复

## 背景与已确认事实（2026-08-28）
素材批次363配置19个账号、0队列/0发帖；账号19在批次360日志726留有HTTP503后的unknown。账号8连续Repost HTTP403明确临时锁定，但普通profile verify仍成功。
短剧17个账号各绑定未完剧：16条下一集队列在348(635—647)、350(667—669)因invalid_media_dimensions失败且attempt=0/unknown=0；另1条q533已有原帖成功、目标转发被X锁定。另有11部pending新剧，不能破坏绑定而改投新剧。

## 目标与范围
1. 新排期首轮只隔离明确的账号待核对/已锁定，不让配置中未建队的异常账号阻断正常实际队列。
2. 保留完整配置审计、实际可用账号容量和实际建队账号三个范围；FIFO、语言路由、未完剧绑定不放宽。
3. 短剧保留逐队列deferred发布，首次X写入前下载、检查并最多修复一次，再依据当前Token会员能力和实际时长发布。
4. 创建计划被业务拒绝是已知的零写入结果，保留具体中文原因，不伪装成响应丢失。
5. 仅对16条已证明零尝试的冻结短剧队列按原身份做一次审计修复/恢复；q533/719/726不清错、不重发、不更换账号。

## 不包含
不解锁外部X账号，不自动把HTTP503判为未发出；不重试未知写入、不改发布时间/账号配置/正文；不重建363或其他历史failed_preflight计划。短剧自身needs_review的既有全池保护保留，本次隔离不改变该独立规则。

## 设计与安全边界
- schedule_preflight仅影响排期verify。首轮跳过精确两个code，身份/Token/网络等其他错误仍fail closed；第二轮候选变化整批拒绝，不临时重配。
- 账号暂停来自只读账本，识别target和relay实际动作；原帖成功不等于目标转发成功，profile查询成功不表示解锁；后续确认的对应动作成功才解除历史锁定证据。
- 计划创建在同一SQLite事务内再次验证实际目标和最终relay；实际冻结队列的批次内unknown/429停止规则不变。
- GPU准备在publish_credentials之前；准备后重验目标/源账号及Token/会员/语言，上传仅在原account lock与最终写入fence内执行。
- 媒体修复参数由受控环境启用，校验job/profile/策略、输出SHA/size/probe和140秒或4小时/512MiB上限；冻结身份和路由不改。
- 历史恢复按完整run清单、源资源ID/URL匹配、媒体证据、0 attempt/无ID/无unknown、一次性审计事务执行。141触发器例外不拓宽。

## 验收
离线测试覆盖隔离/漂移/共享relay/FIFO/冻结幂等/媒体修复和恢复拒绝分支；Linux全X回归通过；线上只读preview/health/账本与hash复核；自然timer消费批准恢复的原队列，不制造测试帖子。真实外部发布结果与仅恢复入队分开报告。
