# Mobo report prewarming

Effects report cold income reads cost about four seconds while valid cached reads
cost about 40 ms. A serial timer now refreshes recently viewed financial projections
before their existing 30-second expiry. It learns at most four successfully queried
tenant/user/role/date contexts, and forgets each after five minutes without a real
report request. A first-ever or inactive date range can still require a cold read.
No global user enumeration, financial sync, promotion request or publication occurs.

The timer calls a loopback internal-token-only endpoint. The macro token cannot
call it, and the public dispatch route cannot invoke it. All public requests still
pass the existing Cookie, module and navigation gates; current role/ownership are
part of every data cache key. Receipt/mapping/catalog changes still invalidate the
cache. The original 30-second limit is unchanged, and failures never extend it.
Fresh cached values remain usable while their replacement is being computed.
Clicks are queried on every real request. The UI shows separate income-read and
click-query timestamps, and preserves the concurrently deployed date sorting.

Use `scripts/deploy_moboreels_report_prewarm.py stage FOLDER`, then `apply FOLDER`
from the pushed GitHub checkout. The established scoped switcher checks in-flight
requests and durable Mobo jobs, fences only port 8864 for the switch, and refuses
to interrupt accepted work. Other publishing services are unchanged. Only after
the sidecar is healthy are the read-only warmup units installed and enabled.
The main runtime's older effects mirror has its independently reviewed before-hash
and backup; the running sidecar is the behavioral baseline.

Rollback: `sh FOLDER/rollback.sh`. It disables only the new timer, waits for an
already-running warmup read, and restores the previous code/static files through
the same scoped switch. It never restores financial data, tokens or job ledgers.

Validation covers prewarm expiry, failed refresh, scope/role isolation, bounded
interest, receipt invalidation, fresh clicks, internal/macro authorization and UI
rendering/revocation/refresh behavior. Production acceptance must observe a real
timer refresh after an authorized request and a cache hit past the original expiry.
