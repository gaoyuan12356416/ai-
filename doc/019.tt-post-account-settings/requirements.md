# 019.tt-post-account-settings 需求说明

## 背景

TT Post 发布池首版把隐私、互动、商业披露和 AI 内容声明放在每条任务中填写。运营希望这些长期偏好按 TikTok 个号集中维护，发布池只保留账号、素材、发布时间与当次发布确认。

## 目标

1. 新增“TT 个号管理”页面，按个号编辑发布设置。
2. 发布池移除账号级设置编辑，只读展示当前账号配置。
3. 未配置账号不能创建新任务。
4. 保存设置和创建任务时均读取 TikTok 最新 `creator_info` 并 fail-close。
5. 每条任务仍单独确认 TikTok Music Usage Confirmation。

## 范围

### 包含

- 导航项 `/tt-account-settings.html`，复用 `tt_posts` 权限。
- 账号级观看范围、评论、Duet、Stitch、商业披露和 AI 声明。
- SQLite 账号设置表、乐观版本控制和安全审计。
- 发布池读取账号设置并冻结到新任务。
- CPU sidecar 与 AI 后台同源代理接口。

### 不包含

- 不修改 `tiktok_personal_account_snapshot`，不展示或保存 Token。
- 不反向修改 TikTok App 内的账号隐私或互动权限。
- 不改 GPU 制作、发布、对账协议。
- 不开启 Direct Post 门禁，不创建真实 TikTok Post。
- 不迁移或改写历史队列任务。

## 业务规则

1. 账号来源仍为只读 `tiktok_personal_account_snapshot` 安全快照。
2. 新账号无默认观看范围，互动默认关闭；运营必须手动保存首版配置。
3. 账号设置包含：
   - `privacy_level`
   - `allow_comment`
   - `allow_duet`
   - `allow_stitch`
   - `brand_organic_toggle`
   - `brand_content_toggle`
   - `is_aigc`
4. 商业披露由两个品牌开关派生；开启披露时至少选择一个品牌类型。
5. 保存前必须实时确认所选隐私范围仍可用；TikTok 禁用的互动项不得开启。
6. 更新设置必须携带当前版本，版本冲突时刷新后重试，防止覆盖他人修改。
7. 发布池不得提交或覆盖账号级设置；服务端始终读取已保存配置。
8. 创建任务时再次调用 `creator_info`，账号能力变化时停止入队。
9. 成功入队后，设置快照冻结在任务中；之后修改账号设置不影响历史任务或同一幂等键重放。
10. 当次 Music Usage Confirmation 不能变为账号级长期设置。

## 用户流程

1. 运营进入“TT 个号管理”，搜索并选择个号。
2. 页面实时读取 TikTok 昵称、可用隐私范围、互动能力和最长视频时长。
3. 运营填写设置并保存；服务端再次实时校验并写入新版本。
4. 运营进入发布池选择个号；页面只读显示设置摘要。
5. 运营选择素材和时间，确认当次内容与音乐条款后入池。
6. 服务端再次校验账号能力，将账号设置快照冻结到队列。

## 验收标准

1. 有 `tt_posts` 权限的用户可访问两个页面，无权限用户均 fail-close。
2. 个号管理页可编辑全部账号级设置，并显示已配置/待配置与版本。
3. TikTok 实时禁止的隐私或互动设置无法保存。
4. 并发旧版本保存返回版本冲突，原配置不被覆盖。
5. 发布池不再出现账号级编辑控件，只显示配置摘要和管理入口。
6. 未配置账号无法入池；客户端遗留字段不能覆盖服务端账号设置。
7. 入池任务保存完整设置快照，历史幂等重放不受之后修改影响。
8. 浏览器、API、日志和 SQLite 账号设置表均无 Token。
9. 现有描述模板、素材制作、队列状态机、GPU 协议和关闭态门禁不回归。
