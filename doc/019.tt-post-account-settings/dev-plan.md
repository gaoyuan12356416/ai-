# 开发计划

## 实现步骤

1. Core 增加账号设置值对象、第四张 SQLite 表、查询及版本化保存。
2. CPU service 增加账号配置列表、保存与 `creator_info` 校验。
3. 新建任务改为读取服务端账号配置并冻结，保留幂等历史语义。
4. AI 后台增加 GET/POST 代理、导航权限和安全审计。
5. 新增个号管理页，发布池移除账号级编辑并显示只读摘要。
6. 更新导航缓存版本和权限显示名称。
7. 增加 Core、Service、HTTP、App 与两个页面的自动化测试。
8. GitHub 提交后仅部署 CPU release、静态资源和 AI 后台；GPU 不变。

## 关键约束

- 所有本地编辑使用独立 worktree。
- 发布门禁保持关闭。
- 不创建测试队列，不调用真实发布。
- 部署前备份 SQLite、当前 release 指针和静态文件。
- 部署后验证服务、页面、账号只读列表和数据库完整性。

## 回滚点

- 代码：切回上一 CPU release。
- 静态页：恢复备份的导航、quick-nav 与发布池页面，删除新增页面。
- 数据：新增表向后兼容；回滚应用可忽略该表。只有出现完整性异常时才恢复部署前 SQLite 备份。
