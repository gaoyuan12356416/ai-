# 普通 X 发布退役与短剧频道画像分配

普通自动发布模板、自动发布记录和普通素材池入口下线。已发布历史保留；未发布任务经证据核验取消。普通池未发布素材按素材 ID/规范键、两套池与发布账本、自动任务及手动预约排重后迁入画像池，保留原作者、上传时间和旧队列绑定。未知或已有源帖的记录保持原样，不因迁移重试。

短剧池新增未绑定剧按受众占比、题材条件占比匹配同语言候选频道；缺画像按原顺序兜底。旧连载绑定保留。每日配置和完整频道范围生成冻结映射，单频道随机时段只取自己的分配。原子预约再校验绑定、集数和映射。现有关闭的短剧排期不自动开启。

## 实施与验证

- `scripts/x_profile_retirement.py dry-run` 默认四库只读，输出逐项计划和证据哈希；`apply` 校验计划、备份、分阶段取消与迁入。中断后原计划可重入，不删除回执或永久预约。中心 pipeline 的 canonical queue/log failed 会阻止后续操作，不清除历史 claims。
- 对正在上传但尚无 Post 意图的个别任务，先冻结父任务并保留非空退役错误，再待节点结束，依据所有代次仅媒体初始化/分块请求的证据单独结算；不能把普通未知写入视为零。
- `scripts/test_x_profile_retirement.py`、`test_x_drama_profile_assignment.py`、`test_x_legacy_publish_retirement.py` 及相关 UI/runner 回归覆盖取消、跨库竞争、重入、原绑定、单频道隔离、缺画像兜底和权限边界。
- 本发布使用已核对的生产 composite 作为测试与部署基础。Git 中改动文件是精确覆盖层，不整仓替换线上；主后台原 `service.py` 与画像发布运行时保持各自版本。

## 部署

先推送 GitHub 精确提交，服务器 fetch/checkout 该提交到独立 source，再运行：

```sh
python3 SOURCE/scripts/deploy_x_profile_retirement.py stage --source SOURCE --commit COMMIT --root DEPLOYMENT
python3 SOURCE/scripts/x_profile_retirement.py dry-run --ordinary-post ORDINARY_POST --ordinary-auto ORDINARY_AUTO --profile-post PROFILE_POST --profile-auto PROFILE_AUTO --manifest PLAN
python3 SOURCE/scripts/x_profile_retirement.py apply --manifest PLAN --backup-directory BACKUP
python3 SOURCE/scripts/deploy_x_profile_retirement.py apply --root DEPLOYMENT
```

必要的已核验媒体初始化失败 ID 只能通过 dry-run 的重复 `--reviewed-no-post-queue-id` 冻结；apply 不接受临时追加。真实 IDs、计划、凭据及备份仅保存在服务器私有任务目录，不进入 Git。

普通 sidecar 从服务端既存画像凭据配置 `X_DRAMA_PROFILE_INTERNAL_TOKEN`，不输出凭据。新增画像依赖模块只覆盖普通 runtime 的明确清单；主后台部署退役过滤模块与静态页面，两个静态目录一致。普通自动触发器永久禁用；普通素材池配置保持关闭。共享短剧计划触发器在旧素材任务取消后恢复，短剧本身保持原 disabled 设置。部署前后保存并恢复影响范围内调度器状态，保留退役触发器的关闭意图。

## 回滚

```sh
python3 SOURCE/scripts/deploy_x_profile_retirement.py rollback --root DEPLOYMENT
```

此操作仅恢复代码及本次环境配置，要求当前文件仍等于本次发布结果。业务取消、素材迁入与所有最新平台回执继续保留；不得覆盖整库或重新启用已退役发布流程。
