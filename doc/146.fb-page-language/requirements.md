# 146.fb-page-language 需求与技术设计

## 背景与目标

2026-09-18 用户要求：完成 145 Page 容量修复后，移除模板语言配置，按每个 Page 在 Page 池中的语言选择剧和素材，再发布。

## 业务规则

1. 模板编辑页移除语言字段，保存请求不再携带该字段；说明文字明确语言来自 Page 池。
2. 对 Page 语言去首尾空白、转小写、下划线转连字符，再应用已有语言别名；通过既有语言格式规则后使用。
3. 同一运行按唯一有效语言读取候选快照，每种语言只读取一次；Page 只能从自身语言的候选中选择。
4. 剧、素材、描述与发布链接使用最终选中的素材；产品、指标、时长、类型、排序、冷却和授权规则继续生效。
5. 空或格式无效的 Page 语言跳过该 Page，记录 `fb_auto_page_language_missing`；本语言无素材记录 `fb_auto_no_eligible_video`。均不能使用模板语言或其他 Page 的语言兜底。
6. 旧模板版本中的 `language` 可读取，但计划器忽略它；新建和更新模板产生的配置不保存 `language`。
7. Page 二次检查出现尚未读取快照的新语言时，使用 `fb_auto_page_language_changed` 延后整次规划，禁止部分落账。
8. 已建立运行的任务、Page 语言、素材、短链、发布结果和历史账本保持冻结。未来运行按规划时的 Page 语言处理。
9. 如扩充已建立的未来运行，只新增该运行缺少的 Page，冻结新增 Page 的语言，保留已有任务 ID、素材和账本；精确范围与执行证据由部署负责人记录。

## 技术设计

- `features/fb_auto_posts/languages.py`：Page 语言规范化、每种语言的候选快照、异常候选的语言隔离。
- `core.py`：按 Page 选材、语言快照、错误原因与指标代次合并；保留既有容量、租约、去重和历史保护。
- `repositories.py`：接受计划器专用 `_candidate_limit`，按冷却占用量保留充足的精确排序候选；公开模板请求不能设置该值。
- `pool_extension.py`：对精确未来自动运行追加缺失 Page，整批事务及独立回执保证失败回滚和幂等。
- `validation.py`：旧字段兼容输入、新版本省略字段。
- `static/fb-auto-publish-template.{html,js}`：删除语言控件、读取和提交逻辑，更新资源版本。
- 沿用 `fb_auto_run_page.language` 保存本次规范化语言；运行扩充按需创建独立回执表 `fb_auto_pool_extension`，不修改既有表结构。

## 候选数量与排序保证

多语言会放大素材仓库查询成本。规划使用 `min(5000, max(500, 最大Page冷却/占用数量 + 100))`，扩充时再预留本次运行数量。仓库仍取得精确排序前 N，选择器仍在排除占用后前 50 项内随机选择；因此保留数量至少为占用数量加 50 时，选择范围不变。写事务内复查占用增长，越过保证边界时延后重试，不能静默缩小可选集合。

## 验收标准

- 英语、西语等混合 Page 池能分别选中对应语言的剧、素材和描述。
- 同语言别名合并为一次候选查询；候选适配器错误返回其他语言素材时将其剔除。
- 无语言、无素材、无 Token 均有可区分原因；不触发错误语言任务。
- 保存不依赖模板语言；旧配置可加载，旧运行重复规划返回原运行。
- 新增独立测试通过；既有 FB 回归、前端验证、未来运行扩充和部署证据由主任务补齐。
