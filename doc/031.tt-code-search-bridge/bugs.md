# 缺陷登记

## 当前状态

尚无已确认产品缺陷。代码、自动化和生产实测均未完成，因此不能据此断言“零缺陷”。

## 登记规则

- 每个经复现确认的缺陷使用独立编号 `BUG-001`、`BUG-002`……。
- 必须记录发现阶段、环境、现象、最小复现、期望/实际、严重级别、根因、修复 commit、验证命令和回归结论。
- 未复现的风险或评审意见保留在 `sa-review.md` / `sa-code-review.md`，不伪装成已确认 BUG。
- 若缺陷内容较长，可新增 `bugs/BUG-xxx.md`，并在本表链接；本文件作为总登记。

## 发布阻断条件

- 任一 P0/P1 缺陷未关闭。
- code 普通碰撞错误触发历史回收。
- Redis 故障导致错误 404/旧路由。
- 横向拖动仍触发卡片跳转。
- 原 `/tt` 文件、路由或行为发生未授权变化。
- 验收路径需要真实 TikTok 发布才能证明功能。
