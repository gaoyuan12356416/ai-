# Facebook Page 素材池开放规则（2026-11-06）

用户明确取消 Page 素材池的删除状态、目录视频时长/地址、单次添加数量、队列/历史重复、旧任务未知结果、文案及剧名/简介限制。此前已取消产品和 Dramawave 同语言上架剧目门槛。此规则仅作用于 source_kind=pool，不修改 group_pool 或其他平台规则。

每条输入生成独立入池记录，重复素材也保留原顺序。每次添加操作继续幂等；重试同一次提交不新增。独立任务可以再次使用已发布或结果未知的素材。原未知任务保留原回执与核对流程，不能作为同一次请求再次发送。Page 同时只允许一个实际写入，已存在任务/真实平台响应不重置。

空文案、缺失剧名/简介、未知宏和长文案可继续，缺失宏字段为空，短链归因剧名使用 none 占位。目录中失效或空视频地址、异常时长不拦截入池，实际下载、加工、平台发布失败如实显示。加工支持普通 HTTP/HTTPS 源地址，不再限定来源域名；传输协议及媒体解码仍遵守实际工具能力。素材 ID、存在性、视频类型、来源类型、剧集 ID、语言配对和发布身份权限仍校验。

数据库仅移除待发布/处理中素材唯一索引，并放宽 Page 池跨任务冲突触发器。调度占用改为任务维度，发布仍保留 Page 写入互斥。迁移在在线账本副本上验证任务、入池项、时点、尝试和链接记录逐字未变。

部署：GitHub 提交后，CPU 运行 scripts/deploy_fb_pool_open_policy.py prepare/activate --folder /mnt/data-disk/...；脚本按差异合并实际运行版本，保留并行修复，备份账本和文件。只切换 FB/协调器 HTTP 服务并核对对应调度依赖。主 API 和公开静态文件无需重启。

加工节点运行 scripts/deploy_fb_pool_render_policy.py，按 GitHub 差异更新单个模块；仅对准备子进程发送正常退出信号，完成当前任务、写回回执后由主进程补充，发布子进程不切换。备用 FB GPU HTTP 服务仅在无请求时切换。

代码回滚：使用同一 source 下 scripts/deploy_fb_pool_open_policy.py rollback --folder DEPLOYMENT。旧版本重新施加严格约束，须先让受影响 Page 池待处理项结束并核对未知任务，脚本不会清空队列或恢复数据库。放宽后的加工模块兼容旧请求，可保留；如需恢复，按 render manifest 的 before.py 正常回滚并完成同样的局部排空。所有当前账本、凭据、外部回执保留。

验证：scripts.test_fb_pool_open_policy、scripts.test_fb_pool_any_product、scripts.test_pipeline_fb_task_isolation、scripts.test_pipeline_fb_source_locks；前端 node --check。覆盖 205 条同 ID、独立再次添加、同一次添加重试、空/长文案和缺字段、旧未知不阻塞新任务、同任务不可重发、Page 并发互斥、实际原生执行策略和中央调度占用。
