# SocialKit refresh writer recovery

The November 13 report remained on an earlier complete snapshot after repeated
refresh failures. A scoped one-day run isolated MySQL error 2013 in
`WarehouseWriter.write_day -> executemany -> _read_bytes`: the writer's 15-second
response deadline expired. The current manifest correctly remained unchanged.

Fact writes now use 100-row batches and a 60-second response timeout. Only
transport errors 2006/2013 permit up to two retries, after 2/5 seconds, on a new
connection with the existing `ads_ai/read_only=0` identity check. Each retry
replays the same frozen version, row keys and absolute-value upsert, including
when a commit reply was lost. It cannot increment metrics twice. Auth, SQL,
permission and lock errors still fail the refresh. Source collection, attribution,
replica control verification and atomic snapshot publication are unchanged.

Validation: warehouse tests cover connection loss before writing, an acknowledged
write with a lost commit reply, exhausted retries, excluded errors and reconnect
identity. Existing data tests cover source controls, failed-publication retention
and replacement of a recalculated day while preserving earlier history.

After committing/pushing, check out the exact GitHub commit under
`/mnt/data-disk/socialkit-analytics/releases/<commit>` and run
`python3 ops/socialkit-analytics/install_refresh_writer.py --apply` there.
The installer switches `/opt/socialkit-analytics/current` only. It retains the
previous immutable release and records the rollback manifest. No API, publishing
service, timer or notification changes/restarts are needed. Existing refresh
processes finish against their original release; new runs use the new release.

Run a scoped `features.socialkit_analytics.refresh --start 2026-11-13
--end 2026-11-13` through systemd with `/etc/socialkit-analytics.env` and the
existing `/run/lock/socialkit-analytics-refresh.lock`. Preserve the internal
refresh lock and verify the newly published manifest, per-day controls and API
query totals. Direct refresh does not send notifications.

Rollback from the installed release:
`python3 ops/socialkit-analytics/install_refresh_writer.py --rollback <manifest>`.
This restores the previous release pointer only; current snapshots, warehouse
facts, credentials and publication receipts remain intact.
