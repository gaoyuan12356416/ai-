# 031 TT Post 剧语言路由需求与技术设计

## 背景

TT Post 自动发布沿用 028 的账号分池模型：素材校验通过后，系统先按素材 ID 在自动发布账号中稳定分配一个账号，后台预制作和正式调度随后只在该账号的素材分片中工作。该模型未使用素材已经具备的 `material_language`，因此无法保证最终领取素材的账号与剧语言一致。

本需求继续保留“素材校验通过即可入池、账号能力延迟到真正发布前检查”的边界，同时增加账号剧语言设置和自动发布时的动态语言路由。

## 目标

- TT 个号管理支持设置 `drama_language`；未填写、旧请求缺失或旧数据为空时统一按 `en`。
- 自动调度到期时，按账号当前剧语言从全池原子领取同语言最老的可用素材。
- 没有同语言账号或没有同语言素材时保持等待，不跨语言降级，不误发。
- 后台预制作状态明确展示每条素材的剧语言和是否已经被账号领取。
- 保留已有队列、发布 ID、立即发布测试、预制作和 TikTok 网络发布安全边界。

## 范围

### 包含

- 个号单条和批量设置的剧语言输入、回填、展示、版本控制和审计摘要。
- SQLite 账号设置表增量字段和旧数据默认值。
- SQLite recurring pool 增量规范路由键、历史回填和语言 FIFO 索引。
- 素材语言与账号语言统一规范化。
- 自动调度跨原账号分片、按语言独立 FIFO 的原子领取。
- 领取时把素材池 `account_id` 和 `is_aigc` 更新为实际目标账号的当前设置。
- 后台预制作状态“剧语言”列及待领取文案。
- 单元、服务、并发、迁移、前端契约和回归测试。

### 不包含

- 不改变 Dramawave 素材身份、违规、剧目映射和视频时长校验规则。
- 不让素材入池或后台预制作重新依赖 Creator Info、Token 或实时账号能力。
- 不为立即发布测试自动更换账号；测试仍使用操作人明确选择的账号和素材。
- 不重选已经生成的 queue，不重试或重选已经取得 `publish_id`、结果未知的任务。
- 不增加新的素材“待匹配”状态；现有 `available` 即表示可继续等待领取。
- 不做 `en` 与 `English`、`pt` 与 `pt-br` 等别名或父子语言回退。
- 本需求验证不创建真实 TikTok Post。

## 用户故事 / 业务规则

1. 运营人员可在 TT 个号管理中填写剧语言；默认显示 `en`，支持单个和批量保存。
2. 语言规范化规则为：去除首尾空白、Unicode `casefold`、下划线改为连字符；空或缺失取 `en`；总长度 1 至 32；各连字符分段只能由字母或数字组成。规范化后做精确相等匹配。
3. 新素材语言来自已校验的 `ads_custom_source.language`，并已经与剧资源语言核对。历史空 `material_language` 只在路由和展示时按 `en`，不把未知语言回退到其他账号。
4. 素材校验通过后，即使当时没有同语言账号，也可进入 intake、完成预制作并保持 `available`。
5. 自动排期到期时，以目标账号当前 `drama_language` 为条件，在整个 `tt_post_recurring_pool` 中领取同语言最老的 `available` 素材；FIFO 顺序为 `created_at,id`。
6. FIFO 按规范化剧语言独立计算。某种语言没有账号不会阻塞其他语言，但同一语言不得跳过更老的可用素材。
7. 自动领取必须在一个 `BEGIN IMMEDIATE` 事务内完成运行去重、候选查询、运行创建和素材 `reserved` 更新。两个同语言账号并发时，同一素材最多被一个运行领取。
8. 自动领取成功后，同一事务把素材池 `account_id` 更新为实际账号，并把 `is_aigc` 更新为该账号当前设置；`tt_post_schedule_run.account_id` 和后续 queue 使用同一实际账号。
9. 没有同语言素材时，本时间槽记录为安全跳过或返回池空语义；不得领取其他语言，不创建 queue、短链或远端发布。
10. 已经生成 queue 后，账号、素材和语言快照保持冻结。配置后改不重写 queue；已经取得 `publish_id` 或未知结果的任务只允许核对。
11. 手动立即发布和一次性 canary 继续按精确账号、精确素材池记录执行，不使用跨池语言路由，也不自动换号。
12. 自动配置中账号仍须可信并拥有本地发布设置；素材入池和预制作仍不调用 Creator Info。

## 交互与流程

### 个号设置

1. 打开 TT 个号管理并选择一个或多个账号。
2. 系统回填保存值；无值显示 `en`。
3. 用户可输入例如 `en`、`es`、`pt-br`，也可输入符合格式的其他语言标签。
4. 保存时沿用账号设置乐观版本；冲突时整次保存失败并要求刷新。

### 素材与自动发布

1. 用户输入素材 ID，服务只读校验真实 Drama ID 和素材语言。
2. 校验通过后立即写入 intake；没有匹配账号不阻断入池和预制作。
3. GPU 预制作完成后素材进入全池 `available`，预制作表显示剧语言和“等待同剧语言账号领取”。
4. 自动账号到期时读取其当前剧语言，在事务内领取该语言最老素材并冻结实际账号。
5. 发布前继续执行 Creator Info、Token、账号设置、视频时长、合规和幂等门禁。

## 技术设计

### 影响模块

- `features/tt_posts/core.py`：语言规范化、账号设置模型/表迁移、自动领取 SQL 和事务冻结。
- `features/tt_posts/service.py`：账号设置 API、自动/手动领取边界、目标账号设置传递和响应字段。
- `app.py`：单条/批量账号设置审计字段。
- `static/tt-account-settings.html`：剧语言输入、回填、批量设置和账号列表摘要。
- `static/tt-post-pool.html`：预制作状态剧语言列、领取账号和待领取文案。
- `scripts/test_tt_posts_core.py`、`scripts/test_tt_posts_service.py`、前端与代理契约测试。

### 数据结构

`tt_post_account_setting` 增量增加：

```sql
drama_language TEXT NOT NULL DEFAULT 'en'
```

- 新库建表直接包含该列；旧库启动时通过幂等 `ALTER TABLE` 增加。
- 旧账号设置行自动得到 `en`。
- `tt_post_recurring_pool` 增量增加内部 `routing_language TEXT NOT NULL DEFAULT ''`；迁移按同一规范函数回填，非法历史值写隔离键，不参与自动匹配。
- 建立 `(status,routing_language,created_at,id)` 复合索引；对外仍只返回 `material_language`，不暴露内部路由键。
- 不新增 queue/run 状态列；`account_id`、`is_aigc` 和 `tt_post_schedule_run.account_id` 表达领取结果。
- 历史空素材语言在比较和页面展示时规范为 `en`。

### API / 接口

- 账号列表的 `account_settings` 增加 `drama_language`。
- 单条与批量账号设置请求接受 `drama_language`；缺失或空值按 `en`，响应回显规范值。
- 素材校验和素材池响应继续使用 `material_language`。
- 自动 schedule/run/publish 的外部请求结构不增加可由客户端覆盖的账号或语言字段；语言从服务端已保存设置和素材记录读取。
- 立即发布测试接口结构不变。

### 自动领取算法

新建自动运行时：

1. 读取并规范化目标账号当前 `drama_language`。
2. 在写事务中按复合索引查询 `status='available' AND routing_language=?` 的首行，按 `created_at,id` 排序；不扫描或在 Python 中物化全池。
3. 创建 `tt_post_schedule_run`，原子把素材改为 `reserved`，并同步实际 `account_id`、目标账号当前 `is_aigc`。
4. 若候选不存在，事务不修改任何素材，不创建 queue。
5. 恢复已有 run 时继续使用已冻结的 pool/run，不因账号语言后改重新选材。

手动运行仍使用旧的 `account_id=?` 分池查询，确保显式目标不被自动路由改写。

### 异常与边界

- 无同语言素材：安全等待，不 fallback，不消费其他语言素材。
- 同语言并发：写事务串行领取，第二个账号领取下一条或安全跳过。
- 账号语言在未领取前变化：下一次自动领取使用新值。
- 账号语言在 run/queue 形成后变化：已有任务继续按冻结身份恢复，不重选。
- 历史空账号/素材语言：仅按 `en`；非空不做猜测或别名转换。
- 非法历史素材语言：保留显示并写隔离路由键，不阻塞其他合法语言素材。
- 语言格式不合法或超过 32 字符：账号设置请求失败，不修改版本或现有设置。
- 自动领取后的任一步骤在远端创建前失败：沿用现有预检释放、失败审计和 FIFO 恢复机制。

## 验收标准

- 旧库可重复迁移，完整性检查通过，旧账号语言为 `en`。
- 个号页单条和批量设置可保存、回填并显示剧语言；缓存旧请求缺字段不会产生空值。
- 无同语言账号时，素材仍能完成预制作并保持 `available`，没有 queue 或 Post。
- 自动账号只领取规范化语言完全相等的最老素材；无跨语言 fallback。
- 两个同语言账号并发不会领取同一素材；每种语言 FIFO 顺序稳定。
- 领取时 pool、run、queue 的实际账号一致，queue 的 `is_aigc` 来自目标账号当前设置。
- 旧空素材只匹配 `en` 账号。
- 已存在 queue、`publish_id`、未知结果不重选账号或素材。
- 立即发布测试保持显式账号和精确素材，不自动换号。
- 后台预制作表显示剧语言，未领取素材显示等待文案，100% 缩放布局不回归。
- 全部验证使用临时 SQLite、fake 账号/GPU/TikTok；不创建真实 TikTok Post。

## 风险与待确认

- 动态跨池领取改变 028 的账号分片含义；所有按账号计算的可用数、列表文案和测试必须同步更新。
- 上线前需在生产副本确认语言 FIFO 复合索引的查询计划和实际领取查询耗时。
- 已生成 queue 的冻结优先于配置后改，这是防重复发布要求，不是即时撤销机制。
- 无产品待确认项；动态匹配、无匹配等待、旧空值 `en`、立即测试不换号已确认。
