# BUG-002 候选机旧 SQLite 无法执行测试 DROP COLUMN

## 发现阶段

生产候选 release 的隔离测试，尚未切换线上 release 或服务。

## 现象

候选机 Python 绑定的 SQLite 不支持 `ALTER TABLE ... DROP COLUMN`，两条“模拟旧库缺列”的测试报语法错误；其余 370 项通过。

## 影响判断

生产迁移代码只使用兼容的幂等 `ADD COLUMN`、回填和索引创建，不执行 `DROP COLUMN`，因此线上数据库未受影响。失败仅来自测试构造旧表的方式，候选目录已自动清理，线上仍保持原 release。

## 修复

测试改为通过 `PRAGMA table_info` 重建不含目标列的临时旧表，再运行真实增量初始化。该方式保留主键、默认值和显式索引，并兼容候选机旧 SQLite。

## 验证

- 两条迁移定向测试本地 2/2 通过。
- 完整 TT Python 回归 372/372、Drama bridge 53 项通过。
- GitHub 精确提交 `af95ea73d95b883e591318c7e0ab09cfeb4716e4` 在候选机实际 Python/SQLite 环境通过 372/372 和 Bridge 53 项，随后才切换生产。

## 状态

已关闭；首次失败未触及线上，兼容修复通过候选复验后已部署。
