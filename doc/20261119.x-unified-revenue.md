# X 画像与运营统计统一收入

账号列表原先从充值账单读取收入，每天北京时间 10/11/12 点更新；画像从社媒效果数仓读取收入，每小时更新。两套来源、日期和快照可能互不一致。

现在两栏统一读取已验证的社媒效果数仓，使用既有精确 campaign 归属、已确认发布边界和整数分金额。收入统计至前一个完整 UTC 日；累计收入和该日收入分别汇总。Post/Repost 保留既有发布账本及北京时间昨日计数，随同一批刷新。页面明确标出收入 UTC 日期和发布计数北京时间日期。

画像生成同时保存运营统计到同一不可变 SQLite。原运营统计缓存路径通过符号链接指向画像 serving/current.json，只有一个原子版本指针。发布前校验每个账号的累计/昨日金额与画像一致、版本和时间一致。账号列表将版本传给画像列表和详情，晚返回的旧请求不能覆盖新批次。失败时保留上一完整批次；源数据缺失不发布为零，归因未匹配金额继续单列。

画像标签查询每批由 100 个剧目改为 25 个；只读查询遇到 3024/1317 超时按范围二分重试，单个 ID 仍失败则保留上一批，其他数据库错误不掩盖。错误日志仅记录阶段和安全错误码。2026-11-19 10:20 的旧日志只有 RuntimeError，无法确定原始数据库错误码；后续旧任务自行成功，不能声称已追溯确定根因。

调度统一沿用 x-channel-tag-revenue-refresh.timer（北京时间每小时第 20 分）；停用旧 x-account-operating-stats.timer。兼容刷新脚本调用同一个带锁生成器，不再单独查询账单或覆盖运营统计。

## 验证

运行 scripts/test_x_tag_revenue.py、scripts/test_x_unified_revenue.py、scripts/test_x_tag_revenue_ui.js、scripts/test_x_unified_revenue_ui.js。新增覆盖日期截止、重复/冲突归因、收入守恒、原子发布拒绝不一致金额、坏数据不显示零、统一失败提示、超时拆批、版本固定及前端竞态。

## 部署和回滚

从已推送提交检出独立工作树，执行：

```sh
python3 scripts/deploy_x_unified_revenue.py prepare --directory /mnt/data-disk/x-unified-revenue-20261119/candidate
python3 scripts/deploy_x_unified_revenue.py install --directory /mnt/data-disk/x-unified-revenue-20261119/candidate
```

prepare 使用当前线上依赖读取真实数据，只在隔离目录生成验证结果，不推进生产 SQL 指针。install 核对提交、源新鲜度及线上文件基线；备份受影响代码、页面、旧缓存和 timer 状态。主 API 重启保留既有在途上传 drain；仅重启主 API 和画像读服务，核对并恢复受影响的 YouTube/coordinator 调度状态。发布服务、发布账本和账号凭据不变。HTML 使用幂等局部补丁，保留列表其他并发功能。

按 install 返回的备份路径回滚：

```sh
python3 scripts/deploy_x_unified_revenue.py rollback --directory /mnt/data-disk/x-channel-tag-revenue/unified-backups/TIMESTAMP
```

回滚校验文件未被后续版本改动，恢复原代码、运营缓存及 timer 状态，保留生成的画像快照和业务记录。
