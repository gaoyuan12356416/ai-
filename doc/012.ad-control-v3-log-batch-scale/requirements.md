# V3 执行日志合并展示与查询保护

## 目标

1. 同一次计划调度产生的“预检观察记录”和“正式执行记录”在列表中只展示一个正式执行批次。
2. 保留底层 Preview、观察执行和正式执行审计数据，不改写历史记录。
3. 首次进入固定读取 20 条；API 单页最多 100 条，执行日志最多访问第 1000 页。
4. 日期区间筛选最多 93 个自然日，避免误提交超大范围筛选。
5. 为管理员时间倒序、Preview 配对以及对象/动作/产品筛选补充索引。

## 合并规则

仅隐藏同时满足以下条件的观察记录：

- `run_mode=observe`；
- `trigger_source=schedule`；
- 存在相同 `preview_id` 的 `run_mode=live + trigger_source=schedule` 正式执行记录。

手动试算、真正的观察模式，以及尚未产生正式执行记录的失败预检仍独立展示。

## 数据保留边界

本需求不自动删除审计数据。建议后续采用“热数据 180 天 + 归档校验后分批删除”的策略；保留期、归档位置和审计要求需另行确认后才能启用。复制关系、created_data 和绩效关联数据不属于日志清理范围。
