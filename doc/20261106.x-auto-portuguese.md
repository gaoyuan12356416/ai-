# X Auto Portuguese catalog matching

X Auto tasks freeze the account language `pt-br`, while the source catalog uses
`pt`. Exact SQL equality returned no dramas. The catalog repository now queries
both spellings and normalizes in-memory selection rows to `pt`. The strict
resolver uses the same selection normalization. Stored account and task
languages are unchanged; existing publisher language comparison already treats
`pt` and `pt-br` as aliases. Other regional tags remain distinct.

The deployed `drama_status=3` filter is retained from the current runtime even
though it was absent from the source baseline. Duration, readiness, spend/ROAS,
blacklist, reservations and global material history checks remain in force.

Validation:

```
python -m unittest scripts.test_x_auto_portuguese scripts.test_x_auto_post_metrics scripts.test_x_auto_post_selector scripts.test_x_auto_no_candidate_recovery -q
```

Deploy a clean GitHub checkout with `scripts/deploy_x_auto_portuguese.py`.
It backs up both ledgers online, records and restores X scheduler health,
overlays only the catalog repository and restarts only an idle X Auto service.
It refuses to interrupt active Auto tasks; independent X publication and other
channels continue. The main API does not load this catalog reader.

Rollback: run the same script with `--rollback BACKUP_FOLDER`. This restores
only the previous repository module. Never restore old ledgers after a recovery
or publication; all receipts, recovery audits, material reservations and token
state must remain current.

For an explicitly authorized no-candidate recovery, run
`scripts/recover_x_auto_no_candidate.py` with exact run and task IDs, actor,
reason and a stable operation ID. Dry run is the default. Rehearse on an online
backup, inspect canonical native execution evidence and dispatcher state, then
use `--apply` once. The script atomically requeues only untouched selection
failures and appends original task/run evidence. It rejects every task with a
reservation, execution identity, attempt, receipt, unknown outcome or claim.
Repeated application of the same operation is a no-op. Normal workers select
and publish the original tasks; the script makes no publication request.
