AI自动规则调控 使用说明

本文档说明当前前端原型中的交互方式：通过“规则组”管理 Meta/Facebook campaign 调控规则，选择限定产品、选择账号、配置规则阈值、保存绑定策略，并通过 Preview/执行日志控制风险。

v1 仅控制 campaign 产品仅 dramawave / hotdrama / freereels 新规则组默认 disabled 真实执行必须先 Preview

1. 功能定位

AI自动规则调控用于管理 Meta/Facebook campaign 的人工配置型调控规则。它不是“自动化投放”链路，也不使用自动化投放 skill 的账号 allowlist、策略参数、本地 ledger 或 emergency switch。

当前前端设计以“规则组”为核心。你先创建一个规则组，规则组中包含产品范围、账号范围、国家组、规则阈值、关闭窗口、重启策略。保存后可以在规则组列表中编辑、复制、启停、急停、Preview、进入运行控制台或查看日志。

上线安全默认值：新建规则组默认 disabled，不会自动进入 runner，不会自动关闭广告。真实关闭必须先生成 live Preview，再进行确认执行。

2. 核心概念

规则组

前端主要管理对象。一个规则组聚合规则定义、账号范围和执行策略。你在列表中看到、编辑、复制、启停的是规则组。

产品

产品下拉只允许三个枚举值：dramawave、hotdrama、freereels。不展示其他产品，也不基于这三个值再派生其他选项。

账号范围

账号必须在选择产品后加载，只展示所选产品下的账号，支持多选。不会展示全量账号列表。

规则阈值

规则由多个条件组成，如运行小时、消耗、安装、ROAS、购买数、CPA、国家组、账号时区。命中后执行 pause 或 observe。

Preview

只读预览。系统按当前配置扫描命中对象并展示结果，不调用 Meta 写接口。

执行日志

记录 preview、dry-run、execute 的结果、跳过原因、失败原因、执行人和执行时间。

底层保存位置

前端看到的对象 底层保存位置 保存内容 说明
规则组中的规则定义 ad_control_rule_set rules_json、默认指标窗口、规则说明 保存 pause/observe 条件。高级模式可查看 JSON。
规则组中的账号选择 ad_control_account_group account_ids_json 保存你手动多选的账号列表。
规则组状态和策略 ad_control_rule_group 产品、规则集、账号池、启停、急停、strategy_json 这是规则定义和账号范围之间的绑定关系。
Preview/执行记录 ad_control_action 命中数量、成功/跳过/失败、错误原因、结果快照 用于审计和问题排查。

4. 规则组管理

规则组管理是进入功能后的主页面。它解决两个问题：你能看到系统里有哪些规则组，也能知道每个规则组现在是否启用、控制哪些产品和账号、有哪些规则、策略是什么。

列表筛选

  • 产品筛选：只允许筛选 dramawave、hotdrama、freereels 或全部。
  • 状态筛选：全部、草稿、禁用、启用、急停。
  • 搜索：按规则组名称、规则组 ID、关键词搜索，例如 +8 跨区。

列表字段

字段 含义 使用建议
规则组 规则组名称和规则组 ID。 名称要包含场景、产品和关键策略，如 +8跨区国家组关停。
产品范围 该规则组适用的产品枚举值。 只能是 dramawave、hotdrama、freereels。
账号范围 该规则组已经选择的账号数量。 点击编辑可以重新加载所选产品下账号并多选。
规则 规则数量和动作类型，如 3 pause / 1 observe。 pause 是关闭规则，observe 是观望记录。
策略 关闭时间、执行时区、重启策略。 跨区场景建议明确“当天禁止重启”。
状态 草稿、disabled、enabled、emergency stopped。 新建默认 disabled；启用前必须先 Preview。

可用操作

  • 新建规则组：进入创建/编辑流程。
  • 编辑：修改产品、账号、国家组、规则阈值和策略。
  • 复制：基于现有规则组复制一份新规则组，适合微调阈值或账号范围。
  • Preview：进入运行控制台并生成只读预览。
  • 启用/禁用：控制规则组是否允许后续 runner 或执行流程使用。
  • 急停：立即停止该规则组继续执行，并写入急停状态。
  • 查看日志：跳转到执行日志，并按规则组过滤。

5. 新建/编辑规则组

新建/编辑规则组采用五步流程。页面可以纵向展示，也可以用步骤条标识当前进度。

1选择场景选择跨区关停、低效消耗关停或观望名单。
2产品与账号从三个产品枚举中选择产品，再加载账号。
3规则阈值配置 pause/observe 条件。
4绑定策略配置关闭窗口、执行时区和重启策略。
5保存规则组保存到底层规则集、账号池和绑定关系。

规则组基础信息

  • 规则组名称：建议包含业务场景，例如 +8跨区国家组关停。
  • 规则组说明：写清楚使用场景、负责人、是否允许隔天重启。
  • 状态：新建时默认草稿或 disabled。不要默认 enabled。

推荐命名

+8跨区国家组关停 - dramawave/hotdrama - WW-4/WW-0/JUWW
低效消耗保护 - freereels - spend30_roas30
8小时观望名单 - dramawave - roas35_45_purchase_gt1

6. 产品与账号

产品选择规则

产品下拉只有三个固定枚举值：

dramawave hotdrama freereels
不允许展示其他产品，也不允许基于这三个值再派生其他选项。这里的产品枚举值就是最终可选产品值。

账号加载规则

  1. 先选择一个或多个产品，例如 dramawave、hotdrama。
  2. 前端按已选产品调用账号接口。
  3. 账号列表只显示所选产品下的账号。
  4. 运营可以在列表中多选账号。
  5. 如果启用 +8 筛选，只保留时区等价于 8、+8、UTC+8、GMT+8 的账号。

账号列表需要展示的字段

字段 说明 例子
账号 ID Meta ad account id。 act_1980...4432
账号名称 业务库账号设置中的名称。 Dramawave North America 01
产品 账号来自哪个已选产品。 dramawave
账号时区 来自 ads_accounts_setting.time_zone。 UTC+8
账号状态 ACTIVE、inactive 或其他状态。 ACTIVE

国家组配置

跨区调控使用 ads_facebook_auto_created_data.country 作为国家组字段，不按 campaign 名称猜测。常见值可以配置为：

  • WW-4
  • WW-0
  • JUWW

7. 规则阈值

规则阈值用于判断 campaign 是否需要关闭或观望。一个规则组可以包含多条规则。关闭规则优先级高于观望规则。

动作类型

动作 含义 执行效果
pause 关闭/暂停命中的 campaign。 真实 execute 时调用 Meta API 设置 PAUSED。
observe 仅记录观望。 写入 Preview/日志，不阻止其他 pause 规则生效。

支持字段

  • age_hours：campaign 从起始时间到当前的运行小时数。
  • spend：实时消耗。
  • install：实时安装数。
  • purchase：购买转化次数。
  • revenue：收入。
  • roas_pct：ROAS 百分比。
  • purchase_cpa：购买 CPA。
  • effective_status：Meta 当前状态。
  • country：业务资产表国家组。
  • account_time_zone：账号时区。

示例规则

规则名 条件 动作 解释
7小时+ 无安装关闭 age_hours >= 7，install <= 0，country in WW-4, WW-0, JUWW，account_time_zone in +8 pause 适合 +8 账号跑跨区地区且长期无安装的 campaign。
消耗 30+ 且安装/ROAS 不达标关闭 spend > 30，install <= 10，roas_pct < 30 pause 防止持续消耗但回收差。
消耗 40+ 且购买弱、CPA 高关闭 spend > 40，roas_pct < 35，purchase between 0..1，purchase_cpa > 50 pause 适合购物转化弱且成本过高的 campaign。
8小时附近接近保留线观望 age_hours between 7.5..8.5，roas_pct between 35..45，purchase > 1 observe 不直接关闭，记录为观望，给数据继续回收的机会。
如果一条 campaign 同时命中 pause 和 observe，pause 优先。observe 只用于标记“需要继续看”的对象，不会拦截关闭规则。

8. 绑定策略

绑定策略决定规则在什么时间窗口、按什么时区、以什么重启策略执行。

策略项 建议值 说明
关闭窗口 账号本地时间 15:00 后 到窗口后才允许命中关闭规则。
执行时区 按账号时区 +8 账号按 +8 时间判断关闭窗口。
当天禁止重启 开启 当天被规则组关停的对象，不允许当天自动重启。
隔天允许重启 开启或按需开启 隔天由后续 runner 按规则判断是否允许重启。
未选账号处理 不参与 preview / execute 避免误控未勾选账号。

9. Preview 与保存

生成只读 Preview

点击“生成只读 Preview”后，系统按当前规则组配置查询命中对象。Preview 不会写 Meta，不会关闭广告。

Preview 表格需要展示：

  • 账号 ID、账号时区。
  • 产品：只可能是 dramawave、hotdrama、freereels。
  • campaign 名称和 campaign ID。
  • 国家组。
  • 运行小时数。
  • 实时表现：Spend、Install、Purchase、ROAS、CPA。
  • 命中规则或跳过原因。
  • 目标动作：pause、observe、skip。

保存规则组

点击“保存规则组”后，前端展示为一个规则组，但底层会保存多个对象。

{
  "frontend_object": "规则组",
  "product_values": ["dramawave", "hotdrama"],
  "accounts": ["act_1980...", "act_2671..."],
  "save_mapping": {
    "rule_set": "ad_control_rule_set",
    "account_scope": "ad_control_account_group",
    "binding_strategy": "ad_control_rule_group"
  },
  "default_enabled": false
}
保存后默认 disabled。保存不等于执行，保存也不会关闭广告。

10. 运行控制台

运行控制台用于对已保存的规则组进行 Preview、dry-run 和真实执行。

推荐操作顺序

  1. 选择规则组。
  2. 点击 live Preview。
  3. 查看命中对象、跳过原因、样例和总量。
  4. 如需要，先执行 dry-run，只写审计，不调用 Meta 写接口。
  5. 确认无误后，输入确认口令，再进行真实 execute。

真实 execute 前必须检查

✓产品只包含 dramawave、hotdrama、freereels 中你想控制的值。
✓账号列表只包含你手动选择的账号。
✓命中 campaign 属于产品白名单。
✓国家组和账号时区符合规则预期。
✓关闭数量和样例符合预期。
✓当天禁止重启策略已启用。
如果 Preview 结果里出现不认识的账号、非目标产品、非目标国家组，必须停止执行，先回到规则组编辑页修正范围。

11. 执行日志与排查

执行日志用于复盘每一次 preview、dry-run、execute。建议每次真实执行后都先看日志，确认成功/跳过/失败的分布。

筛选条件

  • 产品：dramawave、hotdrama、freereels。
  • 规则组 ID。
  • 动作：preview、dry-run、execute、emergency-stop。
  • 日期范围。
  • 跳过原因或错误原因。

常见跳过原因

原因 含义 处理方式
timezone_not_match 账号时区不满足规则。 检查账号筛选是否只选 +8。
country_not_match campaign 国家组不在规则范围。 检查国家组配置是否包含目标值。
missing_campaign_start_at Redis 和 insight 起始时间都缺失。 刷新 campaign 起始时间缓存；仍缺失则跳过，不要用资产创建时间兜底。
token_missing 产品或账号没有可用 token。 到 Token 与权限页配置产品默认 token 或账号 override。
not_in_product_whitelist campaign 不属于所选产品白名单。 不执行；检查产品选择和业务资产表。
same_day_reopen_blocked 当天禁止重启策略生效。 正常保护行为；隔天再按规则判断。

13. 常见问题

Q1：这个页面创建后保存到哪里？

前端显示为一个规则组。底层会保存到 ad_control_rule_set、ad_control_account_group、ad_control_rule_group。执行记录保存到 ad_control_action。

Q2：怎么管理多个规则组？

在规则组管理列表中管理。可以按产品、状态、关键词筛选；可以编辑、复制、启停、急停、Preview、进入运行控制台、查看日志。

Q3：为什么产品只有三个？

这是本功能的业务限制。产品下拉只允许 dramawave、hotdrama、freereels。不展示其他产品。

Q4：账号是不是全量账号？

不是。账号必须在选择产品后按产品加载，只显示所选产品下账号，并支持多选。

Q5：保存规则组会不会直接关闭广告？

不会。保存只是创建配置，默认 disabled。真实关闭必须先 live Preview，再确认执行。

Q6：observe 会不会阻止 pause？

不会。observe 只记录观望；如果同一个 campaign 同时命中 pause，pause 优先。

Q7：同一天被关停的 campaign 能不能重启？

跨区规则建议启用“当天禁止重启”。当天被本规则组关停的对象不允许当天自动重启，隔天再按规则判断。

Q8：如果账号 token 缺失怎么办？

该账号会跳过并记录 token_missing。需要到 Token 与权限页面配置产品默认 token 或账号 override token。

✓确认本次只控制 dramawave、hotdrama、freereels 中的哪些产品。
✓确认账号范围是否只需要 +8 账号。
✓确认国家组值，例如 WW-4、WW-0、JUWW。
✓确认关闭窗口和是否当天禁止重启。

保存规则组前

✓产品下拉没有出现三个枚举值之外的产品。
✓账号列表只包含已选产品下账号。
✓规则阈值符合业务要求，pause/observe 动作正确。
✓保存状态为草稿或 disabled。

真实执行前

✓已生成 live Preview。
✓命中 campaign 的产品、账号、国家组、时区都符合预期。
✓跳过原因没有异常大面积出现。
✓已经确认关闭数量和样例。
✓需要真实执行时，由有权限的人输入确认口令。
