## 必须分阶段执行

以下 `$SOURCE`、`$COMMIT`、`$BACKUP` 是操作者设置的精确值；`$BACKUP` 必须是尚不存在的数据盘目录。

```bash
python3 "$SOURCE/scripts/deploy_x_run446.py" --phase prepare --source "$SOURCE" --commit "$COMMIT" --backup-root "$BACKUP"
```

prepare 保存并暂停 `x-auto-post-runner.timer` 及原来活跃的 `.path`，等待现有 runner 自行结束，不中断 sidecar 或 pipeline worker。若等待超时，触发器保持暂停，排查后执行 `--phase drain --backup-root "$BACKUP"` 继续等待；不要强杀发布过程。

队列 `5393` 的历史媒体上传未知结果，必须由 `recover_x_run446.py` 核对全部节点 outbox、历史写操作许可、原 worker 已结束及中央/原生回执后，仅关闭旧未知标记。旧队列仍失败，尝试与操作记录保留，不重传旧素材。

```bash
python3 "$SOURCE/scripts/deploy_x_run446.py" --phase switch --backup-root "$BACKUP"
```

switch 校验原文件没有漂移，授予 `x-post-daily` 对 dispatch 目录的遍历权限和 DB 只读权限。支持 DELETE/WAL：备份原 ACL，为现有 WAL/SHM 赋予读取权限，并在该专用目录设置未来文件的默认只读 ACL；不授予目录写权限。root 在读取探针期间保持 SQLite 连接，确保只读连接可访问已存在的 WAL/SHM，再以实际服务用户验证查询。若 WAL/SHM 在最后连接关闭后暂时不存在，reader 保守保留等待状态，直到协调器重新创建可读文件。随后原子切换 `current`，只重启 `x-auto-post-service.service`，检查 `127.0.0.1:18833/health`。主 API 无需重启。触发器继续暂停。

如果 switch 在 release 指针切换前失败，可以在原 release 未变且文件 hash 仍匹配的前提下再次执行 switch；不需要重做已应用的任务恢复。

在 `2712` 操作重试审计尚未创建前，可运行：


## 后续：稳定读取协调器状态与大批次详情

实测 SQLite 3.26 的只读 WAL 读取仍会因 SHM 元数据写入、文件重建和 Auto 的 `ProtectSystem=strict` 偶发失败。前述直接授予 Auto 读取 DB/WAL/SHM 的 ACL 是中间处置，最终由本节的本地只读桥替代；不扩大 Auto 的数据库写权限。

`x-auto-dispatch-state.service` 以 root 运行固定只读查询，仅接受 `/run/x-auto-dispatch-state/state.sock` 上的 `queue_id`。socket 为 root:x-post-daily、0660，目录 0750。服务只允许 AF_UNIX，数据库连接为 `mode=ro`、`query_only`；root 的目录可写挂载仅满足 SQLite 自身 WAL/SHM 元数据要求。接口不提供 SQL、发布、账号操作、网络访问或凭据。Auto 客户端没有数据库直读 fallback，证据不可用时继续保留等待。
