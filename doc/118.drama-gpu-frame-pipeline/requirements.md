# 118. 视频制作 GPU 帧处理链路

## 背景与目标

2026-09-15 用户确认执行已建议的 GPU 优化。现场随机模板两分片并行时，8 核 CPU 平均 87.5%，GPU 计算 16.2%、编码 9.3%、解码 0%。主视频与透明 VP9 软件解码、像素转换及设备回传占用 CPU。

目标是减少随机模板制作阶段的 CPU 计算和耗时，保持冻结配方、720×1280/30fps、透明效果、片头及剧集时间轴、音频和任务恢复契约。下载、任务排队和音频处理仍可能限制整任务时间。

## 范围与业务规则

- 主视频 H.264 / 无 B 帧 / BT.709 limited 使用 NVDEC；CUDA 完成像素转换和合成；NVENC 从显存接收 NV12。
- 透明 VP9 与 PNG 离线预解码为只读 RGBA NUT，验证每帧像素、PTS 和 packet duration。透明动画运行时读取预解码帧，不重复软件解码。
- 保留两分片并行、已有任务 ID、冻结配方、下载 6 + 预取 2、检查点、子进程跟踪和确认停止后恢复。
- 无 UI、外部 API、数据库结构或社媒发布变更。实验只使用私有文件，不提交测试业务任务。

## 设计

`gpu_compositor.py` 保留调度、检查点、拼接和音频；新增原生 Python 子进程只处理一段无音频视频，沿用 FFmpeg 进度协议。原有 OpenCL 默认路径保留，生产配置显式选择 cuda。

PyAV 提供压缩包及准确 PTS；NVDEC 输出帧按无 B 帧 FIFO 对应时间戳。解析 H.264 SPS，在横竖屏尺寸切换处排空并重建硬解码器。使用容器起点作为寻址基准，保留视频比音频晚 21ms 的采样相位。

RGBA 缓存版本为 `rgba-nut-demux-v2`，与 TT/FB 旧缓存隔离。单项 8GiB、总量 96GiB、保留 32GiB 可用空间；源和缓存哈希、只读归属、大小、时间信息不匹配时拒绝执行。部署前完整验证 18 项；父进程只对相同 inode/stat 验证结果复用哈希。

## 验收

1. 固定输入分别比较原链路、缓存路径、NVDEC/CUDA/NVENC，报告墙钟耗时与累计 CPU 秒，不能用 GPU 利用率推算速度。
2. 完整解码与媒体契约通过；25/30fps、横竖屏切换、120 秒寻址和两分片拼接通过。
3. 单一分辨率样片比较 SSIM 和抽帧；变分辨率样片使用原素材时间轴作独立基准，不能将旧成片时间偏移复制到新实现。
4. 原任务从已有下载/规格化文件继续；代码回滚保留业务数据和新产生的检查点。
