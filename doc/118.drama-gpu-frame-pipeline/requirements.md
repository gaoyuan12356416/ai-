# 118.drama-gpu-frame-pipeline 需求与技术设计

## 背景

2026-09-15 用户确认执行 GPU 制作链路改造。现场随机模板两分片并行时，8 核 CPU 平均 87.5%，GPU 计算 16.2%、编码 9.3%、解码 0%。主视频与透明 VP9 软件解码、像素转换及设备回传仍在逐帧发生。

## 目标

减少逐帧 CPU 处理和重复素材解码，提升完整模板制作速度，保留透明效果、几何、色彩、帧数、时间轴和业务任务恢复契约。性能结论必须来自同输入对照，不承诺仅凭单帧硬解测试获得整任务提速。

## 范围

### 包含

- 验证内容哈希与只读回执的 RGBA 素材缓存；图片一次解码，透明动画一次预处理并跨分片复用。
- 验证 NVDEC 主视频解码、CUDA 合成/颜色转换、显存内 NVENC 编码的新子进程实现；保留完整分片检查点、超时与子进程跟踪。
- 同素材 baseline、缓存、完整 GPU 链路的分项和整链路基准；横竖屏、25/30fps、旋转、透明动画循环、片头分辨率变化和音画时间轴回归。
- GitHub 精确提交、隔离依赖、备份、窄范围部署和生产验证。

### 不包含

- 社媒发布、新建业务任务、修改冻结配方、改变素材次序和画布规格。
- 为制造高 GPU 利用率而增加无收益并发。

## 验收标准

1. 真实媒体完整解码，输出仍为 H.264 High、720×1280、30fps、BT.709 limited、AAC stereo；首帧关键帧、分片可无损拼接。
2. 缓存替换路径优先要求像素和时间戳一致；新 GPU 内核按固定参考比较 SSIM、抽帧视觉与透明边缘，不接受黑底或颜色漂移。
3. 原有观察恢复、下载预取、发布输入和任务 ID 不变；重复执行仅复用经过验证的检查点。
4. 缓存有单项、总量、空闲空间上限；源/缓存变更拒绝使用；生产不开启未通过完整验证的候选。
5. 最终报告分别给出各候选实测与实际上线范围，列出未通过项及原因。
