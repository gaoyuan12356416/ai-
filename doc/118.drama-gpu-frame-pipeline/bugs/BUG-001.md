# BUG-001 GPU 帧链路验证中发现并修复的问题

## 已修复

1. NVIDIA 1.0.2 自带 demux 时间戳为 0，Seek 可崩溃：改用 PyAV 压缩包和 PTS，使用无 B 帧 FIFO。
2. SDK bf=0 表示全 I 帧，导致文件膨胀：使用 bf=1（IPP，对应 FFmpeg bf=0），QP19；Encode 字节列表显式转 bytes。
3. NVDEC 横竖屏尺寸变化：解析 SPS，在关键帧处排空并重建 decoder；BSF 消费原包后必须检查返回包 keyframe 标志。
4. 旧 RGBA 缓存 PTS/packet duration 被量化：V2 用原始 demux 时间和每帧像素证明重封装。
5. `-stream_loop -1 -ss phase` 会重复 seek 后的 GOP/尾段：先完整循环再 trim，保留绝对时间至 fps 取样后归零。两个动画各 90 帧匹配 FFmpeg。
6. 使用视频 start_time 代替容器起点会改变 25→30fps 重复帧位置：保留容器时钟并加入真实 21ms 偏移回归。
7. Windows ctime 不是可靠修改时间：Windows 完整摘要不使用该 stat memo。

## 对照样片的既有问题

旧 OpenCL 130 秒混合分辨率样片在切换后出现约 10 秒时间偏移：新输出 20 秒画面匹配源视频 20 秒，但旧输出最接近其 10 秒画面。新解码器 3250 源帧逐帧 PTS/尺寸匹配软件解码，抽样 NV12 像素零差异。未将错误旧时间轴作为新实现目标；未单独部署旧 OpenCL 时间轴修复。

## QA 工具问题

PyAV 12.3 在本环境 RGB reformat 的指定矩阵未生效，RGB 差异不能代表 NVDEC 解码错误；改在 NV12 阶段逐样本比较。FFmpeg QA 子进程增加 -nostdin，避免读取远程 shell 脚本输入。失败的私有实验保留，没有进入生产。
