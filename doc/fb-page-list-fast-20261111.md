# Page list first-render latency repair

The 260-row configuration view waited for all live source authorization data before rendering its first 20 rows. Source requests were sequential batches of 200 and 60. Measured through the production FIFO gate they took 2.354 s and 2.161 s. A direct replica connection alone took 1.077 s. Removing TRIM changed the source query from a 32,073-entry index scan to an approximately 800-row range, but query execution improved only from 0.391 s to 0.240 s. Merely adjusting this SQL would not remove the dominant wait.

Administrators now read current tenant configurations and creator snapshots through the independent portrait service, with current Cookie/module/navigation checks and a fresh active-admin DB check. Only Page names use an optional local display snapshot. No authorization result is cached: initial rows explicitly say authorization verification is pending. The existing complete Page source request runs asynchronously, updates availability, and preserves source-owner and publication checks. Ordinary accounts continue through their existing source-owner-filtered list. No publishing process changes or restarts are required.

Source-check failure leaves current configuration, language, creator filtering and portraits usable, while marking authorization as unknown. A new load aborts/invalidates the previous verification; a late response cannot overwrite a subsequent edit/reload. New configurations show their ID immediately when the display name has not yet been refreshed. The portrait collector refreshes display names hourly; a failed name refresh preserves the old names without invalidating financial data.
