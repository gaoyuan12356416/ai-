# BUG-002 - 既有随机模板在音频间隙处停住

上线前已存在的 FB 准备任务重复卡住。108.3 秒源完整解码 3249 视频帧，图像属性和 PTS 正常；AAC 有若干小的时间戳间隙。

受控复现：旧线上、新叠层、替换资产、禁用缓存和同版本另一FFmpeg均在 frame=423 / out_time=14 秒停住。无模板的简单编码使用同样音频过滤与 -shortest 也停；去掉音频正常推进，因此不是新叠层或素材缓存问题。

单变量实验：保留 aresample=48000:async=1:first_pts=0,apad，仅移除输出 -shortest，30 秒视频在 6.27 秒完成。plain audio + shortest 也可完成，说明是该音频补齐/输出同步组合的既有阻塞。不要改变 audio补偿或模板内 framesync EOF；随机模板已有显式 -t 时长界限，以它结束已补齐的音轨。

修复：TT 随机模板、FB build_command 与 Drama legacy adapter 去掉输出 -shortest。媒体编码规格、音频处理、明确时长与模板层顺序不变；direct_outro 不变。

完整 108.3 秒旧、新配方均成功：3249 帧、单音轨，完整解码无错，音频 PCM SHA256 均为 `86fc6469f583d84f285cc921d5c5ed289acfec5225bb78238462ad7768461c0d`。TT 四组源帧时间轴回归 mismatch=0；最终 GPU 验收纳入该停住源，全部通过。

原卡住进程已先备份进程、源和任务现场（HK `/data/random-overlay-gpu/backups/20260920-source-overlay-stalled-prepare`），核对 PID 身份和持续无进展后逐级退出。源文件、业务历史和已完成素材保留，正常推进的其他任务等待自然完成。
