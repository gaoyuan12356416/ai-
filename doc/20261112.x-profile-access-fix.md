# X 画像发布访问修复

普通自动发布和素材池下线后，画像网关仍调用它们的列表接口校验权限，因而将旧接口的 HTTP 410 转发到画像模板和画像素材池。修复将画像权限校验与退役业务接口分离，继续校验登录、模块和对应导航权限。

导航脚本已过滤退役入口，但画像等页面仍使用旧缓存版本。部署脚本仅改写已有 HTML 中 `quick-nav.js` 和画像顶部导航脚本的版本号，保留各页面其他内容；同步画像运行目录的导航脚本，并移除顶部“原自动发布”入口。短剧池保留为现有的画像分配连载入口。

## 部署

先提交并推送精确版本，服务器 fetch 并 checkout 到独立干净 source。运行：

```sh
python3 SOURCE/scripts/deploy_x_profile_access_fix.py install --root /mnt/data-disk/x-profile-access-fix-20261112/deployment
```

脚本校验既有网关和共享脚本的已审核哈希，备份所有目标，检查并发变化后原子写入。只重启 `x-tag-gateway.service`，不重启发布器或主 API，不改变排期、数据库、历史回执、凭据和退役状态。`deployment.json` 记录版本、哈希、备份和其他发布服务的 PID/状态对比。后续应以登录后的模板、素材池、账号、运行记录接口和浏览器刷新验证，不能只检查静态 HTML 的 200。

## 回滚

```sh
python3 SOURCE/scripts/deploy_x_profile_access_fix.py rollback --root /mnt/data-disk/x-profile-access-fix-20261112/deployment
```

回滚只恢复本次代码和静态资源，要求目标仍等于本次发布版本；再次只重启画像网关。业务数据和最新平台回执始终保留。
