# BUG-002 future manual reservation 未排除既有 pool 自动候选

## 严重级别

P1。

## 现象

实时生产 `09d267db…` 允许 operator manual 选择已在素材池中的素材。定时任务在该素材上建立 active reservation 后，`available_pool_items()` 仍可能把原 pool 行返回给自动排期，pool DTO 也显示为 available。

## 影响

到期前自动 runner 可能选择同一素材，最终虽会被 queue reservation trigger 拒绝，但会让自动整批计划无谓失败；运营页面同时错误表达该素材仍可供自动发布。

## 根因

初版设计禁止 manual 选择既有 pool，因此只在新 pool admission、queue 写入和 `query_material_keys()` 中检查 reservation。生产基线增加手动复用后，这个前提不再成立。

## 修复

- manual parent 可在既有 pool/历史 queue 上创建 reservation；auto_template 仍禁止。
- `available_pool_items()` 排除 active reservation。
- pool DTO 和 summary 将“无 queue 但有 active reservation”的行派生为 `occupied`。
- DB queue trigger 继续只允许 reservation 所属 run 建队列，其他 parent fail closed。

## 验证

新增回归覆盖：先加入 pool，再创建 future scheduled manual；任务创建成功、自动可用列表为空、pool DTO 为 occupied；到期后 owner run 原子建队列并 consume reservation；随后仍可按 operator-manual 规则创建新的历史素材复用任务。

## 状态

已修复并关闭。
