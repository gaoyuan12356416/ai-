# BUG-001 active reservation 未进入 unavailable material key 查询

## 发现阶段

SA 代码评审。

## 现象

定时任务已经持久化 active reservation 后，`query_material_keys()` 仍只返回历史 queue（可选 pool），自动模板候选预查可能继续选择该素材，直到创建任务时才失败。

## 复现步骤

1. 创建未来 scheduled manual run，素材 `902` 处于 active reservation。
2. 调用 `query_material_keys(["902"])`。
3. 修复前返回空数组。

## 期望结果

active reservation 与 queue 一样属于 X 账本占用，查询应返回 `902`；released 后才不再返回。

## 实际结果

修复前遗漏 reservation 查询。

## 根因分析

初版只在 create/pool/queue 写入边界增加 reservation 检查，遗漏了自动模板选材前使用的只读占用查询。

## 修复说明

`XPostStore.query_material_keys()` 每批同时查询 `x_post_manual_material_reservation WHERE state='active'`，并与 queue/pool 结果合并；失败释放后自然恢复可选。

## 影响文件

- `features/x_posts/service.py`
- `scripts/test_x_post_auto_template_bridge.py`

## 验证命令与结果

`python -m unittest scripts.test_x_post_auto_template_bridge`：通过；按 40 个模块隔离执行的完整 X 套件 625 项通过、2 项按既有条件跳过。

## 回归结论

已关闭。自动模板、手动立即/定时、历史 queue 与 operator pool 查询语义均保持 fail closed。
