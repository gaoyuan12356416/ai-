# BUG-001 TT 首屏语言与 Featured 延迟约 11 秒

## 发现阶段

生产用户录屏与只读性能诊断。

## 现象

页面很快显示默认英文外壳，但约 10.9 秒后才切换中文并出现 Featured 卡片。

## 复现步骤

1. 使用中文浏览器打开 `https://ai.yingliangads.com/tt`。
2. 冷缓存或刷新页面。
3. 记录英文标题出现、中文标题出现和卡片出现时间。

## 期望结果

第一次可见内容即为中文；搜索外壳和骨架卡不等待主 JS/Featured/封面。

## 实际结果

录屏约 03.80 出现英文，约 14.70 才切中文并显示卡片，差值约 10.90 秒。

## 根因分析

- HTML 写死英文，语言识别函数位于 106 KiB defer 主 JS 中。
- 主 JS 未压缩且 no-store，每次访问重新下载后才执行语言替换。
- Featured 下载全部语言且超时 2 秒；封面仍为较大的外域 JPEG。
- 服务器本机静态读取仅约 6--7 ms，排除 Redis/SQLite 为首要根因。

## 修复说明

已采用服务端 locale HTML、hash JS immutable、gzip、单语言 JSON、首屏
骨架与独立 WebP 缩略图缓存。有效服务端 locale 为权威语言，延后的主 JS
不再重写首屏。

## 影响文件

见需求文档“影响模块”；不涉及发布数据库和 resolver 合同。

## 验证命令与结果

- 23 语言构建检查：通过，hash `e907e1e2a988`。
- 新/旧前端合同：250/250 通过。
- 真实 Chrome：44/44 通过。
- Featured Python：43/43 通过。
- `{code}` 与 TT 发布/链接/app：259/259 通过。

## 回归结论

本地与生产回归均通过。生产真实 Chrome 的中文首次可见内容约 1.284 秒，
没有出现英文标题；10 次冷启动样本的 DCL 中位数为 2.046 秒，5 条动态榜单
完成中位数为 3.072 秒，5 张封面完成中位数为 5.309 秒。一次公网离群样本
虽然整体资源较慢，但首屏仍直接为中文，因此原“等待 JS 后二次切换语言”
缺陷已关闭。

Search 与 Featured 点击均通过拦截测试；现网四字符 code 精确解析及活动
生产 release 的 17 项 `{code}`/resolver 测试通过。状态：已修复并关闭。
