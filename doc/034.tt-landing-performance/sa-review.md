# SA 评审意见

## 结论

有条件通过。性能问题定位充分，改动应限定在静态加载与 Featured 产物层，
不得把首屏优化扩展为 resolver、发布或数据库重构。

## 问题清单

| 编号 | 严重级别 | 位置 | 问题 | 建议 | 状态 |
| --- | --- | --- | --- | --- | --- |
| SA-001 | 高 | 首屏语言 | 仅靠延后执行的 JS 仍会英文闪屏 | 预生成语言 HTML，由 Nginx 白名单选择；保留 JS 校正 | 已采纳 |
| SA-002 | 高 | Nginx alias | 直接拼接请求头存在路径穿越风险 | 请求头只能映射到固定 locale 枚举，路径正则限制 | 已采纳 |
| SA-003 | 高 | 静态缓存 | 未版本化文件设置长期缓存会发布陈旧代码 | 主 JS 和 WebP 使用内容哈希，HTML继续 no-store | 已采纳 |
| SA-004 | 中 | Featured | 多文件发布可能部分更新 | 每个语言文件原子写入且保留 LKG；单桶自包含 | 已采纳 |
| SA-005 | 中 | 缩略图 | 图片下载/解码失败可能拖垮定时任务 | 并发有界、字节/像素/超时限制，单图失败回退原 URL | 已采纳 |
| SA-006 | 中 | CSP | 内联 bootstrap 会要求放宽 CSP | 不增加 inline script，继续 `script-src 'self'` | 已采纳 |
| SA-007 | 高 | 回滚 | 新 HTML 可能依赖新 JSON/缩略图 | 先发布向后兼容数据和资产，再切 Nginx；回滚仅恢复配置 | 已采纳 |

## 决策记录

- 采用服务端选择静态 locale HTML，不采用 Service Worker 或同步 XHR。
- 保留原全语言 v2 endpoint，新页面使用 schema v3 单语言 endpoint。
- HTML 首屏和搜索功能不得等待图片；WebP 为优化层而非正确性依赖。
- 生产发布顺序固定为：数据/缩略图 → hash 资产/locale HTML → Nginx 切换。
