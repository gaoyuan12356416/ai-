# FB 发布记录实时状态

旧列表把创建时 `queued_tasks` 显示为“排队”，并直接显示持久化批次状态。
只要遗留 `planned/ready` 子任务，批次就会长期显示 `running`，即使模板已停用或删除。

本次仅修改读取和展示：列表与详情在同一 SQLite 读快照内，按已授权批次聚合子任务。
保留原 `status`、创建时计数、全部任务和发布回执；新增 `display_status`、
`task_counts`、说明和展示完成时间。查询不执行迁移、清理、发布或重试。

- 有有效执行租约的制作/提交任务：执行中。
- 未知结果、待对账或过期执行租约：待处理，保留暂停/删除说明。
- 其余未执行任务：按模板删除/停用显示已停止/已暂停；独立手动发布保留其开关例外。
- 启用模板的未执行任务若排期早于北京时间今天：待处理；其余区分等待排期与等待执行。
  “排期早于今天”是展示提示，不是新的过期取消规则，跨日任务继续遵守原有执行政策。
- 全部结束：按真实成功、失败、跳过、取消数显示结果，不把未知结果当成功。
- Page 数保留创建时快照标签；任务改为实际已发布/未执行/执行中/待核对/失败/跳过。

只扫描当前列表授权批次 ID，每批最多 400，SQLite 状态聚合不读取视频、文案或凭证。
列表和详情权限逻辑保持，执行代码不使用新增展示状态。

验证：`python -m unittest tests.test_fb_run_summary scripts.test_fb_target_midnight -q`（23 项），
`node scripts/test_fb_run_summary_ui.js`，线上原文件的定点补丁匹配。
覆盖 11 月 22 日 1852 成功/42 失败/3 未执行实例、暂停删除、未知结果、有效/过期租约、
北京时间日界、独立手动发布、分页权限、列表详情一致性与只读无写入。
