# BUG-001 语言容量与全局 FIFO 冲突导致无限重试

## 发现阶段

生产运行审计。

## 现象

Run 345 每 11–12 分钟固定失败 `x_post_pool_fifo_conflict`，始终 claimed、0 queue/log。

## 复现步骤

配置 17 en + 2 ja；先选满 2 个 ja；全局 FIFO 后续仍有 clean ja，之后才有 en。

## 期望结果

clean ja 留给后续批次，继续选择后续 en，最终最大可用 19 条。

## 实际结果

runner 正常跳过语言已满素材，service 要求该素材存在错误码，原子事务回滚。

## 根因分析

runner 与 service 对“语言容量已满”的跨语言 FIFO 契约不一致，且 create 409 位于 preflight catch 外导致 run 不终态化。

## 修复说明

传递精确 run-scoped 容量跳过证据，OAuth 重算完整冻结账号语言容量，SQLite 原子消费；known create error 立即记录失败。

## 影响文件

runner.py、service.py、oauth_service.py、schedule/store tests。

## 验证命令与结果

`python scripts/test_x_post_schedule_runner.py` 与 `python scripts/test_x_post_multi_schedule_store.py` 当前通过。

## 回归结论

线上精确 pool/material 顺序已离线复演通过；待独立全回归与生产只读验收。
