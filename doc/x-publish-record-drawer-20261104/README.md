# X 发布记录详情抽屉

发布记录原先把批次详情插入整页列表末尾，操作者每次都需要滚到页面底部查看失败素材。现在点击「查看详情」立即打开右侧抽屉，手机上占满屏幕；详情独立滚动，标题、关闭和刷新按钮持续可见。关闭按钮、Esc、点击遮罩均可关闭，返回原列表位置及按钮焦点。

继续使用原有批次 GET 接口和任务渲染器，展示素材、账号、发布文案、状态、失败原因及帖子链接。加载失败在抽屉内提示，可以刷新重试。刷新保持详情滚动位置；关闭、切换页面后的迟到响应被丢弃。没有新增发布、回收、重试或数据库写入。

## 范围和来源

- 基于 `4553516`，三个修改前的 Git 文件与线上 Nginx、主 API 和 X 运行目录的文件逐字节一致。
- 仅部署 `static/x-video-publish.html`、`static/x-video-publish.js`、`static/x-video-publish.css`。
- JS/CSS 缓存版本更新为 `20261104drawer1`。共享账号设置脚本及其素材池修复版本保留。
- 不切换 X 发布服务的 release 链接，不重启服务，不改定时器、账号、素材池、任务或发布账本。

## 验证

- `node --check static/x-video-publish.js`
- `git diff --check`
- 使用 Playwright CLI 在本地静态页和只读模拟接口上验证 50 条记录、12 条详情任务。
- 桌面 1440×960：从列表 scrollY=1020 打开，详情滚到 500 后刷新仍为 500，关闭后列表仍为 1020，焦点回原按钮。
- 校验网络错误可在抽屉内重试；关闭延迟响应批次再打开另一批次，旧响应不能覆盖新详情；直接 `?view=records&batch=...` 可以打开抽屉。
- 窄屏 390×844：抽屉满屏，无横向溢出。验证过程只允许 GET，不执行真实发布。

## 部署与回滚

先将提交推送 GitHub，再由 CPU 主机读取该确切提交中的三个文件。发布前复核三个目标根目录的旧 SHA-256，若有并行改动先合并。将旧文件和其路径、模式、SHA-256 写入 `/mnt/data-disk/x-publish-record-drawer-20261104/<UTC>/backup/`，通过同目录临时文件和 `os.replace` 原子替换每个文件，最后更新 HTML。

目标根目录：`/usr/share/nginx/html`、`/root/drama_material_service/static`，以及部署时解析的 `/opt/x-post-automation/current/static`。在部署记录中保存解析后的真实路径，不切换其他服务版本。

上线后比较三个位置及公网返回的文件哈希，确认主 API、X Sidecar、X Auto 服务的状态与 PID；确认页面缓存版本。静态更新不需要重启或 reload。

回滚只恢复部署备份中的九个静态文件，顺序为 JS、CSS、HTML；保留当前所有数据库、Token、任务和发布状态。执行备份目录的 `rollback.py`（路径在部署记录中），它先核对目标仍为本次部署版本，再原子恢复旧文件。若发现后续并行修改，需先合并，不能覆盖。
