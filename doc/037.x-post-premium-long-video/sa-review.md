# SA 评审意见

## 结论

有条件通过。必须先关闭会员误判、非会员长视频被旧修复器裁短、计划后会员失效和 API/网页上限混淆四个 P0 风险。

## 问题清单

| 编号 | 严重级别 | 位置 | 问题 | 建议 | 状态 |
| --- | --- | --- | --- | --- | --- |
| SA-001 | P0 | 账号能力 | `verified`/蓝 V 不能证明长视频权益 | 仅信任本人 token 的 `subscription_type`，缺失/未知失败关闭 | 已接受 |
| SA-002 | P0 | 媒体修复 | 旧 profile 会把所有 >140s 裁为 139s | 修复请求加入标准/会员时长策略并升级 profile/job key | 已接受 |
| SA-003 | P0 | 发布竞态 | 计划时是会员不代表发布时仍有权益 | 每个队列发布前继续实时 `verify_account`，锁内再按最新 DTO 门禁 | 已接受 |
| SA-004 | P1 | X API 合同 | 网页端小时级上限不能直接套到 API | 自动发布保守上限 600s，长视频使用 `amplify_video` | 已接受 |
| SA-005 | P1 | 素材可重试 | 无会员时若写阻塞错误，素材会永久退出扫描 | `x_long_video_requires_premium` 作为非阻塞、未绑定检查结果 | 已接受 |
| SA-006 | P1 | 分配顺序 | 直接 zip 会让第一非会员吃到长素材并裁短/失败 | 短素材先填非会员，长素材只匹配剩余会员，最终按冻结账号顺序提交 | 已接受 |

## 决策记录

- `Basic`、`Premium`、`PremiumPlus` 均判定为会员长视频权益；`None`/`unknown` 不具备。
- 140 秒边界包含在短视频合同内；会员 API 自动发布最大 600 秒、512 MiB。
- 不用真实 Post 做部署验证；通过 mock、迁移演练、真实 `/users/me` 安全字段同步和自然调度零意外写验证。
