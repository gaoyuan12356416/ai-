# MoboReels hourly refresh

The revenue timer now runs at every Beijing hour boundary. Each run requests the
latest 31 UTC calendar dates including today; the existing service caps the
order request at the current time and fetches advertising only for completed
UTC/source dates. Existing active-run reuse and snapshot/write reconciliation
remain unchanged. Catalog synchronization stays on its daily schedule.

The page states the hourly cadence and retains the advertising T+1 notice.
Only the timer needs restarting. The CLI is a new process on every invocation,
so the Mobo HTTP service and publishing owners do not need a restart.
