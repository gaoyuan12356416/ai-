# BUG-004 总播放时长被重复乘安装数

## 发现阶段

生产全量阴影刷新后的源表、SQLite 与清单逐指标对账；公网尚未切换。

## 现象

2026-08-24 清单显示平均游戏时长 `578941.186961` 秒，显著高于合理范围。

## 证据

- 现网 `information_schema.COLUMNS.COLUMN_COMMENT` 明确写明 `play_duration_seconds` 是“总播放时长”；
- 当日总播放时长 `177515527.828` 秒、安装 `165847`，正确均值为 `1070.357` 秒；
- 原实现又计算 `SUM(play_duration_seconds * install) / SUM(install)`，重复乘了安装数。

## 根因分析

历史设计字段名是 `avg_play_duration_seconds`，实现兼容现网字段名时只处理了名称漂移，没有处理“行均值”变成“行总量”的语义漂移。

## 修复说明

- 缓存统一保存总播放时长；
- 现网 `play_duration_seconds` 直接保存；
- 历史 `avg_play_duration_seconds` 在 SQL 读取时乘该行安装数，转换为总量；
- 后端和前端统一用 `SUM(play_total_seconds) / SUM(install)` 派生平均游戏时长；
- 增加现网/历史字段两条 SQL 契约断言和总量聚合单元测试。

## 影响范围

仅影响尚未上线的新报表派生平均时长。源表、SQLite 原始总时长、成本、安装、留存、收入及渠道指标均未被改写。

- `python validate_frontend_contract.py`：PASS（含 `node --check`）；

## 回归结论

本地回归通过；待服务器与真实数据回归。
