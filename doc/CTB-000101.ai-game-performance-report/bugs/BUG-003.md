# BUG-003 手工转化 SQL 返回字面量日期格式

## 发现阶段

生产数据盘首次全量阴影刷新；公开 Nginx、systemd timer 与 production symlink 尚未安装。

## 现象

读取 `ads_manual_daily_performance` 首日数据后，标准化阶段报错 `ValueError: invalid date: %Y-%m-%d`，刷新在发布提交点前失败。

## 复现步骤

1. 从 GitHub 不可变 release 执行 `--full-refresh --publish` 到阴影目录；
2. 生成器执行 `fetch_manual_day()`；
3. MySQL 返回字面量 `%Y-%m-%d`，`validate_date()` 拒绝该值。

## 期望结果

MySQL `DATE_FORMAT` 返回真实日期 `2026-08-24` 和真实更新时间。

## 实际结果

SQL 模板包含 `%%Y-%%m-%%d`；该模板使用 Python `.format()` 而不是 `%` 插值，因此双百分号被原样送到 MySQL。

## 根因分析

从使用 Python `%` 字符串插值的旧查询迁移时保留了百分号转义，但新实现已改用 `.format()`。

## 修复说明

- 日期与更新时间格式统一改为 MySQL 单百分号格式符；
- 新增 SQL 级回归测试，断言查询不再包含 `%%Y`，并验证真实日期可完成标准化；
- 保留失败 release，不做原地修改；修复后从新的 GitHub 提交创建新 release。

## 影响范围

仅影响尚未上线的新报表首次刷新。失败发生在阴影目录且 `latest.json` 发布提交点前，公网现有功能无影响。

## 验证命令与结果

- `python -m py_compile ...`：PASS；
- `python -m unittest discover ...`：18/18 PASS，包含 SQL 日期格式回归；
- `python validate_frontend_contract.py`：PASS；
- 服务器 release：18/18 PASS；
- 全量阴影覆盖 2026-08-10 至 2026-08-25，433,060 条手工转化事实全部返回真实日期并发布成功；
- 自然 timer 增量刷新成功。

## 回归结论

通过。
