# BUG-002 发布目录无法导入现有只读 MySQL 命令模块

## 发现阶段

SA 代码评审。

## 现象

生成器部署在 `/opt/ai-game-performance/current/ops/ai-game-performance` 后，Python 的默认模块路径不包含 `/root/codex_test`，首次刷新会因找不到 `opera_product_daily_dashboard.py` 失败。

## 复现步骤

1. 在不设置 `PYTHONPATH` 的独立目录执行生成器 `--refresh-cache`；
2. 进入 `mysql_command_env()`；
3. 观察模块导入失败。

## 期望结果

生成器从明确、只读、可配置的生产目录加载既有 MySQL 命令模块，且不复制或暴露口令。

## 实际结果

原实现依赖进程当前目录恰好是 `/root/codex_test`，与不可变 release 路径不兼容。

## 根因分析

从现有 TT 脚本迁移时保留了隐式同目录导入假设，但新服务采用独立 `/opt` release。

## 修复说明

- 新增 `AI_GAME_REPORT_BASE_MODULE_DIR`，默认 `/root/codex_test`；
- `mysql_command_env()` 在延迟导入前显式将该目录加入 `sys.path`；
- 配置示例和 README 同步更新；
- service 保持 `ProtectHome=read-only`，只读访问该目录。

## 影响文件

- `ops/ai-game-performance/ai_game_performance_dashboard.py`
- `ops/ai-game-performance/README.md`
- `deploy/ai-game-performance.env.example`

## 验证命令与结果

- 本地与服务器不可变 release：18/18 PASS；
- `/opt/ai-game-performance/releases/479398bed4a2656a431d571ec3b58d0efd452a88` 可从默认 `/root/codex_test` 成功加载既有只读 MySQL 命令模块；
- 全量刷新与 16:12 自然 timer 均成功，日志未暴露口令。

## 回归结论

通过。
