# 画像查询加速与 LGBTQ+ 口径核对

远程 SQL 查询每次需要经过连接闸门、启动客户端并连接数据库。详情此前每次点击还会重新读取频道树，再读取剧目页。已有真实测试中单次查询约 3.4 秒，因此仅缩小 JSON 不能解决连续点击的等待。

保留 `ads_ai.x_channel_revenue_profile` 为权威存储。每次小时刷新在远程行数、金额和完整载荷校验通过后，建立本机只读 SQLite 索引；列表摘要、频道树和剧目行分别存储，明细按索引读取每页 50 条。核对所有投影行数、校验值及 SQLite 完整性后才发布磁盘指针。没有常驻全量 Python 内存缓存。磁盘副本暂不可用时退回原数据库路径；版本固定、频道权限核验及过期提示保持不变。

前端将画像请求与账号加载并行；同一次详情查看已取得的类型、受众和题材树直接展开，已查看的剧目页可返回复用，关闭后新开重新取版本。仅保留当前频道的小量浏览器交互数据。受众摘要展示该类型的所有受众，不再只取前两项。

首次发布使用现有已验证快照生成新的投影版本，不改变其源收入、标签、分类或更新时间口径。只重启画像只读 API；原发布服务和新发布进程、配置、任务及回执不变。

LGBTQ+ 调查冻结版本 `20261110T032000497579Z`：整体收入 6,329,434 分，其中 LGBTQ+ 444,783 分，占 7.0272%。明确 BL/GL 等标签没有被误归入其他方向；问题主要是部分剧情明确的剧缺失 BL/GL 标签，现有规则把 Sweet 等视作女性信号、治愈等视作通用信号。仅按这类中性标签无法可靠识别同性恋爱情节。
