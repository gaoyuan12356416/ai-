# X 素材池每日余量提醒

将原逐批缺素材提醒切换为北京时间每天 10:30 一张汇总卡片。每个语言的阈值为当前有效素材池排期每天用量的两倍；余量小于或等于阈值才播报，没有触发语言则静默。固定排期按每日时间点数，随机排期按每天次数计算。语言和有效账号范围随当前配置读取，不改配置或冻结计划。

提醒服务独立运行，发布服务、队列、素材池、账号 Token 和选材逻辑不变。不调用 X、刷新账号、下载媒体、提交预占或回填校验结果。来源查询使用只读端点和现有 FIFO SQL 连接门控，读取失败写服务日志，不伪装成零库存发送。

库存使用当前发布选择器的可扫描候选范围（默认最新 1000 条），排除所有队列占用和有效手动预占。批量读取来源/短剧/可投放时间，在内存复用当前选择器核验，语言采用短剧映射；无已知时长的素材不会触发媒体探测。数量是来源信息与账号能力快照估算，最终发布仍按正常流程校验媒体与实时会员权限。

无同语言会员排期时，超过20分钟的视频单独展示，不计入可用余量。有会员及普通账号混合时，还检查普通账号所需短视频/图片的两天库存，避免长视频掩盖短素材不足。

投递沿用原群、原 @ 成员及回执库；键为北京时间日期，每日最多一张成功卡片。旧事件不消费、不补发。发送中/未知回执保留且不重试；明确拒绝可在同一调度窗口内以原 UUID 重试。定时器没有开机补发或错过后补发，不发送上线通知。

验证：`python -m unittest scripts.test_x_material_inventory scripts.test_x_material_shortage_alert`。`scripts/x_material_shortage_alert.py --config CONFIG` 为只读真实数据预览；只有 `--send` 且北京时间 10:30 调度窗口才可发卡。

GitHub 提交后，服务器检出精确提交并运行 `scripts/deploy_x_material_daily_alert.py`。安装器先预览、验证，再备份配置、单独投递库、unit 和版本指针；仅短暂停止提醒 timer，等待已接受的提醒自然完成，不重启任何发布服务。回滚：`python3 FETCHED_SOURCE/scripts/deploy_x_material_daily_alert.py --rollback BACKUP/manifest.json`，恢复旧提醒程序/配置/定时器，保留当前投递库及全部发布数据。
