# 028 TT Post 账号无关素材入池

## 背景

当前页面要求先选择并实时校验一个 TikTok 账号，才能把已校验素材加入自动发布素材池。Creator Info 或账号源短暂不可用时，素材本身已经校验通过，仍无法入池等待后台制作，扩大了外部依赖的影响面。

## 目标

- 用户填写素材 ID 并完成素材校验后，可以直接加入素材池。
- 保存自动发布配置、素材入池和后台预制作均不调用 TikTok Creator Info。
- 真正执行发布前仍实时校验账号、Token、发布设置和视频时长限制。
- 保持历史 API 调用和现有账号分池存储兼容。

## 范围

### 包含

- 自动发布配置保存改为只校验可信账号快照、本地发布设置和手动 canary 锁。
- 新页面入池请求不再提交 `source_account_id`。
- 服务端按素材 ID 在当前已保存自动发布账号中稳定分配账号。
- 后台预制作只处理素材，不查询账号源或 Creator Info。
- 页面文案与校验逻辑区分“立即测试账号”和“自动入池”。

### 不包含

- 不移除立即发布测试的账号选择和实时能力校验。
- 不移除自动发布真正执行前的 Creator Info、Token、设置和时长校验。
- 不改变素材池/入池表结构，不重分配历史素材。
- 不触发真实 TikTok 发布作为验收手段。

## 业务规则

1. 入池必须绑定已保存且版本一致的自动发布配置；配置至少包含一个账号。
2. 未显式传账号时，以 `sha256(material_id + 账号列表)` 生成稳定下标，选择配置中的一个账号；相同配置版本和素材 ID 的重试结果一致。
3. 旧调用显式传 `source_account_id` 时继续支持，并要求该账号属于配置；未传配置版本的旧调用仍要求显式账号。
4. 入池账号必须有本地发布设置，用于冻结 `is_aigc`；不读取实时 Creator Info。
5. 预制作只验证成片时长为正；账号最大时长在真正发布前实时判断。
6. 立即测试保持显式账号、Creator Info 和账号能力门禁。

## 影响模块

- `features/tt_posts/service.py`
- `static/tt-post-pool.html`
- `scripts/test_tt_posts_service.py`
- `scripts/test_tt_post_pool_ui.py`

## 数据结构

无数据库 schema 变更。继续使用现有 account-sharded 素材池；新入池由服务端稳定分配到一个已保存账号。

## API

- `POST /api/admin/tt-posts/auto-config`：不再调用 Creator Info；响应结构不变。
- `POST /api/admin/tt-posts/material-pool`：当携带 `expected_config_version` 时，`source_account_id` 改为可选；响应继续返回实际分配的 `source_account_id`。
- 后台 preparation process：请求/响应结构不变，取消账号实时能力依赖。

## 验收标准

- 不选“本次测试账号”时，素材校验通过且配置已保存，即可点击加入素材池。
- Creator Info 故障不阻断配置保存、入池或后台预制作。
- 同一素材的幂等重试只产生一条 intake，并返回相同账号。
- 真正发布路径的 Creator Info/Token/账号设置校验仍存在并由回归测试覆盖。
- 全量 TT Post 测试通过；生产只读验收不产生配置、素材池或发布写入。

## 风险

- 某账号实际最大视频时长较短时，素材可以完成预制作，但会在该账号真正发布前被阻断并保留可审计错误；这是延迟校验的预期行为。
- 稳定分配依赖配置账号列表；配置版本冲突必须拒绝，避免页面与服务端分配依据不一致。
