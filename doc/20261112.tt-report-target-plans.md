# TT 日报账号独立随机计划统计修复

2026-11-11 的两个 TT 模板实际需求为 13 账号 × 4 条 = 52 条、3 账号 × 4 条 = 12 条。旧日报将每个单账号运行再次展开成整个模板账号范围，又补出旧规则随机计划，显示 728 + 48 = 776 条。修复以冻结的目标账号日计划为准，并同步累计未入队统计。

仅更新 `features/post_daily_report/{tt,plans,target_plans}.py`。候选目录从各自线上 release 复制，只覆盖这三个文件，保留 coordinator 已上线的事件查询优化、X tag 调度和其他线上差异。服务切换只涉及 coordinator；日报是定时 oneshot，下次自动执行使用新代码。用户明确要求不重发，此次不启动日报 service，也不调用 `--send` 或更正发送入口。

## 准备与验证

先提交并推送完整 GitHub commit，再从该 commit 取部署脚本执行：

```bash
python3 scripts/deploy_tt_report_target_plans.py stage --commit FULL_SHA
```

返回 `manifest`、`report`、`coordinator` 路径。stage 校验数据盘 UUID、余量、已核对的 live 文件哈希、GitHub FETCH_HEAD，创建候选并验证无关 Python 源码未变，执行只读模块导入。不会切换链接或服务。

用候选 report 的 `scripts/post_daily_report.py --date 2026-11-11 --preview --state-dir /mnt/data-disk/tt-report-target-plans-20261112/validation` 重算，预期 TT 应发 52 + 12 = 64，错误制造的 712 条未建任务消失。历史播报与发送回执不覆盖。使用隔离的 fixture 验证新旧随机、固定/手动排期和缺失证据；验证累计未入队不重复加入已存在运行。

## 激活与回滚

```bash
python3 scripts/deploy_tt_report_target_plans.py activate --manifest MANIFEST_PATH
```

激活前再次核对 live 链接与代码哈希，非阻塞持有日报 `run.lock`，保存 coordinator 调度健康快照。短暂阻止新的 coordinator HTTP 连接，等待已有连接和监听队列清空后正常停止服务，切换并启动。后台采集线程不按固定线程数量判断空闲。验证 HTTP 健康、恢复此前活动的依赖调度器后切换日报链接；保存新旧 PID、下一次日报时间及回滚命令。任一步失败尝试恢复原代码链接，保留所有业务数据库、租约、平台回执和播报记录。

回滚使用部署目录中的 `rollback.sh`，或：

```bash
python3 SOURCE/scripts/deploy_tt_report_target_plans.py rollback --manifest MANIFEST_PATH
```

只回切这次仍生效的代码链接；遇到后续部署会拒绝覆盖。原 release 目录即代码回滚点。回滚不恢复旧数据库、不重发播报、不重新执行历史发布任务。
