# FB automatic template capacity

## Current policy from 2026-11-20

FB Page templates can be enabled at any number of authorized Pages, estimated
jobs per slot, estimated daily jobs, or enabled templates. The same rule
applies to automatic planning, ordinary manual runs and resuming a slot for
upcoming Moboreels titles. The enable response reports the selected template's
Page and workload estimates. Each Page's configured frequency, authorization,
material reservations, cooldowns and publish locks still apply.

Explicit hit-material and hit-drama operations retain their own batch budgets.
The FB service ignores `FB_AUTO_MAX_ENABLED_TEMPLATES`. The first three values
below are still used by explicit batch operations.

## November 11 deployment record

The November 11 release applied the following four limits.

| Environment variable | Previous | Requested |
| --- | ---: | ---: |
| `FB_AUTO_MAX_PUBLISHABLE_PAGES` | 500 | 2000 |
| `FB_AUTO_MAX_JOBS_PER_SLOT` | 200 | 5000 |
| `FB_AUTO_MAX_DAILY_JOBS` | 1000 | 10000 |
| `FB_AUTO_MAX_ENABLED_TEMPLATES` | 10 | 50 |

The runtime previously rejected a configured slot limit above 1000 at startup.
That release accepted a slot limit up to 5000. Its configuration kept GPU
concurrency, publishing rate and saved template status at their previous values.

The November 11 deployment procedure included a backup of `/etc/fb-auto-post.env`,
a scoped FB owner switch, the four environment settings and restoration of the FB
scheduler baseline. The November 20 change ships as code and uses the existing
environment. Its rollback switches the FB owner to the previous release and
keeps the current template configuration and publication ledger.
