# 普通单位符号与文案错误定位

剧目事实中的 `50°C` 被生成正文沿用时，旧版 `one_line` 把 Unicode `So` 全部当作禁用图标，连温度符号也拒绝。一次重试仍引用相同事实，就继续失败并使用原文案。

校验现在保留度数符号、Letterlike Symbols 中的普通文字/单位符号（如 ℃、℉、℥）及 CJK Compatibility 方块单位（如 ㎏、㎞）。保留原文本，不把单位改写或删除。正文图标、控制字符、换行、井号、网址、模板标记、长度和语言等原有校验继续生效。

字符错误包含字段、首个不合格字符、Unicode 码点和从 1 开始的位置，例如：

`invalid_copy_field: opening: forbidden character '💔' (U+1F494) at 6`

缺值、错误类型、超长分别显示对应字段和原因；hooks 无合格候选时保留具体候选字段和字符，有合格候选则继续使用。详细原因沿现有 jobs/retries/告警路径保存，不新增表或整段模型输出日志。诊断保持在现有 120 字符传递长度内。

## 验证

`python -m unittest tests.test_story_copy -q`

覆盖真实故障形式的 50°C 正文入库和原生选稿、普通单位正文和引导语、非法字符定位、类型/空值/长度/网址/模板错误、合格 hook 继续使用，以及首次失败到单次重试和告警的完整诊断传递。

## 部署与回滚

基线为 `ce12a7e82a6fbe9bb032f51741d29bde0520d0f1`。先提交并推送 GitHub；服务器拉取确切提交到独立 source 目录。确认数据盘挂载 UUID 和空间后执行：

```bash
python3 -B ops/story_copy/deploy_unit_symbols.py prepare /mnt/data-disk/story-copy-deploy/unit-symbols-20261123
python3 -B ops/story_copy/deploy_unit_symbols.py apply /mnt/data-disk/story-copy-deploy/unit-symbols-20261123
```

仅将审核过的 `model.py` 覆盖到当前文案 release 的候选副本；保留当前其他文件。保存原 release、前后哈希、服务 PID 和 SQLite 在线备份。复用现有中央切换方式：本服务当前生成批次完成后，在领取事务锁内切换 `story-copy-worker.service`。发布器直接使用已验收的 opening/turn/CTA，不再次校验它们，因此本次不切换 FB、X、Tag 发布器或 settings，不改调度、队列、已完成文案和已发告警。

上线后核对 model 哈希、worker PID/cwd、无中断批次、其他服务 PID，使用冻结任务输入做不写生产账本的校验。历史失败项不自动重新生成或重发。

从同一 GitHub source 目录回滚：

```bash
python3 -B ops/story_copy/deploy_unit_symbols.py rollback /mnt/data-disk/story-copy-deploy/unit-symbols-20261123
```

只退代码；保留当前数据库、生成稿、最终用稿回执和发布事实。旧版本仍能渲染已验收的普通单位正文。
