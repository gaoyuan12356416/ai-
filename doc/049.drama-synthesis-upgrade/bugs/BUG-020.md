# BUG-020 已完成的小视频被缓存误判并重复制作

## 发现阶段

2026-08-27 香港 GPU dark release 的真实 HTTP 幂等验收，P1。CPU 正式流量尚未切入；仅影响本次隔离合成样本。

## 实际证据

- c719beb 的 auto job `0a7cd9dc5cc4a55e1e9b89c76b40c74e` 首轮完成三个素材，视频时长、codec、全帧解码及随机视频 150 帧均通过。
- 首轮 concat 为 691334 bytes，no-BGM 为 747754 bytes，random 为 3360149 bytes。
- 相同 job/payload 再次提交后重新下载、制作并覆盖同一 canary URL；no-BGM 变为 747760 bytes，random 变为 3129473 bytes。不是缺少 manifest：它已存在于 `/data/drama-synthesis-gpu/results/manifests/`。

## 根因

旧 `gpu_video_result_satisfies_outputs` 要求所有视频 HEAD 长度至少 1MiB，把两个合法小视频误判为不可用并进入重新制作。另一个独立的验收脚本错误是全 dict 比较：落盘 manifest 额外含 `updated_at`，即便缓存真正命中也会误报。

## 修复

- 新 GPU manifest 使用版本 2，只在真实制作完成、cleanup 前从对应固定产物文件记录 URL 与正整数字节数。旧 URL 推断分支不伪造新版本元数据。
- 新版本重放必须 HEAD=200、禁止重定向、Content-Length 与记录精确一致；缺字段、URL/长度不符、超时/5xx 均失败关闭，不降级成 cache miss，不覆盖已完成文件。历史无新版本标记的 manifest 保留旧 1MiB 行为，公共校验函数与 FB/X 均不改。
- 缓存返回前重新计算传入配方的规范化 SHA，并比对已保存 recipe SHA；冲突停止重制。只公开稳定业务字段，内部 manifest 元数据不进入缓存响应。
- 验收 v3 使用新固定 job，首次制作与重启后 replay-only 分阶段；除业务结果一致，还验证 manifest SHA/mtime 不变、workdir 不重建。旧 v1/v2 现场保留，不删除旧 job 伪装成功。
