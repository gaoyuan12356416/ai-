# BUG-027：专用 writer 建账号权限前提遗漏

- 类型：部署权限前提/运维流程缺漏，非应用代码问题。
- 优先级：P1；阻断专用 writer/RPC 部署及真实 canary。
- 状态：OPEN / BLOCKED。文档已纠正，待合法 DB admin 完成显式建账号与最小授权；不能据文档修复关闭部署阻断。
- 发现时间：2026-08-27 16:04:58（北京时间）。
- 证据来源：根代理通过 CPU SSH 的实机结果及独立隔离 MySQL 5.7.44 复现；本记录未另行访问服务器。

## 现象与证据

候选 `6e29ba8c07c75dea98caff4d1d2b4fba0ac9df1f` 已 GitHub/readback、CPU clean。16:00 fresh-table rehearsal 9 checks PASS，16:01:35 生产 63353 仅 CREATE 三张专用 `ads_ai` 表成功，结构完整兼容，apply 后管理员验证无 trigger/FK。16:06 正常读端 63350 核验各 0 行；原表零写。

16:04:58，实际 CPU `ads_aius@43.166.187.96` 调用一次精确新 writer GRANT，MySQL 返回 1410：`You are not allowed to create a user with GRANT`。该账号 `global CREATE_USER=false`。在隔离 MySQL 5.7.44，schema ALL + GRANT OPTION 账号同样复现 1410。

未把广权限管理凭据用于 runtime，新 writer/RPC 未安装、未启动；CPU 生产应用未切换，真实 YouTube 上传 0、评论 0，HK 未改。已成功建表与尚未建账号必须分别记录。

## 根因

先前部署说明从 `ads_aius` 持有 `ads_ai.* ALL PRIVILEGES WITH GRANT OPTION` 推断可通过 GRANT 隐式创建新 writer。schema 内建表/写入及授权能力，不证明具备全局账号创建能力；本次生产及隔离实例明确拒绝该操作。缺漏是部署前置权限验证，不是 `ads_ai` 缺少写权限，也不是应用代码或新三表 DDL 失败。

用户的新范围只允许 `ads_ai` 专用新表。旧 `kunlunads_dev` 迁移、旧表备份、旧 migrator 及旧 c719 演练均不是解除此阻断的条件，不能据此重新要求原库写权限。

## 改正与继续门禁

1. 合法 DB admin 将具备建账号及授权能力的管理连接配置保存到 CPU 的 root-owned 0600 文件，仅提供绝对路径。密码不得进入聊天、Git、命令行或日志；仅通过 SSH，不进入云控制台。
2. 只读核对目标实例、身份及精确账号 `drama_youtube_writer@43.166.187.96` 是否存在。已存在即停止核实来源、用途和授权，不 ALTER、重置密码、覆盖或默默复用。
3. 合法管理员先显式 CREATE USER，再分别向该账号 GRANT `SELECT, INSERT, UPDATE`，唯一范围为 `ads_ai.ads_youtube_videos`、`ads_ai.ads_youtube_comments`、`ads_ai.ads_youtube_publish_log`。不得授予 schema wildcard、DDL、DELETE、GRANT OPTION 或额外 routine/proxy 权限。
4. 不将 `ads_aius` 或管理连接交给 runtime。管理连接仍 root-owned 0600；专用 writer 文件为 `drama-youtube:drama-youtube` 0600。
5. 根代理读回真实 writer 身份、最小授权及 `drama-youtube-writer-preflight-v2` / `ads_ai` 健康合同，完成必要服务部署与验证后，才继续已授权的单次 unlisted 视频及一条评论。账号创建、RPC 健康和真实 canary 各自留证，不能互相替代。

## 验收与安全停止

本次只更新部署交接文档，不改应用代码，不重跑完整回归，不声称账号阻断已解除。关闭本缺陷需要合法显式 CREATE USER、精确三表授权和实际专用身份健康验证的证据；完整功能放行还需后续 CPU/YouTube 集成验收。

保留已创建的新表和现场证据，不 DROP/ALTER/DELETE，不为解除权限阻断复制或写原表，不重置既有账号。当前 CPU app 仍 `a956fb...675a3`（缩写），API PID 3841722 / job worker PID 1212，20 done、SQLite `quick_check=ok`、无 YouTube 账本。
