# BUG-025 飞书操作者 ID 被旧数字映射丢失

root 实机核对发现线上 user_id 是不透明字符串，HTTP 原样传入 SQLite TEXT；旧 outbox `_bounded_decimal` 将字母 ID 转为 0，新表初版还保留整数列。canary CLI 仅准正数也无法记录真实操作者。这是审计合同缺陷，未发生生产新表写入或 YouTube 测试。

修复后所有 operator_user_id 为原始字符串，新三表 VARCHAR(128)/utf8mb4_bin，不能截断/strip/lower/int；普通历史未知允许空，拒绝 Cc/Cf/Cs 控制字符。canary CLI、直接 store enqueue、持久记录读回与事务 claim、v2 payload 均要求非空安全 ID，在 OAuth/上传前拒绝旧坏记录。SQLite 既有 TEXT 和历史行不迁移。

验证包括真实 Feishu 形状、Unicode/空历史身份、控制/超长值、三类完整 payload、同 publish 更换操作者冲突、直接 store 绕过与遗留坏记录零 claim/OAuth。当前浏览器已确认管理员“郜远”；实机 canary 绑定其已核验 user_id，不能冒用测试 fixture 的数字或其他人员身份。最终独立回归见 [测试报告](../test-report.md)。
