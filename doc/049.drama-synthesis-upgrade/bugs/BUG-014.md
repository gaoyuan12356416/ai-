# BUG-014 数据库恢复演练门禁无法按实际范围执行

2026-08-27，P1。状态：代码修复/独立 QA 与真实三表恢复演练 PASS，候选 `c719bebf72be900ec3853858dc53b36b83beffd2`。仅本缺陷关闭；生产账号权限、生产 DDL/RPC 及全集群灾备不在此 PASS 内。

## 发现与根因

原迁移脚本仅接受生产固定端点，无法在隔离副本演练；备份 ID 的最短长度还会拒绝实际六位 ID。内部文档把全量收费云集群恢复作为唯一证据，但用户附件只要求本次三表的备份与恢复演练。

## 修复与真实证据

保留生产 host/schema/账号/权限硬门禁；新增三表同一 READ ONLY 一致性 snapshot，随后断开源连接，只在 CPU 127.0.0.1:23357 的独立 MySQL 5.7.44 schema/container/datadir 恢复。Docker 实际身份、镜像 digest、唯一 loopback 端口和数据盘挂载必须匹配；拒绝已有库、非空目录、symlink 或覆写私有文件。恢复后 dry-run→apply→第二次 apply 空计划→dry-run 空计划，三阶段 legacy 行/schema/index 哈希守恒、历史 external-id 全 NULL。
