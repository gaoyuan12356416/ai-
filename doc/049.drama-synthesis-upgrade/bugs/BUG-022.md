# BUG-022 CPU 模板目录查询仍依赖 GPU

## 发现与影响

用户在 2026-08-27 明确所有业务查询留 CPU，HK 只制作、上传 COS、回传结果。只读调用链审查发现 CPU `drama_random_template_catalog()` 在未配置本地素材时会代理 GPU catalog；这会让业务查询依赖制作端，也违背新的明确边界。未发现实际 GPU 业务数据库查询事件。

## 修复

候选 `40042f9692fbec58caa5abbf41af35e9aefb54bc` 新增 CPU 本地原始 manifest loader，严格文件/SHA/JSON/资产合同校验，保留与 FB/GPU 相同的四层 identity 和 315 组合。CPU 无配置或校验失败时脱敏 503，不请求 GPU，也不读取整包素材。HK 只保留制作相关的本地素材诊断。

## 验证及状态

- 实现者专项 16/16 PASS；已包含于独立七套唯一一次合并 204/204 PASS（13.639 秒），不相加。
- 独立另 15 项文件竞态/异常 JSON/no-fallback 对抗 PASS；3 文件 Python compile/3.9 AST、4 冻结 SHA、diff-check PASS，无新增 P0/P1。
- GitHub-first CPU 干净隔离 checkout，Python 3.9.6 真实 7921-byte manifest/精确 app 原函数验证：315、auto/manual 冻结与重复一致、错误配置 503，network/database/media-bundle tripwire 全 0。
- 缺口代码已修复并经隔离环境验证；CPU 正式代码/env/服务未切换。生产上线、HK 正式 COS 前缀激活及指定频道测试仍由既有数据库合法授权门禁阻塞。
