# BUG-016 香港 GPU 随机滤镜自动线程池超出服务上限

2026-08-27，P1，已关闭。线程限制适配已修复，当前 HK release `e1f5a1d04cfb510df9c2444ac592adec2827508b` 已 GitHub-first 部署，v3 真实 auto/manual 随机制作与重启后复用通过。正式发布仍受生产权限/激活配置门禁约束，但本线程故障不再是阻塞。

## 发现与根因

历史现象：片头/拼接/去背景音乐/COS 上传成功，随机成片返回 500。同一命令在普通服务用户进程下成功；在与制作服务一致的 TasksMax=128、CPUQuota=200% 中原命令 0.66 秒失败，FFmpeg 报 `Resource temporarily unavailable`。

原因：复用的 FB 多层滤镜图自动扩展线程池，超出独立剧集合成服务的线程数预算。

## 修复与复验

仅剧集合成适配器为该命令显式添加 `-filter_complex_threads 2`；不扩大系统线程限制，不改 FB 服务及其构图函数。历史 c719 合并回归为 166/166 与 25 文件语法/Python 3.9 AST PASS，不与最新 188 项相加；最新一轮为首次 187 PASS + 1 文档 FAIL、仅失败项修复后复测 PASS，另 27 文件语法 PASS，不能写一次整套全绿。

同沙箱对照及 c719 阶段 auto 制作曾通过，随后发现的重复 POST 幂等失败独立记为 BUG-020；它已在 e1f5 修复，不再沿用为未完成项。e1f5 的 v3 auto + manual 共 4 输出，两个随机均 720×1280/High/5 秒/150 帧，完整下载解码及封面 callback PASS。

真实重启 worker+tunnel 后，fixture HTTP 服务未运行时两 job 重复 POST 均 200，manifest SHA/mtime 不变、workdir 无重建；replay 单元 1.710 秒、Result=success。报告及 8 PNG 独立只读复核通过，非再次运行真机，证据见 [HK 实测](../hk-gpu-setup-20260827.md)。CPU 仍为旧 18787 且未部署/重启应用；生产权限与 HK canary→production 前缀配置/验收门禁见 [部署状态页](../deployment-status-20260827.md)，不影响本缺陷关闭。
