# X / FB automatic-template material products

Editors use `material_products` (a nonempty array), defaulting to `Dramawave`,
with `Moboreels` and `Moboshort` options. FB retains `DramawaveSource` and saved
custom values. Legacy single `material_product` values remain readable.

X freezes the scope in selection rules and uses it in both indexed source SQL
and material validation. FB applies it to ordinary, indexed, exact-material and
Moboreels-link source reads. Multiple products share the existing ranking.
Drama catalogs, metric products, release/language/media rules and deduplication
are unchanged. Historical config versions are not rewritten; frozen legacy
Moboreels-link runs retain their existing catalog scope.

Validation: `scripts/test_auto_material_products.py --platform x|fb`, focused
existing validation/selection suites and `node scripts/test_material_product_picker.js`.
The installer repeats backend checks against copies of the actual live runtimes.
No test posts or production template edits are needed.

Deploy from the pushed commit using `scripts/deploy_auto_material_products.py`
with actions `prepare`, `apply`, then `verify`, and a new data-disk `--folder`.
Only FB Auto and X Tag Auto are restarted, with their accepted-request drain and
prior scheduler states preserved. Static assets activate after backend checks.
The installer checks live hashes, saves changed files and online SQLite backups,
and preserves unrelated live variants. It never restores production databases.

Rollback: run the same committed installer with `rollback --folder DEPLOYMENT`,
then `verify --folder DEPLOYMENT`. Before rollback, revert any newly saved
multi-product templates through the supported editor or prefer a forward fix:
old code does not understand `material_products` and could select the old scope.
