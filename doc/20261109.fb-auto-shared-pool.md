# FB 自动发布模板共用 Page 池

两个新版模板选择同一 Page 池或包含相同 Page 时，原来会在启用、自动/手动建批次和指定素材发布时被拒绝。现在允许各自调度，实际执行继续使用原有同 Page 写入互斥、素材占用、冷却、防重与未知回执保护。

每批任务容量按当前模板的可发布 Page 数检查。原来把所有启用模板名义上的单批数量相加，会在队列已经独立后错误拒绝共用池。例如两个模板各 137 条、上限 200 时，每批均可接受；两模板总估算 274 仍返回用于展示。未提高环境容量值、GPU 并发、每日容量或模板数量上限。旧版独立系统的队列冲突、身份/授权和原有筛选条件保持原规则。

## 验证

```text
python scripts/test_fb_auto_shared_pool.py -v
python scripts/test_fb_auto_material_product.py -v
git diff --check
```

共享池六项用例覆盖：两个模板启用、各自建批和幂等、单批超限拒绝、同 Page 实际写入互斥、未知素材回执保护、指定素材发布。另六项素材产品回归用例覆盖保存回显与独立来源选择。

生产验收只读取模板与候选素材，不启用模板、不创建任务、不调用发布。选材为 0、查询失败和指标缺失分别记录，不能把未知当成 0。模板没有候选时仍按已有规则处理，不自动放宽语言、时长或上线窗口。

## 部署与回滚

分支 `codex/fb-auto-shared-pool-20261109`，先提交 GitHub，再在服务器检出精确提交执行：

```bash
python3 scripts/deploy_fb_auto_shared_pool.py prepare --folder /mnt/data-disk/fb-auto-shared-pool-20261109/deployment
python3 scripts/deploy_fb_auto_shared_pool.py activate --folder /mnt/data-disk/fb-auto-shared-pool-20261109/deployment
python3 /opt/publish-scheduler-health/current/scripts/publish_scheduler_health.py check --lane fb --output /mnt/data-disk/fb-auto-shared-pool-20261109/health-after.json
```

复制当前 FB runtime，仅替换三个 Python 文件和编辑页 HTML；主 API 和 Nginx 只同步该 HTML。保留文件备份、哈希、在线 SQLite 备份、服务切换与依赖恢复记录。使用已验证的局部请求排空，仅切换 FB sidecar，不重启主 API、不重置队列、不修改数据库结构或模板状态。

```bash
python3 scripts/deploy_fb_auto_shared_pool.py rollback --folder /mnt/data-disk/fb-auto-shared-pool-20261109/deployment
```

回滚只恢复代码与 HTML，保留当前任务、回执、凭据与配置，不恢复旧数据库。旧版会重新拒绝共享池模板的新批次，因此需要继续共享池时应保留本次行为或部署兼容修复；已创建的任务保持原执行保护。独立素材产品选择仍在回滚目标中。
