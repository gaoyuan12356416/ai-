# SA 需求评审

## 结论

通过。采用独立两阶段 ledger，不复用“原帖 published 即推进短剧”的旧语义。

## 问题与决策

| 严重级别 | 问题 | 决策 | 状态 |
| --- | --- | --- | --- |
| P0 | Repost 失败后重复上传会造成重复原帖 | `source_published` 为持久化栅栏，只允许继续 Repost | 已解决 |
| P0 | 原帖成功时旧逻辑会提前推进剧集 | 仅 `mark_reposted` 调用剧集推进 | 已解决 |
| P1 | 多进程按内存轮询或每日清零会失衡 | SQLite `BEGIN IMMEDIATE` 内按历史累计 ledger 数量选择 | 已解决 |
| P1 | 会员动态失效 | 原帖前二次验证；零尝试时才允许重选 | 已解决 |
| P1 | 受保护原帖无法被普通目标账号转发 | 中转源必须 `protected=false` | 已解决 |
| P1 | 旧 140s 确定性失败阻塞短剧池 | 仅零写入证据的记录加审计后恢复 | 已解决 |

## PM 修订确认

需求已纳入以上决策，并明确不部署、不真实发帖。
