# BUG-001 账户范围 JOIN 排序规则冲突

## 发现阶段

新 release 切换前的生产只读演练。

## 现象

账户范围加载成功，但 Campaign 候选 SQL 返回 MySQL 1267：两个账户 ID 字符串列的 collation 不一致，无法直接执行等值 JOIN。

## 复现步骤

1. 使用精确账户 SQL 加载 916 个账户。
2. 对 `2026-09-02` 执行 Campaign 候选查询。
3. 字符串 JOIN 在写库/API 调用前失败。

## 期望结果

只在精确账户范围内返回当天正消耗 Campaign，不依赖字符串 collation。

## 实际结果

查询返回 MySQL 1267，无任何数据写入。

## 根因分析

`ads_accounts_setting.account_id` 与 `ads_tiktok_insights.advertiser_id` 使用不同的隐式 utf8mb4 collation。

## 修复说明

两侧均转换为 `UNSIGNED` 后比较。生产账户 ID 已验证全部为十进制数字且处于 MySQL `UNSIGNED BIGINT` 范围。

## 影响文件

- `ops/tt-minis-bid-protection/tt_minis_bid_protection_sync.py`
- `ops/tt-minis-bid-protection/test_tt_minis_bid_protection_sync.py`

## 验证命令与结果

- 单元测试增加无 collation 字符串 JOIN 的契约断言。
- release `838b1c6cba12939f6307b1424f51335d67cf9722` 上复跑 `2026-09-02`：22,921 个 Campaign 候选、574 个有消耗账户、耗时 22.731 秒，查询成功。

## 回归结论

通过，缺陷关闭；修复在清表和正式回填之前完成。
