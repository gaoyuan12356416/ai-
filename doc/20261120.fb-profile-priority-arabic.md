# FB language matching with portrait priority

Explicit FB drama and material batches now keep every authorized language-compatible
Page. Positive audience/theme income ranks first; low sample size, no income, missing
classification, unavailable portraits and nonmatching portraits fall back without
excluding the Page. Language, authorization, material identity, cooldown, capacity,
publication receipts and operation idempotency remain enforced.

New frozen targets use `language_profile_priority_v2`. `profile_score` records real
evidence; `match_score=1` is a language-compatible allocation edge without evidence.
Positive evidence ranks above 1. Existing v1 frozen targets retain their exact scope.
X's selection policy is unchanged.

The shared dictionary adds 170 explicit Arabic aliases, including all nine labels
in the reported Arabic war-god drama. Unknown or semantically ambiguous labels remain
unmapped (for example “unknown” and dwarf; dwarf is not silently mapped to elf).
The dictionary does not infer audience gender. Existing semantic IDs and theme rules
are unchanged.

Validation: FB profile/receipt/drama/material tests, ordinary profile regression,
shared assignment and Arabic semantic equivalence. The receipt fixture's obsolete
single-item error retry assertion was aligned with the existing terminal batch UI;
unknown outcomes still retain the exact operation key for receipt reconciliation.

Deployment: push the commit, fetch that exact commit on CPU, then run
`python3 scripts/deploy_fb_profile_priority.py prepare --folder DEPLOYMENT` and
`python3 scripts/deploy_fb_profile_priority.py apply --folder DEPLOYMENT`.
The controller overlays only committed changed blocks on the current release,
preserving concurrent default-language and disabled-template manual-publish fixes.
It takes an online ledger backup, drains only FB, restores affected schedulers and
updates the shared dictionary plus FB UI. It does not restart the main API or X.

After the current portrait collector finishes, run
`python3 scripts/reclassify_fb_portraits.py --output DEPLOYMENT/portrait-refresh.json`.
This holds the normal refresh lock, rebuilds a new generation from the latest saved
input, verifies every Page's income/spend totals, writes through the normal portrait
storage and verifies the receipt before changing the serving pointer.

Rollback: `python3 scripts/deploy_fb_profile_priority.py rollback --folder DEPLOYMENT`.
It rejects rollback while accepted v2 drama plans remain unfinished, because the old
selector cannot read them. Publication databases are never restored. Immutable
portrait versions and the previous serving pointer remain available; a dictionary
rollback can be followed by the same reclassification command after the refresh lock
is free, without rewriting historical publication or financial facts.
