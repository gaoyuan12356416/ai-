# YouTube material picker loading

The previous sparse-uploader SQL fix restores the index but a 62-video list
still takes 16.214 seconds through the public API because every video waits
for drama title, synopsis and reference-cover resolution before being shown.

The picker now loads video cards without resolving those fields. Selecting a
card starts an exact-ID read through the existing authenticated materials API;
confirmation waits for that response. Switching selections and closing the
picker discard late responses. Submission still performs its existing fresh
material read and metadata/cover/link validation. Legacy clients keep the full
materials endpoint. Cold empty lists poll every 400 ms for five seconds, then
at the existing two-second interval; cache and worker limits remain bounded.

`youtube-material-cards.service` serves only the new card route on loopback
8851. Each request checks the existing main API bootstrap route with the same
Cookie and YouTube navigation/module authorization. SQL uses the existing FIFO
gate, fixed read-only replica, eight-second query deadline and two-worker cache.
Uploader options preserve the deployed login-history/email mapping. No tokens,
SQL writers, queue operations or publishing APIs are introduced.

The separate reader activates without restarting the main publishing owner or
draining unrelated in-flight X/YouTube tasks. Its source is an exact GitHub
worktree under `/mnt/data-disk/youtube-material-cards/releases/COMMIT`, linked
from `/opt/youtube-material-cards/current`. Only the new route, reader service
and the two static files (both live copies) are activated. The main API source
is not replaced; no hot reload is used.

Checks: source/index tests (including compact/full cache isolation and fresh
get), HTTP permission/delegation tests, real frontend VM tests for polling,
selection races, pending confirmation, cancellation and errors; existing
Moboreels source/UI tests. After activation, measure authenticated public cold
cards, warm cards, uploader scope/order, exact-ID full metadata, unauthorized
denial, public asset hashes and unchanged publishing PIDs.

Deploy from the fetched exact commit:

```
python3 ops/youtube-material-cards/deploy.py COMMIT
```

Backups and manifest: `/mnt/data-disk/youtube-material-cards/backups/SHORT_SHA`.
Rollback restores four static files, removes only the new exact Nginx route,
reloads Nginx and stops the read-only service:

```
python3 /opt/youtube-material-cards/current/ops/youtube-material-cards/rollback.py /mnt/data-disk/youtube-material-cards/backups/SHORT_SHA/manifest.json
```

Retain code, manifests and backups after rollback. Main API, publishers,
schedulers, SQL configuration, databases, queues and receipts stay intact.
