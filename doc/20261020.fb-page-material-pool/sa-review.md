# 架构与需求评审

结论：按下列约束实施；部署前必须再次独立复核实现与测试。

| 项目 | 风险与结论 | 实施要求 |
|---|---|---|
| 预约排序 | 旧page_sequence按选择顺序，会让未来素材挡住立即素材 | 预检/提交共用按计划时间+原顺序计算；保留旧协议 |
| 时点唯一性 | 配置重建或计划版本变化可能重放同一分钟 | 永久唯一键使用tenant+真实PageID+BJ日期+HH:mm，不含实例 |
| 事务边界 | 先拿素材再单独提交会留下孤儿或重复 | 槽/池项/配额/任务/链接同SQLite事务；外部读在事务外 |
| 跨槽顺序 | 单槽单batch使旧同batch前序检查失效 | 池项与task关联，claim额外检查同池更早未终态任务 |
| 发布身份 | 定时器没有Cookie，不能复用旧管理员标志 | 每次触发用内部受保护身份解析，复验当前账号/权限/邮箱/Page |
| 未知与失败 | unknown不能当失败换素材重发 | unknown暂停；确定坏素材消费槽进入异常；临时错误不丢素材 |
| 历史事实 | 生产已有1个成功任务及真实短链 | 迁移校验旧列旧行摘要；不回滚数据库、不重建链接编号 |
| 部署漂移 | 当前main app与分支基线不同 | 以线上SHA48975897...做纯函数定点插入，不整份覆盖 |
| 回退兼容 | 新任务可能需要新的池顺序/版本解释 | 功能开关关闭新入口/调度，保留兼容backend与事实 |

已在requirements/API合同及分工中明确上述约束。默认时间为北京时间，素材来自现有FB库，默认原片。
