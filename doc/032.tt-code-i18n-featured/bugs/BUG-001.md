# BUG-001 MySQL 5.7 不支持非捕获正则

## 严重级别

P0（会让分语言榜单整次刷新失败，但不会破坏旧 last-known-good 文件）

## 发现阶段

2026-08-05，生产只读 SQL canary。

## 复现

1. 使用 Python 风格 `(?:...)` 的语言正则构建全语言 Top SQL。
2. 在已验证只读源 MySQL 5.7.18-cynos 执行。
3. 数据库返回正则语法错误，无法生成候选。

## 根因

Python `re` 支持非捕获组，但 MySQL 5.7 的 `REGEXP` 引擎不支持该语法；同一个常量同时用于 Python 和 SQL 时未取两者语法交集。

## 修复

把语言正则改为兼容 Python 与 MySQL 5.7 的捕获组：

```text
^[a-z]{2,3}(-[a-z0-9]{2,8})?$
```

## 验证

- 单元测试固定断言 SQL 参数不含 `?:`。
- 生产只读 canary 返回 2,197 个正消耗候选、22 个语言桶，耗时约 2.5 秒。
- 未写生产数据库、缓存或服务状态。

## 状态

已修复并回归通过。
