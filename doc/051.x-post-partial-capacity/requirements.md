# X 素材池与短剧池可用子集及时发布

## 背景

素材池或短剧池数量少于排程账号数时，旧实现要求候选数量与账号数量完全相等。即使池内已有正常内容，也会将整个时间点记为预检失败，导致所有账号等待。

## 目标

到达排程时间后，只要池内存在至少一条正常、可用且满足账号发布约束的内容，就立即为可发布子集建队列并执行；容量不足只影响缺少候选的账号。

## 范围

### 包含

- 素材池排程按当前可通过预检的候选数量发布。
- 短剧池排程按当前可分配且通过预检的剧集数量发布。
- 缺少前序账号候选时，后续已有绑定短剧的账号仍可发布。
- 冻结计划查询、重入、完成计数和内部接口接受配置账号的有序子集。
- X Auto 指标定时器恢复并验证自然执行。

### 不包含

- 不放宽语言、合规、来源标签、去重、账号授权、Premium、长视频、未知结果或幂等约束。
- 不改变手动发布、粉丝池发布和 X Auto 的业务选择规则。
- 不为测试创建额外的非计划 X Post，不自动补发历史失败批次。

## 用户故事 / 业务规则

1. 配置账号为 `A,B,C`，只有两条正常素材时，为两个匹配账号建两条队列，不等待第三条。
2. 短剧只有一个可用剧集时，至少发布这一条；账号列表前部没有候选时，不得遮蔽后部账号已有的绑定剧。
3. 某条候选媒体预检失败时，继续扫描或处理其他正常候选；零条候选通过时仍为 `failed_preflight`。
4. 新候选账号必须是冻结配置账号的非空、有序、不重复子集。
5. `account_ids_json` 保留完整冻结配置范围，`expected_count` 与本次实际队列数一致；容量说明写入 `error_message`，正常部分发布不设置失败错误码。
6. 已建队列重入时只发布原冻结队列，不重新选材；未知结果仍立即停止。

## 技术设计

### 影响模块

- `scripts/x_post_schedule_runner.py`：候选预检、子集校验、计划请求与发布。
- `features/x_posts/drama_selector.py`：接受配置账号的有序子集。
- `features/x_posts/service.py`：短剧缺口遍历、原子建队列、FIFO 复核、冻结批次计数。
- `features/x_accounts/oauth_service.py`：已有请求结构无需变更，继续对实际候选逐账号复核。

### 数据结构

无 DDL。沿用 `x_post_schedule_run`：

- `account_ids_json`：完整配置账号范围。
- `expected_count`：本次实际冻结队列数，范围 `1..len(account_ids_json)`。
- `queued_count/published_count/failed_count/unknown_count`：仅统计实际队列。
- `error_message`：部分容量中文说明；`error_code` 保持空值。

### API / 接口

- `POST /internal/posts/schedule-plan` 的 `account_ids` 与 `candidates` 改为实际有序子集。
- `POST /internal/posts/schedule-plan/query` 的 `run.account_ids` 仍返回完整范围，`queues` 可为有序子集。
- 外部管理接口和页面请求结构不变。

### 异常与边界

- 零正常候选：记录既有素材/短剧 shortage 或 preflight shortage，队列数为 0。
- 候选乱序、越权账号、重复账号：拒绝建计划。
- 较新素材因本轮已记录的语言/标签/长视频能力原因不可发：允许继续选择后续正常素材；过期或缺失的跳过证据仍拒绝。
- 短剧已绑定账号不可串换；未绑定短剧继续保留同语言账号间既有合法分配能力。
- Sidecar/数据库整体不可用、存储不可用或未知发布结果：仍整批失败关闭。

## 验收标准

- 素材池 1/2、短剧池 1/2 均能创建并完成 1 条队列。
- 配置 `[2,3,4]` 可接受 `[2,4]`，拒绝 `[4,2]`、重复或范围外账号。
- 短剧账号 2 无剧、账号 3 有绑定剧时，账号 3 候选仍返回。
- 无 Premium relay 的长素材不会阻塞后续正常短素材。
- 部分队列全部发布后批次状态为 `completed`，计数等于实际队列数。
- 零候选、去重冲突、未知结果和账号归属冲突保持失败关闭。
- 完整 X 回归、生产数据库副本演练和自然 timer 验证通过。

## 风险与待确认

- 部分容量意味着一个时间点可能少于配置发布量，这是本需求明确接受的结果。
- 候选在预检与原子建计划之间发生变化时，存储层仍会拒绝并留待下一自然时间点。
