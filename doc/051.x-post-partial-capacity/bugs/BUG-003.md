# BUG-003 历史可复检错误恢复后仍被 FIFO 拒绝

## 现象

素材曾记录 `material_not_video`、`material_not_found_or_ineligible` 或 `material_inactive`，当前源数据已恢复正常并通过预检，建计划仍报 `x_post_pool_fifo_conflict`，队列为 0。

## 根因

候选查询允许这些历史错误重新接受检查，但原子 FIFO 重放未纳入它们；成功预检也没有安全路径在建计划前清除旧错误。

## 修复

原子 FIFO 查询纳入可复检记录。只有本次 prepared 中已通过完整预检的候选可继续，并在同一事务内条件清除旧错误后建队；未成为成功候选的可复检记录仍不能被跳过。

## 验证

- 三种历史错误当前恢复正常均可建队并原子清错。
- 三种历史错误未复检成功时均返回 `x_post_pool_fifo_conflict`，零队列且保留原错误。
- 事务后置失败仍由 SQLite 回滚，避免只清错不建队。

不调用真实 X 写接口。
