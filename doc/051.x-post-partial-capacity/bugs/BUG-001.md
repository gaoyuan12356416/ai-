# BUG-001 池内有正常内容但整个排程不发布

## 发现阶段

2026-08-20 生产发布异常复核。

## 现象

短剧池可用数量少于配置账号数时整个时间点 `failed_preflight`；素材池同样要求凑齐全量账号，导致已有正常内容等待。

## 复现步骤

1. 配置两个发布账号。
2. 池内只保留一条正常且满足语言/账号能力的候选。
3. 执行到点 schedule runner。

## 期望结果

立即为可用账号创建一条队列并发布，另一账号本时间点跳过。

## 实际结果

调度器以 shortage 终止，存储层也拒绝候选数少于账号数，队列为 0。

## 根因分析

- Runner 在素材和短剧候选阶段强制 `len(candidates) == len(accounts)`。
- 短剧分配遇到第一个无候选账号使用 `break`，隐藏后续绑定账号。
- 计划请求、查询验证和 SQLite 原子建计划均强制队列账号等于完整配置账号。
- 长素材缺少 Premium relay 时旧 FIFO 规则阻止继续扫描后续正常素材。

## 修复说明

改为配置账号的非空有序子集；完整范围继续冻结审计，实际队列数写入 `expected_count`。短剧缺口继续遍历，候选级预检失败不再阻塞其他正常候选，零候选仍失败关闭。

## 影响文件

- `scripts/x_post_schedule_runner.py`
- `features/x_posts/drama_selector.py`
- `features/x_posts/service.py`
- 对应 X 测试文件

```powershell
python -m unittest scripts.test_x_post_drama_selector scripts.test_x_post_schedule_runner scripts.test_x_post_material_random_relay scripts.test_x_post_multi_schedule_store
```

结果：专项 138/138、完整 X 回归 715/715（2 条条件跳过）通过。

## 回归结论

专项通过；完整回归和生产验收完成后关闭缺陷。
