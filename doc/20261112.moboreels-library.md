# Moboreels 短剧库

AI 后台通过 `/moboreels-library.html` 提供独立短剧库。目录默认显示上架剧目，每页 50 条，按来源上架时间倒序；支持名称或来源剧目 ID 搜索、语言、上下架、剧目类型及音轨类型筛选。详情包含简介、网盘资料和本人推广链接。未知语言编号保留并显示为“未知语言（编号）”。

## 权限和接口

模块权限为 `moboreels_library`：管理员默认拥有，普通用户在用户管理中分配。查看、手动同步和生成本人链接均检查现有 Cookie 登录、模块权限和导航访问权限；写请求还检查同源 JSON。前端不能传入租户、达人或其他用户身份，POST 请求体只接受 `{}`。

接口前缀为 `/api/moboreels`。路径中的 `story_id` 是上游短剧 ID，不是本地表自增 ID。

| 方法和路径 | 用途 |
| --- | --- |
| `GET /dramas` | 列表；`page_index`、`page_size`（最大 100）、`search` 或 `q`、`lang_id`、`is_show`、`local_type`、`audio_type` |
| `GET /dramas/{story_id}` | 剧目详情及本人推广结果 |
| `POST /sync-runs` | 返回新任务或正在运行的任务，HTTP 202 |
| `GET /sync-runs/latest` | 最新任务和最近成功时间，页面刷新后可继续查看 |
| `GET /sync-runs/{run_id}` | 指定任务进度 |
| `GET /dramas/{story_id}/promotion` | 查询本人已有结果 |
| `POST /dramas/{story_id}/promotion` | 创建或复用本人结果；创建中返回 HTTP 202 |

`is_show` 默认 `1`，`0` 表示下架，空字符串或 `all` 表示全部。业务结果还须检查响应中的 `promotion.status`，不能只凭 HTTP 200 判断创建成功。

## 目录同步

`moboreels-library-sync.timer` 使用 `OnCalendar=*-*-* 09:00:00 Asia/Shanghai`，每天北京时间 09:00 触发。`Persistent=true` 会补触发服务停机期间错过的定时任务。定时触发与页面“立即更新”共用运行中的独立服务和任务锁，不另起一套同步逻辑。

每轮完整获取 `project_type=2, status=0` 的全部分页，校验总数、页大小及唯一剧目 ID 后冻结快照和更新计划，再写入 `ads_ai.cdreader_koc_drama`。取数不完整时不改目录。没有变化的记录只更新同步时间和批次；更新记录使用小批事务，定期重建写连接。

上架资料按来源更新；下架资料中的空值、`-`、语言 `-1` 等占位值保留已有有效值。上下架状态、最新 `raw_json` 和同步信息继续更新。本轮未返回的旧记录不删除，也不据此判为下架。

运行记录保存在 `sync.sqlite3`，分页和冻结计划保存在 `sync-runs/`。重启恢复活动任务；写入或校验失败且已有完整快照时，下一次启动可续跑原任务。数据库写超时先从只读端对账，只补齐未确认写入的部分。完整读回校验通过后才标记成功。失败任务保留已提交进度；新增、更新和上下架变化统计来自冻结计划，不能将失败任务的计划数视为全部已完成。

## 推广归属与回执

达人 ID 由机构、登录会话的租户和用户 ID 确定性生成，长度为 32 字符；改名不改变归属。按机构、达人、业务类型及上游剧目 ID 唯一保存，历史接口测试达人不归并到正式用户。

创建前先在 `promotions.sqlite3` 保存请求和唯一占位；同一组合的并发请求返回同一状态。供应方响应先写入 `promotion-receipts/` 耐久回执，再通过后台 outbox 镜像到 `ads_ai.cdreader_koc_promotion`。MySQL 暂不可用时仍可复用本地已成功结果。两张业务表字段使用中文备注。

`succeeded` 直接复用；`creating` 等待结果；`unknown` 暂停该用户和该剧目的再次创建。超时、响应异常等不能确定未创建的情况不得自动重发。下架剧目只能读取已有结果，不创建新链接。

管理员先在供应方平台核实未知结果，再在 CPU 上使用 CLI，必须记录处理人与核对依据。确认已经创建时补录原链接；确认没有创建时将状态改为允许用户显式重试。CLI 本身不向供应方重新发起创建。

```bash
cd /opt/moboreels-library/current
python3 -m features.moboreels_library.cli resolve \
  --star-user-id '<记录中的达人ID>' --story-id '<来源剧目ID>' \
  --decision created --operator '<处理人>' --evidence '<核对依据>' \
  --koc-code '<原推广口令>' --deep-link '<原剧目链接>' --home-link '<原主页链接>'

python3 -m features.moboreels_library.cli resolve \
  --star-user-id '<记录中的达人ID>' --story-id '<来源剧目ID>' \
  --decision not-created --operator '<处理人>' --evidence '<核实未创建的依据>'
```

## 运行维护

CPU 主机为 `43.166.187.96`。独立服务仅监听 `127.0.0.1:8864`，主 API 通过内网凭证转发可信会话身份；不公开内部调度接口。服务器配置为 `/etc/moboreels-library.env`，限制为仅服务管理用户可读，机构 Token 不进入前端、Git 或日志。MySQL 凭证可复用主服务受限配置。

默认持久化目录为 `/mnt/data-disk/moboreels-library`，当前部署通过 `MOBOREELS_DATA_DIR` 配置为其 `data/` 子目录，包含同步记录、快照、推广请求和回执；服务启动检查数据盘 UUID。常规读取走 63350 与现有 SQL FIFO，63353 只写指定业务表。

```bash
systemctl status moboreels-library.service moboreels-library-sync.timer --no-pager
systemctl list-timers moboreels-library-sync.timer --all --no-pager
systemctl show moboreels-library-sync.timer -p NextElapseUSecRealtime
curl --fail http://127.0.0.1:8864/health
journalctl -u moboreels-library.service -n 50 --no-pager

# 立即将一轮同步提交到现有服务；不等待全轮业务完成。
cd /opt/moboreels-library/current
python3 -m features.moboreels_library.cli sync
```

定时 oneshot 成功仅表示任务已提交。全轮成功以页面任务状态、完整校验结果及 MySQL 读回为准。

## 部署与回滚

以实际线上文件为基线，在独立分支验证并提交 GitHub；CPU 拉取精确提交后，执行该版本的定向安装器。部署记录保存真实提交、变更前文件备份、服务状态和验证结果。安装同时覆盖主 API 和 Nginx 使用的静态文件，仅重启激活变更所需服务。主 API 重启前后检查受影响的发布调度依赖，恢复此前运行的依赖并保留已有暂停状态。

```bash
python3 deploy/moboreels_install.py \
  --deployment /mnt/data-disk/moboreels-library/deployments/<部署时间>
python3 deploy/moboreels_activate_routes.py \
  --deployment /mnt/data-disk/moboreels-library/deployments/<部署时间>-routes

# 使用相应部署产生的回滚脚本；执行前核对没有覆盖更新的其他部署。
python3 /mnt/data-disk/moboreels-library/deployments/<部署时间>-routes/rollback.py
python3 /mnt/data-disk/moboreels-library/deployments/<部署时间>/rollback.py
```

回滚恢复代码、静态资源和服务配置，保留两张 MySQL 业务表、SQLite 请求账本、同步快照和推广回执。不以旧数据库备份覆盖新回执，不删除已创建的推广链接。
