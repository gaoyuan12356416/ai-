# FB 自动发布模板允许跨产品 Page 池

保存模板时不再要求所有 Page 池属于同一产品，也不再要求 Page 池标签为 Dramawave。Page 池只决定可用的 Page；保存接口仍验证池存在且在当前用户权限范围内。

保留原素材来源默认值 app 1479 / Dramawave / data_source 6，`material_product` 继续单独选素材产品。已有 `{{m_url}}` Moboreels 分支和归因不变。此次不扩展其他产品的指标或短链能力，也不修改模板、任务、短链、租约、发布回执或未知结果。

针对性测试覆盖混选、单独非 Dramawave 池、缺产品标签的池、越权和不存在的池、空选择，以及 HTTP 创建/更新/版本冲突。测试库独立、模板默认停用、无发布任务。连同既有模板校验共 11 项。

部署遵循 GitHub-first。`scripts/deploy_fb_mixed_product_pools.py prepare --folder DIR` 从当前 FB 运行目录复制候选，仅覆盖当前基线已核对的 service.py，并对 HTML 两处文字做精确替换，保留线上已有的 Moboreels、文案和折叠排期改动。主 API 的 service.py 仅同步同一个方法，不重启主 API。候选再运行 11 项测试。

`apply --folder DIR` 复用既有 FB HTTP 排空切换，保留在途任务，只暂停必要触发器，随后恢复并检查 FB 调度。主 API 和 Nginx 页面副本一并更新。原 FB 目录和受影响外部文件备份记录在 manifest。`rollback --folder DIR` 使用同一排空流程回退代码，验证文件没有后续修改；始终保留最新业务数据库和回执。

本地基础分支未打包 `features.moboreels_library`；本地测试通过独立 test-support 目录加载已提交的 `bb94026d` 依赖，未将依赖改动混入本次补丁。上线前测试使用实际运行副本已有依赖。
