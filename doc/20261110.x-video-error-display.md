# X 个人发布失败原因展示

发布进入队列后的具体错误保存在发布日志，而个人批次读取此前只取运行级错误，导致 Excel 行只显示“失败”。修复逐任务优先读取日志错误，缺少日志错误时保留运行级原因；成功、未知结果和队列状态规则不变。

本次观察到 X 在媒体初始化阶段明确返回账号暂时锁定。账号持有人需要在 X 登录并完成验证，页面修复不解除平台限制，也不自动重试历史发布。

## 验证与发布

运行 `python scripts/test_x_video_publish_core.py`，验证日志原因展示、运行级回退和未知状态等受影响契约。先提交并推送 GitHub，在 CPU 服务器的干净源码目录 fetch/checkout 精确提交，再执行：

```bash
python3 scripts/deploy_x_video_error_display.py --phase prepare
python3 scripts/deploy_x_video_error_display.py --phase drain --folder BACKUP_FOLDER
python3 scripts/deploy_x_video_error_display.py --phase status --folder BACKUP_FOLDER
python3 scripts/deploy_x_video_error_display.py --phase switch --folder BACKUP_FOLDER
```

`prepare` 返回 `BACKUP_FOLDER`。只合入 `core.py`/`service.py` 中实际改变的文件及对应测试，保留运行时其他覆盖。仅暂缓 X 入队并让在途请求正常结束；`status` 或 `switch` 返回 waiting 时，等待相关 X 任务完成后再次 switch，不能结束在途任务或清理未知结果。取消切换使用 `--phase abort`。

进度 API 由 X sidecar 处理，主 API 只代理请求。同步主 API 目录副本以保持后续发布一致，但不重启主 API。切换重启 X owner，恢复其此前运行的 Auto 和个人池调度依赖；使用 X lane scheduler snapshot/restore 核验。备份代码、SQLite 和 token 采用既有 scoped deploy 实现，均在数据盘。

上线验收读取原批次详情，确认失败行带有原始脱敏原因；核对 X/Auto health、个人池调度、下一次 timer trigger 及主 API PID。不要为验收创建测试帖子。

## 回滚

使用部署记录中的精确 GitHub 源码目录执行：

```bash
python3 scripts/deploy_x_video_error_display.py --phase rollback --folder BACKUP_FOLDER
python3 scripts/deploy_x_video_error_display.py --phase switch --folder BACKUP_FOLDER
```

同样等待受影响的 X 在途请求完成。回滚仅恢复原代码及主目录对应文件，保留当前业务数据库、队列、回执、授权及已轮换凭据。日志展示回退不会改变真实发布结果。
