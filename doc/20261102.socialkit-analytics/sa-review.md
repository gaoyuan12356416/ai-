# 设计审查

审查结论：方案可实施，以下具体正确性要求纳入实现与验收；不增加与本需求无关的业务门禁。

| 关注点 | 依据与决定 | 验证 |
|---|---|---|
| 短链归属 | 直接用任务表短码曾只覆盖少量收入；短链主表已验证覆盖整盘收入 | 精确短码关联、源控制总额守恒 |
| 平台转换 | 短链 1/2/3/4 与任务/账号 3/1/4/2 不同 | 单元覆盖各平台及未知值 |
| 时间口径 | 收入只有 UTC 日，任务为账号当地日 | 页面标明两种口径；近14日重算迟到状态 |
| 多团队 | 可见账号包含多个团队，不能硬编码团队2 | 全范围团队发现、全量授权报表 |
| 查询效率 | 收入有 channel+dt 索引，无 updated_at 索引 | 日范围读取、源查询 EXPLAIN/实测；前端只查本地快照 |
| 一致性 | 来源可能失败，退款会修正历史 | 新批次完整核验后发布；失败读旧版，不做金额累加 |
| 写入边界 | 中间表写入已由本次计划授权 | 仅3张专用表，源只读，运行不执行DDL |
| 访问范围 | 用户明确授权用户可看全部报告 | 独立模块权限；不可复用旧个人归属规则 |

具体实施结果、部署检查和剩余问题由测试报告记录，不能把本设计审查当成代码已通过测试。
