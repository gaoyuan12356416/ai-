# 多语种 CTA 前缀、剧情引导句与指定失败文案补齐

共用文案生产器用于 FB、X 素材池、X 短剧池和 X 标签模板。CTA 前半句固定为 `👆 watch full now`，其他语言使用 `model.CLICK_PREFIX` 中的译文，后半句由模型根据当前剧情生成简短引导。例如 `👆 watch full now to see who hid the seal`、`👆 立即觀看完整版，看她反擊`。保留原有指示符、链接、剧情、标签和分集标题排版。新 draft 带 `cta_style=watch_full_now_hook`，继续保留已运行发布器理解的字段，因此只需切换独立文案 worker。

自动重试仍为原有的一次：首次失败进入下一就绪批次，没有新批次则 60 秒后重试；第二次失败终结并告警。本次不增加自动重试次数。

`ops/story_copy/repair_drafts.py refresh-cta` 预览尚未定稿的待发文案，添加 `--apply --audit /mnt/data-disk/.../refresh.jsonl` 更新前缀并保留已有剧情引导句。`--restore-hooks-from` 可读取本次之前的 CTA 更新审计，恢复其中保留的原引导句。缺少引导句的草稿交给 `refresh_click_hooks.py` 根据现有正文单独补齐。检查原生用稿回执并比较中央记录版本；原生已冻结正文始终优先。记录每条更新前后信息；繁忙记录单独 deferred，可再运行，不重新生成剧情。

`regenerate --key TASK_KEY` 只处理显式指定的未定稿失败记录。模型生成并校验后，使用独立 `operator_regeneration` 批次补齐 ready 文案。保留原自动重试的失败批次、次数、原因和告警事实，不修改原生发布队列、不调用发布 API、不回放历史发布。已冻结或并发变化的记录不覆盖。运行前备份中央数据库；原始审计文件仅保存在服务器私密目录。

## 部署与回滚

从 GitHub 拉取精确提交后：

```sh
python3 ops/story_copy/deploy_watch_full.py prepare /mnt/data-disk/story-copy-deploy/watch-full-COMMIT
python3 ops/story_copy/deploy_watch_full.py apply /mnt/data-disk/story-copy-deploy/watch-full-COMMIT
```

部署核对当前生产源与父提交一致，备份中央数据库，等待在途文案生成完成，再仅重启 `story-copy-worker.service`。发布器、设置服务和调度不重启。

代码回滚将同命令的 `apply` 改为 `rollback`。保留当前数据库、补齐文案和发布回执；已补齐的固定 CTA 可被旧发布器正常使用。若另行要求撤回待发 CTA 修改，只按审计逐条比较当前 draft 与记录的新值且仍未冻结时恢复旧 draft，不能整库恢复覆盖后续发布事实。

验证：`python -m unittest tests.test_story_copy`，覆盖四入口、语言别名、十语种正文长度、固定前缀加剧情引导、一次重试、原生冻结保护、恢复后保留自动重试历史及并发版本保护。
