# Moboreels 新剧预扫与小时同步

当前导航里的 X 标签画像和 FB 自动模板支持包含未来天数的时间窗。填写 `-1~0` 表示从扫描时刻到未来 24 小时，含两端。仍按各模板的产品、账号或 Page、语言、频次和素材要求运行。

## 选剧与等待

- 新运行按 `app_id=2373` 和 `content_id` 记录各语言版本。已知可投放时间优先，已经上架的剧读取首次上架时间，尚未上架的剧读取计划上架时间。重复包的有效时间、语言须能确定。预扫会记录当时同语言来源视频数量及样例 ID，最终选材重新查询。
- 到点按已记录的剧目身份重新检查当前排期、机构、短剧业务、上架状态与语言。如果延期，随当前排期顺延。供应方尚未更新或同语种素材尚未入库时，原账号或 Page 的名额继续等待。等待期间没有媒体队列或发布请求。
- 具备条件的账号和 Page 可独立进入原发布流程。跨日释放的自动名额计入实际使用日的模板频次。同一时隙反复扫描或重启沿用相同身份、预占和发布回执。
- X 在原生选材任务中记录等待原因与下次复查时间。FB 在运行的 Page 快照及 `waiting_pages` 中记录等待状态，素材就绪时再创建该 Page 的原生任务。原有 `0`、纯历史窗口、显式爆款入口和已经创建的旧运行继续使用各自的规则。
- Moboreels 剧库每个北京时间整点使用原同步服务更新。同步在途时沿用原任务与互斥锁。单次数据量影响完成时间，到达整点后以供应方上架回读和实际同步结果为准。

## 发布与回退

CPU 服务器部署目录为 `/mnt/data-disk/mobo-upcoming-20261120`。按 GitHub 的精确提交准备 X 和 FB 独立副本。部署工具保存每个服务的原版本、在途身份、只读模板指纹、SQLite 在线备份及调度状态。线上数据库继续向前记录当前业务。

```bash
python3 -B "$SOURCE/scripts/deploy_mobo_upcoming.py" prepare --lane x --folder "$RELEASE/x"
python3 -B "$SOURCE/scripts/deploy_mobo_upcoming.py" prepare --lane fb --folder "$RELEASE/fb"
python3 -B "$SOURCE/scripts/deploy_mobo_upcoming.py" apply --lane x --folder "$RELEASE/x"
python3 -B "$SOURCE/scripts/deploy_mobo_upcoming.py" apply --lane fb --folder "$RELEASE/fb"
```

按需要对同一渠道执行 `rollback`。若已有新版等待任务，先让这些任务完成或使用原模板的取消流程核对其结束。保留新表、等待账本、原生任务、素材预占、已发送内容和回执。目录同步 timer 和静态说明分别可用 `ops/mobo_upcoming/catalog_timer.py rollback`、`ops/mobo_upcoming/catalog_label.py rollback` 加各自备份目录独立恢复。
