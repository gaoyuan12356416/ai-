# BUG-002 续跑批次按 action 拆成多张日志卡

## 发现阶段

生产页面回归，2026-07-15。

## 现象

同一规则同一业务日的每个200条安全批次各显示一张主卡；运营无法直接看到当天最终状态。

## 复现步骤

打开 `/ad-control-logs.html`，筛选 dramawave 和目标规则组，观察2026-07-14/15的连续 action。

## 期望结果

按业务日和稳定规则身份合并为一张日卡；底层 action/preview 保留在批次清单中。

## 实际结果

列表按 action_id 渲染，一批一卡。

## 根因分析

API 在 action limit 后只按 action_id 合并MySQL/SQLite，前端也逐 action 渲染，没有日级只读聚合层。

## 修复说明

已实现 `view=daily`、有界完整分组和日卡片；保留 `view=raw`。主卡不读取 `results_json`，逐批展开时复用原 `/targets` 接口。

## 影响文件

`service.py`、生产补丁、日志JS/CSS、HTML缓存版本和测试。

## 验证命令与结果

`python -m unittest discover -s tests -p 'test_*.py' -q`：59项通过；生产同源app SHA与现网一致，补丁首次changed、二次unchanged且compile通过。

## 回归结论

本地与生产同源演练通过，待线上页面回归后关闭。
