# Meta 删除任务核验恢复

## 问题与目标
Video 的全局正则查询超过 180 秒，34 个对象保持阻止；Creative 权限错误缺少详细提示及实际凭证追踪。修复查询路径、支持原任务只读重核验，保留固定对象、成功记录及人工删除确认。

## 方案
- 单次 gated MySQL SELECT 流式读取全部未删除视频引用，在数据盘生成 SQLite Video→Ad 索引；覆盖全部产品和账户，完整解析 scalar/CSV/JSON。
- 数据代次仅在 EOF、完成标记、零退出码、索引写入与完整性检查全部通过后原子发布。任何未完成/未知格式均不放行。
- 快照有效期从读取开始算 600 秒；Video 执行阶段强制新建代次，每个对象在 Meta GET 后、DELETE 前再次校验有效期。无可靠 CDC 时不使用 updated_at 增量作为删除证据。
- POST /jobs/{id}/recheck 异步且幂等，只读 Meta/源库；仅重核验原冻结对象。成功项、未知项、历史 Post 不重试。归属冲突等永久阻止项需重新预览。
- 元数据记录重核验进度；重核验与删除执行互斥，重启后人工恢复。
- Graph 保存白名单脱敏错误、实际凭证用户、账户状态；不推断错误子码、不轮换 Token 重发 DELETE。
- 保持 Creative→Ad→Video、独立阶段及单对象失败继续的既有约定。所有真实删除由操作人在页面再次确认。

## 非目标
不修改业务源库及索引结构，不变更账户权限，不恢复停用账户，不自动执行失败对象删除。
