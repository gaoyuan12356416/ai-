# Moboreels 收益与社媒推广

## 使用

- 在「数据报表 → Moboreels 收益报表」查看订单充值、退款、订单净额和广告收益，可按日期、短剧、推广口令汇总。管理员可查看机构数据，普通用户仅查看本人推广。
- 用户管理新增 `moboreels_report` 权限，普通用户默认关闭。剧库权限仍为 `moboreels_library`。
- 报表每日北京时间 10:00 同步最近 31 个完整查询日，也可点击立即更新。原短剧目录仍每天北京时间 09:00 更新。
- 在 X、TikTok、Facebook、YouTube 的发布文案或模板中插入精确宏 `{{m_url}}`。YouTube 转发 X 同样支持。
- 素材的来源剧 ID 必须是 Moboreels 上游 `story_id`；它不是素材 ID，也不是原有 Dramawave 内部剧 ID。
- 推广归属采用发布任务、素材池或模板冻结的创建者。姓名变化不改变归属，不能指定其他用户。
- 预览不创建推广。执行前生成或复用该用户与该剧目的推广，保存短链、文案及任务关联；重复执行复用冻结结果。
- 使用 Moboreels 宏时不混用旧 `{url}` / `{{url}}`；旧广告消耗、ROAS 和爆剧筛选不能直接套用 Moboreels 的剧 ID。

## 金额与归因

订单接口 `getorder` 返回美元；广告接口 `getadlist` 返回美分（允许小数），精确除以 100 后以美元展示。订单净额为已核对的充值金额减退款金额，不是佣金。

供应方当前文档及真实推广回执没有独立的推广链接 ID。使用供应方口令 `code/koc_code` 关联本地成功推广记录，并保留本地推广记录 ID、稳定推广关联键、请求 ID。社媒短链另外保存平台、账号、任务、素材和创建者，用于追溯发布来源。

同一用户、同一短剧复用推广口令，可能对应多条社媒短链。广告收益只按来源日期与口令计一次，不能据此将同一笔收入分别计入多个渠道或帖子。无法唯一匹配的金额保留为待归因。

供应方未说明统计时区。报表保留来源日期，查询时间戳按 UTC 构造，不冒称北京时间统计日。广告数据 T+1；空白日期与明确同步完成的零记录日期分开显示覆盖情况。

## 持久化与恢复

`ads_ai` 新增 `cdreader_koc_order`、`cdreader_koc_ad_revenue`、`cdreader_koc_ad_day_snapshot`、`cdreader_koc_short_link`，全部字段使用中文备注。原剧目表、推广表继续复用。

统计接口完整分页验证通过后才写对应分项；广告按完整日版本切换，零记录日也保存完整快照。小批写入、读回核验和检查点支持中断恢复，失败不会标记成功。

推广请求、成功回执和短链先保存在数据盘的耐久记录中，再镜像到 MySQL。数据库暂不可用不丢失已经成功生成的链接。外部创建结果未知时保留核对围栏，不自动重复调用创建接口。下架后禁止新建短链，历史短链保留。

凭据仅存在服务器受限配置中；社媒服务仅能读取宏专用认证，不持有供应方 Token 或数据库密码。常规 MySQL 读取使用 63350 和现有 FIFO，指定业务表写入使用 63353。

## 发布与验证

源码按线上各服务实际文件建立基线，分独立运行目录覆盖差异。上线和回滚工具见 `ops/moboreels-attribution-20261113`。回滚保留目录、收益数据、推广回执和 `/m/` 跳转，避免已发布链接失效。

离线检查覆盖精确宏、权限、创建者归属、未知结果、并发复用、金额精度、分页缺失、跨状态订单一致性、数据库提交超时和真实原生发布入口的文案冻结。生产验收脚本只复用既有正式推广生成验证短链，不发布社媒帖子。实际收入样本须以生产接口回执为准，不能把文档样例写入正式表。
