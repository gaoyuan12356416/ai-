# 剧集合成增加 MoboReels

新建制作任务的产品列表增加 `3360 | moboreels`。剧 ID 使用 Moboreels 短剧库的
`story_id`，从现有剧库读取名称、封面与语言，复用供应方剧集接口获取分集视频。
DramaWave 和 FreeReels 继续使用原来的资源查询。

提交校验和实际开始执行都会重新读取分集地址，不把提交时的一小时临时地址沿用到
排队后的首次执行。已冻结的 GPU 作业和续传记录保持原有身份与回执规则。
该变更不创建制作任务、不发布视频、不重放历史失败任务。

验证：`python -m unittest discover -s tests -p test_moboreels_synthesis.py -v`
（8 项）；变更 Python 编译和 `git diff --check`。真实剧目只读探测返回 23 集，
首集 Range 请求为 HTTP 206、video/mp4，32 字节探测确认 MP4 标记。

部署：推送此提交后从 GitHub 获取精确版本，运行
`python3 scripts/deploy_moboreels_synthesis.py install`。安装器核对两处函数的
父提交基线，只替换对应函数并安装一个适配文件；保留线上所有其他变更。
备份、文件哈希和部署提交写入 `/mnt/data-disk/moboreels-synthesis/<UTC时间>/`。
确认主 API 所有正在制作的任务及其依赖服务没有在途工作后，保存 YouTube 调度
快照和主 API 的活动依赖服务，重启主 API 与合成 worker，并恢复原先活动的依赖。
验证产品接口、Moboreels 只读集数校验和调度快照。

回滚：在同一 GitHub release 中执行
`python3 scripts/deploy_moboreels_synthesis.py rollback --deployment <上述部署目录>`，
在同样的空闲检查和调度快照保护下重启主 API 与合成 worker，并恢复依赖服务。
只回滚代码，不恢复旧数据库；若已有后续文件变更，安装器拒绝覆盖，需合并回滚。
