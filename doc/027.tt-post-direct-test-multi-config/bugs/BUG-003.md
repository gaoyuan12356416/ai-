# BUG-003 自动池消费状态被误当成平台发布状态

## 状态 / 严重级别

- 状态：已实现候选修复，待完整回归。
- 严重级别：P0。

## 现象与根因

`available/reserved/consumed/canceled` 只描述自动 FIFO；`consumed` 可能对应 failed/unknown，不能推断 TikTok 已发布。

## 修复

core 按 material ID 聚合 `tt_post_queue` 与 `tt_post_direct_test`，并把以下字段直接合并到 preview/pool item：

- `publication_state`、`publication_status`；
- `publish_count`、`unknown_count`、`attempt_count`；
- `latest_published_at_utc`、`latest_publish_id`、`latest_publish_url`、`latest_status_at_utc`。

状态只有 `published|unknown|unpublished`。有 published 时主状态为 published 并保留 unknown_count；否则有 unknown/`publishing|reconciling` 时为 unknown；活动但未未知仍是 unpublished。不存在 `processing` 或嵌套 publication 对象。

该投影不回写 auto pool，也不永久决定 auto eligibility：direct-test 明确终态后，原 available pool 可继续按 FIFO 消费。

## 验证

P01-P12；重点覆盖 consumed+failed、published+unknown、仅 active 和无历史。

## 回归结论

待执行；完整证据前不得关闭缺陷。
