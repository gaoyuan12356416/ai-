# BUG-001 建队前重复媒体预检导致到点不发布

## 发现阶段

生产运行诊断，2026-08-20 15:11 素材定时任务。

## 现象

任务按时 claim，但持续下载/探测候选近 50 分钟仍为 0 queue、0 log、0 X attempt；页面看不到发布记录。

## 复现步骤

1. 配置 19 个账号、素材池包含大量跨语言/超长/大文件候选。
2. 到点执行 schedule runner。
3. 观察 runner 串行下载候选并等待凑足目标数，`create_schedule_plan` 尚未调用。

## 期望结果

轻量元数据候选确定后立即创建非空队列，逐条在实际发布时下载/探测；单条已知失败继续下一条。

## 实际结果

runner 在建队前扫描最多整个快照；所有成功候选只驻留内存，未凑足前没有任何队列或发布。

## 根因分析

schedule runner 调 `_preflight_candidate` 下载/probe/repair；`publish_canary` 正式执行时再次下载/probe。全批原子建队位于完整候选扫描之后，形成重复跨区 I/O 与头阻塞。

## 修复说明

引入 schedule-only deferred media mode：建队只做轻量安全检查，媒体只在逐队列实际发布阶段处理；known failure 继续，unknown/429 停止。
