# 需求与设计审查

已确认使用现有日报的归因表，但单独实现可视化报表，不改日报投递。

1. 充值字段是“人数”不是“次数”：保留准确标签与跨日不去重说明。
2. 收入channel空值常见：禁止按channel=youtube过滤，冻结二元组关联。
3. 同一短链多次发布会多归属：先判唯一维度再累加，不分摊。
4. 失败/缺日不得假0；浏览器、表格和CSV保持同口径。
5. 用户过滤在后端执行，options、report、export一致；admin只限同租户。不能把全站未匹配效果暴露给普通用户。
6. 现有主checkout有未提交修改：独立worktree；线上app为复合版本，部署仅添加带hash保护的路由和导航。

接受上述约束后实施。授权沿用用户管理中现有YouTube模块，新增导航项可通过导航管理配置。
