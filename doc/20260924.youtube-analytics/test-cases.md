# 测试用例

## 测试范围

后端 `features/youtube_analytics/report.py`、`routes.py` 的只读归因、聚合、筛选、权限、缓存、分页和导出。前端交互、真实副本查询计划、线上权限配置及部署验证由主任务另行验证。

## 测试数据

- 全部为合成数据：临时 SQLite 中按现有表的相关字段与主键构建自动冻结链接、手动链接、历史发布、准备记录和用户；无真实凭证、Token 或平台调用。
- 租户 A 的 alice、bob 与管理员；租户 B 的 eve；共享归因、不同大小写归因、多次发布、未发布链接、历史创建时间、同账号多租户及内部 canary。
- 效果以 `(UTC 日期, campaign_id, campaign)` 为最细来源键；精确匹配冻结长链中的两个归因值，不按 channel 过滤来源记录。
- `metric_sql` 在 SQLite 中仅替换 MySQL 方言后执行，保留同一 SQL 的筛选和聚合表达式，验证 youtube / none / organic 收入合并；真实 MySQL 兼容性仍需部署前只读核验。
