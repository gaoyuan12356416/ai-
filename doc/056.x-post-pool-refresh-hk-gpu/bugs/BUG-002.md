# BUG-002 显式媒体回填在 GPU 前误判长视频

## 发现阶段

香港 GPU 切换完成后的首轮生产回填。

## 现象

对 8 个显式素材执行既有 backfill 后，报告为 8 条 `x_long_video_requires_premium`、`repair_attempted_count=0`。香港 GPU 没有收到任务。

## 根因

回填工具使用固定虚拟账号调用日常预检，但该账号未声明 `long_video_eligible`，因此探测上限仍为 140 秒。工具也只在探测失败时调用修复，无法满足“即使源视频当前合规也重新制作”的运维要求。

## 修复

- 回填虚拟账号固定使用 Premium 14400 秒媒体上限；素材语言随当前候选设置，仅做能力验证，不参与账号排期。
- 新增 `--force-repair`，只作用于已显式指定、去重且仍在未发布可用池内的视频。
- 强制重制使用 `operator_forced_repair` 和独立确定性 job key；完成 GPU 转码、COS 上传/HEAD、CPU 下载与探测后才清空池错误。
- 默认日常调度和默认回填不启用强制重制，不新增队列或发布路径。

## 验证

- 180 秒合规素材以 14400 秒上限验证，状态为 `validated_ready`，不再出现会员误报。
- 合规源在 `--force-repair` 下仍产生一次 GPU 请求，原因与 duration policy 分别为 `operator_forced_repair` / `premium`，结果为 `repaired_ready`。
- worker 精确请求合约接受新原因，其他未知原因仍 fail closed。

## 生产处理

首轮失败报告与 8 条 before-image 已归档。新版本发布后将按同一 8 个素材 ID 强制重跑；只有逐条完成 COS 和 CPU 复检的素材才更新为可用。
