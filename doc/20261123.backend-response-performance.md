# Backend response latency

The X tag editor returned 503 because its template owner had been stopped for
a completed maintenance stage. The browser gateway remained alive. Restore
the existing owner after verifying the stage's persisted completion; preserve
the canonical hold and all publication receipts. Do not use the gateway's own
health response as proof that its template dependency is serving requests.

After recovery, the actual browser downloaded 223,488 uncompressed bytes for
the 203-account options list in 5.794 seconds. Its loopback request completed in
52 ms. The editor also fetched a separate 461,755-byte account metrics DTO
(34,510 compressed bytes) while the options were still downloading.

This release enables JSON gzip only in the two X tag proxy locations and defers
the optional metrics request until the account-options request settles. The
template remains independently visible. Permissions, no-store responses,
selected accounts and retry behavior stay in place. The public and main assets
retain the already deployed navigation version; the lane's future static source
is synchronized to the same visible editor.

A bounded, rotated Nginx timing log records only API path, method, status, byte
count and request/upstream durations. No query strings, cookies, bodies or user
identifiers are logged. Its data lives at
`/mnt/data-disk/backend-performance/api-timing.log`. This distinguishes upstream
work from response transfer without making unrelated changes to workers.

Validation: JavaScript syntax, template-action UI harness, Python compilation,
`git diff --check`, followed by `nginx -t`, installed hashes, worker PID checks,
authenticated browser requests and rendered editor state. Nginx uses a graceful
reload; no publishing owner is restarted by the installer.

After fetching the pushed commit into an isolated source directory:

```sh
python3 scripts/deploy_backend_response_performance.py apply --state /mnt/data-disk/backend-performance-20261123/deploy-v1
```

Rollback from that same source directory:

```sh
python3 scripts/deploy_backend_response_performance.py rollback --state /mnt/data-disk/backend-performance-20261123/deploy-v1
```

The installer backs up each destination independently and rejects overwriting
concurrent changes. Rollback restores only these assets and Nginx settings. It
does not stop the recovered template service or restore databases and tokens.
