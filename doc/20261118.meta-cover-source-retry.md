# Meta cover source timeout recovery

The continuous worker exited at 2026-11-17 18:10:40 Beijing after its read-only
credential-directory query timed out. SQL diagnostic
`1c235d532a9d4aed92a5042f90b23cff` recorded 130.365 seconds and 50 discarded
partial rows. The generic exception handler created a durable write pause and
returned 78, so systemd intentionally did not restart it. Hourly scans continued;
the 2026-11-18 17:30 report showed 14,444 queued Ads and no daily progress.

Transient SQL timeouts/disconnects now discard the complete failed snapshot and
retry the affected lane after 30, 60, 120, 240 and then at most 300 seconds.
Startup credential loading uses the same bounded backoff. Cleanup continues when
the Ad lane is waiting. Each retry opens fresh source/credential clients; existing
source TTL, FIFO gate, query limits and execution governor remain unchanged.
Only known transient SQL categories qualify. Read-only proof, authentication,
data-integrity, write and ledger failures retain the durable pause.

Before a failed preparation returns, all submitted Ad futures are drained and
their receipts collected. A concurrent write/ledger halt takes precedence over
the source error. Subsequent cycles select the durable ready queue; they do not
reset failed or unknown tasks, recover live reservations, or replay writes.
`work --once` reports transient failure without creating a permanent write pause.

Validation covers credential outage recovery, per-lane backoff/reset, continuing
cleanup, bounded acceptance behavior, preserved permanent-error pauses,
concurrent write-halt precedence, and a real fixture that commits an in-flight
Ad while preparation fails and does not execute that Ad in the next cycle.
