# Keep unavailable cover generation off an otherwise healthy video node

The Hong Kong node advertised YouTube preparation even though its Codex
workspace/model requests returned HTTP 403 and the colocated code-mode host
executable was absent. A reference image arrived successfully, but the model
request failed before an image was produced. CPU generation was independently
verified with fresh images and authenticated cover downloads.

The coordinator can now exclude named capabilities for a specific node in its
private JSON configuration. For the observed Hong Kong outage use:

```json
"node_capability_exclusions": {
  "hk-gpu": ["prepare:youtube", "youtube_prepare"]
}
```

The policy applies both to cached node registrations at claim time and to
subsequent registrations, so an unchanged worker cannot advertise the excluded
tool back into service. Existing claims, receipts, node identity, other tools
and saved pool/channel capacities remain unchanged. Nodes are not restarted
or drained. The policy only removes capabilities; it never grants a tool.

Deploy the exact pushed commit with the guarded coordinator switch, preserving
the current coordinator config and adding only this policy. Compile and test
before the brief HTTP drain. Do not restore an old pipeline database or old
capacity configuration. Verify that CPU retains YouTube preparation, Hong Kong
retains its X/TT/FB preparation/publication capabilities, and worker PIDs and
active generations remain intact. Keep YouTube preparation-only admission.
The versioned settings fragment is
`deploy/pipeline-node-capability-exclusions.hk-gpu.json`; merge only its named
node exclusions into `/etc/pipeline-coordinator.json`, after backing up that
file. Do not replace other node exclusions or the whole configuration.

After the node's actual Codex generation prerequisites are repaired and tested,
an operator can remove the exclusion and restart only the coordinator. The
normal node registration restores its advertised capability. Code rollback
also requires first withdrawing the affected tool from the worker itself or
otherwise pausing new YouTube preparation; older code ignores this policy.

Four regression cases cover cached capability rejection, repeated registration,
other preparation/publication continuing, active completion, unchanged saved
capacity, invalid policy and deliberate restoration.
