# 爆款剧发布：多剧 ID / 资源 ID

Facebook 和 X 模板列表共用的“爆款剧发布”支持多个 ID。保持 ID 类型选择，使用逗号（含中文逗号）、空格或换行分隔，按输入顺序去重。改为多行输入框，按单个 ID 校验格式，取消原来整个输入框的单 ID 长度限制。

每个 ID 通过原有 `run-now` 接口分别创建一轮任务，沿用现有模板版本、身份校验、语言及收入画像匹配、素材选择、发布时点、冷却和占用规则。每条保留独立操作号与运行回执；逐条显示记录链接及跳过原因。某条明确失败或结果不明时继续提交其余 ID；结果不明的条目保留原操作号，用户重试只核对待确认项。刷新或重新打开后恢复原批次；兼容升级前保存的单 ID 待确认请求。取得运行回执不代表已发布，零排队仍明确显示“本轮未发布”。

## 验证

- `node --check static/hit-drama-publish.js`、部署脚本编译、`git diff --check`。
- Playwright 本地浏览器，全部 `fetch` 使用模拟服务：混合分隔符、去重及顺序；X/FB 原请求字段；31 位资源 ID 字符串精度；逐条回执链接；部分成功/失败/未知；无匹配 Page 的原因；零排队；格式错误/空输入；30 个 ID 超过旧输入长度；旧版草稿操作号及模板版本；缺失运行回执；存储失败时不发请求。
- 实际刷新页面后，已成功 ID 不再提交，未知项沿用原操作号重试。
- 不触发真实帖子、历史重放或队列变更。

## 部署及回滚

生产共享 JS 在四个位置的现有 SHA-256 均为 `52fee7459ea631ae2a7e8fba4d57e7530269aec241490d578f469f931b5c74d8`，与本分支基线一致。通过 GitHub 提交后在 CPU 服务器拉取该精确版本。仅更新以下静态副本中的共享 JS 和对应 HTML 的脚本版本参数，保留 HTML 的其他并行改动：

- `/root/drama_material_service/static`
- `/usr/share/nginx/html`
- `/opt/x-tag-publisher/current/static`
- `/opt/fb-auto-post/current/static`

X 与 FB 的运行时为独立复合版本；本次不替换其源码目录或后端文件。脚本同时更新发布源副本，避免后续从当前运行时构建时遗失此修改。所有备份、哈希和实际文件路径记录在数据盘的 `manifest.json`。纯静态部署不重启服务、不停止调度。

```bash
python3 scripts/deploy_hit_drama_multi_id.py plan
python3 scripts/deploy_hit_drama_multi_id.py apply --folder /mnt/data-disk/hit-drama-multi-id-20261117/deployment
python3 scripts/deploy_hit_drama_multi_id.py rollback --folder /mnt/data-disk/hit-drama-multi-id-20261117/deployment
```

回滚只恢复本次静态文件。若检测到后续编辑，则提示核对以保留新改动。数据库、发布账本、凭据、运行任务和回执均不回退。
