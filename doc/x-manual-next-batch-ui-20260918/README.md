# X 手动发布连续操作优化

## 问题和改动

旧版 `openManualPublish()` 发现当前手动任务尚未终结时，直接重新打开旧任务进度，无法新建下一批。这把新建表单与视频预检/发布耗时绑定；本次排查的一笔立即发布实际耗时 6 分 11 秒，未来定时任务也会持续占用这个入口。

`static/x-post-material-pool.html` 现在把创建和查看进度分开：

- 输入素材 ID 后，“手动发布”立即打开新表单，不查询或等待旧任务。
- 创建成功的进度弹窗增加“继续发布下一批”，返回素材输入；已有输入时直接打开下一批表单。
- 同一浏览器标签页保留最近 10 个任务入口，刷新后可恢复；兼容旧版保存的最后一个任务。入口只保存任务 ID，进度通过原有鉴权 GET 接口查询。
- 切换任务/表单时取消旧轮询计时器，递增查询代数，丢弃迟到的旧响应，避免覆盖新表单或更晚的同任务查询。
- 保留提交锁、幂等键、北京时间转换、素材/账号数量验证。后端素材预约、账号锁、预检、顺序发布和未知结果处理均保持现行行为。

本次只部署静态页面，不改后端、数据库、自动排期或已提交任务。连续创建加快的是操作流程，视频预检/上传及实际发布仍由原后台执行。
