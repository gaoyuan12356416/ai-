# X 模板账号数量限制解除

移除标签画像自动发布模板前端和服务端的 100 账号上限，不设替代的账号数量上限。保留至少一个账号、合法且唯一的账号 ID、现有账号授权和可发布资格校验。账号顺序、模板版本、历史任务及发布防重规则不变。

修改共享模板源文件，同时在标签画像运行环境构建的最后应用当前校验器及页面修复，防止旧基线重建恢复限制。线上仅部署独立标签画像模板运行环境中的校验器，以及运行环境、主 API 静态目录和 Nginx 三份标签画像编辑页面。其他发布入口不参与本次切换。

## 验证

- 校验器覆盖 101、124、201、1001 个账号，并保留空列表、重复和非法 ID 拒绝行为。
- 实际编辑器函数在隔离 API 替身下提交完整 124 个账号。
- 隔离 Linux 运行环境中，临时 SQLite 完成 124 账号模板更新和读取；旧版本保留，创建 124 个任务，重复操作不增加任务。所有账号查询和发布执行均由测试替身处理。
- 源码分支是线上组合版本的增量；本地分支缺少组合运行环境中的 pipeline_dispatch 依赖，服务集成测试须运行在生产代码副本中，不能以本地导入失败替代结果。

## 部署与回滚

先提交并推送 GitHub，再在 CPU 数据盘的独立源码目录 fetch 精确提交：

```sh
python3 scripts/deploy_x_template_account_limit.py prepare
python3 scripts/deploy_x_template_account_limit.py activate --folder /mnt/data-disk/x-template-account-limit-20261113/<commit前12位>
```

prepare 校验已核对的线上文件哈希，在隔离副本运行测试，保存受影响文件及 Auto SQLite 在线备份。activate 只暂缓三个 Auto 定时/路径触发器，利用现有非 daemon HTTP handler 的优雅退出重启 x-tag-auto.service，再恢复此前活动的触发器。独立 Post、网关、旧 OAuth 和主 API 进程保持不变。核对公共页面缓存版本、服务 health、对应调度器状态和下一次触发时间。此流程不保存用户的模板、不启动测试发布、不回放历史任务。

回滚命令（从本次 GitHub 源码目录执行）：

```sh
python3 scripts/deploy_x_template_account_limit.py rollback --folder /mnt/data-disk/x-template-account-limit-20261113/<commit前12位>
```

只恢复本次受影响代码和页面；保留当前数据库、模板版本、任务、回执、凭据及业务事实。旧代码会重新拒绝大于 100 账号的模板保存，因此有此类模板时优先前滚修复。manifest.json 记录精确提交、文件前后哈希、备份路径和服务状态；tests.txt 保存隔离测试结果。
