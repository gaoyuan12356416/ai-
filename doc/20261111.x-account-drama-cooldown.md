# X drama cooldown per target account

A template's drama cooldown now applies to `(template_id, account_id, content_id)`.
Another target account can select a different unused material for the same drama.
The same account remains blocked for the configured rolling interval, measured
from reservation. Zero disables the cooldown. Template boundaries and global
material uniqueness are unchanged.

Both candidate filtering and transactional reservation join the immutable material
ledger to its original task to read the target account. Existing history takes
effect immediately without backfilling or rewriting a ledger. Reserved tasks and
historical no-candidate tasks are not redrawn or replayed.

The standard and profile-based X template runtimes share this behavior. The editor
explains the per-channel scope, and new no-candidate errors identify target-channel
cooldown in Chinese. Existing historical errors retain their original text.

Validation covers cross-account selection, same-account rejection, template and
case-sensitive drama boundaries, expiry, cooldown zero, concurrent reservation,
global material reuse rejection, and claimed-task ownership. Run the store and
selector suites against the live composite candidate. The source branch has an
unrelated pre-existing independent-lease test mismatch that the deployed composite
already fixes; deployment preserves that newer implementation.

After pushing this branch, fetch its exact commit into a clean server source tree.
Use `scripts/deploy_x_account_cooldown.py prepare --folder /mnt/data-disk/x-account-cooldown-20261111/deployment`,
then `apply` with the same folder. Preparation overlays only the reviewed code
hunks onto each current runtime, runs offline tests, and takes online SQLite and
static-file backups. Apply checks the current release and hashes, drains only the
two Auto services, restores their triggers, and validates X scheduler dependencies.
It does not restart the publisher, change templates or issue verification Posts.

Rollback: run the same script with `rollback --folder` and the same deployment
folder. Later release/hash changes stop rollback for review. It restores code and
editor text only; never restore an old database, token, reservation or receipt.
