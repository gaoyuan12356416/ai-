# BUG-003 切换前既有 FB 转码停滞

这是上线前发现的生产存量问题，本次只完成保留现场和排空，未修改转码器或声称修复卡顿根因。

2026-09-20 12:19 至 12:23（北京时间），FB worker 内同一 FFmpeg 已运行超过 82 分钟。源视频 108.3 秒，临时文件固定为 9,175,088 字节，mtime 和进程 I/O 连续检查未变化，临时 MP4 缺少 moov，且没有成功 manifest。其运行早于本次目录切换。

先暂停新的 CPU 领取，按 PID、start_ticks、父 worker 和完整 FFmpeg 命令核实同一实例。将源视频、临时输出、OpenCL 源、命令和收据备份到 HK `/data/random-overlay-gpu/backups/20260920-stalled-prepare`，目录权限 0700。发 SIGINT 等待 35 秒无响应；再次核对同一身份和输出无进展后发 SIGTERM，15 秒仍无响应，最后仅向该 FFmpeg 发 SIGKILL。

worker 现有异常路径已核实：子进程非零退出会在探测/上传前返回 `fb_gpu_transcode_failed`；finally 删除未完成临时输出，保留源视频。本次确认这一清理发生、没有生成 ready manifest、没有调用人工重放或发布；三个 GPU 服务的 cgroup 随后只剩主进程。

这是一次有备份和身份校验的存量停滞处理，不能把强制结束任意活跃制作作为日常部署步骤。生产恢复后由既有队列规则处理该失败尝试，不手工修改账本。
