# X selection recovery and drain diagnostics

Selection queries could fail and then fail again while persisting their error,
leaving a selecting task with a three-hour lease. A drain stopped ordinary
runner calls, so that task could keep the main API waiting for hours.

This change gives selection a 180-second lease and preparation a 900-second
lease, renewed every 30 seconds while the request lives. Publishing retains its
existing lease and receipt reconciliation. An OS request lock outlives heartbeat
errors. Expired selection is ahead of fresh pending work, without starving
publication observations. The deployed receipt/work fairness order is preserved.

An independent systemd timer runs every 30 seconds, including during drains.
It checks at most 32 selection tasks unchanged for 60 seconds. Recovery owns
admission exclusively, skips active request locks, then checks native material
reservation, execution identities, attempt counts, unknown/publication facts,
manual-run identity, central execution ownership, operations, claims and receipts.
The native writer runs as its original service user, rechecks the row and ledger
in one transaction, clears only the ended selection claim, and appends
`task_selection_claim_recovered`. Missing evidence or changed state defers recovery.
The existing collector converges the idle central mirror without direct resets.

The same timer emits bounded read-only diagnostics for active service drains.
The monitor's admin-authenticated gateway exposes blocker IDs, stage, progress,
heartbeat, elapsed time and reason. A drain older than 10 minutes is highlighted;
the timeout never releases a hold or kills an upload. Diagnostics older than 90
seconds are marked stale. No Feishu or external notification is sent.

Validation covers recovery idempotence/audit, attempts and reservations, claim
renewal, priority, active-but-expired requests, failure of error persistence,
external execution/receipt exclusion and stale diagnostics. Linux flock cases
must run on the staged server release as well as the existing publisher tests.

Deployment uses a fetched GitHub release. Gracefully stop only the tag control
API after pausing its runner triggers; do not stop rendering or posting workers.
The installer checks both live module hashes, saves each replaced file and patches
only the capacity gateway GET method and the monitor HTML's new script hook.
Save the X scheduler baseline and restore its previously active dependencies.

Rollback: stop the watchdog timer, pause tag runner triggers, gracefully stop the
tag control API, and restore only manifest files whose current hash equals the
installed `after` hash. Remove newly added files, preserving all databases,
receipts and lock files. Reload systemd, start the API, restart the independent
capacity gateway, test/reload nginx, and restore the saved scheduler baseline.
If a manifest path changed later, merge the affected method/hook instead of
overwriting concurrent changes. Remove `/opt/x-selection-recovery/current` only
after the watchdog has stopped. Confirmed publication is never rolled back.
