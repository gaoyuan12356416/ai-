# BUG-001 Nginx reload 后即时探测误判 404

## 发现阶段

2026-07-24 生产发布验证。

## 现象

`nginx -t` 与 `systemctl reload nginx` 均成功，但紧随其后的首个 `/tt` 请求仍命中旧 worker，返回 404，发布脚本据此触发自动回滚。

## 复现步骤

1. 安装新的精确 `location = /tt` 配置。
2. 执行 `nginx -t` 和 `systemctl reload nginx`。
3. 不等待 worker 切换，立即请求 `/tt`。

## 期望结果

发布脚本等待新配置真正接管请求，再执行页面断言。

## 实际结果

探测命中旧配置并把短暂 404 误判为新配置失败。

## 根因分析

`systemctl reload nginx` 返回表示 reload 信号已发送，不保证所有新 worker 已在同一瞬间接管请求。初版脚本缺少就绪轮询。

## 修复说明

- 页面与 Nginx 配置无需修改。
- 发布流程改为 reload 后最多轮询 10 秒，只有 `/tt` 返回 200 且标题匹配才继续。
- 自动回滚后的 reload 增加短暂就绪等待，避免删除配置与旧 reload 解析发生竞态。

## 影响文件

无产品代码变更；规则已补充到 `deploy.md`。

## 验证命令与结果

- 第二轮发布 `/tt` 返回 200，完整安全响应头正确。
- 2026-07-27 再次执行 `nginx -t`、HTTP 探测、哈希核对和 Playwright 点击，全部通过。

## 回归结论

通过。首轮自动回滚后五个目标恢复为部署前的 ABSENT 状态，现有后台未受影响。
