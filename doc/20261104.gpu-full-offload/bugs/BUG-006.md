# BUG-006 High profile avcC 缺少扩展字段

状态：已修复并独立 GPU 回归。严重性 P2，代码审查确认。

新 Annex B→avcC 实现最初只写基本 SPS/PPS。当前 NVENC 使用 H264 High profile，其配置记录还需 chroma_format、bit_depth_luma_minus8、bit_depth_chroma_minus8 和 numOfSequenceParameterSetExt；FFmpeg n7.1 `libavformat/avc.c` 的 `ff_isom_write_avcc` 同样从 SPS 提取并写入。宽容解码器能播放不足以证明配置完整。

修复：GPU 去除 SPS emulation-prevention bytes，解析 Exp-Golomb 前缀并生成扩展字段，不固定假定 chroma/depth。只支持明确的单 SPS/PPS 输出契约。

影响：`features/random_gpu/gpu_mux.py::avcc_config`。独立测试增加 High profile prefix/Exp-Golomb/EPB、截断拒绝及真实 NVENC SPS 尾字段。首次整套被 BUG-007 的 CUDA illegal address 中断；修复后在新测试进程运行 `scripts/test_gpu_mux_boundaries.py`，14/14 通过，1.402 秒。SPS 合成前缀用例验证位解析而不是完整 SPS 解码；真实 NVENC SPS 验证得到正确 `fd f8 f8 00` 尾部。

来源：[FFmpeg 7.1 AVC mux helper](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1/libavformat/avc.c)。
