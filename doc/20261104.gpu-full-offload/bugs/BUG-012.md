# BUG-012 PyNvVideoCodec CQ 初始化静默清空 X 码率预算

状态：已修复并隔离 T4 验证。严重性 P1，可能导致长片超出原成片大小预算。

复现：PyNvVideoCodec 2.2.3 `CreateEncoder(codec=h264, preset=P5, rc=vbr, cq=21, bitrate=5000000, maxbitrate=6000000, vbvbufsize=10000000)` 后，实际初始化配置 getter 返回 `averageBitrate=0/maxBitRate=0/targetQuality=21`，只有 VBV 保留。参数名与官方文档、随包 `samples/advanced/encode_config.json` 相符，不是拼写错误。

官方 NGC 2.2.3 源码（本地研究包 `work/native-video-research/PyNvVideoCodec_2.2.3.zip`）证实 `src/PyNvVideoCodec/src/NvEncoderClInterface.cpp:1096–1103` 的 CQ 分支主动清零平均和最大码率。

还需区别初始化 getter 与当前硬件配置：`PyNvEncoder.cpp:352–364` 的 `GetEncodeReconfigureParams` 读取构造缓存；`919–946` 的 `Reconfigure` 将完整配置传给底层 NVENC，但不刷新该 Python getter 缓存。`NvEncoder_121.cpp:746–753` 调用 `nvEncReconfigureEncoder` 并更新底层配置。重配成功后 getter 仍显示旧 CQ，不能把这个缓存当作硬件重配失败。

修复：非零码率预算加 CQ 时，先省略 CQ 构造，逐项读回断言平均/最大/VBV 配置；在完整配置上设置 CQ 并调用 `Reconfigure`，要求成功返回。sidecar 分别记录初始化读回、应用的重配及 getter 缓存性质。FB 原来的 bitrate=0/CQ21 路径保持原行为。没有修改第三方 SDK 或驱动。

隔离 T4 实测：

- `qa-x-native-rates.json` 保存原始失败；`qa-x-native-rates-fixed.json` 中 30/1200/14400 秒预算配置全部通过。正确属性为 `averageBitrate/maxBitRate/vbvBufferSize`。
- 同一 60 帧复杂画面：5M/6M/10M + CQ21 为 1,619,337 bytes；同预算 CQ40 为 132,677 bytes；96k/102k/204k + CQ21 为 44,207 bytes；未限码率 CQ21 为 3,544,958 bytes。四组 PTS 与完整严格解码通过，证明 CQ 重配实际生效且码率预算影响输出。证据 `qa-x-rate-content.json`。
- 完整 X 两秒链路两组：默认预算输出 1,498,012 bytes；512 KiB 上限输出 435,292 bytes。均为 60 视频帧、95 AAC 包、128 kbps AAC、2.000 秒；原 `validate_output` 和严格完整解码通过。证据 `real-fixture/qa-x-native2.acceptance.json`、`qa-x-native2-smallbudget.acceptance.json`。

这是短样本与配置验证，不代替最终 SHA 下的长片预算、并发和上线验收。现有输出大小硬校验仍保留，未修改发布或未知结果处理。
