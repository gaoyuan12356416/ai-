# BUG-008 MP4 全轨沿用请求时长导致短片轨道时长错误

状态：已修复并独立 GPU/真实 FFmpeg 对照。严重性 P2。

原 mux 将请求 duration 按 48000 tick 上取整后写给 movie 和每条 track。0.01秒请求仍有一帧30fps视频，参考FFmpeg视频结束为1/30秒、音频结束0.01秒；两轨不能都标0.01秒。非整tick请求也不应人为延长媒体包已结束的轨道。

修复：CUDA按各轨max(PTS+duration)求展示结束，tkhd/elst各自转换到movie timebase，movie取最大轨道；mdhd采用展示结束减首PTS，不把AAC负priming或B帧decode delay混入最终展示时长。

验证：`verify_gpu_mux_durations.py --gpu`对0.01/0.10001/1.00001三组全部通过，报告`qa-duration-gpu.json`；0.01秒候选movie1/30与参考0.034差异为48000/1000 timebase舍入。最新14项mux微测、原2秒155packet完整重封装/解码哈希也通过。测试比较同一包集合，不代替native视频帧数舍入验收。
