# 测试用例

2026-11-04，独立 QA 设计。本文是执行清单，不是通过报告。未附命令、精确提交及输出证据的项目均为待执行。

## 范围和基线

- 基线为香港节点实际运行的 `179596a9699393cd377c0e06a0bec94e171f14cd`。以其制作命令、冻结配方和实际输出比较，不使用较早文档代替当前行为。
- 当前视频交付为 720×1280、30 fps、H.264 High、现有 NVENC 参数；音频为 AAC-LC、48 kHz、双声道，保留显式时长、首帧时间以及补静音语义。
- 当前代码已接受 NVENC packed-RGB 的 BT.601 转换。测试应检查新旧一致性并记录实际元数据和解码颜色，不能误用旧 BT.709 转换版本作为基线。
- GPU 算子正确、算子接入流水线、完整文件正确、生产任务完成是四种不同证据，必须分别记录。
- 测试只制作离线文件，使用隔离工作目录；生产自然任务用于部署后读回，不新建测试社媒发布，也不重放结果未知的发布。

## 数据集

1. 固定源片 SHA、固定配方、固定四层模板 SHA。至少包含已有 GPU 路径和全范围色彩兼容路径的真实源片，沿用现成数据时只读取或复制到测试目录。
2. 合成视频：720p/1080p 竖屏、横屏、H.264/HEVC、全范围与有限范围、动态分辨率、非方形像素、VFR/低帧率、延迟首帧、带 B 帧的视频。
3. 音频：48/44.1/16 kHz，单/双声道，静音、正弦、脉冲、左右不同信号、真实对白/音乐、无音轨、短音轨、长音轨、起始延迟和中间时间戳空洞。
4. 哈希：空文件、已知标准向量、全 0/全 255、随机二进制，长度覆盖 55/56/63/64/65/119/120/127/128 字节以及分块边界；另含真实大视频。
5. MP4：普通 `moov` 后置、已有 faststart、32/64 位 chunk offsets、带 edit list、可变包长、B 帧 `ctts`、有/无音轨；大偏移可先使用结构化元数据 fixture，再用真实大文件验证。

## 验证记录要求

- 为每项保存精确代码 SHA、依赖版本、设备/驱动、输入与配方摘要、命令和机器可读结果；不保存凭证或带签名 URL。
- 性能测量同时包含新建上下文、编译/预热、传输和文件 finalize 的成本；冷启动与热运行分开。不能只计内核时间或拿不同并发/不同视频作前后对比。
- 不承诺 CPU 降低比例。质量和数据正确性通过后，真实报告吞吐及资源变化；不得因用户要求全量迁移而隐藏更慢、尚未迁移或未验证的环节。
- 既有回归按实际变动选择：`test_random_gpu_pipeline.py`、`test_random_gpu_asset_cache.py`、FB prepare/render tests，以及受影响的 pipeline worker/lease/receipt/recovery tests。只在实现改变这些路径时扩大回归范围。
