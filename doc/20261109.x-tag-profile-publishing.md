# X 标签画像发布：独立流程

## 已确认范围

新建标签画像自动发布、素材池、运行记录和发布日志。原流程保留。
新旧不共用素材防重、频道发布计数、模板、排期、任务、占用和执行锁。
用户明确要求初始全部为空，等待自行新建；部署不复制任何业务配置或任务，也不发送测试 Post。

## 分配规则

读取第一阶段的频道历史收入画像，按 X 外部用户 ID 匹配频道。
多语言同义标签映射为同一标准 ID，前端统一显示简体中文。同剧先合并同义标签，再平均分摊收入；画像与分配共用同一字典版本。
按已识别标签正收入权重稳定抽选标签，随后保留原有语言、黑名单、素材资格、时长及模板指标筛选。
自动模板同标签内使用原模板排序；素材池同标签内使用原入池顺序。
素材池分配先满足普通账号，再分配会员账号，避免会员先占短视频而使普通账号虚假缺料；同等资格账号内保留稳定轮转，返回结果仍按冻结账号顺序排列。
抽选标签无合格素材时尝试其他偏好标签；无有效画像或无匹配候选时降级为原筛选排序并记录原因。
这属于加权分配，有限批次和素材不足时不承诺发布条数严格等于收入百分比。
任务保留后不重新抽选；日志记录画像版本、标签映射版本、首选/实际标签及降级原因。历史英文审计仅在返回页面时转换显示名称，不修改冻结记录、标签 ID、回执和映射版本。
素材池手动发布仍尊重明确选择的素材、账号和时间，使用新账本。

## 隔离实现

| 项目 | 新流程 |
| --- | --- |
| 运行目录 | `/opt/x-tag-publisher/current` |
| 状态根目录 | `/mnt/data-disk/x-tag-publisher` |
| 素材池、队列、发布回执和归因 | `posts.sqlite3` |
| 自动模板、任务、素材占用和指标缓存 | `auto/x-auto-post.sqlite3` |
| 锁 | `/run/x-tag-post`、`/run/x-tag-auto` |
| 本机服务端口 | 8821、18843、8898 |
| 跟踪短链 | `https://gy.g2flow.com/s2l-tag/<log_id>.html` |
| 数字 ID 起点 | 9000000000000，不重用旧流程的队列/归因 ID |

账号资格和授权信息只读复用；令牌刷新交由原账号授权服务串行处理。
真实平台权限、会员资格、时长及限流规则仍生效。共享只读业务来源、频道画像和媒体基础设施不共享发布防重或发布量。
新执行进程不接入旧 Node 发布协调器，以现有 Python 执行器处理自己的队列。
新服务只绑定 loopback；浏览器网关按每次请求的 Cookie 校验现有页面权限，覆盖客户端传入身份。
初始仅复制最近 31 天可用指标缓存，随后独立刷新；业务表为空。
社媒分析适配器读取两套归因目录，使新流程收入继续进入同一个频道画像；不会影响发布计数隔离。

