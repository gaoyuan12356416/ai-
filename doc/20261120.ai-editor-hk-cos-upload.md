# AI 剪辑：香港 COS 分片上传

新文件由浏览器以 16 MiB 分片、3 路并发直传现有香港私有 COS。
CPU API 仅处理登录、分片签名、上传状态和媒资记录；香港独立校验进程从 COS
读取并验证文件、计算 SHA-256 和视频元数据，然后提交幂等入库回执。
已有本地素材和已打开的旧版上传页面仍兼容，历史任务不迁移、不重放。

页面展示已上传字节、速度、剩余时间与上传后的校验状态。分片临时网络失败最多重试
两次，重新选择原文件复用持久 operation ID 和原 COS UploadId，核对已上传分片的
MD5 后续传。关闭页面后仍保留已合并对象及后台校验；上传未合并时需要重新选择原文件。
不向浏览器分发 COS 密钥。上传记录按租户和用户隔离，签名绑定对象、分片、大小和 MD5。
丢失初始化或合并响应先查原对象/原会话，不重建上传或覆盖对象。

新对象采用私有 ACL，仅登录且有素材访问权限的用户可取得一小时签名预览/下载地址。
香港渲染节点通过任务租约取得 COS 取源地址，使用单独请求下载，不向 COS 传递 worker
凭据。CPU 上的既有 AI 分析/字幕功能仍在首次需要完整源文件时从 COS 缓存到数据盘，
缓存下载不属于浏览器上传请求。旧本地素材继续使用原有读取路径。

COS CORS 仅新增 `https://ai.yingliangads.com` 来源的 PUT/GET/HEAD 规则，不修改桶 ACL
或已有 CORS 规则。来源与签名头规则参见
[腾讯云 CORS 文档](https://cloud.tencent.com/document/product/436/13318)，分片大小绑定见
[Upload Part](https://intl.cloud.tencent.com/document/product/436/7750)。

## 部署与回滚

CPU 使用原 `scripts/deploy_ai_video_editing.py install SHA`，只切换独立 AI 剪辑 API
及相关静态资源。部署前在线备份 SQLite，检查旧式在途上传及独立编辑任务已空闲。
原安装脚本备份位于 `/mnt/data-disk/ai-video-editing-deploy/backups/SHA/manifest.json`。
香港把精确 GitHub SHA 的完整 features/ai_video_editing 包安装到
`/data/ai-video-editing/releases/SHA`，切换 current，并只重启独立渲染 worker；新增
`ai-video-editing-upload.service`，工作目录 `/data/ai-video-editing/upload-work`。
COS 配置变更通过 `scripts/ai_editor_cos_cors.py install BACKUP_JSON`，保留读回结果。

若切换后需要回滚，优先只恢复上传前端，让新云素材读取与校验服务保留。
完整回滚只能在无新云上传/云素材依赖时执行：CPU 原安装脚本 `rollback SHA`；香港
停止 upload worker，恢复记录的 current 指针及旧 render worker。已有 cloud_uploads
表、assets 元数据、COS 对象和业务回执必须保留。COS 规则只可用同一备份执行
`scripts/ai_editor_cos_cors.py rollback BACKUP_JSON`；其他规则保持不动。
