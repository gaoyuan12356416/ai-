# Product-aware Facebook attribution

Facebook automatic templates now store MoboReels publication snapshots in the
same task table as DramaWave. The daily report previously treated all rows as
DramaWave landing-page links; valid MoboReels rows therefore blocked collection.

The collector reads the saved MoboReels product, creator, material, story and
successful link proof. It verifies these against the task and original template
creator and freezes the resolved ownership. Existing task/Page/material/Post
receipt checks and frozen-evidence protection still apply. Missing, malformed or
conflicting proof remains unresolved. Domain name alone is never an exemption.

The existing daily report's effect and billing sources cover DramaWave. Valid
MoboReels identities are retained in the attribution ledger with product and
outside-scope reason, but never joined to DramaWave campaign IDs or represented
as zero-revenue DramaWave performance. Collector metadata reports their count.
Adding MoboReels revenue to this report requires its own verified financial
source and is outside this repair. No publisher state or historical deliveries
are rewritten. Existing unresolved rows recover through normal collection.

Validation covers legacy schemas without the new column, existing frozen
DramaWave rows, recovery, correct product ownership, mismatched evidence,
malformed snapshots, unknown publication outcomes and frozen-evidence changes.
Also run report preparation, completeness, retry and delivery deduplication tests.

Deploy the exact pushed commit using `scripts/install_social_daily_moboreels.py`.
It copies the current composite release and replaces only four attribution
functions, retaining all other AST and the deployed landing-page compatibility.
Stage with `--sha SHA --deployment-dir /mnt/data-disk/social-daily-moboreels-20261120/deployment
--expected-release PREVIOUS`, test the staged composite on Linux and run the
collector on an isolated copy of the attribution ledger before activation.

Once the three report/collector services have no in-flight PID, activate using
`--activate /mnt/data-disk/social-daily-moboreels-20261120/deployment/manifest.json`.
The installer backs up affected code and the report-owned databases, then swaps
the report release symlink. It does not restart the API or publishing services,
change timers, or touch source databases. Let the attribution collector run,
prepare the full report and use the existing delivery entrypoint/ledger to send
the authorized current-day report. GET the returned Feishu message and check
recipient, report date, amount and deletion status. A second invocation must
return already_sent. Verify enabled/active timers and their next Beijing slots.

Code-only rollback (with report/collector services idle):
`bash /mnt/data-disk/social-daily-moboreels-20261120/deployment/rollback.sh`.
Keep live ledgers, receipts and frozen facts; never restore database backups to
erase a delivered message. The old code retains the original Mobo incompatibility.
