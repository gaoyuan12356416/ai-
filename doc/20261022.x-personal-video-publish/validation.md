## 浏览器与实际本地服务

Chrome 浏览器使用正式静态文件 + `PublishingService`/`PersonalStore` + 临时 SQLite；仅 owner/账号/素材为虚构适配器。所有上游出网禁用，没有启动发布 runner。

实际确认创建手动三条任务；原键 HTTP 重放仍为同一批次。实际修改默认文案，素材池 103/104/999 预检两条有效、一条无效；失败项保留、排序及启用/暂停生效。实际 XLSX 解析后对规范化行调用同一本地服务，只有有效行进入 Excel 批次，重复重放没有新增任务。浏览器读取到这些真实临时库批次。

1440、820、390 像素视口均无页面级横向溢出（表格容器可内部滚动）；平板/手机预览在编辑区下方，手机导航可收起。真实服务记录页控制台无应用错误；早期 mock 会话曾出现浏览器扩展消息通道错误，未计为页面脚本错误。

## 复审处理

独立审查修复两项问题：保留原 X 导航分组模块权限，避免自定义旧子项权限放宽；凭证检查改为 SQLite `mode=ro` 查询，避免每个上传请求反复执行数据库迁移。复审无剩余 P0/P1/P2 发现。

## 明确限制

Chrome 自动化的文件选择事件超时。因此 Excel 验证覆盖“真实文件 → 正式随包解析器 → 实际本地 HTTP 预检/提交 → 浏览器记录回读”，未声称完整的浏览器文件选择自动操作通过。

尚未部署生产，也未验证真实 X 上传/发帖回执。生产身份、来源环境、FIFO gate 和 release 合并按 [上线说明](README.md) 单独核对。不能以离线测试通过替代真实发布成功，也不应为验收自动发真实帖子。
