# BUG-001 fb-auto-targeted-backfill

## 发现阶段

本地专项测试。

## 现象

审计报告完成文件写入后，对父目录执行 `os.open(..., O_RDONLY)` 在 Windows 返回 `PermissionError`，导致本地测试失败；Linux 生产需要保留目录 fsync。

## 复现步骤

在 Windows 执行 `test_atomic_report_does_not_overwrite`。

## 期望结果

本地可验证原子新文件语义，Linux 生产同时执行目录 fsync。

## 实际结果

文件已经创建，但 Windows 目录 fd 打开失败，函数报错。

## 根因分析

目录 fd 的打开/fsync 语义为 Unix 专用，未加平台边界。

## 修复说明

临时文件写入、文件 fsync 和 hard-link 新目标在所有平台保留；父目录 fsync 仅在非 Windows 平台执行。

## 影响文件

`scripts/fb_auto_post_targeted_backfill.py`

## 验证命令与结果

`python -m unittest scripts.test_fb_auto_post_targeted_backfill`：PASS。

## 回归结论

专项+store 52/52、FB 全量 141/141 通过，无生产 Linux 持久性能力退化。
