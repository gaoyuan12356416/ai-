# 未发布素材的执行状态说明

## 问题与修复

素材池的 `unpublished` 是池记录状态，包含历史队列占用、失败、批次停止和独立手动发布历史。旧页面把停止批次中的 `queued` 全部显示为普通占用，无法解释为什么未发布总量高但排期没有足够素材。

本次只改变只读查询和页面说明，不修改队列、批次、发布日志、模板或素材绑定，不触发 Post/Repost。

- `repaired_pending`：媒体修复后保留的操作员停止批次，显示等待安排发布。
- `batch_blocked`：本条未执行，但父批次待核查、停止或已结束；不能把同批次未执行条目误标为本条结果未知。
- `published_elsewhere`：池记录未发布，但独立历史任务已有确认的发布记录。显示历史已发布并保留自动排重边界。
- 目标账号未完成的中转原帖链接明确标注，避免当作目标发布成功。
- 页面统计使用一次响应的摘要，说明未发布、占用及各异常子类；未占用数量仍需账号、语言、媒体预检。

新增状态仅用于查询和显示，`available_pool_items`、发布状态机、会员检查和未知结果保护保持原契约。

## 验证

- 素材池、账本、日常发布、核心发布测试：150 项通过。
- 多排期界面测试：19 项通过；内联 JavaScript 语法通过。
- 新回归覆盖停止批次、同批次未知结果、实际未知结果优先级、历史独立发布、只读查询不改变数据库以及素材不重新进入自动池。
- 浏览器使用生产快照的只读结果验证状态、摘要与筛选，无发布请求。
- `audit_x_unpublished_media.py` 提供只读 HTTP/ffprobe 检测；检查上传进行中的批次时跳过媒体探测，保留实时发布流程。

## 发布与回滚

以 GitHub 提交为来源，备份当前不可变发布目录、主服务模块、Nginx/主服务页面以及 SQLite 在线快照。当前自然发布结束并取得发布锁后，才切换匹配的运行目录并重启受影响服务。保留日常定时器原状态。

回滚时恢复备份的 `features/x_posts/service.py` 和 `static/x-post-material-pool.html`（主服务及 Nginx 两份），将 `/opt/x-post-automation/current` 切回记录的旧发布目录，待没有活动发布后重启对应服务。**不恢复旧数据库或 Token，不撤销自然发布和媒体修复成果。**

具体生产 ID、完整检测结果、备份目录和部署验证保存在受控运维报告中，不纳入此代码文档。
