# X 手动发布按可投放时间预约

手动发布预检允许尚未到可投放时间的有效剧目。实际预约时间取请求时间与同产品、语言剧目的各平台可投放时间最大值；立即发布视为当前时间。晚于可投放时间的排期保持不变。确认页显示最终北京时间和自动顺延说明。

只对 `/api/x-video-publish/preflight` 与对应手动批次提交启用未来剧目解析。素材池、自动发布、Excel 及执行阶段继续使用默认的到期校验。主 API 内部只读来源路由仍需 loopback 身份认证；浏览器不能提交可信可投放时间。主 API 与普通 X Sidecar 同步部署，标签画像运行时无需修改。

首次确认重新读取剧目来源；若可投放时间后移至已确认时间之后，要求重新核对。现有预约、发布历史、未知结果和幂等重放保持原样。后台沿用已有到期领取机制，不提前上传发布。

## 验证

在当前线上复合版本的隔离副本执行 `python -m unittest scripts.test_x_manual_release_time -v`：13 项通过。Python 编译、两份 JavaScript 语法及 diff 检查通过。旧素材选择测试 29 项有 4 处失败，未修改基线与候选结果一致：已有产品规则与 SQL 结构变化导致旧断言不适用。

## 部署与回滚

GitHub 推送后，在 CPU 43.166.187.96 的干净源码目录运行 `python3 scripts/deploy_x_manual_release_time.py prepare`，对当前复合版本应用从 `9a172eef` 起的限定补丁，验证 Linux 候选并备份代码与在线 SQLite。

然后运行 `python3 scripts/deploy_x_manual_release_time.py apply DEPLOYMENT`。只切换普通 X 发布及主 API，保留既有 ExecStop 排空保护；恢复先前活动的依赖，并检查 X / YouTube 调度器。

回滚：`python3 scripts/deploy_x_manual_release_time.py rollback DEPLOYMENT`。仅还原代码和入口，不恢复旧数据库或令牌，不重放任务。实际 DEPLOYMENT 路径由 prepare 输出，并记录在部署目录的 record.json。
