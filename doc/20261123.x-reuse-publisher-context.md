# X publisher reuse-context repair

Effect-ranked templates could reserve material but fail before creating an execution run. The publisher runs as `x-post-automation`; the Tag Auto database directory belongs to `x-post-daily` and is mode 0700. Candidate-pool helpers introduced direct cross-owner database reads in `pool_scope`, `local_conflict` and sibling checks. The HTTP catch-all then reported an unrelated `x_accounts_unavailable` error.

The existing authenticated reuse broker now exposes a read-only context action returning only frozen task/account/material identity and reuse policy. Publisher helpers use that route; the broker's own checks retain direct read-only access. Internal authentication, identity mismatch, unavailable context and material conflicts produce specific safe messages through the existing XPostError/ServiceError path. No database permissions or deduplication rules change.

The deployed candidate-pool additions were captured in baseline commit `ea9cc3cf` before applying the fix. Deployment updates only three Tag publisher files and the broker's copy of `reuse.py`, preserves later unrelated changes by checking hashes, and uses the existing Tag publisher shutdown barrier. Tag Auto and its previously active triggers must be running after activation. Standard X scheduler checks supplement the explicit Tag checks.

## Recovery

The operator authorized continuation of the original 250 waiting tasks. The private `/mnt/data-disk/x-reuse-read-context-20261123/recovery-scope.json` freezes the scope. Each task retained a different material, a matching active grant and its original external task key. Before activation all 250 had zero publication attempts, no canonical execution run/queue/log, no post ID and no unknown outcome. Online database backups are in the same directory.

Do not reset tasks, reselect materials, clear grants, or create a replacement batch. The normal runner resumes their existing `retry_wait` records. Verify one execution key/run/queue per task and unique confirmed post IDs. Unknown writes stay under normal reconciliation and must never be replayed.

The unrelated drama-priority test also fails identically against the preserved baseline; that behavior is outside this change.

After committing and pushing, fetch the exact commit on the CPU host into an isolated checkout. Run `python3 -B scripts/deploy_x_reuse_publisher_context.py prepare`, then `activate`. Poll only the Tag publisher until its old process has safely exited and a new PID is active; then run `finish`. The deployment manifest and code backups are in `/mnt/data-disk/x-reuse-read-context-20261123/deployment`.

Rollback is `python3 -B <deployed-source>/scripts/deploy_x_reuse_publisher_context.py rollback`, wait for the managed restart, then `finish`. This rolls back code only. Keep all current databases, grants, publication receipts and credentials. The old code reintroduces the read failure, so recovery will wait again.
