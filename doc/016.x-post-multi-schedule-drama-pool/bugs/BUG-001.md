# BUG-001 相邻时间点和跨午夜冻结批次可能丢失

## 发现阶段

SA 代码评审。

## 现象

初版 worker 每分钟持有媒体锁完成下载、GPU 修复和逐账号发布。若超过一分钟，下一时间点因锁被跳过；原到期查询仅返回当前分钟，无法恢复。另在 00:00 会先停止前一日批次，误伤仍处于 90 秒宽限内的 23:59。

## 复现步骤

1. 配置 10:00 和 10:01。
2. 让 10:00 媒体预检持续超过一分钟。
3. 观察 10:01 worker 因锁跳过，之后不再返回 10:01。
4. 配置 23:59，在次日 00:00:30 查询，初版将其停止。

## 期望结果

所有到点身份先持久化；worker 忙碌后可恢复同日冻结批次。23:59 在 90 秒内仍有效。

## 实际结果

相邻时间点可能永久漏发；跨午夜边界提前停止。

## 根因分析

“时间点认领”和“重媒体发布”耦合在同一个锁内，且查询范围按当前日期/分钟过滤。

## 修复说明

- 新增无媒体锁 claim runner，在每分钟 `:00` 原子写 `claimed` 批次。
- worker 在 `:10` 运行并与旧任务共享 flock。
- 到期查询返回当前窗口以及同日非终态冻结批次。
- stale 清理排除仍在窗口内的前一日槽位，并将陈旧短剧队列标记 `needs_review`。

## 影响文件

- `features/x_posts/service.py`
- `scripts/x_post_schedule_claim_runner.py`
- `scripts/x_post_schedule_runner.py`
- `deploy/x-post-schedule-claim.*`
- `deploy/x-post-schedule.*`
- 相关 store/runner 测试

## 验证命令与结果

```bash
python -m unittest scripts.test_x_post_multi_schedule_store scripts.test_x_post_schedule_runner -v
```

跨午夜、旧冻结恢复和 claim 无锁用例均通过。

## 回归结论

问题关闭；上线时仍必须停用旧 `x-post-daily.timer`。
