# BUG-002 双平台短剧资源被误判为不可用

## 发现阶段

生产页面手工预览。

## 现象

短剧 `bURak9Oyn7` 在 Post 短剧池预览中返回
`drama_resource_invalid`，页面只显示“短剧资源数据不完整”，无法看到具体字段。

## 复现步骤

1. 在 Post 短剧池输入 `bURak9Oyn7`。
2. 点击检查。
3. 页面显示不可用、免费集数 0、集数 0-0。

## 期望结果

- `sub_number=0` 的剧级/平台级记录不作为可发布剧集参与校验。
- 同一集的 iOS、Android 资源行在剧元数据和媒体 URL 一致时允许合并。
- 真正的资源字段错误在页面显示字段级原因。

## 实际结果

- `sub_number=0` 被正整数校验拒绝。
- 排除 0 集后，`app` 字段不同仍会被误判为整剧元数据不一致。
- 后台将底层字段错误替换为统一提示。

## 根因分析

选择器把 `ads_drama_resource` 的所有 `type=2` 行都当作剧集行，并把平台
`app` 加入跨行剧元数据一致性键。生产数据中同一部剧存在两个
`sub_number=0` 平台记录，1–11 集又各有 iOS/Android 两行相同视频记录，
因此合法的双平台资源快照无法通过。

## 修复说明

- `sub_number` 改为非负解析；仅 `0` 作为非剧集记录忽略，负数和非法值仍拒绝。
- 至少存在一条正集数记录，否则继续 fail closed。
- `app` 不再作为剧身份一致性字段；正片行仍要求非空，并稳定返回排序后的代表值。
- 同集 URL 冲突、剧元数据冲突、缺集、无免费集等原有硬门禁保持不变。
- `drama_resource_invalid` 在中文主提示后附加具体字段原因。
