# 016.x-post-multi-schedule-drama-pool 需求与技术设计

## 背景

现有 X Post 素材池使用固定账号和单一每日时间，无法在页面上管理“哪些账号、每天哪些时间点”执行；同时没有以短剧为单位、按免费集数顺序发布的独立池。

## 目标

1. Post 素材池可选择多个有效 X 账号并配置多个北京时间发布点。
2. 新增 Post 短剧池，可录入 Dramawave 短剧 `content_id`，并独立选择账号与多个发布时间点。
3. 定时任务按冻结计划执行、全局排重、可恢复、可审计，避免配置变更、任务重叠或跨日导致重复发布。

## 范围

### 包含

- 素材池和短剧池两套独立排期配置。
- 账号列表来自当前有效且已授权账号。
- 短剧池预览、加入、查询、剧集明细和未占用记录删除。
- `ads_drama_resource` 只读查询、免费集数审计、视频预检、GPU 修复、COS 回传和 X 发布。
- 定时批次、队列、日志、预览链接、失败及待确认状态。
- 快速导航动态权限、页面禁止缓存、操作审计 best-effort。

### 不包含

- 修改 `ads_drama_resource` 或其原始视频。
- 补发未被认领的历史时间点。
- 自动跳过失败或结果未知的短剧继续发布后续剧。
- 修改既有素材池 Post 文案模板和 W2A 参数合同。

## 用户故事 / 业务规则

1. 每个池保存 `账号集合 × 发布时间集合`。一个时间点给每个已选账号创建一条 Post。
2. 同一账号不能在素材池和短剧池配置相同时间，防止同时争用一个账号。
3. 素材池严格按入池时间和池 ID 正序选择；已发布或已有队列的素材全局不可重复使用。
4. 短剧池严格按入池时间和池 ID 正序；当前剧的所有免费集发布完后才进入下一剧。
5. 同一短剧内按 `sub_number=1..N` 顺序发布；`episode_key=content_id:sub_number` 全局唯一。
6. 免费集数 `N` 取该剧所有 Dramawave app 变体记录中 `unlocked_episodes_count` 的最小值；1..N 必须连续。
7. 同一集的重复资源行仅在 URL 和元数据一致时合并；同集 URL 不一致、元数据漂移或缺集时整剧不可用。
8. 视频 URL 的 `http` 自动规范为 `https`；格式或尺寸不合规时复用 GPU 修复流程并上传 COS，再使用修复后 URL。
9. `name_tag` 未提供人工字段，因此按“剧名 hashtag + 最多两个标签 hashtag”确定性生成；无标签时至少保留剧名 hashtag。
10. 短剧 Post 文案固定为：

```text
{url}
 👆Full story continues here:☝️
Episode👉{sub_num}

{name_tag}

 {desc}
```

11. X 字数计算保留 URL、CTA、集数和 `name_tag`；仅允许截断末尾 `desc`。
12. 生产数据抽样确认描述可能包含换行；查询入口统一折叠连续空白，NUL 等非法控制字符仍拒绝。
13. 任一短剧发生预检失败、已知发布失败或结果未知，当前批次停止且该剧标记 `needs_review`，后续短剧暂停，等待人工确认。

## 交互与流程

1. 页面加载账号选项和当前配置。
2. 用户选择多个账号、增加/删除时间点并保存；版本冲突时刷新后重试。
3. 短剧 ID 在加入前查询源表并展示剧名、免费集数和校验结果。
4. 每分钟整点秒由轻量 claim 任务冻结当前时间点的配置版本和账号顺序。
5. 每分钟第 10 秒由 worker 读取冻结批次，执行账号验证、源表查询、媒体预检/修复、队列落库和顺序发布。
6. 发布日志保留短链、长链、X 预览链接、账号、素材/短剧/集数和错误。

## 技术设计

### 影响模块

- `features/x_posts/service.py`：SQLite 迁移、配置、批次、短剧池、队列、FIFO 和日志状态机。
- `features/x_posts/drama_selector.py`：只读短剧审计与集数选择。
- `features/x_accounts/oauth_service.py`：loopback 内部接口和发布权限。
- `features/x_accounts/client.py`、`app.py`：后台页面 API。
- `scripts/x_post_schedule_claim_runner.py`、`scripts/x_post_schedule_runner.py`：认领与发布。
- `static/x-post-material-pool.html`、`static/x-post-drama-pool.html`：管理页面。

### 数据结构

- `x_post_schedule_config`：`source_type` 唯一；保存启用状态、账号 JSON、时间 JSON、版本和操作人。
- `x_post_schedule_run`：`source_type + run_date + publish_time` 唯一；冻结配置版本、账号顺序和执行汇总。
- `x_post_drama_pool`：短剧元数据、免费集数、下一集数、发布数量和校验/失败状态。
- `x_post_queue`：新增 schedule、source、短剧池、episode 和 `name_tag` 字段；保留既有数据兼容。
- 唯一索引保证素材、短剧集数、幂等键和时间点不可重复。

### 调度一致性

- claim 在 90 秒窗口内以 `BEGIN IMMEDIATE + INSERT OR IGNORE` 原子认领。
- worker 与旧 daily/catch-up 共用 flock；claim 不占媒体锁，避免长视频处理让相邻时间点消失。
- 已认领的同日空队列批次可在后续分钟恢复，即使配置已变更也使用冻结账号。
- 未认领且超过 90 秒的时间点不补历史。
- 前一日 23:59 在次日 00:00:30 仍有效，00:00:31 起停止；陈旧短剧队列同步将短剧设为 `needs_review`。
- 保存配置时，当前 90 秒窗口内的时间点拒绝变更，防止边界歧义。

### 权限与容量

- 页面访问只服从快速导航配置和 `x_accounts` 模块权限，不写死管理员。
- 两个页面返回 `no-cache, no-store`。
- 短剧批量加入最多 100 个 ID，内部请求上限 5 MiB；成功响应只返回精简字段。

## 验收标准

- 两个池都能保存多个账号和多个北京时间点，并在刷新后正确回显。
- 只有选中账号进入该池的冻结批次；账号列表实时显示配置来源。
- 素材不重复、短剧不跳剧、不跳集。
- 文案逐字符符合固定模板；描述超长时仅截断描述。
- 格式/分辨率问题走 GPU 修复；失败状态和原因可在页面及日志中确认。
- 跨分钟、跨午夜、配置变更、发布失败和结果未知均不产生重复 Post。
- 旧 timer 停用后仅新 claim/worker timer 生效。

## 风险与待确认

- `name_tag` 的自动生成规则是本次实现假设；如需运营手填，应另增可编辑字段和审核流程。
- 新增短剧池部署后默认不启用自动发布；需用户在页面明确选择账号和时间。
