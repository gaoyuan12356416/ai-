# FB template editing and loading

An enabled FB automatic template can now be edited directly. A successful save
atomically creates the next immutable configuration version and sets only that
template to `disabled`. The editor confirms the disabled receipt and returns to
the list. New templates remain disabled. Invalid input, stale versions, missing
scope and an active Meta submission retain the existing state and display the
error. Existing frozen daily plans, IDs, leases and publication receipts retain
their established behavior; saving does not create a publishing run.

Read-only measurements on 2026-11-23 found the FB template list took 8 ms for five
rows, while Page group statistics took 1.34 s for 47 groups. A separate query
breakdown measured 0.87 s establishing the MySQL connection and 0.48 s executing
the statistics query. Rewriting the query as a derived join was not faster and
was not retained. X Auto's list and account options measured 32 ms and 134 ms.
The FB editor for a 2,413-Page daily plan returned 330,323 uncompressed bytes;
its existing generic Nginx route did not compress JSON.

The changes reuse display-only group statistics for 30 seconds under the exact
user/admin/owner scope. Concurrent reads of the same scope share one query;
other scopes continue independently. Failed refreshes never serve stale success.
Save-time validation instead reads only the selected live group IDs and owner
scope; activation and publication retain fresh checks. The template DTO keeps
every Page ID and local time, omitting duplicated frozen config and internal slot
fields. A dedicated Nginx location compresses this API's JSON and still proxies
to the same authenticated main API with its existing headers and timeouts.

```sh
python -m unittest tests.test_fb_template_edit_performance scripts.test_fb_target_midnight -q
node scripts/test_fb_template_edit_ui.js
node --check static/fb-auto-publish-template.js
git diff --check
```

Deploy the exact pushed GitHub commit. The installer copies the current FB
release and applies only the changed blocks; unrelated candidate-pool and other
runtime overlays are retained. It backs up SQLite online for evidence, backs up
external static files and preserves the old release. It validates the candidate,
uses the established FB owner drain/switch and checks/restores the prior FB
schedulers. The main API and other platforms are not restarted. Nginx receives
a graceful reload after `nginx -t`.

```sh
python3 scripts/deploy_fb_template_edit_performance.py prepare --folder /mnt/data-disk/fb-template-edit-performance-20261123/release
python3 scripts/deploy_fb_template_edit_performance.py apply --folder /mnt/data-disk/fb-template-edit-performance-20261123/release
```

Rollback from the same fetched source directory:

```sh
python3 scripts/deploy_fb_template_edit_performance.py rollback --folder /mnt/data-disk/fb-template-edit-performance-20261123/release
```

Rollback restores the previous FB code, changed static files and removes the
dedicated compression config. It preserves the current database, saved template
versions/statuses and all business receipts. Later unrelated file/release changes
must be reconciled rather than overwritten. Timing figures above describe
server-side samples, not the complete browser load time.
