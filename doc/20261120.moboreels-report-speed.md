# Moboreels report query latency

The effects report performed five serial FIFO-gated MySQL reads on every filter
change. A production read-only baseline measured 8.67–9.03 seconds for both
7-day and 31-day ranges. Most time was repeated connection/gate overhead.

The effects financial projection now reads the exact ad-day pointers and link
story names with the financial query, then joins the unique catalog key while
reading promotion mappings. Typical cold reads use two connections. Larger ID
sets retain bounded 500-ID batches. Legacy report queries remain unchanged.

One persistent effects reader reuses the financial projection for 30 seconds
across grouping/search/channel filters of the same actor, authorization scope
and dates. Identical in-flight reads share their result. Cache entries are
bounded to 32 and failures are never cached. Report receipt changes, promotion
receipts, catalog-sync changes and new linked story IDs invalidate reuse. Click
counts and local link attribution are read on every request. Each response is
detached; admin and owner data never share a key. The browser also coalesces an
identical pending request while cancelling superseded filters; a newly observed
sync completion forces a new request.

Validation: effects/cache regression tests, legacy order tests, service/bridge
authorization tests and the UI interaction harness. Production acceptance uses
frozen SQLite copies and the read-only replica to compare old/new complete
responses (apart from query time), then measures the activated HTTP endpoint.
No upstream refresh, publication or schema migration is required.
